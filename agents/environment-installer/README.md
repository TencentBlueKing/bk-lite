# 环境安装包

Linux x86_64 + systemd；管理员导出一个 `.run`，目标主机执行一次。入口不依赖 Python、Go、curl、jq；素材从客户内网 NATS TLS 下载。完整素材离线模式不在此版范围。

2026-11-13 已在两台全新 Ubuntu 22.04.5 x86_64 VM 通过同包安装、自动注册、Telegraf 连续上报及幂等重跑。同日最新前后端完整镜像构建与真实管理页导出、安装记录、吊销联调通过。此结果不扩展为其他发行版或正式发布支持声明。

## 构建与部署输入

使用 Go 1.23.7，在发布环境提供 Ed25519 验证公钥（base64，无换行）：

```sh
SIGNING_PUBLIC_KEY='<发布验证公钥>' sh agents/environment-installer/build.sh
```

输出 `agents/environment-installer/dist/environment-entry` 和 `setup-worker`，均为 Linux amd64 静态程序。签名私钥不参与编译，也不得提交代码或打入容器镜像。

平台服务通过受控只读挂载及环境变量读取：

- `ENVIRONMENT_INSTALLER_LAUNCHER_FILE`：对应发布公钥的 environment-entry。
- `ENVIRONMENT_INSTALLER_WORKER_FILE`：同次发布的 setup-worker。
- `ENVIRONMENT_INSTALLER_SIGNING_KEY_FILE`：Ed25519 PKCS8 PEM 私钥文件，限服务账户读取。

平台需要应用 node_mgmt 0050 迁移。部署和迁移须按实际测试/发布目标另行执行；本说明不是生产部署授权。

云区域必须配置 HTTPS `NODE_SERVER_URL`、`NATS_PROTOCOL=tls`、TLS `NATS_SERVERS` 和最小权限的 `NATS_INSTALLER_USERNAME/PASSWORD`，不回退管理员下载凭据。控制器 ZIP 必须使用本次更新后的 Linux install.sh；导出预检会检查脚本存在、大小和环境安装协议标记，旧 ZIP 在创建授权前被拒绝；安装器保留二次检查。包固定为已发布 Linux x86_64 Controller 版本且具有 SHA-256。

下载账户除对象读取/消费者权限外，还需要素材桶级 `$JS.FC.OBJ_<bucket>.>` 流控响应发布权限；必须使用实际桶名，不能以管理员或全局通配权限替代。目标平台 CA 与托管组件使用的 NATS CA 均需持久化，不能跳过证书校验。

## 管理与执行

节点管理 → 环境安装包。管理员选择版本、当前组织、有效期、额度及必需托管组件；不选可选组件时仍自动安装 NATS Executor 基础依赖，选择项绑定现有 Linux x86_64 默认采集配置。按素材压缩/展开/暂存开销填写安装预留空间；平台 CA 从当前云区域 `NODE_SERVER_CA` 自动带入，无需在导出页面手工填写；可填写唯一匹配的管理网段。API 显式传入 CA 的兼容能力保留；配置的 CA 无法解析时，导出失败且不创建授权。空间元数据自动计算尚待接入发布流程。

导出文件包含限时安装授权，不等于加密文件。通过可信交付渠道核对下载页面 SHA-256。不要将文件放进公共代码库或公开文件服务器。

```sh
sh ./install-controller-<包ID>.run
```

程序保存随机 node_id/request_id 到 `/var/lib/bklite-environment-installer/state.json`（0700 目录、0600 文件），同一包重跑复用身份；不得复制此目录制镜。跨环境、未知旧安装、地址变化会停止，不能用删除状态文件来绕过冲突。

只有本地 bk-sidecar active、node-id 一致，且平台接收本次安装的摘要回执、近期真实心跳及全部必需组件的正常状态后返回 0。已注册但必需组件异常时保留 registration=success，等待期限结束后退出 70；恢复组件后可用同一个包重试。组件健康不代表业务数据接入已验收。普通 Node 编辑时间不能冒充心跳。安装失败后保留身份，重跑前按错误阶段核查；不会自动接管其他安装。

退出码：10 预检/包校验，20 授权/清单不匹配，30 网络/TLS/素材下载，40 本地安装，50 注册未确认，60 身份/已有安装冲突，70 必需组件未健康。stdout 为一行不含凭据的 JSON，stderr 只显示阶段。已获得 install_id 后会尽力回报枚举失败阶段和退出码；不上传日志正文。新会话请求用请求头传递短期凭据，避免 URL 访问日志记录 Token。官方安装器原始输出不透传，避免其错误正文泄露会话资料。

吊销授权阻止后续申请及未完成注册；已注册节点继续运行。重新导出会创建新的授权，旧授权须按交付需要显式吊销。

## 验证边界

本地覆盖签名/素材篡改、TLS/重定向、状态持久化、目录暂存、服务失败、限额/范围/吊销、跨授权地址冲突、首个和后续心跳、导出事务与管理员权限。SQLite 用例不证明 PostgreSQL 并发锁行为；真实服务/组件健康、无 TTY 两主机安装、镜像克隆冲突、运行期重试、发行版支持和 UI 亮暗主题需保留单独证据。

## PR 审查修正（2026-11-16）

- 环境安装生成配置始终使用严格 TLS。公共 Linux 模板保留旧安装路径原有行为，本次不对旧安装静默迁移 TLS 策略。
- 服务端授权/额度/请求拒绝返回退出码 20，不标记可重试；网络、429 和 5xx 返回 30。错误正文不透传。
- 已注册但本地服务停止或身份文件缺失时，立即退出 60，要求先恢复既有服务；不自动覆盖目录，也不进入必然超时的重试循环。
- 授权列表由服务端按组织、创建者和云区域过滤后分页，单页最多 100 条。安装结果同样由服务端分页，返回 count/items，支持查看超过 1,000 台的记录。
- Server 显式固定 Kombu 5.6.2，保留 Redis 5.0.1；避免 pip 构建升级到要求 Redis ≥6.1 的 Kombu 5.7，同时遵守 FalkorDB 1.2 的 Redis <6 约束。

`deploy/environment-package-lab` 仅为固定隔离环境验收工具，不能作为通用生产部署入口。正式部署仍需通过受控挂载提供上述签名与安装产物。
