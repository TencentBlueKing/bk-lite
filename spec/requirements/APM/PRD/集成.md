## 1. 背景与目标

APM 集成菜单负责把应用遥测安全接入平台，并让用户在接入后看到实际运行实例。它包含两个并列的二级页：

- **添加接入**：选择接入方式，创建受控接入源，配置云区域和默认组织，获得 OTLP 端点、一次性凭证与安装片段。
- **接入列表**：按运行实例展示已经上报数据的 Pod、进程或节点，回答“接进来了什么、通过什么方式、最近是否仍在上报”。

接入列表不是服务目录的另一种排序。接入列表一行一个运行实例；服务目录把同名实例聚合为逻辑服务，用于整体性能和健康分析。

## 2. 范围

P0 包含：

- SDK 接入：Java、Node.js、Python、.NET、Go。
- 自建 OpenTelemetry Collector exporter 接入。
- 接入源创建、一次性 Token、轮换、禁用和默认组织管理。
- 按环境生成 `service.instance.id` 的配置片段。
- 接入实例列表、状态、组织调整、归档与服务下钻。

P0 不包含：

- eBPF/OBI 和 Kubernetes Operator 的真实安装编排；卡片可以保留“后续支持”状态。
- 远程下发或自动修改客户应用配置。
- 高级采样、配额、用量与存储治理页面。

## 3. 领域对象

### 3.1 接入源

用户完成“添加接入”时创建一个接入源。接入源保存：

- 名称、接入方式和云区域。
- 一个或多个默认组织。
- 启用状态、凭证摘要/前缀、首次和最近接收时间。
- 创建、修改审计信息。

接入源不是服务身份，也不是运行实例。它负责证明“这批 Span 从哪个受控入口进入”，并为新发现实例提供默认组织和接入方式。

### 3.2 接入实例

接入实例唯一标识为：

```text
service.namespace + service.name + service.instance.id
```

- 同一水平扩展服务的多个 Pod 必须使用相同 namespace/name、不同 instance ID。
- Pod 重建产生新 instance ID 时生成新实例；旧实例按静默和归档规则保留历史。
- 缺少 instance ID 的 Span 可以进入 Trace 和服务指标，但不生成猜测出来的实例记录。
- 实例的接入方式来自受信接入源，不采信客户端自报的 `integration_method`。

### 3.3 逻辑服务

逻辑服务唯一标识为：

```text
service.namespace + service.name
```

接入源、instance ID、环境和版本都不参与逻辑服务身份。接入列表中的多个实例可以下钻到同一个服务详情。

## 4. 页面设计

### 4.1 添加接入总览

按接入方式分组展示卡片：

- SDK：Node.js、Java、Python、.NET、Go。
- OpenTelemetry Collector。
- eBPF/OBI（P0 只展示后续支持）。
- Kubernetes Operator（P0 只展示后续支持）。

点击 P0 可用卡片进入接入详情；未开放卡片不可进入伪配置流程。

### 4.2 接入详情

详情页采用两步纵向布局，不使用嵌套 Tabs。

#### ① 上报端点

表单字段：

| 字段 | 规则 |
| --- | --- |
| 接入源名称 | 必填，便于识别用途 |
| 云区域 | 必填，决定只读 OTLP 端点 |
| 默认组织 | 多选、至少一个；成为新实例默认权限 |
| API 端点 | 只读，统一为区域 APM Gateway `/v1/traces` |

用户提交后创建接入源并显示一次 Bearer Token。离开成功态后不能再次查看原 Token，只能轮换。

#### ② 接入配置

SDK 页面提供“自动探针”和“Docker 运行”两个片段；自建 Collector 提供 exporter YAML。片段统一包含：

- `OTEL_EXPORTER_OTLP_ENDPOINT`
- `OTEL_EXPORTER_OTLP_PROTOCOL`
- `OTEL_PROPAGATORS=tracecontext,baggage`
- `service.name`
- `service.namespace`
- `deployment.environment`
- `service.version`
- 动态 `service.instance.id`
- `Authorization: Bearer <token>`

实例 ID 按环境生成：

| 环境 | 推荐来源 |
| --- | --- |
| Kubernetes | Pod UID（Downward API） |
| Docker | 容器实例 ID |
| 固定主机 | 平台实例 ID或稳定机器实例 ID |
| 无天然稳定 ID | 探针启动时生成 UUID |

不得在所有副本中复制同一个写死的 `service.instance.id`。

### 4.3 接入列表

顶部工具栏：

- 服务/应用关键字搜索。
- 接入方式筛选。
- 环境筛选。
- 组织筛选。
- 时间窗：15m、1h、4h、1d、7d，默认 7d。

表格列：

| 列 | 说明 |
| --- | --- |
| 服务 | `service.name`，链接到逻辑服务详情 |
| 应用 | `service.namespace`，空值显示“未归类应用” |
| 环境 | `deployment.environment` |
| 实例 ID | `service.instance.id`，支持安全省略与完整查看 |
| 接入方式 | 来自受信接入源 |
| 组织 | 当前实例可见/可操作组织 |
| 接入时间 | 该实例首次发现时间 |
| 最近上报 | 该实例最近 Span 时间 |
| 状态 | 活跃、静默、已归档 |
| 操作 | 查看、调整组织、归档/解档（按权限显示） |

状态规则：

- 活跃：最近 15 分钟有 Span。
- 静默：超过活跃窗但不足 7 天。
- 已归档：静默至少 7 天，或用户手动归档。
- 新 Span 到达后自动解档。

实例状态不复用服务状态。一个 Pod 静默时，只影响该实例，不会把仍有其他活跃实例的服务归档。

## 5. 组织与权限

- 接入源支持多个默认组织。
- 新实例首次发现时复制接入源当时的组织集合。
- 实例默认处于“继承”模式：接入源组织变化时同步更新。
- 用户手动调整实例组织后切换为“自定义”模式，不再被默认权限覆盖；可显式恢复继承。
- 当前实例组织关系同时控制历史和未来实例明细、Trace 的可见与可操作范围；不复制或重写底层 Span。
- 服务拥有独立组织权限，初始复制第一个成功发现实例的组织，后续实例组织变化不自动修改服务权限。
- 服务指标是同一环境下全部实例的全局聚合，不受实例组织权限影响；没有某实例权限的用户不能查看该实例和对应 Trace，但可能在有服务权限时看到包含其贡献的聚合值。

## 6. 接入鉴权与数据可信边界

- 外部端点至少提供 OTLP/HTTP `POST /v1/traces`；内部 Collector 同时支持 4317/4318。
- `/telegraf/api` 保留给现有 Influx 输入，不得接收 OTLP。
- 反向代理校验 Bearer Token，通过内部认证结果传递接入源 ID；错误、禁用或撤销凭证拒绝请求。
- 外部请求中的内部来源 Header 和 `bk.*` 保留属性必须被移除，再由可信网关注入 `bk.ingest_source.id`。
- 明文 Token 不落数据库、不写日志、不写操作记录、不写 Span；创建和轮换时只显示一次。
- 认证不可用时返回明确 503，不允许匿名降级。Token 正向缓存必须有短且明确的撤销延迟上限。
- Django 不接收或转发原始 Span；Collector 负责 OTLP、批处理、派生指标、采样和存储导出。

## 7. 接入发现与数据一致性

- Collector 不同步调用 Django 创建目录对象。
- 运行期对账任务从最近活跃的遥测维度中幂等发现服务和实例，正常情况下 1–2 分钟内出现在接入列表。
- 并发发现由数据库唯一约束仲裁；`first_seen_at` 不后移，`last_seen_at` 单调前进。
- 接入源、服务、实例和组织保存在 PostgreSQL；原始 Span 保存在 VictoriaTraces，派生指标保存在 VictoriaMetrics。
- 外部存储或对账失败不得阻断 BK-Lite Server 启动；页面区分“无数据”和“存储不可用”。

## 8. 验收标准

1. 创建接入源必须选择至少一个组织，成功后只显示一次 Token；刷新后只能轮换。
2. 接入片段包含授权头和动态实例 ID，不再输出 `/telegraf/api` OTLP 配置。
3. 无 Token、错误 Token、禁用源和伪造来源属性不能写入可信数据链路。
4. 同名服务的三个不同 instance ID 在接入列表显示三行，在服务目录聚合成一个服务。
5. Pod 重建产生新实例，旧实例进入静默并最终归档，历史不被覆盖。
6. 新实例继承多个默认组织；自定义实例权限后不再随接入源变化，恢复继承后重新同步。
7. 接入时间、最近上报和状态按实例计算，不复用服务目录状态。
8. 服务链接和实例查看进入不同详情语义；实例权限不足不能通过 trace ID 越权访问。
9. 缺少 instance ID 的数据不会产生伪实例，并能在接入诊断中看到修复提示。
10. Collector、VictoriaTraces 或对账任务不可用时 Server 正常启动，接入与查询返回明确降级状态。
