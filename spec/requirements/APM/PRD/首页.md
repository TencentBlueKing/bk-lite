# APM · 首页

## 1. 背景与目标

APM 首页是平台级 APM 看板,承担"看一眼就知道整个 APM 生态当前健康度"的核心入口职责。首页不重复"服务"一级菜单的单服务详情能力,而是从全局视角汇总健康度、活跃服务、SLO 违约、最近错误、最近部署等关键指标,为运维与 SRE 角色提供进入 APM 后第一眼就要看到的全局画面。

首页是 P0 阶段的能力,在 P0 接入首批数据后即可使用;其内容以各域汇总卡片为主,卡片内容来源于其他菜单的近窗数据,不维护独立状态。

## 2. 范围定义

- 全局健康度:平台级 APM 整体健康度,以服务健康分级汇总表达。
- 活跃服务:近窗(默认 15 分钟)有数据上报的服务清单与数量摘要。
- SLO 违约摘要:近窗 SLO 剩余预算 / 燃尽率 / 违约状态的服务清单。
- 最近错误:近窗(默认 1 小时)新出现的 Issue 或激增 Issue 摘要。
- 最近部署:近窗(默认 7 天)部署事件清单与上线版本摘要。

## 3. 关键能力

### 3.0 权限模型(APM 首页适用)

APM 首页(`/apm`)的可见与可操作遵循 bklite 统一权限体系:

- **菜单操作**:首页菜单项在 bklite 角色系统中声明 `operation=["View"]`;首页是只读汇总页,所有卡片均为只读展示,不涉及 Operate 操作。
- **数据隔离**:首页 5 张卡片均按 Group 隔离,各 Group 看到的是本 Group 范围内的汇总数据。
- **可见性**:Group 内全员(具备 APM 首页菜单 `View` 权限的用户)均可见首页 5 张卡片;不引入"按角色隐藏卡片"的能力。
- **角色配置**:不在 APM 内部声明"首页管理员"角色;用户对首页的查看与点击下钻操作,只需具备 APM 首页菜单的 `View` 权限,由系统管理员在"系统管理 → 角色"中给角色配菜单 operation。

### 3.1 全局健康度

- 以平台级汇总卡片形式展示 APM 当前整体健康度,基于"服务"菜单中各服务的健康分级统计,字段包括健康服务数、警告服务数、严重服务数、待定服务数、陈旧/失联服务数。
- 全局健康度仅作为汇总,点击后跳转到"服务"菜单并按健康严重度排序。

### 3.2 活跃服务

- 展示近窗(默认 15 分钟)有数据上报的服务数量与清单。
- 服务数量按环境(生产/预发/开发)分组统计,点击进入"服务"菜单并按对应环境过滤。
- 服务清单字段包括服务名、版本、吞吐、错误率、P99 时延,点击进入对应服务详情。

### 3.3 SLO 违约摘要

- 展示近窗(默认 1 小时)SLO 违约或燃尽率超阈的服务清单,字段包括服务名、SLO 名称、剩余预算、燃尽率、违约状态、最近一次评估时间。
- 支持按剩余预算排序、按燃尽率排序、按违约状态排序;点击 SLO 条目进入对应 SLO 详情(在"服务"菜单的 SLO 二级)。
- 仅展示配置了 SLO 且近窗有数据的服务,未配置 SLO 的服务不展示。

### 3.4 最近错误

- 展示近窗(默认 1 小时)新出现的 Issue 数量与清单,字段包括 Issue 标题、影响服务、首现时间、累计次数、是否激增、状态。
- 展示激增 Issue(Spiking 标记)的快速入口,点击进入"探索"菜单的错误二级并定位到对应 Issue。
- 展示回归 Issue(Regression 标记)的快速入口,与激增 Issue 共享入口,点击进入对应 Issue 详情。

### 3.5 最近部署

- 展示近窗(默认 7 天)部署事件清单,字段包括服务名、版本、部署时刻、来源(推断/CI 上报)、部署人。
- 点击部署事件进入"服务"菜单的对应服务详情,以该版本为过滤条件。
- 部署列表按"按服务"分组,支持折叠/展开。

## 4. 关键规则

- 首页所有卡片均以"近窗数据"为唯一判定依据,不支持历史趋势展示;趋势分析由"服务"菜单提供。
- 首页卡片的内容由各域菜单(服务/SLO/探索错误)的后端接口在首页接口中聚合返回,首页不维护独立缓存。
- 首页时间窗与各域菜单时间窗独立,首页默认近窗 15 分钟(活跃)/1 小时(SLO 与错误)/7 天(部署),不可在首页自定义。
- 首页按 Group 隔离,各 Group 看到的是本 Group 范围内的汇总数据;Group 内全员(具备 APM 首页菜单 `View` 权限)均可见首页 5 张卡片。
- 首页支持"空状态":未接入任何应用时,首页展示"前往集成菜单完成接入"引导。
- 首页不展示具体 Span / Trace / Issue 详情,点击汇总条目后跳转到对应菜单的详情页。

## 5. 关键技术架构选择

- 首页汇总接口由 APM 后端聚合服务统一提供,聚合服务按"服务健康 / 活跃 / SLO / 错误 / 部署"五张视图分别查询 VictoriaMetrics 与 APM 元数据库,合并后返回前端。
- 活跃服务与 SLO 摘要以 VictoriaMetrics 预聚合查询为主,Issue 摘要以 APM Issue 元数据库(Django ORM)查询为主,部署摘要以部署事件表(Django ORM)查询为主。
- 首页接口采用"按域分项查询 + 合并返回"模式,各分项查询独立超时,任一分项失败不影响其他分项返回;失败分项以"加载失败,点击重试"占位呈现。
- 首页不引入新表与新索引,所有数据来源于既有域(服务 / SLO / 错误 / 部署),首页接口为聚合层而非数据层。
- 首页加载以"近窗小数据量"为前提,默认单接口响应在 200ms 内;若数据量超过阈值,后端按服务数做分页裁剪,首页只展示前 N 条并附"查看更多"入口。
- 首页的数据查询接口在 WHERE 条件中按用户所属 Group 过滤,跨 Group 数据不可见;不引入跨 Group 协同机制。

## 6. 验收标准

- 用户进入 APM 首页可看到全局健康度、活跃服务、SLO 违约摘要、最近错误、最近部署五张汇总卡片。
- 全局健康度按"健康 / 警告 / 严重 / 待定 / 陈旧/失联"统计服务数,点击进入"服务"菜单并按健康严重度排序。
- 活跃服务按环境分组统计,服务清单含服务名、版本、吞吐、错误率、P99 时延,点击进入对应服务详情。
- SLO 违约摘要仅展示近窗有数据且已配置 SLO 的服务,支持按剩余预算、燃尽率、违约状态排序,点击进入 SLO 详情。
- 最近错误展示近窗新出现与激增的 Issue,支持快速定位到对应 Issue 详情。
- 最近部署按服务分组,支持折叠/展开,点击进入对应服务详情并按版本过滤。
- 首页未接入任何应用时,展示"前往集成菜单完成接入"引导。
- 首页按 Group 隔离,跨 Group 数据不可见;Group 内全员(具备 `View` 权限)均可见首页 5 张卡片。
- 首页分项加载失败时,失败卡片以"加载失败,点击重试"占位呈现,不影响其他卡片。
- 首页菜单的 `View` 权限在角色系统中声明,Group 管理员通过系统管理中"角色 → 菜单 operation"控制本 Group 成员对首页的访问;不在 APM 内部声明"首页管理员"角色。
