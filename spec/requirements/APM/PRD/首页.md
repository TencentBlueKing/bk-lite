# APM · 首页

## 1. 背景与目标

APM 首页是平台级 APM 看板,承担"看一眼就知道整个 APM 生态当前健康度"的核心入口职责。首页不重复"服务"一级菜单的单服务详情能力,而是从全局视角汇总健康度、活跃服务、SLO 达成、实时告警、服务排行等关键指标,为运维与 SRE 角色提供进入 APM 后第一眼就要看到的全局画面。

首页是 P0 阶段的能力,在 P0 接入首批数据后即可使用;其内容以各域汇总卡片为主,卡片内容来源于其他菜单的近窗数据,不维护独立状态。

首页定位是「控制塔」风格的实时驾驶舱:顶部 6 个全局主指标(应用 + 服务 + 告警 + 请求 + 错误 + P95)让 SRE 5 秒内对平台态势有判断,中段三块按"分布 / 趋势 / 实时事件"分别回答"严重的有多少 / 趋势是涨是跌 / 现在在告警什么",下段按"排行 / 概览"回答"谁是问题大户 / SLO 守住了没"。首页不展示具体 Span / Trace / Issue 详情,点击汇总条目后跳转到对应菜单的详情页。

## 2. 范围定义

首页为只读汇总页,数据来源于既有域(服务 / SLO / 事件 / 接入),首页接口为聚合层而非数据层。首页不维护独立缓存,卡片内容由 APM 后端聚合服务按域分项查询后合并返回,任一分项失败不影响其他分项返回,失败分项以"加载失败,点击重试"占位呈现。

首页按 Group 隔离,各 Group 看到的是本 Group 范围内的汇总数据;Group 内全员(具备 APM 首页菜单 `View` 权限的用户)均可见首页所有段,不引入"按角色隐藏卡片"的能力。

首页支持"空状态":未接入任何应用时,首页展示"前往集成菜单完成接入"引导,首屏不出现 0 数值的空 KPI 段以避免误导。

首页分以下 7 个段:

- **§3.1 KPI 概览(顶部 6 卡)**:应用数量 / 服务数量 / 活跃告警数 / 请求量 / 错误请求数 / P95 延迟,每个 KPI 配 sparkline,主数值时间窗跟随页面顶部"时间窗"控件。P0 阶段 KPI 卡不展示"较昨日"同比。
- **§3.2 健康度分布**:基于服务健康分级的环形图,4 段(健康 / 警告 / 严重 / 未知)。
- **§3.3 健康度趋势**:3 条线(整体健康度 / 核心服务 / 外部依赖)的时间序列图,默认近 1 小时,支持切换 1h / 4h / 1d。
- **§3.4 实时告警**:当前未恢复的告警清单,按触发时间倒序,含服务 / 告警名 / 状态 / 触发时长。
- **§3.5 服务 TOP5 按错误率**:近窗 15 分钟错误率最高的 5 个服务,横条展示。
- **§3.6 P95 响应时间 TOP5**:近窗 15 分钟 P95 时延最高的 5 个服务,横条展示。
- **§3.7 SLO 概览**:已配置 SLO 的服务达成情况,4 列表格(服务 / 可用性目标 / 达成率 / 状态)。

P0 阶段不展示"最近部署"独立段(部署信息在服务菜单的时序图叠加中体现)。

## 3. 关键能力

### 3.0 权限模型(APM 首页适用)

APM 首页(`/apm`)的可见与可操作遵循 bklite 统一权限体系:

- **菜单操作**:首页菜单项在 bklite 角色系统中声明 `operation=["View"]`;首页是只读汇总页,所有段均为只读展示,不涉及 Operate 操作。
- **数据隔离**:首页所有段均按 Group 隔离,各 Group 看到的是本 Group 范围内的汇总数据。
- **可见性**:Group 内全员(具备 APM 首页菜单 `View` 权限的用户)均可见首页 7 段;不引入"按角色隐藏段"的能力。
- **角色配置**:不在 APM 内部声明"首页管理员"角色;用户对首页的查看与点击下钻操作,只需具备 APM 首页菜单的 `View` 权限,由系统管理员在"系统管理 → 角色"中给角色配菜单 operation。

### 3.1 KPI 概览(顶部 6 卡)

首页顶部一行 6 个 KPI 卡片,每卡含图标、指标名、主数值、近窗趋势 sparkline,横向等宽排布。SRE 进入首页 5 秒内,凭这一行即可形成"平台态势如何"的基本判断。6 个 KPI 在五个维度上完全正交:规模(应用 + 服务) / 事故(活跃告警) / 流量(请求量 + 错误请求) / 性能(P95 延迟)。P0 阶段 KPI 卡不展示"较昨日"同比 delta,主页只回答"现在是多少"与"近窗走向",不开新窗口、不做跨日对比,避免长周期口径不一致误导。

6 个 KPI 的口径如下(均按 Group 隔离,主数值时间窗跟随页面顶部"时间窗"控件:默认 1h,可在 15m / 1h / 4h / 1d / 7d 间切换;sparkline 时间窗为主时间窗的下一档短窗,见下表):

| 指标 | 主数值口径 | sparkline 时间窗 |
|---|---|---|
| **应用数量** | 选定时间窗内 `service.namespace` 去重数(OTel 语义下,一个应用 = 一个 namespace,包含该 namespace 下的所有 service) | 主时间窗长度内的等分点(15m → 15 段 / 1h → 24 段 / 4h → 24 段 / 1d → 24 段 / 7d → 28 段) |
| **服务数量** | 选定时间窗内 `service.name` 去重数 | 同上 |
| **活跃告警数** | 当前触发且未恢复的告警数(严重 + 警告,时间窗不影响,始终为"当前未恢复"快照) | 近 24 小时,每小时 1 个点 |
| **请求量** | 选定时间窗内入口 Span 速率,单位 req/s,所有服务入口 Span 速率之和(选定时间窗内均值) | 主时间窗长度内的等分点 |
| **错误请求数** | 选定时间窗内错误 Span 速率(状态码 5xx 或 `span.status_code = ERROR`),单位 req/s,所有服务错误 Span 速率之和(选定时间窗内均值) | 主时间窗长度内的等分点 |
| **P95 延迟** | 选定时间窗内入口 Span 时延的第 95 百分位,单位 ms(选定时间窗内 P95) | 主时间窗长度内的等分点 |

KPI 数值格式约定:整数(128 / 24)直接显示,带单位(3.42k req/s / 285ms)按需精简到 2 位有效数字;无数据显示「—」而非 0 以避免误导。

6 个 KPI 横向均分容器宽度(等宽,各 1/6),卡内布局统一:左上图标(指标主色) + 指标名(12px 灰) + 主数值(28-32px 黑 / 表格数字字距) + sparkline(底部 28-32px 高,无较昨日 delta)。每张卡本身不可点击下钻,趋势 sparkline 回答"近窗走向"。

### 3.2 健康度分布(环形图 + 图例)

基于服务健康分级(共 5 档:健康 / 警告 / 严重 / 待定 / 陈旧/失联)做视觉汇总,以环形图 + 中心总数 + 右侧图例的形式展示。

- **环形图**:4 段,健康(绿) / 警告(黄) / 严重(红) / 未知(灰)。其中"未知"档位 = "待定"与"陈旧/失联"两档的视觉合并(不发明新档位,仅展示侧把待定 + 陈旧/失联合并为"未知")。
- **中心数字**:当前 Group 内总服务数(数字 + 副标题"总服务数")。
- **图例**:每行一段,色点 + 档位名 + 服务数 + 占比百分比。
- **交互**:点击图例某一行,跳到"服务"菜单并按该健康档位预过滤(档位 = 警告 / 严重直接跳该档;档位 = 未知跳"待定 + 陈旧/失联"二档的并集);点击中心数字,跳"服务"菜单并按健康严重度排序。

环形图以 SVG 自绘,不引入 echarts / recharts 等图表库;环形内圈半径固定、外圈半径固定,4 段按计数比例分配角度,段与段之间留 1px 白缝以提升可读性。

### 3.3 健康度趋势(3 线时序图)

展示 APM 平台 3 条健康度曲线在选定时间窗内的变化,辅助回答"现在是涨是跌"。

- **3 条线**:整体健康度(平台所有近窗上报服务的健康度均值) / 核心服务(被客户标记为「关键链路」的服务子集的均值) / 外部依赖(被标记为「外部依赖」的服务子集的均值)。
- **纵轴**:0% - 100%,网格线在 0% / 25% / 50% / 75% / 100% 5 档;纵轴标签为百分比。
- **横轴**:时间,时间窗可切换(顶部右侧下拉,默认「近 1 小时」,可选「近 4 小时」/「近 1 天」),切换后横轴时间刻度相应变化(1h 为每 15 分钟 1 刻度,4h 为每 1 小时 1 刻度,1d 为每 4 小时 1 刻度)。
- **图例**:图下方,3 条线各一行,色点 + 名称 + 当前窗口内的均值数字。
- **无数据线**:若某条线在窗口内无数据(如尚未标记核心服务),该线不画、图例中显示「— 无数据」而非 0 直线,以避免误导。

健康度趋势图以 SVG 自绘;线宽 1.5px,无平滑(直接折线连接相邻数据点),线下方可加 8% 透明度渐变填充以增强可读性(默认关闭,留克制色)。

### 3.4 实时告警

展示当前触发但未恢复的告警,按触发时间倒序(最近触发的在顶)。仅展示"正在告警"事件,已恢复的告警不展示在本段;P0 阶段告警的「分派 / 认领 / 关闭」操作由"事件"菜单承载,首页段仅做汇总展示,不下放操作入口。

- **告警条目字段**:服务名(链接,跳该服务详情) / 告警名(摘要,如"错误率过高" / "P99 异常" / "连接池告警"等) / 状态(严重 / 警告) / 触发时长(相对时间,如"刚刚" / "2 分钟前" / "5 分钟前")。
- **状态色**:严重(红) / 警告(黄),与 KPI 中的"告警中"主色保持一致。
- **默认行数**:首页展示最多 5 条,超出 5 条时底部出现"查看全部 →"链接,跳到"事件"菜单的"告警中"二级页。
- **空状态**:无未恢复告警时,本段显示"一切正常"文案 + 绿色 ✓,与全局健康度段形成"段间互证"。

### 3.5 服务 TOP5 按错误率

按近窗 15 分钟错误率降序取前 5 个服务,以横条形式展示。横条长度按该服务错误率占 TOP5 中最大错误率的比例分配,辅以该服务错误率与 P95 时延副信息。

- **行字段**:服务名(链接,跳该服务详情) / 错误率横条(主色按严重度:≥ 1% 红,< 1% 且 ≥ 0.1% 黄,< 0.1% 绿) / 错误率数值(右侧) / P95 时延(副信息,小字灰)。
- **排序**:默认按错误率降序,不可在首页段自定义排序(同 spec §4 首页时间窗不可自定义原则)。
- **"查看全部 →"**:跳到"服务"菜单并按错误率降序排序。

### 3.6 P95 响应时间 TOP5

按近窗 15 分钟 P95 时延降序取前 5 个服务,以横条形式展示。横条长度按该服务 P95 占 TOP5 中最大 P95 的比例分配,辅以该服务吞吐与错误率副信息。

- **行字段**:服务名(链接,跳该服务详情) / P95 横条(主色按 P95 严重度:≥ 1s 红,≥ 300ms 且 < 1s 黄,< 300ms 绿) / P95 数值(右侧,带单位 ms) / 吞吐(副信息,如"2.1k/s",小字灰)。
- **排序**:默认按 P95 降序,不可在首页段自定义排序。
- **"查看全部 →"**:跳到"服务"菜单并按 P99 时延降序排序(P95 / P99 排序在服务菜单等价,选 P99 因为可读性更高)。

### 3.7 SLO 概览

展示已配置 SLO 且近窗有数据的服务达成情况,以 4 列表格形式呈现。表格不展示 SLO 详情(SLI 定义 / 错误预算时序 / 燃尽率时序等),仅做总览,详情由"服务 → SLO"二级菜单承载。

- **列字段**:服务名(链接) / 可用性目标(百分比,如 99.9%) / 达成率(实际值,百分比) / 状态(达成 / 未达成)。
- **状态判定**:`达成率 ≥ 可用性目标` → 状态 = 达成(绿);`达成率 < 可用性目标` → 状态 = 未达成(红)。
- **默认行数**:首页展示最多 5 条,超出 5 条时底部"查看全部 →"链接跳到 SLO 列表。
- **无 SLO 服务**:未配置 SLO 的服务不展示在本段,与"仅展示配置了 SLO 且近窗有数据的服务"原则保持一致(spec §3.4 SLO 列表)。
- **空状态**:当前 Group 内无配置 SLO 的服务时,本段显示"暂无 SLO 配置" + 跳转 SLO 配置入口的引导文案。

## 4. 关键规则

- 首页为只读汇总页,所有段均不可编辑;下钻(点击条目)统一跳到对应菜单,不打开页内弹窗或抽屉。
- 首页顶部"时间窗"控件(15m / 1h / 4h / 1d / 7d,默认 1h)是首页的全局时间窗,影响 6 个 KPI 中的 5 个(应用数量 / 服务数量 / 请求量 / 错误请求数 / P95 延迟)的主数值与 sparkline,以及健康度分布、健康度趋势、TOP5、SLO 概览的主口径;**活跃告警数始终为"当前未恢复"快照,不受时间窗影响**;首页时间窗与各域菜单时间窗独立,首页只提供 5 档固定选项,不支持用户自定义。
- 首页 7 段(§3.1-§3.7)的内容由各域菜单(服务 / SLO / 事件)的后端接口在首页接口中聚合返回,首页不维护独立缓存,分项查询独立超时、任一失败不影响其他段;失败段以"加载失败,点击重试"占位呈现。
- 首页按 Group 隔离,各 Group 看到的是本 Group 范围内的汇总数据;Group 内全员(具备 APM 首页菜单 `View` 权限)均可见首页 7 段。
- 首页支持"空状态":未接入任何应用时,首页展示"前往集成菜单完成接入"引导,首屏不出现 0 数值的空 KPI 段(避免误导)。
- P0 阶段 6 个 KPI 卡不展示"较昨日"或"较上周 / 较上月"等跨期对比;SRE 关心的是"现在"与"近窗走向",不开新窗口、不做长周期口径,避免因新接入 / 跨时区导致昨日数据缺失时的误导(展示「—」会与"持平"混淆)。后续若 PM 评估需要"较昨日"再单独提流程,不在 P0 范围。
- 首页不展示具体 Span / Trace / Issue 详情;点击汇总条目后跳转到对应菜单的详情页。
- 首页不展示"最近部署"独立段(部署信息在服务菜单的时序图叠加中体现;若用户后续需要可单独提 PM 流程评估)。

## 5. 关键技术架构选择

- 首页汇总接口由 APM 后端聚合服务统一提供,聚合服务按"6 个 KPI / 健康度分布 / 健康度趋势 / 实时告警 / TOP5 / SLO 概览"7 个分项查询,合并后返回前端;每个分项独立超时(默认 200ms),任一分项失败不影响其他分项返回;失败分项以"加载失败,点击重试"占位呈现。
- 6 个 KPI(§3.1)的主数值由聚合服务按"页面全局时间窗"(首页顶部 segmented 选定)按域分项查询得到:KPI「应用数量 / 服务数量 / 请求量 / 错误请求数 / P95 延迟」按选定时间窗实时聚合,「活跃告警数」为"当前未恢复"快照(与时间窗无关);KPI sparkline 序列由 VictoriaMetrics 预聚合下采样查询,序列长度按主时间窗自适应(15m → 15 段、1h → 24 段、4h → 24 段、1d → 24 段、7d → 28 段);应用数量 = `service.namespace` 去重数(由 OTel 元数据),服务数量 = `service.name` 去重数(由 OTel 元数据),请求量 = 入口 Span 速率,错误请求数 = 错误 Span(状态码 5xx 或 `span.status_code = ERROR`)速率,P95 延迟 = 入口 Span 时延第 95 百分位。
- 健康度分布(§3.2)的 4 段计数由服务元数据(健康分级)按 Group 聚合,时间窗与首页全局时间窗一致;健康度趋势(§3.3)的 3 条曲线由服务元数据 + VictoriaMetrics 预聚合查询,时间窗独立可选(1h / 4h / 1d,默认 1h);实时告警(§3.4)由事件告警表(Django ORM)按 `state = firing` 过滤倒序取前 N;TOP5(§3.5 / §3.6)由服务 RED 指标(VictoriaMetrics 预聚合)按错误率 / P95 降序 top 5,时间窗与首页全局时间窗一致;SLO 概览(§3.7)由 SLO 元数据 + SLO 状态计算结果(已配置 SLO 的服务按选定时间窗的达成率,后端预先批量计算)。
- 首页不引入新表与新索引,所有数据来源于既有域(服务 / SLO / 事件 / 接入),首页接口为聚合层而非数据层。
- 首页加载以"近窗小数据量"为前提,默认单接口响应在 1s 内(7 分项并行的合并响应);若任一分项数据量超过阈值(默认 1k 行),后端按需分页裁剪,首页只展示前 N 条并附"查看更多"入口。
- 首页的数据查询接口在 WHERE 条件中按用户所属 Group 过滤,跨 Group 数据不可见;不引入跨 Group 协同机制。

## 6. 验收标准

- 用户进入 APM 首页可看到 7 段汇总(KPI 概览 / 健康度分布 / 健康度趋势 / 实时告警 / 服务 TOP5 / P95 TOP5 / SLO 概览),按"控制塔"风格排布。
- 6 个 KPI 卡(应用数量 / 服务数量 / 活跃告警数 / 请求量 / 错误请求数 / P95 延迟)横向等宽排布,每卡含图标 / 指标名 / 主数值 / sparkline;主数值口径与 spec §3.1 表一致,主数值时间窗跟随页面顶部"时间窗"控件(默认 1h);P0 阶段 KPI 卡不展示"较昨日"delta。
- 健康度分布(§3.2)以环形图 + 中心总数 + 4 段图例展示;环形图 4 段为健康 / 警告 / 严重 / 未知,未知 = 待定 + 陈旧/失联 视觉合并;中心数字 = 当前 Group 内总服务数;图例每行含色点 / 档位名 / 计数 / 占比。
- 健康度趋势(§3.3)以 3 条线展示整体健康度 / 核心服务 / 外部依赖;纵轴 0% - 100%,5 档网格;横轴时间可切换 1h / 4h / 1d,默认 1h;无数据的线显示「— 无数据」而非 0 直线。
- 实时告警(§3.4)按触发时间倒序展示未恢复告警,每行含服务名 / 告警名 / 状态(严重/警告) / 触发时长;最多展示 5 条,超出 5 条出现"查看全部 →"链接;无未恢复告警时显示"一切正常" + 绿色 ✓。
- 服务 TOP5 按错误率(§3.5)以横条展示近窗 15 分钟错误率 top 5 服务,行字段含服务名 / 错误率横条(按严重度着色) / 错误率数值 / P95 时延;"查看全部 →"跳到"服务"菜单并按错误率降序排序。
- P95 响应时间 TOP5(§3.6)以横条展示近窗 15 分钟 P95 top 5 服务,行字段含服务名 / P95 横条(按严重度着色) / P95 数值 / 吞吐;"查看全部 →"跳到"服务"菜单并按 P99 降序排序。
- SLO 概览(§3.7)以 4 列表格(服务 / 可用性目标 / 达成率 / 状态)展示已配置 SLO 的服务;状态二态(达成 / 未达成),`达成率 ≥ 可用性目标` 判定为达成;最多 5 条,超出出现"查看全部 →"链接;无 SLO 配置时显示"暂无 SLO 配置"引导。
- 首页未接入任何应用时,展示"前往集成菜单完成接入"引导,首屏不出现 0 数值的空 KPI 段。
- 首页按 Group 隔离,跨 Group 数据不可见;Group 内全员(具备 `View` 权限)均可见首页 7 段。
- 首页分项加载失败时,失败段以"加载失败,点击重试"占位呈现,不影响其他段。
- 首页菜单的 `View` 权限在角色系统中声明,Group 管理员通过系统管理中"角色 → 菜单 operation"控制本 Group 成员对首页的访问;不在 APM 内部声明"首页管理员"角色。
- 首页不展示"最近部署"独立段;P0 阶段不展示 Issue 详情 / Trace 详情 / Span 详情,所有下钻统一跳到对应菜单的详情页。
