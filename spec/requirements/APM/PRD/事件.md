## 1. 背景与目标

事件菜单承担"APM 度量告警"职责,参照 monitor 事件菜单的形态(事件 group 下挂"告警"+"策略"两个子菜单),为 APM 服务/端点的可观测指标(错误率、时延、吞吐)提供完整的告警查看与策略配置能力。

事件菜单的策略评估与告警产生对齐 monitor 事件菜单:每条策略周期性地对服务/端点的指定度量做阈值评估,触发后形成事件,事件按规则聚合成告警,告警按已配置的通道进行通知。APM 是告警状态机的源 of truth。

事件菜单是 P1 阶段的能力,在"服务"的指标接入(错误率、时延、吞吐)就绪后开放。

## 2. 范围定义

- **告警(查看)**:APM 度量告警列表与详情,展示触发后的告警状态、维度筛选、关联事件流。
- **策略(配置)**:APM 度量告警策略配置,定义监控目标、度量、阈值、触发恢复、无数据告警、通知通道。
- SLO 不在本规格书范围内,见「服务」规格书。

## 3. 关键能力

### 3.1 告警(查看)

#### 3.1.1 告警列表

告警列表展示触发后的告警记录。列表列(按显示顺序):

1. **级别**(critical / error / warning,3 级别)
2. **触发时间**(YYYY-MM-DD HH:mm)
3. **告警标题**(如 `payment-svc 错误率 > 80%`)
4. **指标**(错误率 / P99 时延 / P95 时延 / 吞吐)
5. **服务 / 端点**(服务为粗体,端点若有则灰色副行)
6. **通知**(已通知 / 未通知,带 ✓ 图标)
7. **处置人**(头像首字母 + 用户名)
8. **操作**(详情 / 关闭)

列表上方辅助:

- **告警分布图(近 24h 堆叠柱状图)**:横轴时间(按小时分桶),纵轴告警数,3 级别堆叠(critical / error / warning),点击柱体可跳到对应时段告警。柱体右侧汇总 chip:严重 N / 错误 N / 警告 N。
- **自动刷新**:关 / 30s / 1m / 5m。
- **时间范围**:1h / 24h / 7d / 自定义。
- **搜索框**:按告警标题 / 服务 / 规则模糊匹配。

状态机(对齐 monitor i18n key):

- `new`(新告警):策略触发且当前仍在阈值之上,通知通道已下发。
- `recovered`(已恢复):触发条件消失,告警已自动恢复,记录保留为历史告警。
- `closed`(已关闭):由用户手动关闭;关闭后即使阈值再次命中也不会再触发新告警,仅作为历史记录保留。

操作列交互:

- **详情**:点击行任意位置(标题/任意列)打开告警详情抽屉(见 3.1.2)。
- **关闭**:仅当状态为 `new` 时可用;点击弹出 Popconfirm 确认,确认后状态置为 `closed`。

#### 3.1.2 告警详情(抽屉)

从列表点击"详情"打开右侧抽屉(宽度 880px)。抽屉分两个 Tab:**告警** | **事件**。

**抽屉头部(固定区):**

- 状态 tag + 级别 tag + 指标 tag + 告警标题
- 元信息行:所属服务、所属端点(若有)、所属版本(若有)、关联规则、触发时间

**Tab 1:告警**(对齐 monitor `Information`)

`Descriptions` 表格,2 列带边框,字段(顺序):

1. 时间
2. 级别(左侧 4px 色条 + 级别文字,色条颜色 = 级别色)
3. 首次告警时间
4. 所属对象(服务 + 端点,端点若有则灰色副行)
5. 所属版本
6. 关联规则
7. 度量(指标 tag + 分组标签)
8. 阈值
9. 告警结束时间(仅 `closed` 状态显示)
10. 通知(已通知 / 未通知)
11. 操作人
12. 通知人

下方:

- **关闭告警** 主按钮(仅 `new` 状态可用;带 danger 样式)
- **触发时快照图**:告警前后 1 小时折线图(SVG 自绘,带阈值虚线 + 触发点红圈 + 告警时段红底)

**Tab 2:事件**

- 顶部 **事件分布热力图**:7 天 × 24h SVG 网格,按小时事件数 5 级颜色(无 / 少量 / 中等 / 密集 / 爆发),爆发时段(≥16 条)红框标注
- 下方 **事件流列表**:时间(秒级,粗体) + 内容(endpoint 路径) + 值(时延/错误码),按时间倒序,告警时段(09:42-09:50)红底高亮,列表 max-height 400 + 滚动

**抽屉 footer**:仅"取消"按钮(对齐 monitor)。

**事件范围限定**:事件严格限定到该告警所属 service(若告警有 endpoint 则同时限定)。

#### 3.1.3 告警分布图(替代分面筛选)

- 替代 monitor 风格的多分面筛选,使用堆叠柱状图直观展示 3 级别告警时间分布。
- 不展示独立的"按服务/按时间"分面数字(从堆叠图直接读出)。

### 3.2 策略(配置)

策略编辑采用 4 步垂直 `Steps`,与右侧变量表 + 指标预览并列(对齐 monitor strategy/detail 布局)。

**整体布局:** 左侧 4 步 Steps(最大 820px)+ 右侧 400px 粘性面板(模板变量表 + 指标预览)。

**Form 布局:** `layout="horizontal"`,`labelCol={ style: { width: 100 } }`,label 文字黑色,右对齐,label 后冒号 `:` 与内容间隔 12px。Form.Item 内容限宽 360px(`inputStyle = { width: 360 }`)。

#### 3.2.1 步骤 1:基本信息

| 字段 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| 策略名称 | Input | 是 | "结账错误率" | 必填,1-100 字符 |
| 告警名称 | Input + tooltip | 是 | `${service} 错误率 > ${threshold}` | 告警名称模板,变量从右侧变量表复制 |
| 检测频率 | InputNumber + addonAfter="分钟" | 是 | 1 | 1-60 分钟,后端评估周期 |

#### 3.2.2 步骤 2:指标定义

| 字段 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| 服务 | Input | 是 | "checkout-api" | 必填 |
| 端点 | Select mode="multiple" + helpText | 否 | `['POST /checkout', 'GET /cart']` | 下拉多选;**helpText: "不选则按服务级别监控(整体聚合)"** |
| 指标 | Select | 是 | error_rate | 固定 4 选项:错误率(%)/ P99 时延(ms)/ P95 时延(ms)/ 吞吐(req/s) |
| 汇聚周期 | InputNumber + addonAfter="分钟" | 是 | 5 | 1-60 分钟 |
| 汇聚方法 | Select | 是 | avg_over_time | avg_over_time / last_over_time / max_over_time / min_over_time |

> **APM 不暴露"分组评估"字段**(monitor 那边对应 group_by):APM 按版本/端点分组时是**每个分组独立触发告警**,不需要跨组聚合,后端按指标默认行为处理即可(错误率 max、时延 max、吞吐 sum)。
>
> **APM 不暴露"汇聚方式"字段**(monitor 那边对应 group_algorithm avg/sum/max/min):同上,后端默认即可。

#### 3.2.3 步骤 3:告警条件

**3 级别阈值表**(对齐 monitor `ThresholdList`,用 antd `Table` 表格布局):

| 列 | 字段 | 说明 |
|----|------|------|
| 级别 | Tag(critical 红 / error 橙 / warning 浅橙)| 不可编辑 |
| 比较符 | Select(>/≥/</≤)| 3 级别独立 |
| 阈值 | InputNumber + addonAfter="%"| 错误率 0-100,critical 必填,error/warning 可选(不启用留空)|

**触发 / 自动恢复条件**(label + inline InputNumber + helpText,单行格式对齐 monitor):

| 字段 | 默认 | helpText |
|------|------|----------|
| 触发条件 | 1(连续 N 次命中)| 连续 [N] 个汇聚周期结果满足告警阈值,触发告警。 |
| 自动恢复 | 5(连续 N 次未命中)| 当连续 [N] 个周期不满足阈值时,则告警自动恢复。 |

**无数据告警条件**(label + inline helpText 单行拼装,3 段 inline 控件):

| 字段 | 控件 | 默认 |
|------|------|------|
| 无数据告警 | "当检测指标最近 [N] 分钟查询结果为空时,触发 [Select:不触发无数据告警/触发严重告警/触发错误告警]"| 5 分钟 + 触发严重告警 |

**无数据告警名称**(label + Input + helpText):

| 字段 | 控件 | 默认 |
|------|------|------|
| 无数据告警名称 | Input size=small,style={ width: '100%' } | `${monitor_object}${resource_name}产生${metric_name}无数据告警` |

> helpText: "告警名称模板,变量从右侧变量表复制"。

#### 3.2.4 步骤 4:通知配置

| 字段 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| 通知(总开关)| Switch(checkedChildren="✓",unCheckedChildren="✕")| 是 | true | 总开关,关闭后整个通知配置隐藏 |
| 通知通道 | Tag.CheckableTag 列表 | 是(开关打开时)| ['email', 'nats'] | 6 个固定通道:邮件 / 企微 / 飞书 / 钉钉 / Webhook / NATS 告警中心 |
| 通知对象 | Select mode="multiple" | 是(开关打开,且非纯 NATS 时)| ['sre.wang', 'sre.li'] | 多选接收人;**仅在通道非全 NATS 时显示**(纯 NATS 走告警中心) |

> **APM 通知配置不包含通知模板字段**:对齐 monitor `NotificationForm`,通知模板由 system_mgmt 通道自身处理,APM 不维护独立模板。
>
> **APM 通知配置不包含"通知级别"字段**:monitor 也没这个,通知级别由告警自身级别决定。

**通知通道与通知对象限制逻辑:**

- 通道列表:从 system_mgmt 已配置的通道中勾选(产品 mock 展示 6 个固定通道)。APM 不维护独立通道配置,新增/修改通道在「系统管理」操作。
- 通知对象:当所选通道**全部为 NATS** 时,通知对象字段隐藏(NATS 走告警中心,不需要选人)。

#### 3.2.5 策略启停(不在编辑页)

- 策略启停**不在编辑页表单中**,在**策略列表的 Switch 列**单独控制(对齐 monitor `effective` 列)。
- 编辑页 footer:取消 / 删除(danger) / 保存策略,无启停开关。

#### 3.2.6 右侧面板(变量表 + 指标预览)

- **模板变量表**(对齐 monitor `VariablesTable`,antd Table 布局):变量 / 说明 / 操作 3 列,操作列"复制"按钮(点击调 `message.success`)。10 个变量:`${service}` / `${endpoint}` / `${version}` / `${metric}` / `${current_value}` / `${threshold}` / `${level}` / `${alert_name}` / `${trigger_at}` / `${group_by}`。
- **指标预览**(对齐 monitor `MetricPreview`):SVG 自绘折线 + 阈值线 + 实时模拟,标题 + 副标题(指标 · 汇聚周期 · 实时模拟)。

### 3.3 策略列表

策略列表页面字段(对齐 monitor 策略列表,7 列):

1. **策略名称**(纯文本,无 link)
2. **监控对象**(service + 端点,双行,对应 monitor `monitoringTarget`)
3. **创建人**(头像首字母 + 用户名)
4. **创建时间**
5. **执行时间**
6. **启停**(Switch,编辑页无此字段)
7. **操作**(编辑 / 删除,删除带 Popconfirm)

列表上方:搜索框(策略名称) + 新建策略按钮。**底部无 Alert 设计说明卡片**(抑制/通道等设计说明不展示在 UI)。

## 4. 关键规则

- **状态机 i18n key**:`new` / `recovered` / `closed`,产品文案用「新告警」/「已恢复」/「已关闭」,代码与 API 一律用英文 i18n key。
- **告警中心/抑制/通道复用** 等设计说明不展示在事件菜单 UI(规格书维护,产品页面不出现)。
- **APM 端到端为告警的 source of truth**:触发 / 恢复 / 关闭状态机由 APM 侧维护,告警中心单向接收,不回写。
- **策略启停与编辑解耦**:启停状态在列表 Switch 控制,编辑页不展示启停字段,避免误操作(用户在编辑态不会误关策略)。
- **无数据告警可选**:产品可启用(走 Select 触发),也可禁用(默认不触发)。对齐 monitor `AlertConditionsForm` `noDataAlert` 字段。
- **端点下拉多选,不选则按服务级别**:产品语义上"端点是服务下更细粒度的监控范围",不选时退回服务级聚合。
- **通知对象仅在非纯 NATS 时显示**:NATS 通道走告警中心分发,不需要在 APM 选具体人。
- **告警详情抽屉而非独立页**:从告警列表点击进入,右侧滑出,关闭后回到列表;不在路由中提供独立详情 URL(避免面包屑/URL 状态管理)。

## 5. 验收标准

### 告警列表

- 列表 8 列(级别 / 触发时间 / 告警标题 / 指标 / 服务/端点 / 通知 / 处置人 / 操作)按顺序展示,告警标题无"触发 N 次"tag。
- 状态机 `new` / `recovered` / `closed` 三态,i18n key 前后端一致;产品文案为「新告警」/「已恢复」/「已关闭」。
- 操作列有"详情"和"关闭"两个操作;关闭仅在 `new` 状态可用,且带 Popconfirm 确认。
- 顶部告警分布图(堆叠柱状图)展示近 24h 3 级别告警数;支持自动刷新(关 / 30s / 1m / 5m)和时间范围(1h / 24h / 7d / 自定义)。
- 搜索框支持按告警标题 / 服务 / 规则模糊匹配。

### 告警详情抽屉

- 从列表点击"详情"打开右侧 880px 抽屉,固定头部 + Tabs(告警 / 事件)。
- 告警 tab:`Descriptions` 2 列带边框,字段顺序与规格书一致;级别用左侧 4px 色条 + 文字(色条 = 级别色)。
- 告警 tab 包含触发时快照图(SVG 折线 + 阈值虚线 + 触发点红圈 + 告警时段红底)。
- 事件 tab:7d × 24h 事件分布热力图(5 级颜色,爆发红框),下方事件流列表(时间 + 内容 + 值),告警时段红底高亮,事件严格限定到该告警 service+endpoint。
- 抽屉 footer 仅"取消"按钮。

### 策略列表

- 列表 7 列(策略名称 / 监控对象 / 创建人 / 创建时间 / 执行时间 / 启停 / 操作),无"度量/分组/作用服务/阈值/通知通道/触发次数"等多余列。
- 操作列仅"编辑"和"删除",无"复制"。
- 启停 Switch 在列表列直接控制,不在编辑页表单。
- 列表页底部无 Alert 设计说明卡片。

### 策略编辑(4 步)

- 整体布局:左侧 4 步 Steps(最大 820px,horizontal layout,label 100px 右对齐 + 冒号 + 12px 间距)+ 右侧 400px 粘性面板(变量表 + 指标预览)。
- **基本信息**:策略名称 + 告警名称(带 tooltip) + 检测频率(InputNumber + "分钟" addonAfter)。
- **指标定义**:服务 + 端点(Select 多选 + helpText "不选则按服务级别")+ 指标(4 选 1)+ 汇聚周期 + 汇聚方法。**无"分组评估"字段**;**无"汇聚方式"字段**。
- **告警条件**:3 级别阈值表(critical 必填)+ 触发条件(单行 inline helpText)+ 自动恢复(单行 inline helpText)+ 无数据告警(单行 inline 三段拼装)+ 无数据告警名称(input + helpText)。
- **通知配置**:总 Switch + Tag.CheckableTag 通道多选 + 通知对象 Select(仅在非纯 NATS 时显示)。**无通知模板字段**;**无通知级别字段**。
- 右侧变量表(10 个变量 + 复制按钮)+ 指标预览(SVG 自绘折线 + 阈值线)。
- footer:取消 + 删除 + 保存策略,**无"启用策略"开关**。

### 关键规则

- APM 端到端为告警 source of truth;抑制/告警中心/通道复用等设计说明不展示在 UI。
- 状态机 i18n key `new` / `recovered` / `closed` 前后端一致。
- 无数据告警可选(走 Select 触发),MVP 不强制启用。
- 端点不选按服务级别聚合,产品语义明确。
- 通知对象仅在非纯 NATS 时显示。
