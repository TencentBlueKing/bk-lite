## 1. 背景与目标

探索菜单承担"从汇总下钻到单条 Trace / 单个端点 / 单个错误"的能力,是 APM 的诊断主战场。探索菜单不重复"服务"一级菜单的汇总能力(全局 RED / 健康分级 / 上下游等),而是把单条 Span 级别的数据以检索、聚合、详情、归因四种交互方式呈现,让用户能从"看到服务"进一步"看到具体请求"。

探索菜单的错误子菜单同时承担"应用错误归因"职责:在 Span 层面把异常事件聚类为 Issue,并提供生命周期管理、回归识别、影响面分析等能力。错误追踪的数据完全来源于 APM 内部的 Span exception event,**不调用日志模块**。

## 2. 范围定义

- 调用链:多维结构化 Trace 检索、Trace 与 Span 列表、聚合分析、可视化切换、实时尾随、保存检索视图;Span 详情以瀑布图、火焰图、关键路径、错误标注、Span 详情面板、Span Links、跨服务边界与断裂标注呈现。
- 端点:端点级 RED 时序、时延分布、端点健康判级、状态码细分、时延构成与下游分解、端点归并与折叠、端点列表与排序、跨维度切片、样本 Trace 下钻、端点元信息。
- 错误:Issue 自动聚类、Issue 列表与筛选、影响面与典型样本、聚合异常栈、请求上下文、版本分布、端点分布、Issue 生命周期、回归识别、激增标记。

## 3. 关键能力

### 3.1 调用链

#### 3.1.1 多维结构化检索

- 支持按服务、环境、版本、入口资源/操作、状态(OK/Error)、最小/最大耗时、SpanKind、时间窗组合检索 Trace。
- 提供分面栏点选(服务/环境/SpanKind/状态)与 `key:value` 查询框两种检索方式,两者检索条件实时同步。
- 查询框支持自动输入建议(基于近窗使用过的 key 与 value),检索条件同步写入 URL 便于分享。
- 支持按整条 Trace 的结构特征筛选:是否包含数据库调用、是否包含错误 Span、Span 数量、总耗时、跨服务数。
- 支持按任意 Span 属性或资源属性过滤,匹配方式支持等于、不等于、大于等于、小于等于、包含、集合匹配。

#### 3.1.2 Trace 与 Span 结果

- Trace 列表以一条 Trace 一行展示,字段包括入口服务、入口资源、总耗时、Span 数、状态、开始时间,支持按总耗时、开始时间、状态排序。
- 支持在 Traces 视角与 Spans 视角之间切换,Spans 视角展示所属服务、操作名、SpanKind、HTTP 方法与状态码、自身耗时、状态、发生时间,并可定位到所属 Trace。
- 时延散点图按桶分布展示 Trace 时延,支持在图上框选时间和耗时区间,框选结果回填检索条件,帮助定位长尾慢请求样本。
- 实时尾随(Live 模式)按自动刷新策略拉取最新 Trace,展示当前吞吐量和命中数。

#### 3.1.5 调用链检索页 UI 规格(对齐 monitor/datadog)

调用链检索页的视觉与交互严格对齐 monitor(告警/事件)和 datadog(探索)参考,不允许自创字段或自创组件。

**顶部工具栏(从左到右,单行)**

- **Entity 切换**:`Spans` / `Traces` 二选一,默认 `Spans`,切换后下方主区表格列随之变化。
- **搜索框**:`key:value` 过滤(例 `service:auth status:error duration:>30ms`),占满中间剩余宽度,带前缀搜索图标和清除按钮。
- **时间范围 Select**:`15m` / `1h` / `4h` / `1d` / `7d`,默认 `7d`,样式紧凑(宽 90px)。
- **实时尾部 Select**(替代独立"实时尾部"按钮):值为 `off` / `1s` / `2s` / `5s` / `30s` / `1m`,默认 `off`。
  - 前缀圆点指示:`off` 状态为空心灰圈,启用时为实心 primary 蓝圈,作为状态指示。
  - 切换到非 `off` 时进入 Live 模式,按所选间隔持续拉取近窗数据;切回 `off` 立即停止,不写入检索历史。
  - 不再单独展示"实时尾部"按钮或"检索视图"/"保存为视图"按钮(检索视图保存入口另设)。

**主区头部(顶部数字 + 视图切换)**

- 左侧大数字:当前吞吐量(例 `0.01`)+ 单位说明(例 `spans/s`)+ `· 命中 N`(命中数)。
- 右侧 `Segmented` 切换:`明细` / `聚合`,默认 `明细`。两态共享同一组检索结果。

**散点图(仅在"明细"模式展示)**

- 标题 `时序分布` + 副说明 `在图上拖选一段时间锁定结果`,散点按时间横轴和耗时纵轴分布,颜色区分正常(蓝)/错误(红)。
- 散点图本身是一个时间/耗时区间的过滤入口,在图上框选后回填到检索条件并触发重新拉取。
- "聚合"模式不展示散点图(聚合已是过滤后的汇总,散点图无新增信息)。

**明细表格(列严格对齐 datadog)**

- Spans 视角(5 列):`服务` / `资源` / `HTTP` / `耗时` / `时间`。
  - `服务`:主行服务名(可点击),副行 `kind`(客户端/服务端/生产者/消费者)。
  - `资源`:操作名(例 `GET session:*`),等宽字体。
  - `HTTP`:`方法` + `状态码`,方法等宽灰字,状态码按成功/错误着色(成功灰、错误红)。
  - `耗时`:数字带下划线(便于点击排序),超过阈值(默认 1000ms)红色加粗。
  - `时间`:相对时间(例 `6 天前`),不展示绝对时间戳。
- Traces 视角(6 列):`入口服务` / `资源` / `总耗时` / `跨度数` / `状态` / `时间`。
  - `入口服务`:主行入口服务名(可点击),副行 `Trace ID` 前 16 字符等宽灰字。
  - `资源`:入口操作(例 `GET /api/user/profile`),等宽字体。
  - `总耗时`:数字带下划线,超过阈值(默认 400ms)红色加粗。
  - `跨度数`:该 Trace 的 Span 总数,右对齐,等宽数字。
  - `状态`:`正常`(绿)/ `错误数 N`(红,N 为该 Trace 中错误 Span 数)。
  - `时间`:相对时间。
- 表头点击排序,`时间` 列默认带 `↓` 指示。

**聚合视图(在"聚合"模式展示)**

- 页面顶部大字标题 `Top 榜`(视觉权重等同二级页面标题)。
- 维度切换 Tabs:`按服务` / `按端点` / `按版本` / `按环境`,切换 Tab 决定下方数据源;`按环境` 维度内置 `production` / `staging` 数据,其他维度使用聚合常量。
- 右侧 chip 区(共 5 个,排成两行,右对齐):
  - 第一行(指标选择,3 选 1):`请求数` / `错误率` / `P95 耗时`,决定排序与展示口径。
  - 第二行(视图选择,2 选 1):`Top 榜` / `表格`,决定渲染形式。
- Top 榜形态:每个维度项一卡片,展示 `指标值` + `维度名` + 副标识(版本/环境/所属服务)。
- 表格形态:表头按当前维度展开,每行一个分组,数值列右对齐带下划线。

**左侧分面栏(筛选是复选框,不是按钮)**

- 标题 `分面筛选`,每个分面为独立分组,组内为 `Checkbox` 多选。
- 分面顺序(自上而下,严格按此):`状态` / `服务` / `环境` / `SPAN 类型` / `耗时`。
- 状态分面:选项 `错误` / `正常`,左前缀圆点颜色区分(红/绿),右侧 `count`。
- 服务分面:按命中量倒序,典型如 `api-gateway` / `checkout-api` / `user-api` / `catalog-api` / `inventory-svc` / `payment-svc` / `auth-svc` / `web-storefront` / `notification-worker`。
- 环境分面:`production` / `staging`。
- SPAN 类型分面:`CLIENT` / `SERVER` / `PRODUCER` / `CONSUMER`。
- 耗时分面:数字范围筛选,使用 `InputNumber min - max` + 单位 `ms`,作为最后一个分面。
- 选中后:整行加 primary 软底色 + primary 蓝字,标题后出现 `(N)` 选中数 badge。
- 不展示"结构特征"等自创分面;分面项均为真实字段。

#### 3.1.6 Trace 详情页 UI 规格(对齐 datadog)

Trace 详情页的视觉与交互严格对齐 datadog Trace 详情页,不允许自创组件或自创字段。

**顶部面包屑(单行)**

格式:`服务 › {入口服务} › {入口资源}`,后接 `GET` 方法 tag + `/{path}` 路径 + `✓ 200` 状态 tag(状态 tag 配色按成功/错误区分)。

**概览 stat strip(单行,卡片)**

从左到右依次为:
- `Trace ID`:完整 ID 截断显示(例 `59165a3a...451d07d4`),后接一个复制/分享图标按钮。
- `总耗时`:大号字,带单位 `ms`。
- `跨度数`:该 Trace 的 Span 总数。
- `服务数`:该 Trace 涉及的服务数(按 `service.name` 去重)。
- `状态`:成功展示 `正常`,异常展示 `含错误`(红字 + 错误图标)。
- `跳到首个错误` 按钮(危险色 + 火苗图标),点击后选中第一个 `status=error` 的 Span 并将其设为右侧详情面板的当前 Span。
- 不展示缩略柱状图 / 缩略火焰图 / 任何"trace 概览缩略"组件。

**视图切换 Segmented**

三个互斥视图,共享同一组 Span 数据和当前选中 Span:
- `瀑布图`
- `火焰图`
- `跨度列表`

切换视图不影响 Span 选中状态,也不影响右侧 Span 详情面板的当前 Span。

**瀑布图视图**

- 左列(宽度约 240px,树形缩进):
  - 每行一个 Span,缩进按 `depth * 12px`。
  - 前缀小圆点:颜色按 `SERVICE_COLORS[service]`,错误 Span 用 danger 红色。
  - 主文本:Span `name` 等宽字体;关键路径 Span 加粗。
  - 副文本:`service`,灰色小字。
- 右列(条形区):
  - 顶部时间轴:展示 `0 / totalDur * 0.2 / ...` 的毫秒刻度,共 5 个刻度。
  - Span 条:宽度 = `(span.dur / totalDur) * chartW`,X 位置 = `(span.start / totalDur) * chartW`。
  - 颜色按 `SERVICE_COLORS[service]`,错误 Span 加红色边框,关键路径 Span 不透明度 1.0,非关键路径 0.7。
  - 内部虚线连接父子 Span 的时序关系。
  - 条形右侧(在条宽 > 30px 时)显示 `dur + ms` 文字标注。
- 选中态:整行加 `primarySoft` 底色 + 左侧 2px `primary` 蓝条。

**火焰图视图(icicle 冰柱图)**

- 根 Span(深度 0)占整条 trace 宽度,在最顶层。
- 子 Span 在 `depth + 1` 行,按调用栈深度递归展开。
- 每个方块:
  - 宽度 = `(span.dur / totalDur) * 容器宽度`,最小 2px。
  - X 位置 = `(span.start / totalDur) * 容器宽度`(绝对时间偏移,不强制嵌在父区域内)。
  - 颜色按 `SERVICE_COLORS[service]`,错误 Span 用 danger 红色 + 白色边框。
  - 关键路径 Span 在方块底部加白色 2px 内阴影。
  - 宽度 > 60px 时显示 `name` 文字,等宽白字。
- 行高 24px,行间距 2px,整体高度 = `(maxDepth + 1) * 24 + 4`。
- 点击任一方块切换右侧 Span 详情面板。

**跨度列表视图**

- 顶部一个 `搜索跨度名 / 服务` 输入框,前缀搜索图标,带清除按钮。
- 搜索匹配 `name` 或 `service` 子串(大小写不敏感),输入即过滤。
- 列表行(单行,无嵌套):
  - 前缀 8x8 颜色方块:错误 Span 用 danger 红色,其余按 `SERVICE_COLORS[service]`。
  - 主文本:Span `name` 等宽字体,缩进按 `depth * 12px`,关键路径加粗。
  - 中段:服务名,右对齐 120px。
  - 末尾:耗时,右对齐 70px,等宽数字;耗时 > 100ms 用 danger 红色;错误 Span 右侧加 ⚠ 警示。
- 选中态:同瀑布图。

**右栏(两段式,sticky)**

第一段 — 服务执行占比:
- 标题 `服务执行占比`,右侧灰字 `% 执行时间`。
- 内容:按 `service` 聚合每个服务的 Span `dur` 总和,占整条 trace dur 的百分比。
- 排序:按 `dur` 总和降序。
- 每行:服务色方块 + 服务名 + 进度条(按百分比填色)+ 百分比 + 绝对毫秒数。
- 进度条使用 `SERVICE_COLORS[service]` 填充,底色 `TOKENS.bg` 灰条。

第二段 — Span 详情面板(根据当前选中 Span 渲染):
- 顶部第一行:Span `name`,加粗等宽字体。
- 顶部第二行:服务名(可点击链接)+ `kind` tag(SERVER/CLIENT/INTERNAL/PRODUCER/CONSUMER)+ `查看端点` 链接 + `错误追踪` 红色边框链接(仅错误 Span 显示)。
- 错误栈(仅错误 Span):浅红底 + 红字 + 红边框的 `<pre>` 区域,展示 `exception type + 消息 + 关键栈帧`。
- Tabs(4 个,默认 `概览`):
  - `概览`:四行 key-value(总耗时 / 自身耗时 / 起始偏移 / 状态),状态值错误时红字加粗。
  - `属性`:`service.name` / `service.version` / `service.namespace` / `deployment.environment` / `host.name` / `http.method` / `http.route` / `http.status_code` / `order.id` / `user.id` 等 OTel 标准属性,等宽字体展示 key/value。
  - `事件`:Span 上的 exception / log / metric 等事件名 + 时间戳列表。
  - `采样`:占位说明 `暂未启用日志关联`,不展示"未观察到"等猜测性文案。
- 不展示"结构特征" / "归因" / "抑制" 等自创组件。

**Span 选中态联动**

- 任意视图(瀑布图 / 火焰图 / 跨度列表)点击 Span 都会:
  1. 立即更新右栏 Span 详情面板的当前 Span。
  2. 立即在当前视图内将该 Span 标为选中态(底色 + 左侧 2px primary 蓝条)。
  3. 不强制切换视图,允许用户在"列表选中 Span → 切换到瀑布图查看位置"的工作流。
- 切换视图不改变当前选中 Span,只改变渲染方式。

#### 3.1.3 聚合分析与可视化

- 支持按服务、入口资源、状态、版本、环境、主机等维度分组聚合,展示吞吐、错误率、P50、P75、P90、P95、P99、平均耗时。
- 支持在列表、时序、Top 榜、聚合表格等视图之间切换,共享同一组检索结果。
- 支持将检索条件、聚合设置、时间窗偏好保存为个人视图,并支持通过链接分享完整检索状态。

#### 3.1.4 Span 详情(瀑布图 / 火焰图 / 关键路径 / 错误标注 / Span 详情 / Links)

- 单条 Trace 详情以瀑布图展示所有 Span 的父子关系、开始偏移、持续时间、自身耗时、等待下游耗时。
- 支持将单条 Trace 切换为火焰图,按调用栈层级展示各 Span 耗时占比,与瀑布图选中状态联动。
- 自动高亮决定 Trace 总耗时的最长 Span 链(关键路径),并支持"只查看关键路径"过滤。
- 对状态为 Error 的 Span 进行醒目标注,支持跳到首个出错 Span,展示错误状态文本和异常事件。
- Span 详情面板展示选中 Span 的基本信息、计时信息、状态、属性、事件、异常栈和数据库查询信息,包括操作名、服务、版本、环境、SpanKind、主机/实例、耗时、状态文本、HTTP/数据库/RPC/消息属性等。
- 展示跨 Trace 的 Span Links,支持跳转到被链接的 Trace 或 Span,便于分析消息队列、批处理、异步任务等非父子调用关系。
- 跨服务边界与断裂标注:在瀑布图和火焰图中区分跨服务边界、网络等待段和缺失 Span,对可能受采样或未插桩影响的不完整链路进行提示。
- 超长 Trace 展示优化:支持重复子树折叠、短 Span 过滤、长列表虚拟滚动和超限提示,帮助在 Span 数量很大的 Trace 中保持可读性。

### 3.2 端点

#### 3.2.1 端点级 RED 与时延分布

- 按服务内端点维度展示吞吐、错误率、时延三联时序,时延支持 P50、P75、P90、P95、P99 和平均值。
- 时延分布以直方图或热力图展示不同时间桶和耗时桶的 Span 数,展示 P50、P75、P90、P99、平均、最大值、样本量,支持识别双峰与长尾。

#### 3.2.3 样本下钻与元信息

### 3.3 错误(APM 内部错误追踪)

#### 3.3.1 业务错误判定

业务错误判定与 SLO good 口径**完全解耦**,是两套独立配置:

- **业务错误判定**由 **OTel Error 语义 + 业务侧 Span 标签**共同决定:
  - 默认规则:OTel Span 的 `status=Error` 才算业务错误,与 HTTP 4xx/5xx 无关。
  - 客户端 4xx 默认**不**计入业务错误(因为 4xx 通常是客户端问题,非服务端业务错误)。
  - 业务侧可通过 Span 标签 `error.type=business` 自定义标记"这是业务错误",被标记的 4xx/任何 Span 也会聚类为 Issue。
  - 业务侧可通过 Span 标签 `error.type=client` 显式排除某 Span 不计入业务错误。
- **SLO good 口径**(在"服务"菜单的 SLO 二级配置)独立于业务错误判定,详见服务.md 3.3.4。

#### 3.3.2 Issue 自动聚类

- 将被判定为业务错误的 Span 与 Span 上的 exception 异常事件归一化,按异常类型、归一化消息、关键栈帧、服务等维度聚类为 Issue。
- 客户端 4xx 默认不计入业务错误,不会被聚类为 Issue(除非业务侧通过 `error.type=business` 显式标记)。
- Issue 聚类以"归一化异常类型 + 归一化消息骨架 + 关键栈帧 + 服务"为聚类键,相似度判定由 APM 自有引擎处理。
- 聚类结果以 Issue 记录持久化,Issue 与 Span/Trace 的关联以 Span ID 反查。

#### 3.3.3 Issue 列表与筛选(对齐 monitor/datadog)

Issue 列表是错误追踪的入口,采用"顶部工具栏 + 概览 KPI 条 + 卡片列表"三段布局,严格对齐 monitor(告警列表)与 datadog(Issue Explorer)的视觉与交互,不在卡片内自创组件。

**顶部工具栏(从左到右,单行)**

- **时间 Radio**:实心 `15m` / `1h` / `4h` / `1d` / `7d`,默认 `7d`。
- **服务 Select**:默认"全部服务",选项为各 APM 服务名;选中后卡片只展示该服务下的 Issue。
- **环境 Select**:默认"全部环境",选项 `production` / `staging` / `dev` 等;选中后卡片只展示该环境下的 Issue。
- **不展示状态 chips**(待分诊 / 已分诊 / 已解决 / 已排除)、**不展示 tag chips**(全部 / 新增 / 回归 / 激增 / 未认领 / 仅生产);这些维度第一版暂不在 UI 暴露,后端能力保留(见 §3.3.5)。

**概览 KPI 条(全宽 4 列网格,垂直分隔线分隔)**

- 异常 Issue 数(红色高亮)
- 出现次数
- 受影响 trace 数
- 受影响服务数

**Issue 卡片(列表,每张卡为一个 Issue)**

- **顶部信息行**:服务名(粗体链接,点击跳到该服务的 TracesSearch)+ 受影响版本 tag 列表(`v5.2.0` / `v5.3.0` 等)+ 受影响端点 tag 列表(`POST /charge` 等)。
- **主体(横向三段)**:
  - 左侧:红点(异常)+ Issue 类型(`DownstreamUnavailableError` / `NullPointerException` / `PaymentDeclinedError` 等)+ Issue 消息(完整堆栈第一行,带 mono 字体)。
  - 右侧三列数据(对齐):受影响 Trace 数 / 出现次数 / 最近出现(相对时间,如 `7 天前`)。
- **折叠区**(默认折叠;点击 Issue 主体展开):
  - 完整堆栈(`Stack` 段,多行 mono)
  - 版本分布(版本 + 次数 + 占比)
  - 端点分布(端点 + 次数 + 占比)

**入口与下钻**:点击 Issue 主体(不含链接 / 标签 / 占比区域)展开 / 折叠;点击受影响 Trace 数字跳到该 Issue 的样本 Trace(走 TracesSearch 预填检索条件);点击服务名跳到该服务的服务详情;**第一版不设独立 Issue 详情页**——所有 Issue 维度信息(影响面 / 异常栈 / 版本分布 / 端点分布)均通过 Issue 卡片本身 + 样本 Trace 下钻获取,避免在 Issue 内再开一层"详情页"造成信息割裂。

#### 3.3.4 (已移除)Issue 详情

第一版**不设独立 Issue 详情页**。Issue 维度的影响面 / 异常栈 / 版本分布 / 端点分布均通过 Issue 卡片本身 + 样本 Trace 下钻呈现;典型样本 Trace(最近 / 最旧 / 最慢 / 生产)、请求上下文(操作 / 版本 / host / 业务标签)走 TracesSearch 以预填检索条件方式拉取,不另开详情页。

> **设计边界**:不在 Issue 卡片里再造一个"抽屉 / 浮层 / 子页"模拟 Issue 详情。Issue 卡片的"折叠区"已经是该 Issue 的全部维度信息,展开后用户可下钻到 Trace 详情看样本;**两层结构**(Issue 卡片 + Trace 详情)替代了"三层结构"(Issue 列表 + Issue 详情 + Trace 详情)。

#### 3.3.5 Issue 生命周期与激增标记(后台能力,UI 暂不暴露)

第一版 UI 不展示 Issue 状态、标签、激增 / 回归标记;但后端能力保留,作为 Issue 数据的元字段存储,后续版本按需开放:

- Issue 状态机:**待分诊 → 已分诊 → 已解决 / 已排除**。**不设静音 / 降噪 / 忽略能力**,用户处置 Issue 仅通过"已分诊 / 已解决 / 已排除"三种主动操作完成。
- 回归识别:已解决 Issue 在近窗(默认 7 天)再次出现时自动重开为待分诊并标记 Regression,辅助及时发现修复失效或新版本回归。回归识别按聚类键严格匹配;当栈帧或消息变化导致聚类键改变时,新聚类为新 Issue 不视为旧 Issue 回归。如需跨版本同根因识别,平台提供"自定义归并规则"以业务侧手动合并。
- 激增标记:当单个 Issue 在短时间内次数陡增时自动标记 Spiking,提升关注优先级。
- 第一版 UI 不展示"已分诊 / 已解决 / 已排除"状态切换入口,Issue 卡片只展示"受影响 Trace 数 / 出现次数 / 最近出现 / 折叠区"四个维度;状态切换与激增 / 回归标记作为后端能力,等 P1 验证后再开放 UI。

## 4. 关键规则

- Trace 检索结果在分面与查询框之间实时同步,任一修改立即触发另一端的展示同步。
- 检索条件、聚合设置、时间窗偏好支持保存为个人视图,视图在 URL 中可被完整分享,链接打开后状态完全一致。
- 业务错误判定走 OTel Error 语义 + 业务侧 Span 标签,与 SLO good 口径完全解耦,不共享配置。
- 业务侧可通过 Span 标签 `error.type=business` 标记业务错误;可通过 `error.type=client` 显式排除;不传则按 OTel 默认规则判定。
- Issue 聚类键在数据写入时计算,聚类结果持久化;已聚类的 Issue 不因后续归一化规则变化而重新归类。
- 回归识别按聚类键严格匹配;跨版本的同根因(栈帧/消息变化)需业务侧通过"自定义归并规则"手动合并。
- 已解决 Issue 在近窗(默认 7 天)再次出现自动重开并标记 Regression;时间窗可在系统配置中调整。
- Issue 状态机不设"已忽略"状态;用户对 Issue 的主动处置仅为"已分诊 / 已解决 / 已排除"三类。
- 错误追踪的所有数据完全来源于 APM 内部 Span exception event,**不调用日志模块,不复用告警中心**。
- 端点列表的排序与筛选仅作用于当前时间窗内的端点,跨时间窗聚合需通过跨维度切片或时间窗切换实现。
- 实时尾随(Live 模式)刷新策略以"近窗持续拉取"为准,不写入检索历史,关闭后立即停止拉取。
- 探索菜单的所有数据按 Group 隔离,用户仅可查看与操作本 Group 内的 Trace / Span / 端点 / Issue;Group 间的数据不互通,不沿用 incident 式跨组协同。

## 5. 关键技术架构选择

- Trace 检索与 Span 详情查询走 VictoriaTrace,支持 OTLP 属性索引(白名单制)与全量属性回查(非索引字段按需拉取)。
- 调用链聚合分析(吞吐/错误率/分位)由 VictoriaTraces 的有界 Span 查询派生，不写入 APM VictoriaMetrics 副本。
- 端点归一化在查询适配层按路由模板、SQL 模板和消息目标处理；归一化结果作为 VictoriaTraces 查询维度，不进入独立指标存储。
- 业务错误判定按"OTel Error 语义 + 业务侧 Span 标签 `error.type`"执行；SLO good 口径在 SLO 配置时独立计算，不与业务错误判定共享配置。
- Issue 聚类以"归一化异常类型 + 归一化消息骨架 + 关键栈帧 + 服务"为聚类键,在 APM 自有的聚类服务中实时计算;聚类结果以 Issue 记录持久化,Issue 与 Span/Trace 的关联以 Span ID 反查。
- 端点时延构成(自身耗时、等待下游耗时、未归因耗时)由 VictoriaTrace 在 Span 落库时按父子关系计算,作为 Span 的预聚合字段存储,避免在线递归。
- 跨服务边界与断裂标注基于 Span 的 parent_span_id 与 service.name 差异判定,缺失 Span 以"未观察到"标注并给出可能原因(采样、未插桩、网络)。
- 实时尾随(Live 模式)以 VictoriaTrace 的"近窗近实时"查询接口实现,前端按可配置间隔(默认 5 秒)拉取,流量受客户端连接数限制。
- Issue 回归识别与激增标记在聚类服务的近窗作业中按 Issue 维度计算,标记结果以 Issue 标签形式存储,不修改原 Issue 状态。
- 端点跨维度切片(环境/版本/实例)使用 VictoriaTraces 的资源与 Span 属性执行有界下钻查询。
- 探索菜单的数据权限以 system_mgmt.Group 为唯一隔离边界,数据查询接口在 WHERE 条件中按用户所属 Group 过滤;不支持 incident 式跨 Group 协同。

## 6. 验收标准

- 用户可按服务、环境、版本、入口资源、状态、最小/最大耗时、SpanKind、时间窗组合检索 Trace。
- 分面栏与 `key:value` 查询框的检索条件实时同步,自动输入建议基于近窗使用过的 key/value。
- Trace 与 Spans 两种视角可切换,时延散点图可框选并回填检索条件。
- 调用链检索页顶部仅展示 `Spans/Traces` 切换、搜索框、时间范围、实时尾部(下拉 `off`/`1s`/`2s`/`5s`/`30s`/`1m`);不展示"服务入口"按钮和"检索视图"/"保存为视图"按钮。
- Spans 表格列为 `服务` / `资源` / `HTTP` / `耗时` / `时间`;Traces 表格列为 `入口服务` / `资源` / `总耗时` / `跨度数` / `状态` / `时间`;耗时数字带下划线。
- 聚合视图标题为 `Top 榜`,维度 Tabs 顺序为 `按服务` / `按端点` / `按版本` / `按环境`,右侧 5 个 chip 为 `请求数` / `错误率` / `P95 耗时` / `Top 榜` / `表格`。
- 左侧分面栏为 `Checkbox` 形态,顺序为 `状态` / `服务` / `环境` / `SPAN 类型` / `耗时`,不展示自创分面。
- Trace 详情页顶部为面包屑(`服务 › 入口服务 › 入口资源`)+ 概览 stat strip(`Trace ID` / `总耗时` / `跨度数` / `服务数` / `状态` / `跳到首个错误` 按钮),不展示缩略柱状图等自创组件。
- Trace 详情页支持 `瀑布图` / `火焰图` / `跨度列表` 三个视图互斥切换,选中 Span 跨视图保持。
- 火焰图(icicle 冰柱图)按调用栈深度递归,根在第 0 层,子按 `depth + 1` 行展开,颜色按 `service` 稳定分配。
- 右侧栏两段式:`服务执行占比`(按服务聚合 dur 占比,横条展示)+ Span 详情面板(操作名 / 服务 / kind / `查看端点` / `错误追踪` / 错误栈 / 4 个 tabs)。
- Span 详情面板 Tabs 为 `概览` / `属性` / `事件` / `采样`,默认 `概览`;不展示"归因" / "结构特征" 等自创 tab。
- 端点列表页顶部工具栏为 `搜索路径模板 / 服务` 输入 + `全部环境` Select + `全部服务` Select(带漏斗图标)+ 排序 Select + 时间 Radio 组(实心 `15m`/`1h`/`4h`/`1d`/`7d`);不展示 Title / 描述副文。
- 端点列表页单表 7 列,顺序为 `方法` / `端点` / `所属服务` / `吞吐量` / `错误率` / `P95` / `最近活跃`,不展示"健康" / "P99" / "总耗时贡献"列,不按服务分组。
- 错误率列三档配色:`< 1%` 绿 / `1%-5%` 黄 / `>= 5%` 红;`最近活跃` 列只展示相对时间,不展示绝对时间戳。
- 端点详情页不展示"状态码细分"和"时延构成与下游分解"两块独立区;这两类信息按需通过跨维度切片或样本 Trace 下钻间接获取。
- 端点详情页"样本调用链"标题右侧不展示任何筛选器或"查看全部"链接;调用链筛选能力由 TracesSearch 接管。
- 端点详情页"样本调用链"表头顺序为 `入口服务` / `资源` / `总耗时` / `跨度数` / `状态` / `时间`,与调用链检索页 Traces 视角表头一致;`时间` 列只展示相对时间。
- Trace 详情以瀑布图展示所有 Span 的父子关系,火焰图与瀑布图选中状态联动;关键路径高亮最长 Span 链,错误 Span 醒目标注。
- Span 详情面板展示基本信息、计时信息、状态、属性、事件、异常栈、数据库查询信息,支持 Span Links 跳转。
- 端点按服务分组展示,支持按总耗时贡献、错误率、P95/P99 时延、吞吐排序。
- 端点归一化在数据写入时执行,避免高基数端点膨胀;跨维度切片支持环境、版本、实例。
- 业务错误判定由 OTel Error 语义 + 业务侧 Span 标签决定,与 SLO good 口径完全解耦;客户端 4xx 默认不计入业务错误(除非业务侧通过 `error.type=business` 显式标记)。
- Issue 自动按归一化异常类型、归一化消息、关键栈帧、服务聚类;聚类键严格匹配,跨版本同根因需通过"自定义归并规则"手动合并。
- Issue 列表顶部工具栏仅含时间 Radio(`15m` / `1h` / `4h` / `1d` / `7d`)+ 服务 Select + 环境 Select,**不展示状态 chips**(待分诊 / 已分诊 / 已解决 / 已排除)与 **tag chips**(全部 / 新增 / 回归 / 激增 / 未认领 / 仅生产);这些维度的后端能力保留但第一版暂不在 UI 暴露。
- Issue 列表 = 概览 KPI 条(异常 Issue / 出现次数 / 受影响 trace / 受影响服务)+ 卡片列表(服务名 + 版本 tag + 端点 tag + 类型 + 消息 + 三列数据 + 折叠区)。
- **第一版不设独立 Issue 详情页**;所有 Issue 维度信息(影响面 / 异常栈 / 版本分布 / 端点分布)通过 Issue 卡片本身 + 样本 Trace 下钻获取,避免三层结构(列表 + 详情 + Trace)造成信息割裂。
- Issue 状态机后端保留:待分诊 → 已分诊 → 已解决 / 已排除;不设已忽略状态,也无降噪 / 静音能力;第一版 UI 不展示状态切换入口。
- 已解决 Issue 在近窗(默认 7 天)再次出现自动重开并标记 Regression(后端能力);时间窗可在系统配置中调整;第一版 UI 不展示该标记。
- 实时尾随(Live 模式)以近窗近实时拉取,关闭后立即停止,不写入检索历史。
- 检索视图(条件 + 聚合 + 时间窗)支持保存为个人视图,链接分享后打开状态完全一致。
- 探索菜单的所有数据按 Group 隔离,跨 Group 数据不互通,不支持 incident 式跨 Group 协同。
