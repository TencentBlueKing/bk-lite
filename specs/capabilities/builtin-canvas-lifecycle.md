# 运营分析内置画布生命周期

## 目标

内置画布与内置数据源随版本同步内容，同时保持用户引用和组织可见性配置稳定。
内置对象的定义内容受平台保护，但“内置”不等于组织可见性不可配置。

## 稳定身份

- `build_in_key` 是内置目录、画布和数据源的稳定业务身份。
- 重复执行 `init_builtin_canvases` 必须原位更新同一 `build_in_key` 对应的对象，不得删除重建。
- 版本同步不得改变存量对象主键；浏览器链接、分享链接和报告订阅必须继续指向同一对象。
- 新增内置画布遇到同名用户对象时必须保护用户对象，不得按名称覆盖或认领。

## 种子内容与运营配置

- 名称、描述、画布布局、过滤器、数据源定义和目录归属属于随版本同步的种子内容。
- 内置画布与内置目录的 `groups` 属于部署后的运营配置：新建使用 Default 组织，更新存量对象时保留当前值；具备既有编辑权限的调用方可通过仅包含 `groups` 的 PATCH 配置组织可见性。
- 内置数据源的 `groups` 与画布/目录分流：新建写入 `groups=[]`（全员可见）；更新保留已有名单，空名单不再回填 Default；仅超管可通过仅包含 `groups` 的 PATCH 配置组织可见性；空名单表示全员可见，非空名单表示组织白名单。
- 内置对象的 PUT、删除及内容字段 PATCH 继续拒绝。

## 退役与失败

- 仅在所有配置的内置定义文件均存在、非空、完整解析且导入成功后，才可删除配置中明确移除的内置对象；文件临时缺失或为空时跳过退役清理。
- 定义文件声明的 `meta.object_counts` 必须与实际内容一致；退役支持 `--dry-run` 预检、可配置数量上限和逐项结果，超限时整体回滚。
- 缺少 `build_in_key` 的历史内置对象身份不明确，不得由自动退役清理删除。
- 分阶段退役的安全敏感数据源可先从新装清单移除，同时按明确路由保护存量主键；只有存量画布迁移完成并有可验证回滚后，才可移除保护并进入自动退役。
- 退役 Dashboard 或 Screen 前必须走报告订阅终止服务；分享链接按画布删除信号明确失效。
- 同步、标记和退役必须处于同一数据库事务；任何失败都整体回滚。
- 内置画布是非关键可重建资源，同步失败必须保留原始错误并保持启动 fail-open。

## 验收

- 空环境可创建内置对象。
- 新组织无需配置即可列出空名单内置数据源。
- 相同配置重复执行时主键、分享、订阅和 `groups` 不变。
- 种子内容变化时在原主键上更新。
- 用户同名对象不被修改。
- 明确退役的对象被删除，关联订阅被终止且分享链接被标记失效。
- 分阶段退役的数据源不再向空环境发布，升级同步保留其存量记录与主键。
- 导入失败不留下部分更新或部分清理。
