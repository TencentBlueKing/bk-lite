# 节点管理 · 控制器

> Migrated from `spec/prd/节点管理/控制器.md` as legacy capability evidence.

## 1. 背景与目标

控制器是部署在节点上的代理，负责执行安装指令、管理采集器生命周期并与服务端通信，是节点纳管与采集执行的基础。

## 2. 范围定义

- 控制器定义：按操作系统与 CPU 架构定义控制器。
- 控制器安装与卸载：自动/手动安装、进度追踪、卸载清理。
- 包管理：控制器安装包的版本管理。

## 3. 关键能力

### 3.1 控制器定义

- 按操作系统（Linux/Windows）与 CPU 架构定义控制器，记录名称、描述与版本获取方式。
- 支持系统预置控制器。

### 3.2 控制器安装与卸载

- 自动安装：服务端生成引导脚本/命令，节点执行后反向下载并启动，支持 SSH 密钥与密码认证。
- 安装过程分步骤追踪进度，支持超时保护与失败重试。
- 手动安装：获取安装脚本由管理员在节点手动执行后确认状态。
- 安装请求可选择将已存在节点同步至 CMDB、监控系统；系统只处理被选择的目标并保留结果，首次安装后等待节点激活的延迟同步尚未接线。
- 删除节点时可选择对已关联的 CMDB、监控对象尝试退役；默认不触发，失败不影响节点删除。

### 3.3 包管理

- 支持控制器安装包的上传、版本管理与下载。

## 4. 关键规则

- 每个操作系统与 CPU 架构组合对应一个控制器。
- 安装任务以"任务 → 节点级进度"的方式记录步骤日志与失败信息。
- 跨模块同步不是控制器安装完成的必经步骤：仅针对已经落库的节点执行，后续可通过节点详情按目标补推。

> 证据来源：server/apps/node_mgmt/views/node.py:337-366，server/apps/node_mgmt/services/module_push.py:129-193　|　同步基线：d2769559　|　【已实现】

## 5. 关键技术架构选择

- 控制器作为节点侧代理，通过 NATS 订阅指令并回复结果，承担采集器的下发与执行。
- 安装过程以流式事件实时推送进度。

## 6. 验收标准

- 用户可完成控制器的自动与手动安装，并实时查看安装进度。
- 控制器安装包可上传、版本化并下载。
- 删除节点时控制器可被正确卸载清理。
- 已纳管节点可按选择同步到 CMDB、监控系统，或在节点详情按目标补推；不承诺首次安装后的自动延迟同步。
