# ITSM 工单服务

服务目录决定谁可以发起哪类工单。已发布的流程版本决定这张工单使用哪份表单、经过哪些节点，以及每个节点允许谁执行哪些操作。工单保留版本引用，后续发布的字段、处理规则和按钮配置按新版本生效。

| 用户任务 | 行为与验收依据 |
| --- | --- |
| 找服务、快速提单、配置门户 | 目录、搜索、收藏和最近使用从可见服务中选取；直接访问提单入口也要检查服务范围。[服务门户](../changes/itsm-portal-workbench/spec.md) |
| 准备字段、表单和集成 | 表单模型、字典、数据表和集成动作可复用。字段类型决定可选来源、返回格式及映射方式。[表单与集成](../changes/itsm-data/spec.md) |
| 配置和发布流程 | 选择模板、配置处理人和操作、预览各节点的字段，再发布版本。子流程引用须能解析到已发布定义。[流程设计](../changes/itsm-workflow-designer/spec.md) |
| 查单、协作、处理与导出 | 工单可见范围、节点操作权与字段权限分别校验。批量操作、后台导出和下载也受约束。[工单中心](../changes/itsm-ticket/spec.md) |
| 配置自动化和时效 | 事件触发器、SLA 时钟和定时任务各有执行记录，可核对已执行的动作及其失败原因。[自动化与时效](../changes/itsm-rule/spec.md) |
| 维护应用和设置 | 知识、值班、变更和交接承载业务操作。通知模板、满意度、打印及运行配置集中在设置。[应用](../changes/itsm-apps/spec.md) · [设置](../changes/itsm-settings/spec.md) |

完整交付范围见[新增功能清单](itsm-feature-list.md)。首次部署、可内置数据和重跑边界见[新环境初始化](itsm-initialization.md)。

## 工单与流程引擎如何协作

| 动作 | ITSM 的职责 | Flowable 的职责 |
| --- | --- | --- |
| 发布、发起、重开 | 保存流程版本，记录工单、启动轮次及启动结果 | 部署 BPMN、启动对应定义，提供实例与历史证据 |
| 认领、转单、审批和退回 | 校验当前任务、处理权限、字段和意见；记录操作并同步待办 | 变更引擎任务的处理人，推进任务或回到指定活动 |
| 自动节点 | 执行业务动作并保存结果，分别跟踪动作和引擎回执 | 提供可领取的外部作业，接收完成回执后继续流转 |
| 查列表、关注、打标签、导出 | 从有权查看的业务记录中查询或更新 | 这些操作无需推进流程实例 |

ITSM 与 Flowable 分别提交事务。请求超时时，恢复逻辑要区分「确定未发送」「已执行且有证据」「结果未知」。结果未知时保留原工单、原操作和错误原因。重复点击、重扫或 Worker 重启均须复用该记录；能够确认原动作成功时只补本地结果或引擎回执。具体的恢复权限和验收反例见[工单的异常恢复](../changes/itsm-ticket/spec.md#异常恢复)。

## 平台调用入口

- 平台 OpenAPI 提供按组织查询流程、表单和工单，以及创建和办理工单。入口按操作声明权限，并要求调用方绑定一个有效组织。列表只返回该组织的数据；办理时按工单约束任务 ID。[组织隔离与接口定义](../../server/apps/itsm/openapi_api.py)
- 内部 NATS 调用 `itsm_create_ticket` 接收流程标识、标题和创建人，经工单服务建单，返回 ID 与单号。流程没有当前版本时返回错误。这一入口的契约只覆盖建单，告警侧回写有独立规格。[NATS 建单入口](../../server/apps/itsm/nats.py) · [告警侧对接范围](../changes/alert-itsm-ticket/spec.md)

## 运行与验证

Flowable REST 使用 `/flowable-rest/service`。后台导出、定时建单、SLA 扫描和恢复任务依赖对应的 Celery Worker 或 Beat；页面保存成功与后台任务实际执行是两个独立验收点。单元和服务测试覆盖权限、并发与回执异常。验收真实部署时，还应从门户提交工单，在处理人账号下完成节点，再核对工单状态、引擎实例及后台执行记录。[服务端行为测试](../../server/apps/itsm/tests)
