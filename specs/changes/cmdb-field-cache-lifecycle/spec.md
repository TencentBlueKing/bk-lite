# CMDB 字段缓存运行期生命周期

Status: implemented

## Problem Statement

CMDB 曾在 Django `runserver` 启动时清空并重建全部字段缓存。该触发点把可重建的
查询投影放进服务启动路径，使启动依赖图数据库和缓存后端，同时每次本地重载都会
扫描所有模型、预热所有模型 attrs。原实现还存在三类一致性问题：全局缓存缺失会
连带重建全部单模型缓存；图数据库异常会被转换为空列表并发布为成功结果；批量预热
和单模型按需加载对相同 attrs key 使用不同的数据形状。

## Solution

字段缓存改为运行期读穿加载和写后失效：

1. 删除 `CmdbConfig.ready()` 中的缓存初始化，启动阶段不读、不删、不刷新缓存。
2. 全文检索排除字段与 organization/user 字段映射由同一次模型扫描构建为一个完整
   快照 `cmdb:field_metadata:v2`，首次使用时加载，TTL 为一小时。
3. 单模型 attrs 使用 `cmdb:model_attrs:v2:<model_id>` 独立按需加载，数据统一来自
   `ModelManage.search_model_attr`，包含其既有标准化与唯一规则信息。
4. 模型创建、复制、删除及字段新增、删除成功后，失效目标模型 attrs 和全局快照；
   字段展示配置、字段分组、唯一规则、自由标签选项和公共枚举快照变化只失效目标
   模型 attrs。
5. 模型初始化导入按成功模型批量失效。若批次中途失败，已经写入成功的模型仍在
   异常返回前完成失效。
6. 提供 `refresh_cmdb_field_cache` 管理命令，支持刷新全局快照或指定模型 attrs。

## Failure Semantics

- 缓存未命中或缓存读取失败时查询模型事实；缓存写入失败时直接返回本次新数据。
- 图数据库读取失败、attrs 解析失败或快照结构不完整时向调用方返回原异常，不写入
  空值或部分快照。
- 主动刷新采用先构建、后覆盖；失败保留已有快照，记录一个带 `failed_stage`、
  `error_type` 和安全调用链的边界 ERROR，并返回非零命令状态。
- 写后缓存失效失败不回滚已成功的模型事实写入，记录安全错误并由 TTL 最终收敛。
- 合法的空排除字段列表表示当前模型没有需排除字段，全文检索可正常执行。

## Compatibility and Rollout

v2 key 与旧缓存命名空间隔离，避免读取历史 attrs 的不一致数据形状。模型写后失效
和 `clear_cache()` 会定向清除相关旧 key；缓存均有 TTL，因此发布不要求停机、数据库
迁移、启动预热或 Redis 全库清理。

多进程生产环境沿用平台共享缓存配置，必须提供 `REDIS_CACHE_URL`；LocMem 是单进程
开发与测试回退，无法跨进程传播写后失效。

回滚代码后旧版本会继续使用其 v1 key 并自行重建。v2 key 只占用一个 TTL 周期，
不会影响旧版本读取。
