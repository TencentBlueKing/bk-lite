# 监控策略组需求文档

状态：待评审

本文是本期策略组的需求说明。原始规格和交互原型不在本文上修改。

## 1. 要解决的问题

运维接入一个监控对象时，要让这批实例按一套告警规则生效。现在要在接入页逐条挑选策略模板、填写名称前缀，并决定是否推送告警中心。同一对象的规则散在模板卡片上，策略页再看到按实例复制出来的一条条策略。节点管理或 CMDB 同步进来的实例，常常只有采集、没有告警。

## 2. 本期目标

把一整套告警收成策略组。实例加入一组，组里的规则一起生效。用户的主路径是选组和加入实例，不再从空白策略逐条配置。

策略模板仍是单条规则的配方库，用来新建策略组，不直接作用到实例上。每个组织的每个监控对象可以有一个默认策略组，给没有人在接入页上选择的新实例使用。

## 3. 名词

| 名词 | 含义 |
| --- | --- |
| 策略组 | 某个组织、某个监控对象下的一套告警规则，加上已经加入的实例 |
| 规则 | 策略组里的一条告警条件，包含指标、阈值和无数据。通知方式和通知人在策略组上统一设置 |
| 策略模板 | 单条规则的配方。内置模板随对象提供，自定义模板由用户另存 |
| 默认策略组 | 该组织该对象用于自动加入的那一个策略组 |
| 成员 | 已经加入某个策略组的监控实例 |
| 旧策略 | 切换前按实例复制出来、现在仍在生效的策略 |
| 单独规则 | 不在任何策略组里、只挂在某一台实例上的规则 |

一台物理机上的主机、进程、MySQL 等是不同监控对象的实例，各自加入自己对象的策略组。

## 4. 谁可以做什么

- 能接入实例的人，可以在确认接入前为这批实例选择策略组或关闭加入。
- 能编辑该对象策略的人，可以改规则、设默认组、删除策略组、在实例页和策略组里调整成员。
- 安装 Agent 或执行 CMDB 同步的人可以没有策略编辑权限。系统仍按该实例所属组织的默认策略组加入。

组织以操作者当前组织为准。策略组只列出当前组织、当前监控对象下的组。实例不属于该组织时，不能加入该组织的策略组。

## 5. 加入策略组

加入是同一个动作，出现在三处。差别只在给谁选组。一台实例同时只在一个策略组里。换组是离开原组再进入新组。

### 5.1 接入页

对象是本次表格里还没提交的实例。

- 打开页面时，带上当前组织该对象的默认策略组，并列出组内规则和阈值。
- 确认前可以更换策略组。更换只改这一批待接入实例，不修改默认组，也不挪动已经在组里的实例。
- 可以关闭加入。这次只写入采集，这些实例记为不自动入组。
- 表格里能看到每条实例将加入哪一组，或「不加入」。
- 这次没有采集的指标，对应规则标明不会有数据。
- 接入时不填策略名称前缀，不逐条挑选模板，也不填写通知。通知方式和通知人在策略组上设置。
- 接入页只预览当前插件在这个策略组里的规则。其他插件的规则对这批实例不适用，并在页面上标明。

### 5.2 实例页

对象是已经接入的实例。按当前组织和监控对象列出。

- 能看到所属策略组、成员状态，以及是否仍有旧策略或单独规则。
- 可以单台或批量加入策略组、更换策略组、退出。
- 可以先选中某一台实例，再为它补一条策略组里没有的单独规则。单独规则只从这里创建。
- 只影响选中的实例。默认策略组和其他实例不变。
- 改采集间隔或采集项时，所属策略组不变。

### 5.3 策略组里的实例管理

对象是当前打开的这一组。

- 列出已加入实例，以及它们如何加入、是否仍有旧策略或单独规则。
- 可以把已有实例加入这一组。实例已在别的组时，先离开原组。
- 可以把成员退出，或换到同一组织、同一对象的另一组。
- 可以停用该实例上仍在生效的旧策略。未停用时，旧策略和组内规则同时告警。
- 策略组列表在事件里，和告警、策略、模板并列。策略列表仍然只放旧策略和单独规则。列表上的已加入实例数进入这一页。

## 6. 成员状态

每台实例最多一条成员决定。

| 状态 | 何时写下 | 之后的自动同步 |
| --- | --- | --- |
| 无记录 | 还没有做过加入决定 | 不会被批量补进默认组。只有节点管理新建、CMDB 首次对上这两条链路可以写入默认组 |
| 在组 | 从三处入口加入，或自动加入成功 | 不改组 |
| 不自动入组 | 接入时关闭加入、用户退出，或所属策略组被删除 | 不拉回 |
| 未入组 | 第一次出现时没有默认组，或当时已经有旧策略 | 不再匹配 |

退出后采集还在。该实例在原组规则上尚未恢复的告警结束。要恢复告警，用户在实例页或策略组里手动选择一个策略组。

升级前已经存在、且没有成员决定的实例保持无记录，不因为发布策略组而被扫进默认组。指标自动发现产生的新实例也保持无记录。

删除监控实例后，不再作为成员告警。CMDB 只解除与监控实例的关联、实例还在时，策略组关系不变，告警继续。

## 7. 默认策略组

默认组用来处理没有人打开接入页的新实例。

- 每个组织、每个监控对象至多一个默认策略组。
- 节点管理新建监控实例时，若该实例还没有成员决定、也没有旧策略，加入该组织这个对象的默认组。
- CMDB 第一次对上一条还没有成员决定、也没有旧策略的监控实例时，同样加入默认组。之后的同步只维护实例关联，不重新匹配策略组。
- 指标自动发现产生的新实例不因为出现就加入策略组。
- 创建实例时只带了一个组织，就用这个组织的默认组。接入页使用当前组织。一次带了多个组织、又没有明确选组时，不猜测，记为未入组。
- 某个组织第一次需要该对象的默认组时，用该对象的内置策略模板生成一套系统策略组，并设为默认。该对象没有内置模板时，不生成空组，默认保持为空。
- 这套系统组只自动生成一次。用户删除默认组，或把默认改到别的组之后，不再自动再生一套。
- 没有默认组时，同步仍建立实例并完成采集，只是不告警。
- 修改「哪一个组是默认」之后，只影响之后新来的、还没有成员决定的实例。

系统生成的组可以改规则。改动只影响这一组已经加入的实例，不回写内置模板，也不影响其他组织的组。

## 8. 规则与模板

- 同一插件下的规则，对该插件的全部成员生效，不能只给其中一台关掉某一条。只有一台不想要某条规则时，复制一套不含该规则的组，把这台换过去。
- 在组里调整一条规则的阈值或条件后，该规则当前覆盖的成员一起按新规则检测。按旧条件正在告警的事件结束，再按新条件判断。
- 通知方式和通知人在策略组上设置一次。保存时写入该组当前全部规则对应的策略，使用策略上已有的通知字段。只改通知不结束未恢复告警。新建和系统生成的组不预填通知人，也不猜测通知方式；把告警中心选进通知方式后才会推送。生产主机和测试主机要发给不同的人时，分成两个策略组。某一条规则要单独通知时，以后改那条策略上的同一组字段即可。
- 策略组列表可以整组生效或停用。停用后组内规则停止扫描，这些规则上尚未恢复的告警结束，成员仍留在组里。再次生效从当前时间继续扫描，不补历史告警。默认组停用后，新实例仍会加入，但在重新生效前不会告警。
- 策略组按监控对象建，不按采集插件拆成多个默认组。同一对象有 WMI、SSH、Telegraf 等多种采集方式时，仍是一个默认策略组。生成时纳入这些插件的内置模板，每条规则记住自己的插件。
- 实例加入后，一条规则只覆盖当前采集插件与该规则一致的成员。只用 WMI 的主机不执行 Telegraf、SSH 的规则，也不因那些指标没有数据而告警。之后又启用第二种采集时，不用换组，对应插件的规则开始覆盖这台实例。采集从一种插件换成另一种时，成员关系不变；原插件的规则停止覆盖，新插件的规则开始覆盖。
- 从模板创建策略组时，模板按插件分组供勾选，可以只选某一个插件的规则。组内是这些模板的一份副本。之后改组不影响模板，改模板也不改已经建成的组。新组没有成员。模板页不直接生成旧策略或单独规则。
- 把组内规则另存为模板时，模板库增加一条，当前组和其他组不变。
- 复制策略组得到独立的规则副本，不带走原组成员，也不成为默认组。
- 组里的每一条规则各自按现有策略的方式到点执行。一次执行只覆盖该规则插件下的当前成员，不为每台成员再拆一条执行，也不把其他插件的成员算进这次执行。成员加入、退出或变更采集插件时，只改各条规则所覆盖的实例，不因为成员数量增删执行次数。
- 实例退出、换组，或因更换采集插件而不再被某条规则覆盖时，该实例在原规则上尚未恢复的告警结束。之后不再按原规则产生新告警。
- 这些执行不在策略列表里单独出现。用户从策略组的组内规则查看和修改。告警详情仍显示策略名称；组内规则在名称旁标明组策略，编辑不可用。单策略和旧策略可以从告警详情进入编辑。
- 实例刚加入、采集还从未上报时，不因无数据立刻告警。曾经上报过又中断，才按组里的无数据规则告警。
- 删除策略组后，其中的实例不再按该组告警，并记为不自动入组。若删的是默认组，之后新实例只采集、不自动告警，直到另指定默认组。

## 9. 旧策略与单独规则

- 切换前按实例复制的策略继续按原来的实例范围告警，不自动并进策略组，也不自动停用。
- 这些实例视为已经配过告警。自动同步不再把它们加入默认组。
- 用户确认策略组已经覆盖后，自行停用对应旧策略。暂时不调整的实例保持旧策略，行为与切换前一致。
- 允许某台实例另有一条不在策略组里的单独规则。这是例外。它和组内规则同时告警时，页面标出并存，由用户自行避免重复。
- 策略页保留，只列出旧策略和单独规则，用来查看和停用。策略组里的规则不在这个列表出现。
- 策略页不再提供空白新建，也不再把模板批量应用成按实例复制的策略。单独规则的新建入口只在实例页，并且必须先选定一台实例。保存时标明它会和该实例所属策略组同时告警。
- 模板页保留，用来维护单条规则，并进入「从模板创建策略组」。

少数实例的阈值和默认组不一样时，新建或复制一组再把这些实例换过去，不直接改默认组。改默认组会影响所有已在该组的实例。

## 10. 验收场景

1. 接入进程时，页面已选中当前组织的默认策略组。确认后，表格中的实例成为该组成员，组内规则生效。
2. 确认前换成另一组，只有这批新实例进入那一组。默认组和原成员不变。
3. 关闭加入后确认，实例有采集、不告警，并记为不自动入组。再次同步不会把它拉进默认组。
4. 未采集的指标在对应规则上标明这次没有数据。
5. 在组里提高一条规则的阈值后，仅该规则当前覆盖的成员按新阈值检测，正在告警的事件结束。同一组里其他插件的成员不受这条规则影响。模板库和其他组的同名规则不变。
6. 从模板创建一组、复制一组，新组都没有成员。两组之后修改阈值互不影响。
7. 节点管理新建一台主机，且该主机没有旧策略、也没有成员决定时，进入该组织主机的默认组。再次同步不改组。
8. CMDB 首次对上一条符合同样条件的实例时，进入对应默认组。已经在接入时选过组的实例，后续同步不改组。
9. 对象没有默认组时，新实例仍完成采集，状态为未入组。之后即使补上默认组，这些实例也不会被自动加入。
10. 已有旧策略的实例不会被自动加入。实例页能看到旧策略仍生效，停用后只剩策略组告警。
11. 在实例页把一台实例换到另一组后，它只属于新组。原组规则上尚未恢复的告警结束，之后不再按原组产生新告警。
12. 在策略组实例管理中加入一台已在其他组的实例时，该实例离开原组并进入当前组。
13. 退出后，采集仍在，同步不拉回。再次手动加入后恢复告警。
14. 删除默认组后，新实例不再自动告警。其他组织的默认同名组不受影响。
15. 没有策略编辑权限的人安装 Agent，实例仍能进入默认组。同一人不能修改规则或更改默认组。
16. 打开策略列表，只能看到旧策略和单独规则。策略组里正在执行的规则不在此列表中，只在对应策略组的组内规则里。
17. 一个策略组有八条规则时，执行次数是八，不是「成员数乘以规则数」。每条规则只覆盖采集插件与它一致的成员。一台成员退出后仍是八次执行；它原先所在插件的规则不再覆盖它，并结束它在这些规则上尚未恢复的告警。
18. 策略列表和模板页都不能空白新建一条单独规则。在实例页选中一台实例后可以补一条，并看到它将与所属策略组同时告警。
19. 在策略组上选择通知方式和通知人并保存后，该组每条规则对应的策略都写成这一套。未恢复告警不因此结束。新建组在保存通知前不预填通知人，也不推送。
20. 主机默认策略组同时包含 WMI、SSH、Telegraf 的内置规则。只用 WMI 采集的主机只被 WMI 规则覆盖。在 WMI 接入页看到的是该组里的 WMI 规则，其他插件的规则标明对这批实例不适用。
21. 在策略组列表停用一组后，组内规则停止扫描，这些规则上尚未恢复的告警结束，成员仍留在组里。再次生效后从当前时间继续扫描，不补出历史告警。默认组停用期间，新实例仍会加入，但不会告警。

## 11. 本期不做

- 按磁盘、网卡等子对象自动铺开规则。
- 在接入时按实例勾选要采集的指标子集。
- 打开 CMDB 自动创建监控实例。本期只规定实例一旦由节点管理新建，或被 CMDB 首次对上且还没有成员决定时，如何加入默认组。
- 指标自动发现的新实例自动加入策略组。
- 自动把旧策略收进策略组，或自动停用旧策略和单独规则。
- 某一条规则单独设置通知方式和通知人。在此之前，策略组上的保存会覆盖组内全部规则。
- 插件升级后，把新增的内置规则合并进已经生成的策略组。
