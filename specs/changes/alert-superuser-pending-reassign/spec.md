# 告警超级管理员待响应转派豁免

Status: done

## Completion Evidence

- `AlertOperator.reassign`：待响应且 `is_superuser` 时替换处理人、状态保持 pending；处理中仍要求当前处理人。
- Web `operator` 与 OpenAPI `operate_alert` 把认证用户的超级用户标志传入操作服务，默认不是超级用户。
- 告警操作按钮：超级用户在待响应看到并可点转派；认领/关闭规则不变。
- 测试：`apps/alerts/tests/test_alert_operator.py`、`test_open_api_operator_service.py`；前端 `web/src/app/alarm/utils/__tests__/alertActionAccess.test.ts` 与 `pnpm test:alarm-superuser-pending-reassign`。
- 验证（2026-09-03，`uv run pytest apps/alerts/tests/test_alert_operator.py apps/alerts/tests/test_open_api_operator_service.py --no-cov --nomigrations`；`pnpm test:alarm-superuser-pending-reassign`）：上述用例通过。

## Problem Statement

告警已经分派、处理人还没认领时，超级管理员在页面上看不到可用的转派，后端也会按「必须是当前处理人，且告警已在处理中」拒绝。值班分派人未响应时，超级管理员无法把单转给别人。处理人一旦认领，超级管理员也不应再改处理人。

## Solution

只给平台超级用户放开「待响应」告警的转派：不必是当前处理人，直接换人，状态仍是待响应。未分派继续用原有分派。已认领后不给超级用户额外豁免；若超级用户本人就是当前处理人，仍按普通人转派。认领、关闭、事故不动。

## User Stories

1. As a 平台超级用户, I want 把未认领的已分派告警直接转给其他人, so that 处理人未响应时我不必先把自己加进处理人再转走
2. As a 已经认领告警的处理人, I want 认领之后超级管理员不能再改处理人, so that 我接单后的处置不被管理员中途换人打断
3. As a 平台超级用户 who is also the current assignee, I want 仍能转派自己处理中的告警, so that 我交班时走普通人规则而不是被豁免误伤
4. As an 普通用户 or 组织管理员, I want 待响应告警仍然不能转派, so that 值班分派不会被有编辑权限的人随便改走
5. As a 能看见未分派告警的人, I want 未分派告警继续只能分派不能转派, so that 状态机入口保持一条

## Implementation Decisions

- 豁免身份只认平台超级用户标志，不认组织管理员、应用管理员或告警编辑权限。
- 不新增操作类型。继续走现有转派：待响应且操作人是超级用户时，允许只替换处理人，状态保持待响应；处理中仍要求操作人是当前处理人。
- 告警操作服务目前只持有用户名。由已认证调用方把超级用户标志传入，默认不是超级用户。自动分派等机器身份不得获得这条豁免。Web 操作接口与 OpenAPI 告警操作共用同一判断，避免两套口径。
- 处理人校验、通知、提醒任务、升级重置、操作日志沿用现有转派副作用；日志操作人记实际点击的超级用户。
- 批量操作逐条判定：待响应由超级用户转派成功；处理中且操作人不是当前处理人则该条失败；其它状态失败原因与今天一致。
- 页面只改按钮可见与可点：超级用户在待响应告警上能看到并点击转派。认领、关闭的「必须是当前处理人」不变。列表批量栏、详情操作、共享告警操作组件凡是告警转派入口都要一致。事故入口不改。

## Testing Decisions

- 只测对外行为：谁能转派、状态怎么变、处理人是否替换、非超级用户与已认领场景是否仍被拒绝。不测内部如何读取用户标志。
- 主缝是现有告警操作服务测试。补：超级用户转派待响应成功；普通用户转派待响应失败；超级用户转派处理中且自己不是处理人失败；超级用户本人是处理人时处理中转派成功；未分派转派失败。OpenAPI 走同一服务时，超级用户与非超级用户各一条即可。
- 前端用与现有告警操作按钮相同的源码契约测试，锁住：超级用户待响应可转派；非超级用户待响应不可转派；处理中转派仍要求当前处理人。

## Out of Scope

- 事故分派、转派、认领、关闭。
- 超级用户替别人认领或关闭。
- 新的管理员转派接口或权限点。
- 改变未分派分派、处理人跨组织校验、转派替换语义。

## Further Notes

这是值班模型上的管理员兜底，不是把超级用户变成万能处置人。待响应转派是交班：新处理人替换旧处理人，旧处理人不再能认领这条告警。
