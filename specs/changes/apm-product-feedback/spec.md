# APM 产品走查整改

## 背景

产品走查确认 APM 在服务身份、告警状态、探索入口、策略配置和接入信息架构上仍混用了技术实现口径与用户任务口径。本变更以 `DESIGN.md`、`web/DESIGN.md` 和现有 APM 真实接口为约束，收敛对应生产路由，不引入模拟数据。

## 产品决定

- 服务目录展示遥测 SDK 语言；“状态”表示应用或服务的最高活跃告警级别，不再展示推导健康度。
- 应用卡进入独立应用详情。应用管理是集成默认入口，“添加接入”是具体应用上的操作。
- 删除内置“未归类应用”。只有显式存在且对当前组织可见的 `service.namespace` 才能进入服务目录。
- 服务不会因静默被自动归档；接入实例的产品状态只保留 `active / silent`，不再存在归档历史、手工归档/恢复或自动归档。已有 `archived` 实例迁移为 `silent`。服务归档能力不受影响。
- SLO 启用状态是列表级操作，不进入创建或编辑表单。
- 调用链和错误页在未带深链参数时查询当前组织权限与当前时间窗内的全部结果；查询必须使用游标/分页且单页最多 100 条。错误查询在服务端限定 `status=error`。
- 端点指标在表头排序，详情展示端点级 RED 趋势与对应调用链。
- APM 告警列表展示服务与端点，不重复展示状态和值；详情提供所选告警对应服务的 RED 趋势。
- APM 告警事实仍由 APM 策略和事件流产生，不与 Monitor 的告警表合并；两者对齐交互和状态语言，但保持领域与权限边界。
- 策略列表移除测试查询与监控对象列；创建使用独立页面，启用状态保留为列表级操作。

## 拓扑术语

- 原“样本”指当前时间窗内受查询上限约束的 Trace 观测，不代表全量流量；界面统一改为“观测 Trace/观测调用”。
- 原“SVC”是 service 的缩写；界面统一显示“服务”。
- 连线箭头以节点边界为起止点，并使用固定用户空间 marker，避免缩放后箭头穿过节点或大小失真。

## 验收

- 服务页可见语言、最高活跃告警状态和独立应用详情入口，无遥测依赖宣传文案。
- 服务详情吞吐与错误率使用主题实际色值绘制，亮暗主题 Canvas 均有效。
- SLO 创建/编辑无启用项且“端点”不重复显示可选提示。
- 调用链、错误、端点在真实空数据时仍有可操作筛选或明确空态；不伪造数据。
- 告警详情、策略创建、应用详情均为生产路由并通过权限与真实 API。
- 集成菜单顺序为应用管理、接入实例；实例默认活跃，可切换查看静默实例，不暴露归档产品概念。
- 后端目录、序列化、实例状态迁移、Issue 查询和 endpoint RED 查询有聚焦回归测试。

## APM 其他产品优化（2026-08-14）

本切片只覆盖服务、服务拓扑、探索和集成；明确不修改 APM 事件告警、策略与快照。

### 页面与交互

- 服务目录继续使用内容优先的响应式列；服务身份固定为“语言标识 + 服务名”。表格只在确有超宽内容的局部允许横向滚动。
- 从服务页应用卡进入应用详情：桌面为左侧约 `2/3` 应用范围拓扑、右侧约 `1/3` KPI，下方为应用内服务列表；窄屏按拓扑、KPI、列表顺序纵向排列。
- 服务详情与端点详情均展示三张独立 RED 趋势图：吞吐量、错误率、时延。时延同图展示 P95/P99，以线型和图例共同区分。
- 服务拓扑只保留自动分层图形布局；调用方向固定为调用方 → 被调用方。双向调用绘制两条分离曲线，每条只有目标端单箭头；标签使用用户空间字号并带背景描边，缩放时保持清楚。节点圈内显示遥测 SDK 语言图标。
- 调用链空查询表示“当前组织权限 + 当前时间窗内全部”，并继续使用 50 条默认页、100 条硬上限和时间游标；清空查询后立即回到该默认查询。耗时输入仅在合法范围下经 400ms 防抖、回车或失焦提交，不保留“应用耗时”按钮。
- 接入配置字段完整且校验通过后经 500ms 防抖自动生成。每次生成带递增请求序号；旧请求无法取消时忽略过期响应，失败状态保留同一组有效字段并提供重试。服务端继续无状态生成，不新增持久化模型。
- 接入实例只显示 `active / silent`。静默只表示最近 15 分钟没有新遥测，不影响组织调整；时间范围筛选仍用于元数据定位，但没有“归档/历史”状态。

### Issue 查询 interface

正式持久化 Issue 生命周期不在本切片内伪造。本期提供一个真实遥测驱动的、只读的 Issue 投影 interface：

`GET /api/v1/apm/issues/`

- 输入：`started_at / ended_at`（默认 1h，最大 7d）、可选 `service_namespace / service_name / environment`、`cursor`、`limit`（默认 50，最大 100）。不接受客户端传入 `status`，服务端固定查询 Error Span。
- 权限：先按当前组织可见的服务/实例身份过滤错误 Span，再读取对应 Trace；没有当前组织或无权身份时返回空页，不可枚举其他组织数据。
- 数据：只读取真实 Error Span 与其 Trace 属性。聚类键为 `服务身份 + 异常类型 + 归一化消息骨架 + 关键栈帧` 的稳定指纹；异常字段优先使用 OTel `exception.type / exception.message / exception.stacktrace`，缺失时回退到真实的 OTel error status 描述，绝不使用 `root_span_name` 作为 Issue 类型或聚类键。
- 输出：`items + next_cursor + truncated`。每项含稳定 `fingerprint`、异常类型、消息、代表堆栈、服务/环境、出现次数、受影响 Trace 数、最近出现、版本分布、端点分布与样本 Trace。计数只代表当前有界页的投影，`truncated=true` 时界面必须明确提示不是时间窗全量。
- 资源边界：单页 Error Span 最多 100；每页最多读取 100 个唯一 Trace；Trace 详情继续执行既有脱敏与响应截断。

未来若落地可处置的正式 Issue，必须新增持久化模型、聚类版本、生命周期和重算/迁移策略；不得把本期只读投影冒充为已持久化 Issue。
