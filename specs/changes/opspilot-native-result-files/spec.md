# OpsPilot 原生结果文件接入

## 范围与决定

仅复用当前 Deep Agents 0.6.12 的结果卸载、范围读取、搜索和 Backend 路由。
删除固定 1,000 字符的 `read_tool_result`，不增加动态预算算法、数据库、跨轮持久化或新的执行权限。
不修改 Pod 日志、Redis SCAN 和子进程输出的既有采集边界。

## 当前实现

- `RunResultBackend` 复用 `FilesystemBackend` 的读写与搜索，限定在当前任务的 `large_tool_results/`，关闭后不可继续访问。
- `CompositeBackend` 将原生 `/large_tool_results/` 路由到该目录；已有技能 Backend 继续作为默认执行 Backend。无技能时没有 Shell 执行能力。
- 分步执行使用公开 `create_agent`，安装一次原生 `FilesystemMiddleware`、必要的 `SkillsMiddleware`、`PatchToolCallsMiddleware` 和既有 OpsPilot 中间件；审批继续使用原生 HITL 中间件。
- 原生 `create_deep_agent` 没有公开的文件系统阈值参数。分步执行已有独立计划与步骤控制，不复制上游工厂或修改依赖私有字段；非分步路径仍使用原生工厂及其默认卸载阈值。
- 分步原生阈值使用现有 `max_single_message_tokens` 配置。上游按 4 字符/token 估算，故传入该额度除以 4 的保守值（上限 20,000），使返回字符量保持在现有单消息额度内。默认额度 4,000 对应原生阈值 1,000，即约 4,000 字符；读取按行、支持调整范围与搜索，不是固定 1,000 字符翻页。
- 分步工具正文由原生文件中间件处理，不再经过步骤级二次截断。`ContextWindowMiddleware` 继续负责工作窗口和摘要，因此分步不再重复安装上游摘要器；最终上下文保护保留。
- 清理历史结果保留原生文件引用和消息身份、artifact；不再提示重新执行业务操作。步骤提示和工作区提示提供仍然有效的结果路径。
- 普通步骤常驻 `read_file`、`grep`，不开放写文件或执行。纯技能脚本成功后可读取结果，但不能再次执行；禁止借读取结果访问技能包。
- 结果文件工具写入被拒绝；已有 Python/Shell 的 OS 权限不因本次改造收紧或扩大。
- 结果读取仍计入现有模型次数/token 上限；允许上下文清理后的合法重读，业务工具重复执行限制保留。
- 文件按当前节点运行生命周期清理；跨轮需要保留的产物继续走原附件服务。

## 兼容与回滚

不新增依赖、配置步骤、数据库迁移或外部 API。同步/异步、作业展示 artifact、多模态内容块与审批均需回归。
临时路径只在当前运行有效，无持久化数据迁移。按完整变更回滚代码/镜像即可恢复原机制，不单独回滚读取器或 Backend。
