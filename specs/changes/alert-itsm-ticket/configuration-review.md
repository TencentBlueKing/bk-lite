# ITSM 配置与使用流程复核

日期：2026-09-24
状态：错误诊断、连接启用与表单测试整改已实施（见第 7—9 节），其它整改待实施；真实 ITSM 契约尚未完成适配。早期复核背景保留，连接启用条件以第 9 节为准。

本文针对用户反馈的“无法启用、提示等待开发、配置后如何测试”重新审视完整使用流程。它修订主规格第 15.2 节的交付要求，不把现有临时禁用行为作为最终产品设计。本文不宣称新增测试入口或实际建单已完成。

## 1. 结论

现有实现未形成用户可独立完成的配置和使用闭环。根因不是用户不会填写，而是将后端未完成的协议适配转成了用户界面的永久禁用条件。此前自动化测试验证了该限制及内部业务逻辑，却没有证明用户能从首次配置走到真实成功建单。

连接配置的启用与工单协议适配应分离：允许配置和启用连接，规则与执行阶段继续校验工单协议，避免未适配时发送建单请求。开发完成情况属于业务交付条件，不应成为连接开关无法操作的原因。具体修正见第 8 节。

继续保留已确定范围：单条 Alert、一告警一主工单、异步建单、周期同步、可选关闭告警、明确失败后的手动补建；不恢复留言、URL、Incident 建单或通用平台适配框架。

## 3. 修订后的配置流程

### 3.1 全局配置：管理连接和认证

保留集成名称、ITSM 地址、认证令牌、可选 CA、失败通知及启停。响应字段与工单状态语义由后端固定适配，不再交给用户填写。

- 地址填写站点根地址时，后台补 `/openapi/v1/itsm/bklite_expand/api/v2`；填写完整 API 根地址时保持该目标。界面显示实际调用的 API 根地址，避免重复追加前缀。
- 编辑中的“测试连接”使用当前表单，而不是数据库里的旧地址、旧令牌或旧证书。新输入令牌不保存、不回显；同目标留空可使用已保存令牌；更换目标不能复用旧令牌。
- 测试只执行已知只读列表接口，不创建工单，不要求集成先启用。空列表也是有效成功结果。
- “保存草稿”允许先记录尚不可用的配置；不能因为测试失败丢失用户填写值。
- 对已经启用的连接，修改地址、令牌或证书后，应先用候选配置验证，成功才替换正在使用的配置；失败保留原有效配置，避免错误令牌覆盖后所有规则一起失效。显式停用不需要远端测试成功。
- 启用由后端对本次配置执行真实连接校验，不信任前端传入的“已测试成功”。不新增用户要理解的协议就绪开关或复杂连接状态机。
- 测试结果显示测试目标、时间、范围、成功或失败原因。修改或重新读取配置后不沿用旧结果。

最终用户流程：填写 → 测试当前配置 → 修正错误或保存 → 启用。保存并启用时后端仍需保证校验的是同一份配置，网络请求不得放在数据库行锁事务中。

注意：这套启用流程以开发已经交付可用的协议适配为前提。当前代码尚不满足此前提；连接测试不能自动推导出创建 ID 路径或关闭状态含义。

### 3.2 告警处理规则：管理流程和业务内容

选择 ITSM 动作后，确定规则所属团队，展示其全局集成名称和地址，提供“前往全局配置”。当前团队只有一个目标系统时，不要求重复选择连接。

用户配置匹配条件、创建触发事件、流程标识、工单字段映射以及默认关闭的“工单关闭后关闭告警”。本期只有创建动作，没有分派、认领、恢复、关闭留言。

流程标识仍需用户从 ITSM 流程配置或接口提供方获得；现有资料没有可依赖的流程目录及表单元数据接口，不能承诺自动下拉流程、自动发现所有必填项。标题默认提供 `ticket__title ← title`，其他目标字段按实际流程填写；告警侧来源字段提供已支持字段的选择和样例值。

增加“预览工单内容”：选择有权限的样例告警，显示是否命中规则、字段解析结果、类型和缺失项。预览不能创建关联、占用一告警一主工单名额或发送远端请求。流程标识存在、远端必填项完整及创建权限，仍需真实建单验证。

### 3.3 真实建单验证：复用正式链路

使用专门的测试规则和测试告警验证，避免另建一套只能测试通过却不同于正式实现的直接 POST 路径。样例内容可以模拟，HTTP 调用和持久化必须走正式业务链路。

- 展示将使用的告警、规则、目标系统及工单内容。
- 按钮明确为“创建工单并验证”，清楚说明将产生真实工单及该告警的正式关联。不是无副作用的“测试连接”。
- 复用唯一关联、异步执行和幂等控制；显示已受理、建单中、成功、明确失败、结果待确认。
- 先完成真实创建与查询，再等待一次周期同步验证同步链路。手动读回成功不能替代周期任务运行的证据。
- 已有关联则展示原工单，不再新建；明确失败可按既有补建规则重试；超时或结果不明必须核查，不能再点一次就重复建单。
- 首轮测试关闭回写开关保持关闭；需要验证回写时，使用专门测试告警开启该开关，再在 ITSM 正常结束工单，检查告警端是否按现有关闭语义结束。
- 工单测试数据由 ITSM 按其流程处理；不新增自动删除、终止或关闭远端工单的动作。

## 4. 三种测试的边界

| 能力 | 位置 | 验证内容 | 不代表什么 | 远端副作用 |
|---|---|---|---|---|
| 测试连接 | 全局配置弹窗及卡片 | 实际地址、网络策略、TLS、令牌被接受、列表接口权限与响应格式 | 不证明具体账号身份、流程存在、创建权限或同步／关闭链路 | 只读 |
| 预览工单内容 | 告警处理规则 | 样例告警是否匹配、映射值和类型、缺失字段 | 不证明 ITSM 流程存在或远端必填项已完整 | 无 |
| 创建工单并验证 | 专用测试规则／告警的验证入口 | 正式创建、关联保存、查询读回、周期同步；单独测试可选关闭 | 排队受理不等于创建成功；一次成功不代表全部流程枚举已覆盖 | 创建真实工单 |

## 5. 验收必须从用户操作出发

1. 只填站点地址，展示正确 API 根地址；完整 API 根地址不会重复追加；非法路径返回明确提示。
2. 首次未保存、未启用时能测试当前表单；测试失败后输入仍保留。
3. 令牌错误、权限不足、证书错误、网络策略拒绝、超时、错误路径和不兼容响应分别可识别；提示不含凭据或响应正文。
4. 测试中修改配置、其他管理员修改配置、切换团队、迟到响应和刷新后，都不能把旧测试成功套用到新配置。
5. 空列表测试成功；没有建单、流程或账号详情证据时，不显示这些能力已经验证。
6. 启用使用后端实际校验结果；篡改前端成功标志无效。更新正在使用的认证配置失败时，不破坏原连接；远端故障时仍可停用。
7. 规则归属团队与集成一致；切换团队后旧连接失效；加载失败不显示为未配置。
8. 映射预览正确处理 0、false、对象、缺失字段和必填标题；无远端写操作、无关联记录。
9. 测试告警完整走过规则触发、Outbox、Worker、建单、关联、详情和周期同步；看到受理不能提前显示建单成功。
10. 重复点击、明确失败补建和结果不明核查符合一告警一主工单约束。
11. 开关默认关闭时 ITSM 结单不关闭告警；打开后只关闭活跃测试告警；已恢复／关闭告警不被覆盖。
12. 失败通知配置有效且实际投递可验证；建单失败与通知失败分别展示。

## 6. 实施顺序及当前限制

1. **补齐开发证据**：取得当前可用流程、创建与详情成功响应、真实关闭状态语义，由后端完成固定适配。不要继续使用文档中已实测不存在的流程重复发送创建请求。
2. **修正全局配置和连接测试**：地址、当前表单测试、持久错误反馈、配置一致性和安全更新。
3. **修正规则使用流程**：单团队集成、明确加载状态、映射预览、测试入口。
4. **以真实测试告警验收完整链路**，同时保留现有并发、权限和失败隔离自动化回归。

步骤 2、3 中不依赖真实契约的部分可以先实施；真实建单验收必须等步骤 1。不得只移除 `contract_ready` 就宣称完成，也不得用大量替身测试通过替代从配置到建单的用户验收。

初次复核产物为设计审查与修订文档；后续实现进度见第 7 节。未新增或发送真实测试工单。

## 7. 连接错误诊断修正（2026-09-24）

本节更新第 2 节“失败反馈不指导修复”的实施进度；其它整改仍按上文标注，未整体完成。

- 本机对开发 ITSM 地址执行无认证信息的只读 TLS 握手，得到证书验证错误 20：`unable to get local issuer certificate`。这是本机信任库下的实测结果，不等同于已经取到告警服务端运行环境的原始异常，也未验证令牌或创建工单。
- 处理方式：ITSM 部署方提供经确认的 CA PEM，在集成的“受信 CA 证书”中配置；若服务端遗漏中间证书则补齐服务端证书链。证书有效期和访问地址匹配也必须满足，保持 TLS 验证开启。
- 客户端已区分 TLS、超时、网络连接、HTTP 请求及 JSON 格式错误；只读接口的 401、403、404、重定向和服务端错误在读取响应正文前分类。错误使用固定文案，不透传原始响应或异常。
- 页面已持续显示测试失败的具体原因，避免只在瞬时提示中出现；重新测试时清除上次错误。此次不把证书诊断当成真实工单联动验收，不解除未完成适配的启用限制。
- 非幂等 POST 的异常结果保持 unknown，不因错误分类而自动重发。既有明确业务拒绝仍按原有规则处理。
- 本次新鲜验证：97 项 ITSM 后端测试通过，客户端行覆盖率 93%；13 项 Web 交互测试通过；官方类型检查及改动文件 ESLint、Flake8、diff 检查通过。Web 首次与类型检查并行执行时有 1 项超出原有 5 秒上限；未提高超时，停止并行文件执行后原断言全部通过。未重复执行整个告警模块回归。


## 8. 连接启用与工单协议校验分离（2026-09-24）

用户确认连接测试成功后仍无法打开开关，根因是把工单响应适配进度错误地作为连接配置启用条件。此次修正：

- 全局表单允许首次配置及编辑时选择启用；移除固定禁用开关及“暂不可启用”提示。
- 后端保存连接不再验证工单响应契约，仍校验地址、证书、凭据、授权团队与目标变更约束。
- 规则的集成列表按启用状态、授权团队及连接基础格式筛选，不因工单协议未就绪而隐藏连接。
- 规则保存及运行时仍验证工单响应契约；缺少适配时明确拒绝，不发起未经适配的建单请求。
- 连接测试仍是只读 GET 列表；成功不代表创建权限、流程必填字段或状态闭环已经验证。

此次修改只解决连接启用和选用，未补造真实创建响应或关闭状态映射，也未更改开发环境的启用状态。完整工单能力仍需真实流程联调。

新鲜验证：先复现后端启用返回 400、前端开关被禁用；修正后 97 项 ITSM 后端测试、9 项集成表单／规则字段前端测试通过，类型检查、改动文件 ESLint、Flake8 通过。未部署或宣称真实建单验收通过。


## 9. 表单内测试成功后启用（2026-09-24）

用户要求测试连接放到表单内，失败不能打开开关，成功才能启用；这替代第 8 节允许直接打开开关的交互。

- 卡片移除测试按钮，配置表单在证书与启用开关之间提供测试入口和持续的成功／失败结果。首次配置无需先保存，测试使用当前表单。
- 地址、令牌或证书变更后测试结果失效；迟到响应、关闭或重开表单不能沿用旧成功。测试失败保留字段，未启用配置仍可保存为草稿。
- 已启用连接始终可显式停用。编辑已启用连接测试失败时阻止覆盖原连接，不自动停用保存的配置。
- 后端保存 enabled=true 时独立只读复测候选配置，不信任前端标记；外部 HTTP 不在数据库事务锁内。复测后检查配置版本，避免并发编辑被旧结果覆盖。失败不写数据库；enabled=false 无需网络测试。
- 草稿令牌仅在请求内存中使用，不保存、不回显；同地址留空使用当前团队已存令牌，换地址必须提供新令牌。CA、SSRF、实际连接 DNS 校验、超时和响应上界与现有客户端一致。
- 不新增表、迁移、测试凭证或状态机。空请求测试接口保留为已保存配置的只读诊断入口。
