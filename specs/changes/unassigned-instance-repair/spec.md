# 超管未归属对象修复

Status: implemented

## Problem Statement

特殊操作或缺陷会把节点、监控实例、日志采集实例、APM 应用 / 服务 / 接入实例的组织关联删光。控制台列表按当前组织命中关联表，关联为空则所有人（含超管）都看不见，也无法重新指定组织。需求标题里的「无数据实例」容易理解成无数据告警，实际要修的是未归属对象。

超管在按当前组织查询时无条件并上未归属对象不可行：每个组织的日常列表都会被全平台幽灵对象污染，列表看见也不等于能改组织，公共组织过滤一改还会把策略、Trace、告警一起放开。

## Solution

给平台超级用户一个显式的「未归属」修复入口，默认关闭。开启后只列出组织关联为空的目录对象，允许指定至少一个真实组织重新归属，或删除该对象。日常当前组织列表不变。不为超管放开这些对象的指标、日志、Trace 或告警查询。同时禁止用户操作和节点同步再把组织关联写成空。

## User Stories

1. As a 平台超级用户, I want 在节点、监控、日志和 APM 目录里打开「未归属」, so that 我能找到全平台已经丢光组织的对象。
2. As a 平台超级用户, I want 给未归属对象指定至少一个组织, so that 目标组织的成员能重新看见并管理它。
3. As a 平台超级用户, I want 删除确认无用的未归属对象, so that 修复列表不会一直堆着无法回收的残骸。
4. As an 普通用户或组织管理员, I want 未归属对象继续不可见、不可改, so that 租户隔离不会因为别人丢了组织而变成全员可见。
5. As a 任意组织的使用者, I want 日常实例列表仍然只显示当前组织范围内的对象, so that 超管打开控制台时不会在每个组织里看到同一批幽灵对象。
6. As a 平台运维, I want 设置组织、移除组织和节点同步都不能把最后一个组织删光, so that 修完的对象不会再次变成未归属。

## Implementation Decisions

### 身份与入口

- 豁免身份只认认证用户的持久化超级用户标志，与登录态和告警待响应转派相同。不认组织管理员、应用管理员或请求体里的超级用户声明。
- 控制台 HTTP 目录列表增加显式「未归属」开关，仅超级用户可打开。非超级用户携带该参数返回 403，不得静默忽略。
- 开关打开时，列表查询替换为「组织关联条数为 0」，不与当前组织结果做并集，也不受当前组织范围裁剪。
- 开关默认关闭。关闭时现有当前组织过滤保持原样，包括超级用户。

### 查询谓词

- 未归属用「不存在组织关联行」表达，必须走 Exists / 子查询。禁止在关联表 INNER JOIN 上写「当前组织或组织为空」。
- 该谓词放在公共组织范围工具里，由节点搜索、监控实例列表、日志采集实例列表、APM 应用 / 服务 / 接入实例列表显式选用。默认的当前组织过滤函数不得被改成自动并上未归属。
- 详情、设置组织和删除：若对象已无组织关联且调用方是超级用户，允许访问；否则仍按当前组织授权。这样从「未归属」点进现有编辑弹窗不会 404 / 403。
- 指标查询、日志检索、Trace、拓扑、告警列表与详情不加这条豁免。NATS 与 OpenAPI 也不返回未归属对象。

### 重新归属与删除

- 超级用户给未归属对象指定组织时，目标组织仍走现有可分配组织校验；超级用户可分配全部未归档真实组织。
- 设置组织必须至少保留一个组织。空列表拒绝，不得先删光再写入。
- 监控按组织移除若会删光最后一个关联，整笔拒绝。
- 删除走各域现有删除能力，不新造删除协议。超级用户删除未归属对象后，该对象不再出现在「未归属」列表。

### 防再丢

- 节点 Sidecar 组织同步在期望名单为空时不得删除已有关联；视为本次未上报，保持原组织。这将推翻「空名单删光全部组织」的旧契约。
- 节点批量改组织已经拒绝空名单，保持。
- 监控设置组织在空名单时不得删光关联。
- 日志设置组织空名单继续视为无操作，不得改成删光。
- APM 设置组织继续要求至少一个组织。
- 本变更不回填历史未归属对象到 Default 或其它占位组织。

### 前端

- 仅超级用户在节点列表、监控接入实例列表、日志采集实例列表、APM 服务列表和 APM 接入实例列表看到「未归属」筛选，默认关闭。
- 开启后请求带显式未归属参数；组织列展示未归属而不是当前组织。
- 行操作复用现有设置组织和删除入口。APM 已有组织分配弹窗和「未分配」文案，补筛选即可。
- 非超级用户不渲染该筛选；即使用户改请求参数，服务端仍 403。

## Testing Decisions

- 只测对外行为：谁能列出未归属对象、默认列表是否保持干净、设置组织后目标组织是否可见、删光组织是否被拒绝、空同步是否保留原组织、非超级用户和数据面是否仍 fail-closed。不测私有 Exists 实现细节。
- 最高测试缝是各域现有目录列表、设置组织、删除和节点 Sidecar 同步。公共谓词通过这些 HTTP / 服务行为覆盖，不为谓词单开与调用方脱节的测试。
- 先验：监控实例组织列表与权限围栏、日志采集实例权限、节点搜索与批量改组织、Sidecar 空名单删光、APM 服务 / 接入实例组织过滤与组织分配。空名单删光的节点测试必须改成「保持原组织」。
- 必覆盖场景：超级用户默认列表看不到未归属对象；打开未归属后能看到并设置组织；设置后目标组织成员可见、未归属列表消失；超级用户可删除未归属对象；非超级用户列表与带参请求均不可见；超级用户不能用未归属对象去查指标 / 日志 / Trace；监控移除最后一个组织失败；Sidecar 空名单不删光；空名单设置组织失败。

## Out of Scope

- 无数据告警、无流量策略，以及把「暂无上报」的有组织对象放进本入口。
- 策略、告警、Trace、拓扑的未归属修复。APM 策略无组织仍 fail-closed，不另做超管修补。
- CMDB 主机及其它未列入需求的对象。
- 自动回填到 Default 或新建「待分配」组织。
- 新的独立权限点或给组织管理员的修复入口。
- 为超级用户放开跨组织取数。
