# 网络采集未知 SOID 确认并回写特征库

Status: ready

## Problem Statement

网络设备采集只认四类模型：交换机、路由器、防火墙、负载均衡。sysObjectID 对上特征库就落到对应模型；对不上时，采集把品牌和型号标成「未知」，设备类型却写成交换机，并照常入库、挂接口。未知设备因此变成交换机脏数据，拓扑也会跟着挂错。扫描发现已经不把未知 SOID 建成交换机，并允许在命中详情里补指纹；周期采集这条仍在制造脏数据。

## Solution

网络采集遇到特征库未命中的 sysObjectID 时，不写入任何网络模型。未识别设备留在本次任务结果里，管理员勾选后有两条路：只补 SOID 映射，或写入模型。两条路都先按 SOID 去重，在一张表里批量填写设备类型、品牌和型号。先补过的映射，之后写入时直接带上厂商和型号，不再采集。已有的精确命中和前缀命中保持自动入库。

## User Stories

1. As a CMDB 管理员, I want 特征库没有的 SOID 不再变成交换机, so that 未知设备不会污染交换机模型和拓扑。
2. As a CMDB 管理员, I want 在该网络采集任务的结果里按 SOID 看到未识别设备, so that 我能一次处理同一类设备，而不是逐台猜测。
3. As a CMDB 管理员, I want 勾选设备后按 SOID 去重，在一张表里批量填写设备类型、品牌和型号并只保存映射, so that 同一类设备不用逐台补特征库。
4. As a CMDB 管理员, I want 把勾选的未识别设备写入交换机、路由器、防火墙或负载均衡, so that 我决定它们进哪个模型。
5. As a CMDB 管理员, I want 写入时若映射已经填过，设备上直接带上该 SOID 的厂商和型号, so that 不用为了补这两个字段再采集一次。
6. As a CMDB 管理员, I want 已在特征库中的 SOID（含只命中厂商前缀的）继续自动入库, so that 确认只发生在真正没有映射的时候。
7. As a CMDB 管理员, I want 还没写入的设备留在未识别列表里，直到我写入或下一次采集覆盖本次结果, so that 未确认不会偷偷入库。

## Implementation Decisions

- 只改网络采集（模型 `network`）的未知 SOID。扫描发现的未匹配抽屉、手选类型不写特征库、以及「未知不建 CI」保持原样。安全设备不是第五类网络模型，确认时不能选它。
- 「未命中」只指解析后既没有精确 OID，也没有达到最短前缀的特征库行，因而走到今天的默认映射（品牌「未知」、型号「未知」、类型交换机）。特征库里已经有行、但型号文本是「未知」的前缀命中，仍算已识别，按该行的设备类型自动入库。
- 未命中设备及其接口不进入本次新增、更新、删除。不以 `{ip}-switch` 建实例，不建接口归属，不把以该设备为端点的拓扑链路写入。已识别设备的入库和拓扑保持原逻辑。自动录入和手动审批都一样：未识别行不得出现在待审批的交换机新增里，审批通过也不能把它们带进交换机。
- 未识别结果挂在该采集任务最新一次的分类结果上，按 SOID 分组。每组保留原始 SOID、IP、系统名，以及确认后要一起入库的接口快照。不新建跨任务收件箱。下一次采集完成会覆盖上一份未识别列表；未确认的设备不会累积，也不会入库。
- 任务结果在现有新增 / 更新 / 删除之外展示「未识别」设备表，可勾选。列至少有 IP、系统描述、SOID；该 SOID 已有特征库行时，展示其设备类型、品牌和型号。执行未结束时不能补映射，也不能写入。
- 勾选后的两个动作都先按 SOID 去重。十台设备若只有三个 SOID，表里只有三行，并显示每行对应的勾选台数。SOID 不可改。设备类型只允许交换机、路由器、防火墙、负载均衡。品牌和型号必填。已有特征库行的 SOID 预填且不可改，不覆盖原行。
- 「补全映射」只写特征库用户行（非内置），不写 CMDB 实例。设备仍留在未识别列表，并显示刚保存的类型、品牌和型号。同一 OID 已存在时不新建第二行。
- 「写入模型」只写入勾选的设备及其接口，不写未勾选的同 SOID 设备。写入使用特征库里的设备类型、品牌和型号，数据来自本次快照，不重新采集。勾选里还有没映射的 SOID 时，先弹出同一张去重表，补完并保存映射后再写入。全部已有映射时，表只读确认后直接写入。
- 写入成功后从本次未识别结果里去掉这些设备。实例名沿用 `{ip}-{设备类型}`。不重放拓扑。自动录入和手动审批都一样：这次写入就是入库许可，不进通用待审批新增。特征库同步不得改写这些用户行。
- 没有 sysObjectID 的网络采集行今天会被丢掉、不会变成交换机。本变更不把它们放进未识别列表。
- 历史上已被默认规则写成交换机的实例不迁移、不删除。

## Testing Decisions

只测外部行为：未命中 SOID 的采集结果里没有交换机实例和它的接口；四类精确命中和合法前缀命中仍自动入库；补全映射只写特征库、设备仍未识别；写入时使用映射上的类型、品牌和型号，且只写入勾选设备；OID 已存在时不新建第二行；下一次采集同一 SOID 不再进入未识别。不测页面像素。

测试缝沿用网络采集格式化和采集任务结果，不新开运行时：

- 网络采集格式化：默认映射不再产出交换机；前缀命中仍产出特征库上的类型。
- 采集入库：未识别组出现在任务分类结果中，且不在新增 / 更新里；接口与指向未识别设备的拓扑不落库。
- 补全映射：按提交的去重 SOID 写入非内置特征库行，不调用实例写入；重复 OID 不新建。
- 写入模型：只入库请求里的设备；品牌和型号来自特征库行，不来自重新采集；同 SOID 未勾选的设备仍留在未识别里。缺少映射时拒绝写入。
- 扫描未知 SOID 仍不建网络 CI。特征库同步不改写用户行（沿用现有目录同步测试）。

Prior art：网络设备字段映射测试、OID 目录同步测试、扫描身份与认领测试。

## Out of Scope

- 清理或合并已经落在交换机模型上的历史未知设备。
- 把安全设备、或四类之外的类型，加进网络采集或特征库允许类型。
- 改扫描发现的未匹配交互，或让采集未识别写入扫描命中。
- 无 sysObjectID 的行、确认时重放拓扑、跨任务未识别队列。
- 只选手动类型、不写特征库的旁路。
- 改内置 SOID 目录内容。

## Further Notes

扫描侧已经把「未知当交换机」标成采集债务，并在扫描写入前丢掉。本变更还的是采集侧这笔债。扫描规格里「不改采集未知当交换机」仍约束那些扫描改动，不约束本变更。实现以本文和 `plan.md` 为准。
