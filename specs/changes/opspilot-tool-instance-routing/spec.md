# OpsPilot 工具实例选择修复

## 问题与范围

Jenkins、Elasticsearch、MSSQL 的公开子工具未透传实例选择，用户选择第二实例时仍访问第一或默认实例。PostgreSQL 同样缺少选择参数，且连接辅助函数把字典的 `items` 当成属性下标，导致多实例配置报错。AD 对未知实例名称或 ID 回退到所有域控。

范围仅为上述工具的路由及回归测试；保留 MySQL、Oracle、Redis 和 K8s 的既有行为。

## 行为

- PostgreSQL、MSSQL、Jenkins、Elasticsearch 的公开工具提供可选 `instance_name` / `instance_id`，ID 优先；显式选择只连接目标实例。
- 未指定时使用配置的默认实例，没有有效默认值时沿用第一实例；不新增批量扫描或批量写操作。Jenkins 构建仅在单个目标执行。
- 未知名称或 ID 在连接之前报错，不回退到默认或全部实例。旧平铺配置仍可不带选择参数运行；显式选择时明确拒绝。
- PostgreSQL 修正字典访问；指定数据库时直接建立一次目标数据库连接，不先连接再重连。MSSQL 显式选择也保留只读连接意图及原数据库名称校验。
- AD 有效选择、默认选择和不带默认配置时的现有聚合行为保持；仅移除未知名称或 ID 的全量回退。
- 不改工具结果格式、既有确认护栏、只读查询事务或连接超时；不修改传入配置，不把单次选择写入共享状态。

## 验证与发布

`server/apps/opspilot/tests/test_tool_instance_routing_service.py` 从公开工具入口逐一检查名称和 ID 路由到 SDK 边界，另覆盖默认值、未知目标、旧平铺配置、数据库覆盖参数及 AD。配合原有数据库、ES、Jenkins、AD、SQL 护栏及 K8s 回归测试。

无数据迁移。历史配置可继续读取；未知 AD 实例原先扩散为全量查询，现在返回错误，调用方须使用配置中真实的名称或 ID。回滚仅回退本次代码；会重新暴露错误路由问题。

2026-11-12 验证：上述定向回归合计 389 passed；本次新增/修改的可执行行覆盖率 317/317（100%），改动行 flake8 与 `git diff --check` 通过。所有外部连接均在 SDK 边界替换，本机缺少 unixODBC，MSSQL 在独立测试进程中替换驱动模块验证；未做真实数据库/集群联调。
