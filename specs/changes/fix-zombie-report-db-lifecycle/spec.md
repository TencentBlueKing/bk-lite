# 僵尸主机报告子线程连接回收（#7076 部分修复）

## 已确认问题

NATS 标准同步入口只清理调用线程。get_zombie_host_report 在线程池中执行 _query_zombie_logins，后者直接调用日志接口访问 ORM，没有经过 NATS 包装器。真实 PG 诊断在 CONN_MAX_AGE=0 下复现任务结束后 idle 遗留，控制 GC 时连续三轮为 1、2、3 条；工作线程内补清理后三轮均为 0。

## 契约与边界

- 在 _query_zombie_logins 实际工作线程开始和 finally 中调用 Django close_old_connections，遵循既有连接寿命配置。
- 保持登录统计结果、失败转换和报表输出不变，不重试、不改权限及 NATS 回复/ACK。
- 清理成功时保留原任务异常，包括 BaseException；清理自身失败沿用标准 finally 传播，不新增异常仲裁。
- 不关闭其他线程连接，不将清理移到 NATS 主线程，不修改其他 OpsPilot 候选路径。
- 回归覆盖完整 NATS 分发→报表线程池→本地日志接口→真实 PG 查询，以及异常路径和配置的持久连接行为。

## 未解决范围

线上五条长期 idle 连接尚未完全关联具体调用来源，不能认定本路径解释全部现场或历史连接数超限。本 PR 仅关联 #7076，保持 issue 打开。之前附件调度器修复为 #7077，独立于本次提交。
