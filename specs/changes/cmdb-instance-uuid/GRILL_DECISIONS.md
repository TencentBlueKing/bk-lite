## Q1. 用户价值与成功标准

**为什么要定**：决定验收是否必须包含「图 `_id` 变化后引用仍正确」。

**现状**：身份 = 图原生 int；重建/搬迁会改 ID；seed 已用 `inst_name` 规避跨库。

**推荐**：成功标准定为——同一 BK-Lite 内，图库重建或数据搬迁后，凡以业务主键持久化的引用仍指向原实例；同系统内运行期图查询仍可用内部数字 ID。

**其他代价**：若成功标准不含重建证明，产品动机只剩「预留跨系统」，范围易漂。

**状态**：假设采纳推荐（低风险、符合动机）。

## Q2. 对外身份策略（双身份 vs 硬切换）

**为什么要定**：决定 API、迁移窗口、前端节奏与代码复杂度。

**现状**：对外几乎全是数字 `_id`/`inst_id`。

**已确认（2026-08-10，含跨模块澄清）**：

- **最终态**：`inst_uuid` 是跨模块业务身份，也是 **CMDB 前后端交互** 的实例定位键。  
- **「对外 UUID 唯一」**：节点管理、监控中心、告警中心（以及 OpenAPI/NATS、配置采集、运营分析等）均可通过同一 `inst_uuid` **确定同一 CMDB 实例**，不再依赖会变的图数字 ID。  
- HTTP/OpenAPI/NATS/跨模块协议与活跃持久化引用：收发与存储均以 UUID 为准。  
- **`inst_id` / 图 `_id` 可保留在 CMDB 后端内部**：仅用于同进程 Graph Adapter / `InstanceManage`（及明确的图算法）一次操作工作集（如 `ID(n)` 建边、拓扑遍历）。  
- **禁止**：把数字 `inst_id`/`_id` 作为 CMDB Web 或跨模块的业务定位键；禁止写入跨模块活跃持久化契约；禁止跨请求缓存为业务身份。  
- **不做**长期双身份响应；**默认不提供**仓外数字入参废弃窗（破坏性发版说明即可）。若日后运维要求短窗，须另开变更并写死截止日期。  
- **注意**：Telegraf/节点侧 `instance_id=cmdb_{task_id}` 仍是**采集任务身份**，不等于 CMDB 实例 UUID；监控/告警若要绑 CMDB 实例，应使用 `inst_uuid`。

**否决**：08-02 式长期双主身份（响应同时主推 `_id`/`inst_id` + `inst_uuid`）。

**状态**：**已锁定**。

## Q3. 关联边是否持久化端点 UUID

**为什么要定**：影响迁移脚本、查询路径、Adapter 复杂度。

**现状**：边属性存 `src_inst_id`/`dst_inst_id`；查询大量靠边属性过滤。

**08-02**：边只存 `src_inst_uuid`/`dst_inst_uuid`。  
**旧实现**：边不存端点身份，从连接节点读——更「纯」，但服务层仍大量用图 ID 工作集，文档却写「不出 Adapter」，造成混乱。

**推荐**：边持久化 `src_inst_uuid`/`dst_inst_uuid`（及现有 `model_asst_id` 等业务属性）；**删除**数字端点属性。对外关系键 = `(model_asst_id, src_inst_uuid, dst_inst_uuid)`。图关系 ID 不对外。同进程内建边时仍可用图节点 ID 做 `ID(a)/ID(b)` 连接，属 Adapter 实现细节。

**代价**：边冗余端点 UUID（与节点属性重复）；需保证边与节点一致（迁移校验）。不存端点则所有按端点过滤的算法要改 MATCH 模式，旧代码迁移成本更高。

**状态**：假设采纳推荐（贴近 08-02，且比「不存但文档说封装」更易读）。

## Q4. PG / 历史例外

**推荐**：

| 数据 | 规则 |
|---|---|
| 活跃一等键 | 干净切换为 UUID（ChangeRecord 当前查询、ConfigFileVersion、订阅 filter、关注资产、采集目标快照、OA 画布活跃配置） |
| ChangeRecord | 新增/使用 `inst_uuid`；无法映射的已删实例历史允许保留旧数字 `inst_id` 只读 |
| before/after 快照 JSON | 尽力补顶层 uuid；不强制重写全部嵌套 `_id` |
| 操作日志 / mirror 历史 | 本阶段不迁；不得用作当前实例定位入口 |
| 孤儿 | 活跃配置移除/禁用并报告；默认阻断无法映射的必填引用；MinIO 不因孤儿删除对象 |

**状态**：假设采纳。

## Q5. 受控带入 UUID

**推荐**：本阶段日常创建**仅服务端生成** UUIDv4；预留内部/迁移命令写入既有 UUID 的形状；**不**对本阶段交付仓外「带 UUID 创建」产品接口。创建后不可变。

**状态**：假设采纳（缩小范围；08-02「未来预留」保留为非目标说明）。

## Q6. 迁移窗口与启动编排

**推荐（已修订）**：

- **部署默认**：`batch_init` 只注册 Celery 周期任务并 `delay` 一次；Worker 起来后
  幂等 `--apply`，失败下轮重试，**不**同步扫图、**不**阻断 `supervisord`。
- **大流量切换**：仍可用短暂停写 + 人工 `migrate_*_uuid_refs --dry-run/--apply/--verify`
  留证据；流量恢复前失败可协调恢复 PG+图备份；恢复后只前向修复。
- **不做**请求路径懒回填；**不**把同步 `--apply` 塞进 `batch_init`。
- 运行期同一命令继续补 PG 残留：订阅 `snapshot_data`、采集 instances/结果快照、
  Operation snapshot 与未成功 Outbox；孤儿不阻断 verify。变更历史 JSON 与操作日志不迁。

**状态**：已锁定（部署自动收敛 + 维护窗口可选）。
