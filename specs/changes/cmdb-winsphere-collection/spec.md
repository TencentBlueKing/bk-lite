# CMDB WinSphere 配置采集

Status: implemented

## 目标

企业版通过 WinSphere 9.4 管理 HTTPS API，以一组平台凭据采集管理平台、资源池、集群、宿主机、虚拟机、存储池、交换机和端口组，并在 CMDB 中建立稳定身份与关联。

## 边界

- 连接方式是 HTTPS 管理 API，不使用 SSH，也不向目标执行脚本。
- 一项任务只允许一个管理端点和一组凭据。
- 任务类型固定为 `cloud`，驱动类型固定为 `protocol`；不接受 `ip_range` 或其他批量目标输入。
- 凭据字段为 `user`、`password`、`https_port`、`verify_tls`；密码加密存储，API 返回掩码。
- 不新增数据库模型或迁移。凭据结构由服务端进程内静态注册表描述，采集对象目录把同一份元数据提供给前端。
- 能力仅在企业扩展启用时出现在采集对象树中；社区版直接提交同类任务必须拒绝。
- 当前管理地址只接受 IPv4 或 DNS 主机名，不接受协议、端口、路径或 IPv6。

## 采集与身份

- 官方列表接口的 `start` 是从 1 开始的页号，`size` 是页大小。
- 分页过程中页号、`total` 或稳定 ID 重复/漂移均使本轮快照失败；宿主机标准交换机和端口组分别使用宿主机、父交换机作用域内的复合身份检查重复。
- 八类模型全部带 `platform_id`；实例身份使用 WinSphere 原生 ID。标准/分布式交换机和端口组增加类型前缀与父级 ID，避免 ID 空间冲突。
- 无稳定 ID 的单条次对象跳过；某个统一模型全部没有稳定 ID 时整轮失败。
- 可选网络接口返回 404/405 时保留已获得数据，但对应模型标记为非权威，不能据此删除历史实例。

## 快照完整性与清理

采集端为每轮生成 `snapshot_id` 和版本化 manifest。manifest 固定声明八类模型，并为每类记录资源数、排序后稳定 ID 的 SHA-256 摘要和 `authoritative` 标志。

manifest 只随平台指标传输；每个模型仍必须产生数据指标或空集合哨兵。CMDB 端只有在下列条件全部满足时才把快照视为完整：

1. manifest 版本和 `snapshot_id` 匹配；
2. 期望模型集合与实际八条指标流精确一致；
3. 每个模型无重复稳定 ID；
4. 实际数量与身份摘要逐模型匹配。

缺失或损坏的 manifest 可用于保守新增/更新，但不能触发差集删除。即时清理还必须逐模型通过 `is_authoritative_snapshot(model_id)`，非权威的交换机或端口组不能删除旧数据。

## 凭据契约

- 服务端注册表是字段默认值、必填、加密字段、端口范围、TLS 规则、标签和帮助文案的唯一事实来源。
- 前端 WinSphere 表单从采集对象目录携带的 `credential_schema` 创建默认值、渲染字段和执行同构校验。
- 更新请求中的密码掩码 `******` 表示沿用既有密文；创建请求不得把掩码当成真实密码。
- `verify_tls=false` 是兼容默认值，界面必须显示风险提示；生产环境建议开启。

## 验收与测试

- Agent：登录、重认证、官方页号分页、漂移/重复保护、八模型格式化、可选网络 API、manifest 和传输边界。
- Server：凭据默认/校验/掩码/加密、端点规范化、企业能力启用、manifest 完整性、逐模型权威清理、关系映射和最新失败轮次保护。
- Web：由 schema 生成默认值和提交结构、中英文元数据、密码掩码编辑语义、端口范围，以及 label/control 的可访问关联。
- 模型配置工作簿必须包含八类模型、字段和既定关联；不产生 Django migration state 漂移。
