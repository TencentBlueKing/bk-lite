# 网络状态拓扑叠色改为监控中心活跃告警

Status: ready

## Problem Statement

运营分析「网络状态拓扑」组件目前用告警中心的活跃告警（按 CMDB `model_id` + 实例 UUID 配对）给节点上色。运维在拓扑上看到的红/黄，和监控中心里该设备作为监控实例的活跃告警对不上：没推到监控的设备可能被告警中心误上色，已接入监控的设备又可能因为告警中心资源字段不一致而假绿。内置「网络状态拓扑大屏」也是同一口径。运维需要的是：CMDB 设备上的 `monitor_id` → 监控中心当前 `status=new` 的告警。

## Solution

所有网络状态拓扑组件改为前端编排叠色：场景接口只返回 CMDB 拓扑结构；再用两个内置 NATS 数据源，先按实例 UUID 批量查出 `monitor_id`，再按监控实例汇总活跃告警。没有监控 ID 的节点显示未知（灰），与「已监控且无告警」的绿色区分。点击角标或告警数打开弹框，展示该设备最新 N 条监控告警；角标数量和节点颜色分别对应该设备的活跃告警总数和全量最高级别。

## User Stories

1. As an 运维人员, I want 拓扑节点按该设备关联的监控实例活跃告警上色, so that 大屏上的红黄绿和监控中心一致
2. As an 运维人员, I want 未关联监控的设备显示为未知而不是正常, so that 我不会把「没接监控」当成「全绿」
3. As an 运维人员, I want 已关联监控且当前无活跃告警的设备显示为正常, so that 巡检时能确认这些设备在监控里是安静的
4. As an 运维人员, I want 节点角标显示该监控实例的活跃告警总数, so that 数量不被「最新 N 条」截断
5. As an 运维人员, I want 节点颜色反映该实例全部活跃告警里最严重的级别, so that 列表外的致命告警不会被漏画成黄
6. As an 运维人员, I want 点击角标、浮层告警数或「查看告警」时弹出该设备最新 N 条监控告警, so that 不必跳转告警中心就能看明细
7. As an 运维人员, I want 未关联监控或总数为 0 时不能打开告警弹框, so that 空点击不会打出误导列表
8. As a 查看者, I want 分享和报表里仍能看到叠色并打开告警弹框, so that 只读分发和 PDF 与编辑态口径一致
9. As a 查看者, I want 分享模式下仍不能跳到 CMDB 详情, so that 外链不会把人带出画布
10. As an 运维人员, I want 配置抽屉仍然只选模型、实例和深度, so that 叠色数据源是内置能力而不是再配一套图表数据源

## Implementation Decisions

- 范围是运营分析网络状态拓扑场景组件（含内置大屏及用户画布上的同一组件）。不改 CMDB 网络拓扑编辑页，不回退告警中心叠色。
- 结构仍走现有场景组件接口（模型、实例 UUID、深度、权限、截断）。该接口不再查询告警中心，响应节点不再带告警状态字段（`status` / `alert_count` / `pulse` / `severity` / `color`）。
- 叠色由前端在拿到拓扑后编排：按 `rest_api` 从内置数据源目录解析两个数据源，经现有数据源取数入口调用 NATS（含分享会话的 query 入口）。配置抽屉不出现数据源选择。
- 组件固定依赖这两个内置 `rest_api`：`cmdb/get_monitor_ids_by_inst_uuids` 与 `monitor/query_latest_active_alerts`，在组件内写死，不落用户可改配置。保存、导出、分享允许列表、报表 `widget_manifest` 按组件类型把这两个 `rest_api` 解析成当前环境的数据源身份并纳入依赖（即使没有普通图表的单个 `dataSource` 字段）。内置大屏 YAML 的数据源引用从空改为这两个 key。
- 新增 CMDB NATS：按实例 UUID 批量返回监控 ID。跨模型，不收模型 ID；最多 100 个 UUID（与拓扑节点上限一致）；身份走运营分析注入的 `user_info`，按当前团队与实例查看权限过滤。响应每项含 `inst_uuid`、`model_id`、`monitor_id`（未关联则为空字符串）。不存在或无权限的 UUID 不出现在列表中。不返回整实例。补充 RPC 转发并登记为内置数据源。不经 OpenAPI 网关对外暴露。
- 改造现有监控 NATS `query_latest_active_alerts`（不另起汇总接口）：
  - `count` 改为过滤后活跃告警总数，不再等于返回条数
  - 增加 `max_level`：这批告警的最高级别，无告警为 null
  - 增加 `instance_summaries`：`[{ instance_id, count, max_level }]`，覆盖请求中且当前用户有权的每个实例 ID，包括 `count=0`
  - `items` 仍是最新 N 条，默认 10、最多 100
  - 活跃口径仍是 `status=new`，默认包含 `no_data`
  - 部分实例无权时只从 summaries 中省略，不让整次查询失败。指定了 `instance_ids` 且过滤后一个都没有：保持现有「无权限」失败。前端把这次失败当成叠色失败（节点未知），不得画成全绿
  - 请求继续支持 `instance_id` / `instance_ids`；内置数据源参数补上 `instance_ids`
- 铺图：先批量映射 UUID→`monitor_id`，再一次传入全部非空 `monitor_id`，`limit=1`（只要汇总）。点开弹框：再查该 `monitor_id`，`limit=10`，用 `items` 填表、用 `count` 做标题总数。
- 前端合并规则：
  - 映射列表没有该节点，或 `monitor_id` 为空，或 summaries 没有该监控 ID → `unknown`（灰，无角标，浮层写「未关联监控」而不是 0）
  - 有 `monitor_id` 且 `count=0` → `normal`（绿，无角标，浮层写 0）
  - `warning` 或其它非空非红级别 → 黄；`error` → 红不脉冲；`critical` → 红且脉冲
  - 角标数字为该实例 `count`，超过 99 显示 99+
- 点击：点设备图标仍是选中与故障链路高亮。点角标、浮层告警数、右键「查看告警」打开弹框。未知或 `count=0` 时这三项不可点。不再跳转告警中心。右键 CMDB 详情保留；分享态禁用该跳转，但允许打开弹框。
- 弹框为画布内 Modal：标题含设备名、总数与「最新 N 条」说明；表格列至少含级别、类型、内容、开始时间。关闭弹框不改变拓扑选中态。点开时现查，不复用铺图那次 `limit=1` 的明细。
- 拓扑取数失败：沿用现有空态/错误。叠色失败（数据源缺失或 NATS 失败）：结构仍画，节点全部未知，展示可重试的叠色错误，不回退告警中心。弹框失败：拓扑不变，弹框内报错可重试。组件 `onReady` 仍只表示是否有拓扑节点。
- 分享/报表白名单：除现有场景拓扑 POST 外，允许这两个数据源的取数。分享查询允许 `inst_uuids`、`instance_ids`、`instance_id`、`limit`；权限仍由 NATS 侧按会话身份过滤。一个拓扑组件在报表 manifest 中对应两行数据源身份。
- 级别映射只认监控字符串 `critical` / `error` / `warning`（大小写不敏感即可）；其它非空级别且 `count>0` 按预警处理。

## Testing Decisions

- 好测试只验证外部行为：给定 UUID 列表或监控实例 ID，接口返回的映射/总数/最高级别/明细是否符合契约；前端在给定拓扑 + 两路取数结果下，节点状态、角标、弹框开关是否正确；保存/导出/分享/报表是否把两个数据源纳入允许范围。不锁定 X6 内部 DOM 或事件名。
- 接缝与 prior art：
  - CMDB NATS 纯契约/权限测试（现有实例批量查询与 NATS 权限测试风格）
  - 监控 `query_latest_active_alerts` 现有 NATS 单测，扩展 count、max_level、instance_summaries、部分无权
  - 网络状态拓扑前端现有 fetch 测试，改为结构与叠色分路，覆盖未知/绿/黄/红、不可开弹框、点角标才打单实例查询
  - 场景组件现有「合并告警中心状态」测试改为「只返回结构、不含告警字段」
  - 内置画布初始化测试：内置大屏引用这两个数据源
  - 报表 render token 与分享查询测试：允许两个 overlay 数据源取数，并仍拒绝无关数据源
- 不强制本阶段做完整大屏 E2E。手动验收：内置或任意网络状态拓扑画布上，未推送监控的节点为灰、已监控无告警为绿、有致命为红脉冲；角标为总数；弹框为该设备最新列表且标题总数正确；分享可开弹框但不能跳 CMDB。

## Out of Scope

- 告警中心叠色回退、双来源切换配置
- 状态时间回放
- 将这两个 NATS 经 OpenAPI 网关对外暴露
- CMDB 网络拓扑编辑页、接口 up/down、监控指标健康度
- 把内置大屏示例实例从旧数字 `instId` 迁到 UUID（叠色不依赖示例实例一定能展开）
- 为叠色新增运营分析专用后端表
- 改变自动布局算法或布局持久化行为

## Further Notes

- 「活跃告警」在本变更中指监控中心 `status=new` 的 `MonitorAlert`，不是告警中心的 pending/processing/unassigned。
- CMDB `monitor_id` 来自设备推送到监控后的回写；本变更不负责补写历史实例的 `monitor_id`。
- 现有表格若已绑定「监控活跃告警」数据源，`items` 列不变；信封上的 `count` 会变成真实总数，这是有意行为。
