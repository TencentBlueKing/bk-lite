# 工作台流程按用户语言回复

Status: implemented

## Problem Statement

告警从 NATS 触发工作台流程时，流程输入没有语言。智能体把缺省语言当成英文，并在提示词末尾要求用英文回复。后面的邮件如果打开了大模型优化，优化提示词是中文，又不声明要保持哪一种语言。一段英文正文可能被改成中文，也可能中英混在同一封邮件里。

定时任务、钉钉、企业微信应用、企业微信智能机器人和微信公众号也没有把平台用户的语言写进流程。页面和 API 入口已经带有本次请求的语言，不在这个问题里。

轻量直答会在已经写好的回复语言后面再加一句「直接用中文简洁回答用户」。英文用户走这条短路时，两句要求相反。意图分类如果也接上回复语言，模型会改写意图名，分支就对不上。

## Solution

一次流程使用一种回复语言，并把它写在流程输入的 `locale` 上。智能体给用户看的回答和同一封邮件使用这个值。意图分类不使用它来改写输出。

NATS 按 `user_ids` 的原顺序，用数字 id 查平台用户主键。查到的第一个用户提供 `locale`。没有数字 id，或者每个数字 id 都查不到用户，流程写 `zh-Hans`。

定时任务使用机器人创建者的语言。创建者按用户名和机器人所在域查询。查不到，或者创建者为空，流程写 `zh-Hans`。

四个 IM 入口不查平台用户，直接写 `zh-Hans`。页面和 API 入口继续使用现在已经写入的请求语言。

## User Stories

1. As a 平台用户, I want NATS 触发的智能体和邮件使用 `user_ids` 里第一个能查到的人的语言, so that 告警回复不再一律变成英文。
2. As a 平台用户, I want 定时任务的智能体和邮件使用机器人创建者的语言, so that 周期流程和创建者在个人设置里保存的语言一致。
3. As a 钉钉、企业微信或微信公众号里的对话用户, I want 工作台流程固定用简体中文回复, so that 这些入口不会因为对不上平台账号而变成英文。
4. As a 流程设计者, I want 意图分类只返回配置里的意图名, so that 回复语言不会把分支名翻译掉。
5. As a 英文用户, I want 轻量直答和计划规划遵守同一种回复语言, so that 无工具的回答不会被单独拉回中文。
6. As a 收件人, I want 一封经过大模型优化的邮件只使用流程语言, so that 正文不会中英混杂，也不会按每个收件人各写一版。

## Implementation Decisions

流程语言只有一个字段，名字是 `locale`。本次改动的入口在执行前写入它。智能体节点现有的缺省英文保持不动。这些入口写完以后不会再落到那个缺省。

NATS 只把数字 id 当成平台用户主键，和现有参与人解析使用的主键相同。不按用户名查，也不按可空的 `user_id` 字符串查。一条主键最多一个用户。非数字项跳过，继续看下一项。用户行存在就使用该行保存的 `locale`，原样复制，不改写成别的代码。保存值为空时，这个人没有可用语言，继续看下一个人。列表耗尽后写 `zh-Hans`。参与人名单的现有解析不变。

定时任务用机器人的 `created_by` 和 `domain` 查唯一用户。查到则复制该用户的 `locale`。值为空、用户不存在或创建者为空时写 `zh-Hans`。不跨域挑选同名用户。

钉钉、企业微信应用、企业微信智能机器人、微信公众号四个工作台入口把 `locale` 写成 `zh-Hans`。不新建外部身份到平台用户的反查，也不使用「跟随用户这句」的回复规则。

页面和 API 入口不改。这包括 restful、openai、agui、embedded_chat、web_chat 和 mobile。它们继续使用请求里已经确定的语言。

回复语言规则保持现有规则。`locale` 去掉下划线并转成小写后，以 `zh` 开头就要求简体中文。其他值要求英文。轻量直答和计划规划都只留这一句回复语言。轻量直答删掉固定的「直接用中文简洁回答用户」。无工具和空计划两条轻量路径都删。不假装调用工具、不泄露密钥这两句保留。非知识技能后面的中文附件操作说明保留，不翻译。

告警 RCA 最后一步只把「写完整中文 Markdown」改成「写完整 Markdown」。第一行仍是「# RCA 报告」。章节仍是事件概述、异常对象清单、根因分析、修复建议、待确认项。完成度判断继续认这些中文标题。重启原因报告和其他终稿不改。

邮件优化读取流程上的同一个 `locale`。它在现有中文 HTML 要求之后追加同一句回复语言。优化结果仍是一段 HTML，不按收件人拆成多种语言。流程上没有 `locale` 时，优化按 `zh-Hans` 追加规则。

意图分类调用模型时不追加回复语言。分类提示词继续要求只返回意图名原文，并与配置项完全一致。其他模型调用的回复语言保持原样。

## Testing Decisions

测试只断言调用方能观察到的流程输入和模型提示词。不断言内部查询函数怎么组织。

沿用现有的 NATS 流程执行测试、定时任务输入测试、IM 流程输入测试、邮件优化测试、意图分类测试、轻量直答提示词测试和告警 RCA 终稿提示词测试。缺哪一种行为，就在对应测试上补断言。

NATS 要看到三种输入。第一个数字 id 不存在而第二个存在时，流程 `locale` 是第二个人保存的值。列表里只有非数字项，或者所有数字 id 都不存在时，流程 `locale` 是 `zh-Hans`。参与人解析结果和改语言之前一致。

定时任务要看到两种输入。创建者存在时，流程 `locale` 等于该用户的 `locale`。创建者不存在时，流程 `locale` 是 `zh-Hans`。

四个 IM 入口的流程输入都包含 `locale=zh-Hans`。测试不要求它们查询平台用户。

邮件优化在 `zh-Hans` 下，提示词要求简体中文，并且仍然只返回 HTML。在 `en` 下，提示词要求英文，并且仍然只返回 HTML。提示词不因本次改动丢掉原有的事实保持要求。

轻量直答的系统提示词不再包含「直接用中文简洁回答用户」。传入的角色提示里如果已经有英文回复要求，这句要求还在。

意图分类交给模型的提示词不包含中文回复要求，也不包含英文回复要求。节点仍按意图名原文做完全匹配。

告警 RCA 最后一步的提示词包含「写完整 Markdown」，不包含「写完整中文 Markdown」，并且仍包含四个中文章节名。

这些测试锁定的是提示词和流程输入。它们不证明线上模型一定服从。模型是否服从仍然是推断。

## Out of Scope

技能通道里企业微信智能机器人的「跟随用户这句」不改。飞书长连接复用这条规则，也不改。

不把外部 IM 身份反查成平台用户。账号关联不接到工作台流程。

不改页面请求语言的来源，不改 `X-BK-Locale` 的传递，也不改用户资料里只有英文和简体中文两个选项的事实。

不把告警 RCA 的标题和章节改成英文。不改接口报错文案、工具结果词表、规划器目标语言和浏览器工具里已经按 `locale` 分叉的规则。

不补 `user_timezone`。不按收件人生成多封不同语言的邮件。

## Further Notes

平台用户主键是数字。用户表上另有一个可空的 `user_id` 字符串，它不是本次查找键。用户名和域一起才唯一，所以 NATS 不用用户名决定语言。

`zh-Hans` 是本次缺省和四个 IM 入口要写入的字面值。用户行里如果保存的是别的 `zh` 开头值，流程原样复制该值。回复规则会把它当成简体中文。
