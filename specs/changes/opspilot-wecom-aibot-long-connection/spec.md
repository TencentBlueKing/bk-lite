# 智能体企微机器人长连接

Status: implemented

## Completion Evidence

- 渠道类型仍是 `enterprise_wechat_aibot`。短连接继续走回调 Token / EncodingAESKey；长连接用已有 `connectionMode=websocket` 与 `websocket.botId` / `websocket.secret`。没有新表，也没有迁移已有短连接数据。
- 发布页可选「是，长连接」并保存 BotID 与长连接 Secret；切回短连接仍保存原回调凭据。长连接渠道的短连接回调不再投递智能体任务。
- 常驻命令 `run_wecom_aibot_long_connection` 由 Supervisor 程序 `opspilot_wecom_aibot_long_connection`（priority 20）在 `supervisord` 之后拉起，不进入 `batch_init`。未安装 opspilot 时启动脚本删除该配置。
- 环境内一把 Redis 锁 `opspilot:wecom-aibot-long-connection:leader`（TTL 30 秒，持有者令牌续期）。只有持锁进程连企微；被踢且仍持锁则重连，否则停掉本地连接。默认地址 `wss://openws.work.weixin.qq.com`，私有化地址用 `WECOM_AIBOT_LONG_CONNECTION_URL`。
- 假连接测试覆盖：订阅凭据不入日志、第二个进程不连接、凭据变更与停用、踢线、传输断开重试、文本流式覆盖、非文本固定回复、事件忽略、打断与历史、10 分钟超时、失败文案、空回答、超长截断。短连接已有回调测试除 sqlite 线程锁的两条既有失败外通过。启动打包测试通过。

## Problem Statement

智能体发布里的企微机器人只能用短连接：要有公网回调地址，并填写 Token 和 EncodingAESKey。部署在内网、没有固定回调地址时，企微消息到不了智能体。企微智能机器人的长连接由我们主动连出去，不需要回调地址，但当前渠道即使选了长连接，也只是保存 BotID 和 Secret，没有进程去连，用户发消息没有回复。

## Solution

企微机器人渠道继续用现在的「是否长连接」。选长连接并启用后，由一个常驻进程用 BotID 和 Secret 连上企微，接收单聊和群聊文本，把智能体的回答以流式消息推回同一条连接。短连接渠道保持原有回调。同一机器人在整个环境里只有一条长连接。

## User Stories

1. As a 运维人员, I want 给企微机器人选择长连接并填写 BotID 和 Secret, so that 没有公网回调地址也能接入智能体。
2. As a 企微用户, I want 发文本后马上看到「正在处理」，随后看到回答逐步出现, so that 我知道机器人已经接上，而不是一直空白。
3. As a 企微用户, I want 回答出来之后不再留着「正在处理」, so that 会话里只看到回答本身。
4. As a 企微用户, I want 在同一会话里接着发下一句时，上一轮停掉, so that 机器人按我的新消息回复，而不是两条回答抢着刷。
5. As a 企微用户, I want 发送图片、文件、语音、视频或图文时得到「当前仅支持文本消息」, so that 我知道这条消息没有进入智能体。
6. As a 运维人员, I want 多个 Server 副本同时运行时只有一个进程连着这些机器人, so that 连接不会互相踢掉。
7. As a 企微用户, I want 处理失败或超过时限时，这条消息停在一句明确的结果上, so that 它不会一直停在「正在处理」。

## Implementation Decisions

- 渠道类型不变。长连接与短连接都是企微机器人渠道，用已有配置区分：短连接保存回调 Token 和 EncodingAESKey；长连接保存 BotID 和长连接 Secret。不新增渠道类型，不新增表，不迁移已有短连接数据。
- 发布页的选项和凭据保存已经存在。本变更补运行时：只连接已启用、且选择了长连接、BotID 和 Secret 都有值的渠道。停用、删除或更换凭据时断开对应连接，凭据变了再重连。
- 常驻进程在服务启动完成之后由进程守护拉起，不参与启动门禁。连不上企微只重试。一个进程维护全部长连接。默认连接企微公网长连接地址；私有化地址用环境变量覆盖，不写进每条渠道。
- 多副本用 Redis 锁选出唯一持有者。只有持锁进程建立连接并续期。锁过期后其他副本接管。收到「被新连接踢掉」时，若锁仍在自己手里则重连，否则停止本地连接。
- 长连接消息是明文，不再做短连接那套解密和回调地址回复。文本沿用现有的 @ 清理、会话归属和智能体执行。回复必须从收到该消息的那条连接发出，并带上该回调的请求标识。
- 同一会话同时只流式回复一条。又收到文本时，立刻停止上一轮生成；上一条企微消息用已经显示的内容结束（还没有正文就停在「正在处理」）。新的一轮只包含这句新的用户消息。半截回答写入会话历史，供下一轮阅读。不把「未完成的问题、半截回答、新消息」拼成一条用户消息。
- 流式内容只有最终回答正文，不包含思考过程和工具调用。收到文本后立即推「正在处理」。之后大约每 2 秒用当时已生成的全文覆盖同一条消息。第一次出现正文时不再包含「正在处理」。智能体结束时标记该条消息完成。
- 10 分钟从第一条流式回复（「正在处理」）起算，不是从用户发消息起算。接近上限时主动结束：已有正文就用正文，没有正文则改为「处理超时，请再发一次」。结束后不再补发，也不再改这条消息。
- 中途失败时，把这条消息改成该渠道已经展示给用户的失败说明，并立即结束。失败说明和「处理超时，请再发一次」写入助手历史。超时前已有正文时，历史只留那段正文。打断时若还没有正文，历史里只有上一条用户消息，「正在处理」不写入历史。
- 图片、文件、语音、视频、图文混排只回复「当前仅支持文本消息」并结束，不先推「正在处理」，不跑智能体，不写入会话历史。单聊能收到这些消息；群聊的图片、文件、语音、视频企微不会推送。
- 进入会话、模板卡片点击、用户反馈、连接断开都不回复、不跑智能体。连接断开只驱动持锁进程的重连。
- 断开期间的用户消息不补收、不补回。重连后只处理新消息。
- 短连接的回调校验、解密和回调地址回复保持不变。同一渠道同一时刻只按当前选项工作。

## Testing Decisions

- 测外部行为：给定渠道配置和一条企微入站帧，断言发出的回复帧、会话历史和是否执行了智能体。不连接真实企微，不断言进程内部的线程或心跳实现。
- 长连接客户端用假连接验证：订阅凭据、文本流式覆盖、非文本固定回复、事件被忽略、同一会话打断后再开一条新回复、超时和失败的结束文案。
- 锁用假的 Redis 验证第二个进程在锁被持有时不建立连接。
- 短连接已有的回调测试继续通过，用来锁住未选长连接的渠道不受影响。
- 历史写入沿用智能体会话消息的现有断言方式：用户原文、半截回答、失败说明是否落库。

## Out of Scope

- ChatFlow 里的企微智能机器人节点仍只有短连接。
- 不把图片或文件解密后交给多模态模型。
- 不回复欢迎语，不发送模板卡片，不采集赞踩反馈。
- 不把思考过程或工具调用刷到企微。
- 不按字推送，不做打字机式的每个 token 一次刷新。
- 不断线重放，不在超时或打断之后另发一条补答。
- 不新增长连接专用渠道类型。

## Further Notes

- 企微后台的 API 模式必须改成长连接。同一个机器人不能同时开回调地址和长连接。Secret 是长连接专用密钥，不能用短连接的 Token 或 EncodingAESKey 代替。
- 每个机器人同一时间只能有一条有效长连接，新连接会踢掉旧连接。
- 同一会话的回复大约 30 条/分钟。每 2 秒刷新一次，并且同一会话只保留一条流式回复，是为了停在这个额度内。
- 发布页已经能保存长连接选项和凭据。在常驻进程落地之前，选长连接并启用不会收到或回复消息。
