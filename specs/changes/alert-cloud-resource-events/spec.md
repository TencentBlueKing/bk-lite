# 云资源变化事件接入告警中心

状态: done

## 问题

云主机重启、坏盘、计划停机这类变化，监控指标经常滞后，或者根本采不到。客户只能到阿里云、腾讯云控制台里看。告警中心需要在事件发生时就能检索、关联已纳管资源，并沿用现有告警策略通知。

## 方案

告警中心增加两张内置集成源。一张接阿里云 EventBridge，一张接腾讯云事件总线。两边都用 Webhook 把 JSON 推到各自的地址。适配器按该源的上报字段映射收成标准事件，再走现有同名字段映射入库。

会发生告警的事件进入现有即时告警和窗口聚合。客户自己建策略并选中这条集成源后，通知走现有通道。恢复关掉同一业务 ID 的未关闭告警。无状态事件只留在事件列表。能对上 CMDB 的写入实例 UUID，对不上也入库。

## 用户故事

1. 作为接入人员，我希望阿里云和腾讯云各有一张集成源，以便每家云有自己的回调地址、密钥和字段目录。
2. 作为接入人员，我希望接入说明展示回调地址、组织密钥、字段映射和默认事件类型，以便把它们填进云厂商控制台。
3. 作为接入人员，我希望用资源 ID、事件名、账号、地域，以及发生、恢复或无状态检索事件，以便不新增事件列也能找到。
4. 作为值班人员，我希望发生事件经现有策略变成告警，对应的恢复关掉同一条告警，以便继续用已经配好的通知通道。
5. 作为值班人员，我希望无状态事件只留在事件列表，以便一次性的生命周期通知不会留下永不恢复的告警。
6. 作为接入人员，我希望事件组织里恰好有一台已纳管云实例时挂上它，以便没有纳管的事件也不会丢。
7. 作为接入人员，我希望重复投递和目录外的事件类型返回成功，以便云厂商不会一直重推。
8. 作为接入人员，我希望事件上保留云厂商原文，以便在原始数据里核对字段映射。

## 实现决定

- 两张内置源。一张是阿里云 EventBridge，一张是腾讯云事件总线。不并进尚未使用的云监控源类型，也不用通用 Webhook 适配器。页面不能再手工添加同类型的第三张。目录随源配置发布，重新初始化内置源时会被覆盖。本期不加目录编辑器。接入说明只读展示目录。
- 复用现有的按源 Webhook。报文是 JSON。一个对象是一条事件。对象数组里每个元素是一条事件，并且都归这次请求密钥对应的组织。空体、非 JSON、数组里夹了非对象，拒绝入库。云回调不带源 ID。路径决定是哪张源。
- 认证用这张源已经发放的组织密钥。源级总密钥拒绝，和除 SNMP Trap 以外的源一致。两家都应放在请求头 `SECRET`。腾讯云控制台若不能加请求头，这条源的地址同时接受查询参数里的同一枚密钥。阿里云说明仍要求用请求头。不另做一套认证，也不新增 OpenAPI。
- 每张源有自己的上报字段目录。解析器产出标准事件，再由现有同名映射写入事件。阿里云固定路径是账号 `aliyunaccountid`、地域 `aliyunregionid`、事件类型 `type` 并去掉过程态后缀、时间 `time`、业务 ID `data.eventId`。实例资源 ID 取 `data.instanceId` 或 `data.resourceId`。磁盘资源 ID 取 `data.diskId`。磁盘父实例取 `data.ecsInstanceId`。名称取 `data.instanceName`、`data.ecsInstanceName` 或 `data.diskName`。腾讯云监控模板的地域是 `alarmObjInfo.region`，事件类型是 `conditions.eventName`，时间是 `firstOccurTime`，CVM 资源 ID 是 `dimensions.unInstanceId`，业务 ID 是 `sessionId`，状态是 `alarmStatus`，规则名是 `policyName`。腾讯云 CloudEvent 的账号是 `appId`，地域是 `region`，事件类型是 `type`，时间是 `time`，资源 ID 是 `subject`，规则名是 `ruleName`，状态是 `status`。监控模板的账号在已公布示例里没有稳定字段，第一条真实报文补上这个路径。标题和级别不从报文取，由目录生成。
- 落库用事件列表和策略匹配已经认识的字段。云厂商是源名称。账号是 `labels.account`。地域是 `location`。事件类型是 `item`。资源 ID 和资源名称用对应字段。标题是目录中文名加资源 ID。内容包含账号、地域，以及发生、恢复、无状态三者之一。云厂商原文放在事件原始数据的 `original`。集成源事件筛选只能搜标题、内容、处理状态和推送来源。不加列，不加筛选项。不写 `push_source_id`，保持 `default`。
- `external_id` 是账号加厂商业务 ID。阿里云业务 ID 是 `data.eventId`，腾讯云是 `sessionId`。一对真实的产生报文和恢复报文必须证明所选业务字段两边相同。不同就把稳定的那个字段换进来。拼接规则仍是账号加该字段。
- `resource_type` 表示事件发生在什么资源上，不是 CMDB 模型 ID。阿里云实例两边都用 `aliyun_ecs`。阿里云磁盘的事件类型是 `aliyun_disk`，查 CMDB 时用父实例去对 `aliyun_ecs`。腾讯云 CVM 两边都用 `qcloud_cvm`。磁盘事件的 `resource_id` 仍是磁盘 ID。
- 状态写成事件动作。阿里云 `Executing` 是发生。`Executed`、`Avoided`、`Canceled` 是恢复。`Failed` 是发生，但不新开一条告警。`Scheduled`、`Inquiring` 是无状态。腾讯云文案「未恢复」或状态值 `1` 是发生。文案「恢复」或状态值 `0` 是恢复。文案「无状态」以及其它值是无状态。已公布的腾讯云示例只有 `1`。把 `0` 当成恢复依据的是模板文案，第一条真实回调后可以只改目录。认不出的状态原文留在内容里。
- 只有这个 `external_id` 还没有未关闭告警时，发生事件才新建告警。之后的发生，包括 `Failed`，挂到这条告警上，不再通知。恢复关掉这条告警。没有未关闭告警时，恢复只入库，不新建。恢复先到时，后到的发生仍会建告警。本期不用「已经恢复过」的记录去吞掉后到的发生。现有即时路径是一条发生事件建一条告警，所以这次挂接检查要发生在那条路径之前。
- 无状态事件使用新动作 `record`，显示名「记录」。内容里仍然写「无状态」。即时告警、窗口聚合和恢复都不选 `record`。不允许省略动作。省略后会被存成发生。
- 事件级别是 `0` 严重、`1` 错误、`2` 警告、`3` 提醒。告警级别只到 `2`。实例故障、系统错误、磁盘损坏、磁盘严重变慢是 `0`。正在执行的系统维护是 `2`。计划、问询、状态变化、抢占释放、热迁移、磁盘欠费释放是 `3`。腾讯云 CVM 重启和故障类是 `0`。目录里其余 CVM 事件是 `2`。`Failed` 保持该类型原来的级别。无状态事件停在 `3`，不变成告警。
- 阿里云默认只收云监控过程态里影响连续性的事件，同一件事的原生事件不收。范围是实例故障重启，系统错误重启、停止、重新部署、删除，系统维护重启、停止、重新部署、隔离坏盘、重新初始化坏盘，以及重启并处理坏盘的变体，再加上磁盘损坏和磁盘严重变慢。状态变化、抢占释放、热迁移、磁盘欠费释放没有过程态，按无状态入库。其它认得出的阿里云类型跳过。
- 腾讯云默认只收 CVM。监控模板读 `unInstanceId`。CloudEvent 读 `subject`。其它产品在目录写上产品名和实例字段之前一律跳过。两种报文形状都对不上的包拒绝，包括 DDoS 高防。
- 时间在进入现有映射之前收成毫秒。阿里云 ISO8601 按其偏移解释。腾讯云 CloudEvent 的 `time` 已经是毫秒。没有时区的 `firstOccurTime` 按东八区，因为公布示例没有时区。缺时间则用接收时间，并走现有的分钟级幂等。
- 回执不走通用入口的部分成功和全部跳过。成功、重复投递、认得出但不在目录里的事件都返回 200。目录跳过不入库，也不把整包打成 422。密钥错误返回 403。认不出的包返回 400。内部失败返回 500，交给云侧重试。日志只记源、事件类型和处理结果，不记报文、密钥和原文。
- CMDB 查询放在现有丰富步骤里，范围是事件所属组织。按模型属性 `resource_id` 匹配。不对实例名，也不把云实例 ID 当成实例 UUID。恰好一条时，把该实例 UUID 写入 `cmdb_id`，报文里已有的资源名称保留。零条、两条及以上、超时或查询错误都让 `cmdb_id` 留空，事件仍然入库。回调仍返回 200。
- 接入说明建议建一条选中该集成源的即时策略。窗口策略也能匹配，但要等窗口结束。不自动创建策略。复用现有通知模板。不新增权限。能看这张源的人能看它的事件、原始数据和组织密钥。能改策略的人选择通知通道。发生事件仍走现有屏蔽。被屏蔽的发生事件不建警。

## 测试决定

- 测 Webhook 的 HTTP 边界，不测解析器内部。送入固定报文，看回执状态和入库字段。核对标题、内容、指标、资源 ID、资源类型、地域、账号标签、动作、级别、外部 ID、原始数据里的 `original`，以及 `cmdb_id`。
- 覆盖一条阿里云对象、两条事件的 JSON 数组、重复投递、目录外类型、错误密钥和认不出的包。目录跳过和重复投递都要返回成功，并且不新增第二行。
- 覆盖同一业务 ID 的先发生后恢复、后一次发生和失败挂到同一条未关闭告警、没有未关闭告警时的恢复，以及只留在事件列表的无状态事件。
- 覆盖 CMDB 一条、零条、两条和查询失败。每种情况事件都在。只有一条命中时填写 `cmdb_id`。磁盘事件保留磁盘 ID，并关联父实例。
- 参照现有 Prometheus 适配器测试和告警接收入口测试。CMDB 在丰富边界替身。
