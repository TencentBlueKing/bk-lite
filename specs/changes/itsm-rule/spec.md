# ITSM 自动化与时效

Status: done

本模块维护决策表、工单事件触发器、定时任务、服务日历、SLA 和状态流转。决策表保存条件、结果和规则行，供流程决策节点引用。状态变更受本域已配置的流转关系约束。

## 工单事件触发器

1. 在自动化与时效中建立规则，选择触发事件，配置全部、包含或排除范围。可指定流程、服务和表单模型；同一维度内任一项匹配即可，不同已设置维度须同时匹配。表单模型优先按工单所用流程版本的快照匹配。
2. 触发条件可以引用带名称的工单系统变量和表单字段，按「且／或」组合。规则可按顺序执行打标签、发送通知、变更状态等多个动作。规则编辑时校验配置；执行时记录每项结果。遗留坏配置或个别动作失败不得阻断工单操作。
3. 发送通知时选择提单人、当前处理人、指定人员、处理组或表单人员字段，合并并去重。站内和已选即时消息渠道分别投递；即时消息使用 BK-Lite 消息通道及账号映射。映射缺失记入结果，不能扩大接收范围或回退到未选渠道。
4. 内容模式为模板或自定义。自定义内容支持选择变量并按当前工单渲染，例如标题、单号、流程、当前节点、详情链接。选择的模板被删除时应记录失败。测试工单不向真实 IM 渠道发消息。账号关联在集成身份和接收字段仍兼容时保留手工映射，同步发现冲突时保留手工结果并记录冲突。[手工映射保留条件](../../../server/apps/system_mgmt/services/im_notification_service.py)
5. 工单详情展示有权查看的执行记录，规则删除后保留历史。通知随业务事务登记，提交后派发；若回调丢失，后台可恢复。各渠道单独记回执，已确认送达或发送结果未知时均不能盲目重发。

**验收**　分别用命中和不命中范围的工单触发同一规则；配置两条动作检查顺序。对多人、多渠道用例核对实际接收集合、消息变量和详情链接。模拟一条渠道失败和回执写回失败，确认其他选定渠道可完成、已确认的投递不会重复。[触发配置](../../../server/apps/itsm/tests/test_trigger_resources.py) · [事件及动作执行](../../../server/apps/itsm/tests/test_trigger_execution.py) · [通知投递](../../../server/apps/itsm/tests/test_trigger_notice_service.py)

## SLA 计时与升级

计时采用工单适用的策略、工作日历及时区。挂起时冻结工作时间消耗，恢复后继续累计。预警与超时升级分别记录执行结果，重复扫描同一阶段不得重复通知。挂起期间完结的工单不再因经过自然时间而超时；找不到接收人时不得广播。

**验收**　在工作时段内启动计时，依次挂起、跨过非工作时间、恢复，再跨过预警和超时阈值。每个阈值前后均重复扫描，核对剩余工作时间、执行记录和通知数量。[SLA 时钟与通知](../../../server/apps/itsm/tests/test_sla_notifications.py)

## 单次与周期任务

定时建单和定时提醒支持带时区的单次时间或五段 Cron。建单目标须为本域启用且已发布的流程；领取任务时按「任务＋到期时点」保存唯一执行记录，记录关联工单、结果和原因。单次执行后编辑任务不能重放原时点。周期扫描在停机恢复后仅补领一次，随后计算下一时点。

**验收**　对同一到期任务连续扫描两次，只应产生一条执行记录和一张工单。再模拟建单时启动回执未知，原工单应可追踪，下一次扫描不能另建第二张。执行记录按权限读取。[调度行为](../../../server/apps/itsm/services/schedules.py) · [定时建单验收](../../../server/apps/itsm/tests/test_scheduled_runs.py)
