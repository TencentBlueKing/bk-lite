# 主机自动采集写入操作系统主机名

Status: implemented

## Problem Statement

运维人员希望主机自动采集把操作系统主机名写到主机实例上。主机模型里已经有「主机名称」字段，查询 VictoriaMetrics 再写入图库的链路也已经存在。缺的是确认采集脚本会把这个字段报上来，并沿原链路落图。

## Solution

不新增字段，不调整字段分组，不改查询和写图。Linux 与 Windows 主机采集脚本在原有结果里上报操作系统主机名。后续仍按原指标查询 VictoriaMetrics，再把该字段写入主机实例的已有主机名称属性。实例名继续用 IP，或「IP[云区域]」。

## User Stories

1. 作为运维人员，我希望主机自动采集写入操作系统主机名，这样主机实例的主机名称来自目标机自身，而不是手工填写。
2. 作为运维人员，我希望 Linux 和 Windows 都上报主机名，这样两类主机走同一条采集结果。
3. 作为运维人员，我希望主机名沿用现有的指标查询和写图，这样不需要另建一条入库链路。

## Implementation Decisions

- 使用主机模型已有的主机名称字符串字段。它留在基本信息分组，非必填、可编辑、不唯一。
- 不修改模型种子的分组，也不为这次采集增加 Django 迁移。
- Linux 采集结果包含主机名：优先完整域名，取不到时用短主机名。两条都取不到时留空，不写 `unknown`。
- Windows 采集结果包含主机名：优先计算机名，取不到时用 DNS 主机名。两条都取不到时留空，不写 `unknown`。
- 主机名称不是必填。空主机名仍走原指标查询和写图，实例上的主机名称为空字符串。
- 标准化只拆走进程、挂载点和网卡；主机名留在主机对象上，作为主机信息指标的标签上报。
- 字段映射保持「模型主机名称 ← 指标标签主机名」。格式化后的实例字典带上该字段。
- 新建实例整份写入图库。更新实例只保留模型里可编辑的属性；主机名称可编辑，因此会写回。
- 实例名算法不变。

## Testing Decisions

好的测试只看外部结果：采集输出里有主机名，查回的指标标签里有同名值，格式化后的主机实例字典里主机名称等于该值。不断言脚本内部命令细节。

- 已有主机指标格式化测试覆盖「标签主机名进入实例主机名称」。这次不新增重复单测。2026-10-21 本地复跑：该断言 `hostname == myhost` 已通过；同一用例随后在无关的云区域断言失败（实际空串，期望 `vpc-1`），与主机名无关。采集标准化端到端用例通过，主机名保持 `web01.prod.example.com`。
- 真机验收目标是 `10.10.41.149`。在目标机上执行现有 Linux 主机采集脚本，输出 JSON 的 `hostname` 必须与该机 `hostname -f`（失败时 `hostname`）一致，且不是空串。
- 平台侧验收：该次采集写入 VictoriaMetrics 的主机信息序列带有相同 `hostname` 标签；随后一次主机采集同步把该值写入图库主机实例的主机名称。实例名仍是 IP 或「IP[云区域]」。
- 本机没有到该目标的 SSH 密钥。2026-10-21 探测：22/80/443/8428 可达；`ssh -o BatchMode=yes` 返回 `Permission denied (publickey,password)`；`http://10.10.41.149:8428` 上 `host_info_gauge` 序列数为 0。真机脚本执行和写图验收因此停在登录凭据。

## Out of Scope

- 把主机名称挪到技术信息，或再增加一个同名字段。
- 修改 VictoriaMetrics 查询、字段映射或图库写入。
- 把实例名改成主机名。
- VMware 虚拟机模型上的客户机主机名。
- 为这次采集新增对外 API。

## Further Notes

代码侧已经满足上述决定，本次没有产生功能差异。真机验收需要能在 `10.10.41.149` 上执行主机采集脚本的登录方式；拿到凭据后只补 Testing Decisions 里的两步，不改采集链路。
