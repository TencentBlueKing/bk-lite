# CMDB 实例异步导入导出

状态：前端及交互原型已确认；用户已确认复用 MinIO 的 CMDB 配置文件桶、不新增桶，
每天执行一次过期任务和文件清理。
用户已授权按本文补充测试并实施；其余建议值作为第一版默认值。2026-09-21。
实现与本地自动化验证已完成；已补充真实图库/MinIO 的单任务导出压测，见
[压测报告](./benchmark-report.md)。真实队列端到端联调和多 Worker 压测仍待部署验收。

## 目标与范围

资产页面的实例导入、导出改为持久化后台任务，前端不再等待 Excel 处理结束。
每个用户的任务历史最多保存 7 天、最多 5 条，同时限制并发与文件规模。
本稿先覆盖实例导入导出；模型配置导入、服务树导入、场景视图导出不自动切换。
下载导入模板继续同步。

第一版产品规则：

- 导入与导出合计 5 条，跨模型计算；第 6 条接纳成功时淘汰最早的已结束记录。
- 创建时间起最多 7 天，不因下载而续期。
- 单次导入 1 万数据行（含校验失败行）、导出 10 万行；后续按压测校准。

## 前端交互

资产页工具栏新增“导入导出记录”入口，显示本人进行中数量。点击打开 Ant Design
Drawer，展示当前域本人跨模型记录，最多 5 条，不新增分页或复杂筛选。

顶部说明：“仅保留最近 7 天的 5 条记录，超限自动清理最早的已结束任务，请及时下载。”

记录内容：类型、模型、提交组织、范围、文件名、提交时间、状态、处理阶段、处理条数、
结果摘要、到期时间、操作。失败摘要有界，详细错误放在结果文件中。
导出成功的记录在提交时间下方显示“成功时间”，使用后端 `finished_at`：结果文件及授权清单
上传 MinIO、最终授权复核通过后，任务成功落库的时间。未成功或没有该时间的记录不显示。

| 状态 | 展示与操作 |
|---|---|
| 排队中 | 等待执行；允许取消 |
| 处理中 | 正在校验 / 写入实例 / 写入关联 / 生成文件；显示已处理条数 |
| 成功 | 导出可下载文件；导入显示新增、更新及关联数量 |
| 部分成功 | 导入显示成功/失败数量，可查看摘要、下载错误报告 |
| 失败 | 明确原因；导出允许“按相同条件重新提交”，新任务接纳成功后自动移除旧失败记录；提交失败则保留旧记录 |
| 结果待核对 | 导入进程中断且存在写入不确定性；不可显示成零写入或提供一键重跑 |
| 已取消 | 保留短期记录，可删除 |

导出保留已选择、当前页、全部及字段/关联选择。按钮改为“提交导出”；通过字段校验后立即
关闭配置弹窗并打开右侧记录抽屉，不等待接纳请求返回。接收到 202 后提示
“导出任务已创建，可在导入导出记录中下载”，加入新记录，不自动触发下载。
提交失败时恢复配置弹窗，保留选择及幂等键供重试；不在记录中伪造已接纳任务。
当前页和已选择在点击时固定 UUID 集合；全部暂保持当前模型授权范围，不叠加页面筛选。
若增加“当前筛选结果”，应作为独立选项明确传递条件，不静默改变“全部”。

导入继续先选模型、下载模板、选文件。上传阶段显示真实传输进度；202 表示文件已保存、
任务已接纳，不表示数据已导入。任务结束后，仅当仍在对应模型页面时刷新列表一次。
导入失败不自动重复上传或重复执行。

轮询先采用普通 GET：抽屉打开且存在进行中任务时每 3 秒；抽屉关闭但 CMDB 页面仍可见时
每 15 秒轻量刷新进行中状态；页面隐藏时暂停，回到页面立即拉取。所有任务结束停止轮询。
跨标签页各自读取服务端事实，不依赖本地倒计时判断完成，不伪造百分比。

## 第一版限制（代码默认值，容量仍需压测）

| 规则 | 默认值 |
|---|---|
| 历史 | 当前域内每人合计 5 条、创建后最多 7 天；所有模型共用，不按组织增加额度 |
| 本人进行中 | 导入、导出合计最多 1 个排队或执行中的任务；拒绝时返回现有任务入口 |
| 执行容量 | 复用默认 Worker；数据库配额控制导入导出全局并发 2，与 Worker 的总并发配置分开 |
| 导入互斥 | 相同资产模型的后台导入串行，避免两个导入同时基于旧匹配结果修改实例；不替代普通资产写入已有的唯一约束 |
| 导入文件 | 仅 `.xlsx`，最大 20 MiB、1 万数据行（含校验失败行）；当前 UI 的 `.xls` 与 openpyxl 不一致，应明确纠正 |
| 解析预算 | 同时约束解压大小、物理行列数、单元格长度及关系数；仅压缩文件大小不足以限制内存；建议解压总量先设 200 MiB，其余按现有模型契约设置 |
| 导出 | 最多 10 万实例、输出文件最大 100 MiB；处理期间复核，超限整项失败，不提供悄悄截断的文件 |
| 执行时限 | 15 分钟协作停止预算；默认 threads 池不能强杀单任务，Celery 的 soft/hard limit 仅在池支持时生效；排队最多 30 分钟 |

达到记录上限时先选择可淘汰的终态；绝不通过删除运行记录释放并发名额。
输入未通过校验、存储失败或创建失败，不应丢掉用户旧的有效记录。
终态数据中“结果待核对”也不能自动允许同一未确认执行与新导入重叠。

这些限制是初始产品与容量提案，不是根据线上压测得到的保证。

## 后端 Module 与持久化事实

在 CMDB 内新增 Transfer Module，接纳任务、状态转换、配额、结果及清理集中处理。
HTTP 和 Celery 是它的 Adapter；不建设跨应用通用任务平台。

实施文件：

- `models/transfer_task.py`：任务记录及必要的配额/执行占用事实。
- `services/transfer_validation.py`、`views/transfer_task.py`：接纳、查询、取消与下载授权。
- `services/transfer_service.py`：用户作用域、历史上限、接纳幂等、状态转换。
- `services/transfer_execution.py`：调用导入/导出执行逻辑，报告进度，处理终态。
- `services/transfer_files.py`：源文件、产物和错误报告的对象存储生命周期。
- `tasks/transfer.py`：只接收 task_id；执行、派发补偿和定时清理。
- `web/src/app/cmdb/components/transfer/`：任务抽屉与详情；`api/transfer.ts`、`hooks/useTransferTasks.ts`。

`CmdbTransferTask` 保存：UUID task_id、type、稳定用户主键及 domain、模型、提交组织和
include_children、规范化请求参数、幂等键与参数哈希、status、phase、处理计数、有限结果摘要、
源文件/产物/错误报告的私有对象键、文件大小、created_at/started_at/finished_at/expires_at、
执行令牌与租约、派发截止与重试状态、删除状态。

不保存 Token、Cookie 或整个 request，不把文件内容放 JSONField，不用 Celery result backend
作为用户任务记录。用户不能通过请求体指定 owner。索引覆盖 owner+created_at、状态+租约、到期时间。

## 前后端 Interface 草案

以下为 CMDB 内部登录态接口，沿用项目统一响应 envelope；以后若提供外部 API，另走 OpenAPI 网关。

| 方法与路径 | 契约 |
|---|---|
| `POST /cmdb/api/transfer_tasks/export/` | JSON：model_id、scope、inst_uuids、attr_list、association_list；202 返回 task_id/status/created_at/expires_at |
| `POST /cmdb/api/transfer_tasks/import/` | multipart：model_id、file；源文件持久化后 202，组织及用户从认证上下文取得 |
| `GET /cmdb/api/transfer_tasks/` | 仅本人有效记录，最多 5 条；附可提交状态和配置限制供前端展示 |
| `GET /cmdb/api/transfer_tasks/{task_id}/` | 当前阶段、处理计数、结果摘要及允许的操作，不返回原始权限数据或对象键 |
| `POST /cmdb/api/transfer_tasks/{task_id}/cancel/` | 第一版只允许取消尚未领取的排队任务；与领取竞争时通过数据库条件更新判定 |
| `DELETE /cmdb/api/transfer_tasks/{task_id}/` | 仅删除已结束历史及文件，不撤销已导入的实例 |
| `POST /cmdb/api/transfer_tasks/{task_id}/retry/` | 仅失败导出，重新鉴权；原子创建新任务并标记旧记录待清理；同键重复请求返回同一新任务 |
| `POST /cmdb/api/transfer_tasks/{task_id}/download/` | 请求 artifact 类型，重新鉴权后返回短时下载凭证或受控文件响应 |

创建携带 `Idempotency-Key`：同一用户同键同内容返回同一任务；同键不同内容返回 409。
文件以摘要参与参数哈希，重复接纳产生的临时上传要回收。
幂等保障覆盖保留窗口；不能承诺任务与幂等记录已清理后还永久识别旧请求。

错误使用稳定 code：400 参数/格式、403 权限、404 不属于当前用户或不存在、409 状态冲突、
413 文件/规模超限、429 并发或容量受限。Worker 发现行数或权限变化等问题时，写任务失败，
不指望创建请求返回处理结果。

示例详情（省略统一 envelope）：

```json
{
  "task_id": "UUID",
  "type": "import",
  "status": "partial_success",
  "phase": "finished",
  "processed_rows": 1000,
  "total_rows": 1000,
  "summary": {"created": 700, "updated": 280, "failed_rows": 20, "failed_relations": 3},
  "available_actions": ["download_errors", "delete"],
  "expires_at": "2026-09-28T03:00:00Z"
}
```

实例行计数与关联计数分开，不能把三条关联失败误算成三条实例失败。

## 执行、权限与故障语义

1. 接纳：验证身份、模型、请求规模与当前权限；导入先将文件放入私有暂存区。
2. 短 ORM 事务内锁定稳定的用户配额对象，检查进行中数、创建任务并标记待投递；
   淘汰旧终态和接纳新任务在同一事务中确定。不可只 count 再 create。
3. 提交后由 `on_commit` 发起非阻塞投递提示：每个 API 进程最多 2 个发布线程，不维护内存等待队列；
   Broker 建连和发布使用 2 秒预算、关闭建连及发布重试，HTTP 不等待消息发送。提示饱和或进程退出后，
   任务记录中的投递意图由每分钟维护补发；重复消息通过原子领取去重。`on_commit` 本身同步执行，不能直接在其中等待 Broker。
   维护批次首次发布失败后停止本轮发送，但继续收敛排队超时，避免故障时累计数百次连接等待。
4. Worker 原子领取全局/模型配额及任务，取得执行令牌；所有进度、续租、产物发布和终态
   更新都验证该令牌。消息只含 task_id，身份与参数从库读取。
5. 执行前重新加载用户有效身份，提取 HTTP/Worker 共用的授权逻辑；第一版采用保守失效：最新授权快照必须与提交时一致，变化即拒绝，权限为空即失败。更新已有实例同时检查原实例及目标组织权限。
6. 模型结构在排队中变化时重新校验，不能静默少导字段；模型被删除或不可见则明确失败。
7. 导出复用每批 500 条的读取与 write-only 写入；生成完成上传私有存储，校验产物可用后
   才发布成功。导出数据是在执行时读取，不承诺提交时快照。
8. 导入保留部分成功语义：文件结构致命错误不写入；合法行继续执行，非法行写错误报告。
   关联在实例写入后处理，已存在关系幂等保留并单独计数；异步路径不执行全模型关系回退查询。需修改已有提前返回分支，成功写入必须有变更记录与后续调度。
9. 导入补充行号、处理类型、确定成功/失败的结构化结果；不从多行 message 中猜计数。
   避免按整个模型加载已有实例，按本批唯一标识查询匹配，并保留文件内重复检测与唯一约束。
10. 进程中断后的导入不能整文件自动重试。已确认成功保留，未确认部分显示“结果待核对”；
    第一版不承诺断点续跑或整文件事务。数据库状态 fencing 不能单独撤销已发往图库的写入；
    回收不能直接启动第二个导入覆盖未确认的旧执行，必须确认执行停止并核对副作用。
11. 失败导出可由本人明确重新提交新任务；中断任务须先核对解除占用，不自动重跑。每次使用独立执行对象键，过期令牌不能发布产物。
    重新提交成功指新任务已持久化接纳（202）；在同一事务中标记旧失败记录待清理，再执行 5 条历史限制，
    不额外淘汰无关历史。新任务参数保存内部来源 ID，旧记录隐藏或日清后，同一幂等键仍能返回同一新任务。
    旧文件沿用每日清理，提交校验或事务失败均保留原记录。
12. 源文件、错误报告与导出文件仅本人可取；下载时检查当前模型/组织权限。
    保存生成时的有效授权范围，权限改变导致旧产物不能安全复用时拒绝下载、要求重新生成。
    用户权限版本可辅助失效，但不能替代资源归属/授权规则的校验。

执行状态为 `queued → running → succeeded / partial_success / failed / interrupted`，
`queued → cancelled`。删除/过期是保留策略状态，与执行结果分开；不增加无实际用途的复杂重试状态。

## 文件与 60 秒代理限制

已确认使用 MinIO，不采用 CMDB 本地目录作为结果文件的持久存储。
按用户要求直接复用已有私有桶 `cmdb-config-file`，引用现有 `CONFIG_FILE_BUCKET` 常量，
不新增桶、不调整桶级访问策略或为整个桶设置导入导出的过期规则。
导入导出使用独立前缀 `transfer/`，对象键为
`transfer/<owner_id>/<task_id>/<execution_id>/<artifact_name>`；上传暂存使用
`transfer/tmp/<upload_id>/source.xlsx`。标识由服务端生成，原始文件名不参与对象路径拼接。
现有配置文件孤儿清理只扫描 `tmp/config-file/`，导入导出清理只处理任务记录关联的
`transfer/` 对象和该前缀下的孤儿，不扫描或删除整个桶的文件。
复用桶和存储配置，任务元数据仍由 `CmdbTransferTask` 管理，不写入 `ConfigFileVersion`。
流式上传同时遵循 `MINIO_BUCKET_CHECK_ON_SAVE`：首次保存时检查并按需初始化这个既定桶，
不在启动期连接 MinIO；并发建桶时只容忍桶已归当前凭据所有的响应，其它错误按失败处理。
永久产物不能仅放 Worker 本地临时目录；临时文件只承担生成和上传过程。

异步处理消除的是等待生成的长请求，上传和下载仍可能受网络超时限制。
第一版采用同源鉴权下载，不签发浏览器直连 MinIO URL。仅上传和下载端点使用 300 秒
客户端/Next 代理传输预算（首包与正文都覆盖）；其它 API 正文保持 60 秒。
生成时保存私有授权清单，下载前重新检查模型、授权快照，以及清单中实例与关联对端的
当前组织/权限；资源移出授权范围、删除或模型变化时拒绝旧文件下载。
文件按 64 KiB 分块从 MinIO 复制到临时文件，再通过 ASGI 异步迭代传输并关闭临时文件。
入口网关的请求体上限与 300 秒文件通道超时需在部署环境一起验收。

## 清理与部署

用户列表和下载鉴权实时判断 expires_at，过期即不可访问，不等待定时任务。
新任务接纳时执行 5 条限额，不等待日清任务才淘汰超额历史。
按用户要求，Celery Beat 每天执行一次过期任务及文件清理，覆盖导入原文件、导出结果、
错误报告，以及已超出安全保留窗口且不属于有效执行的孤儿暂存对象。
默认服务器时区每天 03:00，可在 `apps/cmdb/config.py` 调整；独立维护任务每分钟检查租约/排队超时并补发。
删除先标记不可见/不可下载，保留对象键作为清理凭据，后台幂等删文件再物理删记录。
存储暂不可用时继续补偿；不先物理删记录丢失对象定位。短期删除凭据不算用户可见历史。
7 天是业务可访问的硬上限；正常情况下物理擦除在下一次每日清理完成，存在约一个日清周期
的延迟，存储故障可能延长该时间，不能描述成绝对即时删除。
历史任务删除不删除 CMDB 资产变更审计，也不回滚已导入资产。

历史保留到期与执行超时分开：执行预算、排队截止和心跳失联的状态收敛不等待日清。
超时任务先停止执行或进入结果待核对；仍在使用、仍待核对的文件和执行占用不得被日清
直接删除。日清可以发现漏处理异常并触发核对，但不能用“删除记录”代替终止执行和结果核实。

导入和导出直接投递到现有 Celery 默认队列，使用 `make celery` Worker；不新增专用 Worker、
队列或 Supervisor 配置。`make celery-beat` 驱动每分钟补发与日清，见 [开发说明](../../../DEVELOP.md)。
HTTP 只做接纳和投递，文件处理只在 Celery 执行。旧队列中的未超时排队任务由数据库维护补发到默认队列，
沿用原任务 ID，原子领取避免重复执行。
维护任务与导入导出共享 Worker；因此可能受 Worker 忙碌影响。截止时间和执行令牌在执行路径中也会检查，
不能假设维护任务一定准点运行。默认 threads 池无法强杀阻塞线程，未确认停止的执行继续占用名额。
运行期进行派发补偿与清理，不在 batch_init 中等待 Worker 或依赖其响应；服从已有启动顺序。

## 交付与验证建议

先交付任务接纳、权限、配额、存储、Worker 和记录抽屉，再接入已优化的导出；之后改造导入
结果、按批匹配和部分成功审计，最后联合验收清理、故障恢复与容量限制。各阶段属于同一功能，
不能只交付 `.delay()` 调用就认为异步改造完成。

保留旧同步 Interface 的响应契约供存量调用方使用；新页面切换至新任务接口。查清其它调用者后
再评估旧端点下线，禁止原路径悄悄从文件/结果变成任务 ID。

验证重点：

- 同域不同用户、跨域同名用户、跨组织访问、用户停用和权限收回。
- 同时创建两个任务、幂等重发、并发第 6 条、过期边界与活动记录保护。
- 提交成功投递失败、重复消息、领取与取消竞争、租约过期旧执行回写、Worker 中断。
- 导入部分成功、成功行审计、行号计数、文件内重复、越权更新、关联失败及不确定写入。
- 超大压缩包、物理行列异常、导出上限、超时和内存；实际 FalkorDB 与部署环境压测。
- 文件上传成功落库失败、成功文件未发布、删除失败补偿、下载权限和短时凭证到期。
- 同桶隔离：导入导出日清不删除配置文件，配置文件孤儿清理不删除导入导出文件。
- 前端 202 与成功状态区分、刷新页面恢复、轮询停止、状态对应操作、当前模型列表刷新。

范围已锁定：导入导出跨模型合计 5 条，只切换资产页面实例入口。真实数据容量与外层网关仍需部署验收。

## 前端确认后的后端收敛事项

以下为本次实施采用的约束。

### 数据所有权与执行占用

- Django 数据库是任务状态的事实源，Celery 只传递 task_id，MinIO 只保存文件。
- 用户历史记录与执行占用分开处理。正常终态释放执行占用；导入中断且图写结果不确定时，
  清理历史、到期或用户删除不能释放尚未核实的执行占用。后台核对执行已停止及写入结果后
  才能解除阻塞，避免新任务与旧图写交叠。
- 用稳定用户记录或专属配额行加 ORM 事务锁，保护“检查活动任务 → 创建 → 淘汰旧历史”；
  空任务集合本身不能充当并发锁。全局执行配额须持久化领取，多 Worker 共用。
- 记录级执行令牌只阻止过期执行更新任务状态和发布文件，不等价于对图库写入 fencing。
  第一版不对结果不确定的导入自动重试，也不宣称整文件 exactly-once。

### 提交、排队与模型变化

- 202 仅在源文件（导入）与任务记录已持久化后返回；源文件存储失败不创建可执行任务。
- 投递失败继续保留受截止时间约束的待投递任务，由独立维护调度有限重试；超过排队预算
  转失败并释放占用，不永久停留 queued。
- 校验现有模型和字段配置的语义指纹，至少覆盖类型、必填、唯一标识及所选关联。
  排队期间影响本任务的结构变化应失败并要求重新提交，不能静默套用新模板。
- `selected/currentPage` 持久化用户提交的 UUID 集合；不持久化易失效的图内部 ID。
  `all` 仅固定模型与提交授权范围，读取执行时的数据，不承诺提交时快照。

### 导入结果和重试分层

- 保留部分成功语义；文件结构和全局预算先校验，再跳过不合法行。全部实例行无效时为失败，并提供错误报告。写图边界后的未知异常保留结果待核对，不继续或重放。
- 保存源行号及每类结果，实例新增、更新、失败行与关联失败分开计数；API 仅返回有界摘要。
- 已成功写入的审计/后续调度失败属于结果记录或投递故障，应补偿相关副作用，不能再次执行
  已成功的实例写入。必须保留可核对的任务/操作关联事实，不能只在进程内累计最终字符串。
- 文件存储重试、消息重复投递与导入业务重跑是不同动作。前两者可以幂等补偿，后者需要
  明确知道哪些写入已成功，第一版不提供自动整文件重跑。
- 错误报告只给行号、字段和受控原因，不回显凭据字段值；Excel 文本内容按文本输出，
  不把用户输入解释成公式。

### 文件下载的部署选择

已选择同源鉴权文件通道；复用现有存储客户端与桶，不要求增加浏览器直连 MinIO 域名。
授权清单也属于任务文件，由相同保留与清理规则管理，不通过公开 API 暴露。

### 第一版实施验收

必须联合验证提交事务、投递补偿、权限收回、并发领取、过期执行拒绝回写、部分成功审计、
结果不确定不重放、私有文件下载与删除补偿。独立线程/进程池配置和消费者部署是交付的一部分，
不能将演示服务的内存状态及定时模拟当作生产异步能力。

管理员核对中断任务：先确认对应 Celery 执行已经停止（threads 池不能靠单任务 revoke 确认退出），再按


命令只解除执行占用，不重放导入；备注不得包含凭据或实例原文。
