# 02 — APM 聚合序列按服务设上限并过期

Status: ready

Blocked by: 01

**What to build:** 单个服务的 Span 名失控时，聚合进程内存和聚合库活跃序列只按该服务的上限增长；
不活跃的接口在过期后释放名额；容量文档与告警反映真实语义。

- [ ] 核对 spanmetrics v0.153 源码：上限的作用范围、序列过期与资源过期字段、资源缓存默认值，在报告里写明结论
- [ ] `APM_AGG_CARDINALITY_LIMIT` 默认改为 500，文档写明是“每服务”；开启序列过期，默认 1 小时；显式设置资源缓存上限
- [ ] 契约：超过上限的组合并入溢出序列；序列过期后再次出现，`increase()` 结果正确（夹具用短过期时间）
- [ ] 容量文档重写：最坏值 = 每服务上限 × 服务资源数 × 每组合序列数，同时给出典型值；删除“全局 9 万组合”
- [ ] 告警清单增加“出现溢出序列”（聚合库可查询的条件），说明处理办法（修 Span 命名或调高上限）
- [ ] `make -C deploy/apm test validate` 通过；契约结果记录

## Notes

- 溢出序列没有服务名和环境标签，Server 查询不改；不要为此改成按 `job` 查询。
- 过期时长与 Server 的最长查询窗口无关：`increase()` 能处理计数器重置，过期只影响内存和活跃序列数。
