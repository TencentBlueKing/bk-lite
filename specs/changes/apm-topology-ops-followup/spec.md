# APM 服务列表批量操作与拓扑排查口径

Status: implemented

## Problem Statement

服务列表只能逐条调整组织和归档。服务拓扑把推断下游、请求切片和 Trace 冒泡错误叠在一张图上：卡片重叠、异常被整条链路重复计数，「只看异常」按节点健康度过滤，和边上的失败调用对不上。

## Solution

服务视角列表支持勾选后批量调整组织、归档。全局服务拓扑只画插桩服务；推断下游只留在应用详情画布。卡片按真实尺寸排版，不为塞进视口而缩小间距。异常数只统计本服务出站下游调用，连线有异常才为红。「只看异常」只保留 `error_calls > 0` 的边及其两端。

## User Stories

1. As an APM 使用者, I want 在服务列表勾选多个服务后批量调整组织或归档, so that 不必逐行操作。
2. As an APM 使用者, I want 服务拓扑只看已插桩服务的调用, so that 推断的 mysql 等不会挤占全局图；应用详情仍能看到直接推断下游。
3. As an APM 使用者, I want 拓扑卡片和连线不重叠，异常数等于该服务调下游的失败次数, so that 我能顺着红线找到真正失败的一跳。

## Implementation Decisions

- 批量操作复用单服务 `organizations` / `archive` 接口，按 `serviceId` 去重后逐个提交；部分失败回写成功/失败条数。不新开批量 API。
- 列表行是服务×环境，勾选与批量都作用在服务上。应用卡片视角和应用详情下属表不加批量。
- 全局服务拓扑 `include_inferred=false`；应用详情保持 `include_inferred=true`。推断仍不进目录。
- 插桩节点 `error_spans` = 出站边 `error_calls` 之和；健康度按出站错误率分档。叶子服务没有出站失败则为 0。推断节点仍用打到它的 Client Span。
- 连线 `error_calls > 0` 才描红；异常数字 0 用灰色，大于 0 用红色。不再用绿 0 表示健康边。
- 「只看异常」前端按边过滤，不重新取数；正常下游边一并隐藏。
- 服务拓扑去掉「仅错误请求」和「操作」输入；耗时下限保留。摘要为「X 服务 / X 异常 / X 调用」，统计用未过滤的查询结果。
- 布局禁止把节点间距缩到小于卡片尺寸；图画不下时靠平移和缩放，不叠卡片。服务卡片图标 20px。

## Testing Decisions

- 拓扑服务：一条 Trace 上多段 Server Span 都标 error 时，叶子服务异常数为 0，上游异常数等于其出站边之和。
- 服务拓扑页传 `include_inferred: false`；应用详情仍传 true。
- 「只看异常」只留下 `error_calls > 0` 的边，不触发重新查询；同层多个服务卡片中心距不小于卡片宽。
- 服务列表勾选两个服务后批量归档会分别调用 archive；组织不一致时保存覆盖为同一组组织。

## Out of Scope

- 批量专用后端 API、跨筛选结果的全选、应用详情下属表批量。
- 恢复全局服务拓扑上的推断节点或「仅错误请求」切片。
- 独立拓扑指标流水线。
