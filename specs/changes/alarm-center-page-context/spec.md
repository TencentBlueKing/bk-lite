# 告警中心页面问答

Status: done

## Problem Statement

运维人员在告警中心看活跃告警、所有告警或事故时，右侧智能问答看不见当前筛选和当前页结果。打开某一条告警详情或进入事故详情后，仍要把名称、级别、关联告警手工复述给机器人。监控告警列表已经按同一套全站问答接上当前页；告警中心还没有。

用户要的是对着**已经看见的列表**和**已经打开的那条详情**提问，不是把筛选条件下的全量告警或事故 dump 进模型。

## Solution

告警中心按全站页面问答对接规范接入。用户在 `/alarm/alarms` 的活跃告警或所有告警、`/alarm/incidents` 事故列表、以及 `/alarm/incidents/detail` 事故详情提问时，智能问答自动带上当轮页面快照。未打开告警抽屉时，告警列表快照等于当前筛选加上当前页已渲染行。打开告警详情抽屉时，同一轮再附上这条告警的字段和 Event。事故详情是独立路由，快照等于这条事故的字段加上当前已加载的关联告警切片。集成、配置页保持不采集。公共上限沿用全站框架（约 8K 字、最多 6 张缩略图、约 2 秒采集），本期不放宽，也不为 Recharts 分布图/甘特图补截图适配器。

## User Stories

1. As an 运维人员, I want 在活跃告警或所有告警列表直接问「现在筛出来的哪些最紧急」, so that 不必把当前页的级别、名称和内容手工复述给智能问答。
2. As an 运维人员, I want 改完级别、状态、告警源、时间、搜索、我的告警或翻页后再提问时答案跟新结果走, so that 机器人不会复述上一问的旧筛选或旧页。
3. As an 运维人员, I want 快照写明共 N 条、当前第 X 页, so that 模型知道这是当前页切片，不会把 20 行当成筛选全量。
4. As an 运维人员, I want 打开某一条告警详情后，提问能同时用到当前列表和这条详情（含 Event）, so that 沟通可以针对这条告警。
5. As an 运维人员, I want 关掉告警详情后再提问时不再带上那条告警的详情, so that 对话回到当前列表。
6. As an 运维人员, I want 在事故列表按当前筛选提问, so that 不必把事故名称、级别和状态手工复述。
7. As an 运维人员, I want 打开某条事故详情后提问能用到这条事故和它当前附上的关联告警切片, so that 可以针对这条事故沟通。
8. As an 运维人员, I want 列表或详情还在加载时问答明确未就绪、且不把空白当成零, so that 总览不会系统性说错。
9. As an 运维人员, I want 在集成或配置页仍是普通聊天, so that 不会把告警列表的采集规则套到别的页面上。

## Implementation Decisions

- 告警列表：pathname `/alarm/alarms`，Tab `activeAlarms`（活跃告警）与 `historicalAlarms`（中文「所有告警」）共用一个旁路 pilot。闸门只认这条路由，不把 Tab 写进 codegen。
- 事故列表：pathname 恰好是 `/alarm/incidents`（规范化后带尾斜杠）。**含 `/detail` 时列表 pilot 必须返回空快照**，避免 KeepAlive 残留列表或详情页误采。
- 事故详情：pathname `/alarm/incidents/detail`。这是独立页不是抽屉，用 `useAiPageContext` 注册详情提供函数；不依赖列表 DOM。
- 告警详情是列表页（以及事故详情里嵌套表格）上的抽屉。信息 Tab 与事件 Tab 互斥挂载，Event 目前要点「事件」才请求。因此详情走 hook：打开抽屉即预取 Event，关闭后返回空 section。这是对接规范允许的例外。
- 不新做问答 UI。不改 GlobalWebchat，不改 skill_channel 注入，不放宽图片/文本预算，不为 Recharts 或甘特图补截图适配器。
- 列表只读 URL/DOM；查询范围锁在本页可见壳上，跳过 `display:none` / `aria-hidden` 的 KeepAlive 缓存。不扫其它产品线的表格，不把抽屉里的行误当成列表行。
- `getMessage().title`：告警列表用 `alarm-center:` + Tab；事故列表用 `alarm-incident:list`。`currentTime` 必须随 Tab、筛选、搜索、我的告警、时间窗、分页和当前页行指纹变化。**刷新频率不充当时间窗**。活跃告警时间控件只有刷新，文案写「活跃告警不按时间窗过滤」。事故列表同样只有刷新。
- 告警列表文字通道：身份与筛选（10）、结果范围（8）、当前页表行（4）。分布图是 Recharts，`images: []`，第一期不写图文。表行去掉操作列。抄当前页全部已渲染行，不另打列表接口。加载中不输出表行。
- 告警详情文字通道：身份（10）、字段（9）、Event 最近 30 条（8）。身份含告警 id、名称/内容、级别、状态、持续时长、首次/最近事件时间、所属事故（若有）。字段含操作人、通知状态、对象类型与对象。Event 按时间降序，写「共 N 条，已附最近 M 条」；加载中写「事件加载中」，空则「暂无事件」。不采集 raw_data、凭据、拓扑、动作记录。
- 事故列表文字通道：身份与筛选（10）、结果范围（8）、当前页表行（4）。去掉操作列。
- 事故详情文字通道：身份（10）、字段（9）、关联告警最多 30 条（8）。字段含创建时间、来源、状态、负责人、团队、备注。关联告警写「共 N 条，已附 M 条」，不把 page_size 10000 的全量 dump 进模型。协作 Tab、甘特图、变更时间线本期不采集。加载中写「详情加载中」或「关联告警加载中」。
- 在事故详情再打开告警抽屉时，同一轮合并事故快照与该条告警详情。关掉抽屉后不再带该条告警。
- 超 8K 由现有 `mergePageContexts` 按 priority 丢弃。身份和当前这条详情不能先被挤掉。

## Testing Decisions

好测试只锁对外契约：给定 DOM/URL 或详情 provider 入参时，`getMessage` / `getTextContext` / 详情纯函数的返回值。不测 JPEG、不测 Recharts、不测 GlobalWebchat、不测 LLM。

- 告警列表：非 `/alarm/alarms` 不采集；主机 Tab 的 title 含 tab；改筛选/翻页 `currentTime` 变，只改刷新间隔不变；文字含筛选、共 N 条、当前页行；加载中不当零；活跃告警写不按时间窗过滤
- 告警详情：抽屉关闭无 section；打开后含身份、字段、Event；超过 30 条只留最近 30；加载中不把空事件当零
- 事故列表：`/alarm/incidents/detail` 不采列表；列表页含筛选与当前页行
- 事故详情：关闭/未加载写加载中；关联告警超过 30 条截断并带总数
- codegen 前缀：`/alarm/alarms/`、`/alarm/incidents/`

## Out of Scope

- 集成、配置、屏蔽策略、丰富规则等其它告警中心页面
- 把筛选全量或事故下 10000 条关联告警 dump 进模型
- 为分布图/甘特图补截图适配器，或放宽 6 张 / 8K / 2 秒
- 新问答 UI、改 GlobalWebchat 或后端注入
- 让问答关闭告警、声明事故或改指派
- 为对接而改列表页可见展示

## Further Notes

中文 UI 把 `historicalAlarms` 写成「所有告警」，与监控中心「历史告警」不是同一条产品线。事故详情走独立路由，是因为页面会卸载列表；KeepAlive 仍可能把列表留在隐藏 DOM，所以列表 pilot 必须以 pathname 排除 `/detail`。告警详情走 hook，是因为 Tab 互斥和 Event 懒加载让 DOM 读不全。
