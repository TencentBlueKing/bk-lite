# 告警处理：参数手动填写、执行时改值与按需自动执行

Status: ready

## Problem Statement

告警处理把作业脚本参数全部绑成告警字段，配置人没法用手填常量或脚本默认值。作业模板虽有默认值，告警中心当前调用的执行入口不会在缺 key 时补默认值，规则里也看不到、改不了这些值。规则命中后一律自动跑脚本，不能改成「只手动」；手动再跑时也不能改手填参数。作业模板后来增删参数时，规则也没有明确的更新方式。

## Solution

告警中心自己持有每个脚本参数的取值，执行时把完整参数列表传给现有作业入口，不改作业平台补默认值的契约。选作业后每个参数默认「手动填写」并回写明文默认值；配置人可改成告警变量，或保留手填。规则增加「自动执行」（默认开，存量当开）；关掉则命中不跑，仍可在告警上手动执行。仅「手动填写」可打开「执行时可改」；手动触发时只弹这些项，覆盖值随这次执行提交。编辑规则时按作业最新参数做结构对齐，并提供「从作业模板重新加载」覆盖手填默认值。

## User Stories

1. As an 告警处理规则配置人, I want 选作业后每个脚本参数默认带上模板明文默认值且可手改, so that 不必把所有入参都绑到告警字段。
2. As an 告警处理规则配置人, I want 每个参数在「手动填写」和「变量传递」之间切换, so that 有的值写死、有的从告警取。
3. As an 告警处理规则配置人, I want 变量传递必须选好告警字段或触发事件类型才能保存, so that 不会存下一份执行时必失败的规则。
4. As an 告警处理规则配置人, I want 给手填参数打开「执行时可改」（默认关）, so that 值班人员手动跑时可以改这几个值。
5. As an 告警处理规则配置人, I want 规则可以关闭自动执行且默认仍为开启, so that 现网继续自动跑，需要人工确认的规则可以改成只手动。
6. As an 告警值班人员, I want 自动执行关闭时告警产生不跑脚本、但仍能手动执行该规则, so that 我决定何时处置。
7. As an 告警值班人员, I want 手动执行（含再次执行）在存在可改手填项时弹出这些项并预填规则常量, so that 我能改完再跑；取消则不执行。
8. As an 告警处理规则配置人, I want 编辑规则时自动对齐作业模板新增/删除的参数, so that 新参数能配、已删参数不再下发。
9. As an 告警处理规则配置人, I want 一键从作业模板重新加载, so that 手填项能更新为模板最新默认值，变量映射仍保留。
10. As an 告警处理规则配置人, I want 变量传递可以选择「触发事件类型」并看到各操作对应的 Key, so that 脚本能按创建/分派/认领/恢复/关闭分支。

## Implementation Decisions

- 取值与下发由告警中心完成。继续调用现有作业脚本执行入口，传入完整参数列表；本轮不改为 `script_id` 执行，也不依赖作业侧「缺 key 补默认值」。
- 「自动执行」是规则级布尔字段，默认 `true`。存量无该字段视为 `true`。它与规则启停分离：停用规则则自动、手动都不可用；仅关自动执行时，评估命中不创建自动执行记录、不调作业。
- 自动执行开启时保持现网：命中触发事件后落 `trigger_type=auto` 记录并执行；之后仍允许手动再跑。手动执行不校验触发事件，组织与权限边界与现在一致。生命周期已结束（`closed` / `auto_close` / `auto_recovery` / `resolved`）禁止手动执行，接口与界面一并拦截。
- 规则关闭自动执行且勾选了 `closed` 时，单条告警手动关闭前询问是否按现有手动执行流程跑一次；跳过仍关闭。批量关闭不弹。
- 每个脚本参数一行绑定，形状为 `{ name, from: "const" | "field", value, allow_adjust? }`。`allow_adjust` 只对 `from=const` 有效，默认 `false`；保存时 `from=field` 的项不保留该开关为真。
- 新选作业（含更换作业）：丢弃旧绑定，按脚本参数顺序全部生成 `from=const`，`value` 为明文默认值，`allow_adjust=false`。无默认值或默认值被脱敏（如 `******`）则 `value` 为空，不把掩码当真实值写入。
- 变量传递的 `value` 是告警 payload 字段路径，保存时必填。手填允许空字符串。
- 解析：`const` 用绑定值（含空）；`field` 从告警取值，缺失时回退脚本默认值，两者都没有则这次执行为配置错误。未出现在当前脚本参数里的旧绑定不下发。
- 手动触发请求可带覆盖字典，key 必须是当前规则里 `from=const` 且 `allow_adjust=true` 的参数名；其它 key 拒绝且不创建执行记录。覆盖只作用于这一次。取消弹框不落记录。
- 没有任何可改手填项时，手动执行不弹框，行为与现在一致。告警操作下拉与执行记录「再次执行」共用这一套。
- 打开规则编辑时拉取作业最新参数定义并做结构对齐：新参数补 `const`+明文默认值；脚本中已删除的参数从表中去掉，保存时不再带上；同名参数保留已有 `from` / `value` / `allow_adjust`。改名视为删除旧名并新增新名。下发顺序跟脚本当前参数顺序，不跟历史绑定顺序。
- 「从作业模板重新加载」再拉一次定义，做同样结构对齐，并把仍为 `const` 的项的 `value` 覆盖为模板最新明文默认值（加密/无默认则置空）。`from=field` 的字段映射与手填项的 `allow_adjust` 不因重新加载而改。打开抽屉期间模板变化只通过该按钮更新，不在输入过程中静默改手填值。
- 自动路径不接受覆盖。手动覆盖后的实际下发参数写入该次执行记录结果，便于事后查看；幂等键、回调、状态机与现网一致。
- 前端：规则表单增加自动执行开关；参数表提供取值方式、值（输入框、告警字段或触发事件类型）、仅手填可见的「执行时可改」，以及重新加载。变量下拉旁用 Tooltip 标明各生命周期事件下发给脚本的 Key。手动执行弹框只渲染可改手填项。
- 绑定 `trigger_event` 时，作业 handler 写入参数 payload。自动路径为当次生命周期事件 `created` / `assigned` / `acknowledged` / `resolved` / `closed`；手动路径按告警当前状态映射为同一套 Key（未分派→created，待响应→assigned，处理中→acknowledged，已处理→resolved，已关闭→closed）。不把该字段并入规则匹配 payload。
- 本轮不改作业平台执行接口、不引入参数加密存进规则、不把目标主机改成与参数表同一套手动/变量模型（主机仍用现有从告警取 / 固定 IP）。

## Testing Decisions

好测试只锁对外行为：给定规则配置、告警 payload 和触发方式，断言是否创建执行记录、下发给作业的参数列表、拒绝原因和弹框是否出现；不锁组件内部函数名。

- 引擎：自动执行开且命中 → 有 `auto` 记录且作业入参完整；自动执行关且命中 → 无自动记录、不调作业；规则停用 → 自动和手动都不可用。
- 参数：选作业后的默认绑定；`const` 原样下发（含空）；`field` 取值与缺失回退默认；绑定 `trigger_event` 时下发当次执行的事件 Key；未选字段不能保存；非法手动覆盖被拒绝且无执行记录；合法覆盖只改对应常量。
- 结构对齐：脚本新增/删除参数后打开编辑的绑定结果；重新加载覆盖手填默认值但保留变量映射。
- 脱敏默认值不会作为真实 `value` 写入或下发。
- 手动路径：无可改项时不弹框；有可改项时取消不落记录；告警下拉与再次执行同一覆盖规则。
- 存量规则无自动执行字段时按开启处理。
- 优先接在现有动作引擎、作业 handler、手动触发视图、参数解析纯函数和告警前端动作规则/手动触发测试上扩展，而不是另起一套执行器。

## Out of Scope

- 作业平台「接口不传 key 则补默认值」的行为变更。
- Playbook、ITSM、Webhook 动作类型。
- 手填参数在规则中的加密存储。
- 审批流、维护窗口、批量多告警一次手动执行。
- 目标主机绑定改造成与脚本参数相同的手动/变量表。
- 监控 / 日志 / APM 域内告警处理人闭环（与本能力无关）。

## Further Notes

作业脚本库快速执行只有在参数列表里带了该项且标记未修改时才会回填默认值；告警中心当前入口直接传脚本内容和参数列表，缺 key 不会补。因此规则必须存齐并下发每个参数。加密默认值在脚本详情里是掩码，告警中心不能把它当明文回写。
