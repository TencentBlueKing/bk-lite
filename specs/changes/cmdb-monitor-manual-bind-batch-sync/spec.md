# CMDB 关联监控：列表批量自动同步与详情手绑 / 解绑

Status: implemented

> 叠在现有 CMDB→监控无凭据推送之上。不重写自动认领主路径；不在监控侧做选人。

## Problem Statement

CMDB 与监控中心的存量资产经常对不上：监控侧身份不干净（IP 空、主键怪异、同名多条），自动认领会失败或不敢乱绑。运维只能进单条详情点「同步到监控」，失败后没有办法指定那台监控实例，也不能在资产列表一次性处理一批未关联 CI。绑错了也无法解开。

## Solution

在 CMDB 做成关联工作台，且只做这一侧：

- 资产列表勾选后批量触发 **现有自动认领**（无凭据、不新建监控）。已关联的跳过；整批跑完给汇总；失败行保持未关联。
- 详情保留自动同步；未关联或未找到时可 **手动指定一台监控实例**。选择器展示监控实例名（及 IP、对象类型），不成对内部 ID 作为主字段。
- 详情可 **解绑**：两边清指针，不删监控资产、不动节点关联。改绑需确认。已被其它 CI 占用的监控实例不能抢走。

适用对象是主机、网络设备、物理服务器、数据库、中间件和 Docker 容器；K8s / 云平台 / vCenter / 配件不做。

## User Stories

1. As a CMDB 用户, I want 在资产列表勾选一批未关联 CI 并点同步到监控, so that 能一次触发自动认领而不必逐条进详情。
2. As a CMDB 用户, I want 批量结果按成功 / 已关联 / 未找到 / 冲突 / 失败汇总且整批不回滚, so that 对不上的行可以接着去详情处理。
3. As a CMDB 用户, I want 详情在自动同步未找到时用手选监控实例完成关联, so that 监控身份不干净时仍能绑上正确的那一台。
4. As a CMDB 用户, I want 手绑列表看到监控实例名和可辨认信息而不是内部 ID, so that 我知道自己在选谁。
5. As a CMDB 用户, I want 解绑后两边关联指针都清掉且监控资产仍在, so that 绑错可以重来。
6. As a CMDB 用户, I want 手绑占用中的监控实例时被拒绝并看到占用方名称, so that 不会两台 CI 指向同一台监控。

## Implementation Decisions

### 入口与对象名单

- 入口只在 CMDB，且已售监控模块才展示。权限复用资产编辑权。
- 详情同步 / 手绑 / 解绑与列表批量共用同一份对象名单（后端为源，前端对齐）。
- 名单：`host`；`switch` / `router` / `firewall` / `loadbalance`；`physcial_server`；`mysql` / `postgresql` / `mssql` / `influxdb` / `oracle` / `redis` / `mongodb` / `es`；`apache` / `tomcat` / `nginx` / `rabbitmq` / `kafka` / `zookeeper` / `activemq` / `minio` / `etcd` / `haproxy`；`docker`。
- `docker` 对应监控对象 `Docker Container`。K8s / K3s / 云平台 / vCenter 及配件、无对应监控对象的存储：不露出入口，并从类型身份映射中移除，避免和它们自己的关联逻辑打架。

### 列表批量同步

- 对勾选实例逐条调用现有无凭据「推送到监控」，不重写 ingest 匹配顺序。
- 已有 `monitor_id` 的计入已关联并跳过，不改监控侧身份。
- 未关联的走现有认领：节点 ID → CMDB ID → 类型身份 → 同名。Docker 类型身份不看宿主机 IP，只按同对象下唯一实例名。
- 整批跑完不中途停止、不回滚。单次上限约 100 条，同步返回。批量不选手绑、不弹选择器。
- 汇总口径：成功、已关联跳过、未找到、冲突、失败。

### 详情同步、手绑、解绑

- 「同步到监控」保持现有无凭据认领：成功成对回填 ID；未找到 / 冲突只提示，不新建监控。已关联再点仍是重新同步关联，不改绑。
- 未关联或同步未找到时提供手动关联。候选仅当前模型映射的那一种监控对象、调用方可见范围；主字段为监控实例名，并带 IP、对象类型；支持按名称、IP 搜索。
- 手绑不走自动匹配：校验类型、权限、未被占用后，成对写入 CMDB `monitor_id` 与监控 `cmdb_id`。
- 目标监控实例已有其它 CI 的 `cmdb_id`：拒绝，提示占用方 CMDB 实例名（可定位），须先去那边解绑。不允许两台 CI 指向同一台监控。
- 已关联时换绑须确认。解绑成对清指针；不删监控资产；不改 `node_id`。解绑失败须说明哪一侧未清掉，避免只清一半。

### 自动认领的最小改动

- 主机 / 网络 / 数据库 / 中间件的既有认领规则不动。
- 仅名单级调整：`docker` 改为 `Docker Container` 且跳过宿主机 IP；从映射表拿掉 K8s / 云 / vCenter。
- 手绑 / 解绑是新的小接口，不进入自动匹配分支。不改扫描带凭据创建路径。

### 冲突

- 节点 ID 与 CMDB ID 各指不同监控实例：不合并。批量记冲突，详情提示后由人解绑 / 手绑处理。

## Testing Decisions

只测外部行为，不测内部函数拼装。优先复用现有推送与 ingest 单测风格（无凭据认领结果、`link_status`、占用拒绝）。

必测：

- 批量：未关联成功认领、已关联跳过、未找到 / 冲突计入对应桶且其它行不受影响；超上限拒绝；无编辑权拒绝。
- 手绑：按映射类型列出候选且主字段为实例名；写入后双方指针一致；占用中拒绝且占用方名称可见；跨类型拒绝。
- 解绑：双方指针清空，监控实例仍在，`node_id` 不变。
- Docker：自动认领不因同宿主机 IP 绑到引擎或误绑其它容器；唯一实例名可认领。
- 从映射移除的模型：无同步入口，类型身份不再认领。

## Out of Scope

- 监控侧手绑 / 解绑 / 批量同步。
- 无凭据创建监控资产或策略；扫描带凭据创建不在本变更改行为。
- 后台异步任务、中断续跑、大于约定上限的单次批量。
- 抢走已占用监控实例；允许一对多指针。
- K8s / K3s / 云平台 / vCenter / 配件 / 存储设备（待监控有对应对象后再开）。
- 修复监控侧脏身份本身；冲突向导自动合并。
- 节点关联的建立或拆除。

## Further Notes

- 与既有节点 / CMDB / 监控推送联动一期正交：本期补的是 CMDB 存量关联的可操作性，不取代自动认领。
- 前端现有同步模型名单窄于后端映射，实现时必须改成与本 spec 名单一致，避免详情有按钮、列表没有或类型对不上。
