# CMDB：JOB 采集发现支持选择主机

Status: implemented — 代码已实施；真实 Nginx 联调受目标 SSH 认证/连接失败阻塞，成功验收待完成（见 validation.md）

日期：2026-09-21

配套文档：[实施设计](plan.md)、[实施与验证记录](validation.md)。本需求以当前工作区代码为分析基线，包含工作区已有未提交改动；代码阅读不等于真实环境验证。

## 1. 背景与目标

用户在 Nginx 等 JOB 采集插件下创建任务时，目前可以选择 IP 或已有资产，但不能直接选择 CMDB 已登记的主机。首次发现时，Nginx 资产尚不存在，用户需要重新录入主机 IP，无法直接利用现有主机库存。

本次新增「选择主机」：选择 CMDB 主机，使用主机的 IP 执行当前插件的发现脚本，发现该主机上的对应资源。例如，在 Nginx 插件下选择主机，执行 Nginx 脚本，结果仍为 Nginx 资产，不切换成主机信息采集。

## 2. 已确认的业务语义与范围

### 2.1 发现与更新是不同目的

| 选择方式 | 用户目的 | 目标含义 | 结果语义 |
| --- | --- | --- | --- |
| 选择 IP | 发现资产 | 执行脚本的主机地址 | 发现目标上的资源，按既有规则新增或更新匹配资产 |
| 选择主机 | 发现资产 | CMDB 中登记的执行主机 | 从主机解析 IP，发现目标上的资源，按既有规则新增或更新匹配资产 |
| 选择资产，例如 Nginx | 更新已有资产 | 用户希望更新的具体资产 | 业务上应将结果匹配到所选资产，只更新对应资产 |

例如主机 A 上运行两个 Nginx：选择主机 A，应允许发现两个 Nginx；选择其中一个 Nginx 资产，业务目的只是更新该资产。

**现状差距：**当前「选择资产」仍取资产 IP 执行发现脚本，再按插件结果与任务归属对账，没有完整实现「仅更新所选资产」。本次保留其已有运行行为，将严格定向更新作为独立后续事项，不纳入本次交付，也不得在新文案中宣称该限制已经实现。

### 2.2 本次交付

- 增加主机发现入口及其新建、编辑、复制、详情回显。
- 复用现有 JOB 脚本、凭据、执行通道、结果上报和对账流程。
- 补齐新模式的可信主机校验、云区域传递和发现结果组织归属。
- 采用保存时的 IP 快照；不增加运行期自动跟随主机 IP 的机制。
- 修复与新模式切换直接相关的旧目标残留问题。

## 3. 已确认的适用插件范围

JOB 是执行方式，不足以单独证明目标就是普通主机。已确认采用以下范围：

| 插件类别 | 本次处理 |
| --- | --- |
| JOB 中间件、JOB 数据库 | 增加「选择主机」，包含 Nginx、Redis、MongoDB、Docker 等，以及企业扩展中同类 JOB 入口 |
| 物理服务器 SSH/JOB（`physcial_server`） | 增加「选择主机」，用于通过已有主机发现物理服务器信息；不扩展到 IPMI/Redfish |
| 主机采集（`host`） | 已有资产选择就是选主机，不新增重复选项 |
| 主机配置文件采集（`config_file`） | 已有主机选择与专用回传流程，保持现状 |
| PC、HMC、FC 设备等专用 JOB | 本次不统一接入普通主机选择；保留专用目标与连接语义 |
| Protocol、SNMP、云平台等非 JOB 入口 | 保持现状 |

企业版以合并后的有效插件目录为准。增加入口不代表补齐插件原本缺失的脚本能力；占位或未验证插件不能据此宣称完成真实发现。插件原有操作系统限制继续生效。

## 4. 用户操作与交互

### 4.1 新建任务

支持的插件保留「选择 IP」「选择资产」，增加「选择主机」。默认选择方式保持原样。

选择主机模式后：

1. 使用已有组织和接入点配置，不增加独立配置步骤。
2. 未选择接入点或无法确认接入点云区域时，主机选择按钮禁用，并说明原因。
3. 主机选择抽屉查询 CMDB 的 `host` 模型；只展示用户有权限、与接入点同云区域且处于本任务组织范围的主机。
4. 抽屉及已选列表展示主机名称、IP、云区域，支持分页选择、单项移除和批量移除。
5. 跨页选择保留此前勾选；当前页取消勾选仅移除对应主机，不覆盖其他页结果。
6. 至少选择一台主机才能保存。无合法管理 IP 的主机不能选择。

提示文案建议：「在所选主机上执行 {插件名称} 发现脚本，发现并采集对应资产。」

### 4.2 模式与条件切换

- IP、资产、主机三种来源互斥；切换来源时清空上一来源的目标，避免隐藏目标继续参与执行。
- 主机模式下更换接入点或任务组织，清空已选主机并提示重新选择，避免保留失效范围。
- 同一主机按 UUID 去重；不同主机记录具有相同管理 IP 时拒绝保存，不静默合并。
- 新主机模式每任务最多 2048 台，与当前 IP 范围页面上限保持一致；达到上限时明确提示，不静默截断。该数值为本次确认的上限。

### 4.3 编辑、复制与详情

- 新任务明确保存目标来源，编辑和复制必须回显「选择主机」，不能仅凭 `ip_range` 为空就回显为「选择资产」。
- 详情展示目标来源和已保存的主机名称、IP、云区域，用户能看出实际执行的地址。
- 复制沿用现有任务名称、凭据掩码和凭据引用规则；主机目标在保存时重新校验和解析。
- 保存时按 UUID 重新获取可信 IP；周期执行不重新读取主机资产。主机 IP 在 CMDB 中变化后，需重新保存任务才能刷新。
- 主机被删除或权限发生变化后，再次提交该主机目标时应拒绝并提示调整选择。已下发任务的运行期撤销机制不在本次新增范围。

## 5. 执行与结果规则

### 5.1 主机只提供执行目标

任务的插件模型、驱动和任务类别保持原值。例如：任务模型为 `nginx`，所选目标的资产模型为 `host`，最终结果模型仍为 `nginx`。

主机 UUID 不作为 Nginx 的资产 UUID，不得将 Nginx 数据覆盖到主机记录。一次脚本执行可返回零个、一个或多个实例；无对应软件时不构造虚假资产，继续沿用现有空结果展示与轮次处理，不新增状态枚举。

### 5.2 接入点、云区域与凭据

- 一个任务只使用一个接入点，所选主机必须属于该接入点云区域。
- 服务端从可信接入点记录确认区域，并贯穿节点查询；不只依赖前端筛选或客户端传入的区域。
- 匹配到可执行的目标 Agent 时沿用本地执行通道；否则沿用接入点远程登录通道及其凭据要求。
- 选择主机本身不代表已安装 Agent，不自动获取主机密码，不改变凭据优先级、超时和失败策略。

### 5.3 入库组织与资产归属

- 新主机模式发现的新资产，组织取任务配置的组织；选一台或多台主机应一致。
- 所选主机的名称、组织、UUID 不应被当成新发现资源的默认身份或归属。
- 已有资产继续遵守当前更新、组织保留和任务归属规则：不抢占其他采集任务管理的资产，不扩大自动接管范围。
- 同任务重复发现沿用既有身份与幂等规则，不因引入主机 UUID 创建重复资源。
- 清理策略、完整轮次守门、部分失败保护继续沿用现有机制。本次不新增删除规则，也不允许清理所选来源主机。

## 6. 明确不包含的内容

- 将「选择已有资产」改为严格按所选 UUID 定向更新。
- 主机 IP 变化后的自动刷新、动态主机组或动态条件发现。
- 同任务跨云区域执行、自动选择多个接入点。
- 自动建立「发现资源运行于所选主机」关联。
- 强制结果 `ip_addr` 等于连接 IP、统一多网卡资产身份。
- 改写各插件脚本、补齐企业占位采集器、扩展操作系统支持。
- 调整 Agent/SSH 路由优先级、安装 Agent、修改目标服务配置。
- 新增数据库表、公开 API、服务或启动依赖。

## 7. 验收标准

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| AC-01 | Nginx 插件没有任何 Nginx 资产，但 CMDB 有主机 | 可选择主机创建发现任务，无需预建 Nginx |
| AC-02 | 一台主机返回两个不同 Nginx 实例 | 两个结果进入现有发现流程；源主机不被写成 Nginx |
| AC-03 | 执行成功但没有发现对应软件 | 不新增虚假资产，沿用现有空结果处理 |
| AC-04 | 分页选择和取消选择 | 非当前页选择保留；重复 UUID 不产生重复行 |
| AC-05 | 无 IP、重复 IP、非主机、无权限、跨区域或超出数量上限 | 服务端拒绝，且不下发无效配置；不能绕过前端构造请求 |
| AC-06 | 存在相同 IP、不同云区域的节点 | 查询使用可信区域，不能命中另一区域节点 |
| AC-07 | 有 Agent／无 Agent 且提供正确凭据 | 分别沿现有本地／SSH 通道执行同一插件；失败仍可见 |
| AC-08 | 单选主机和多选主机 | 新发现资产均按任务组织入库；已有资产按原规则保留归属 |
| AC-09 | 编辑、复制、详情 | 来源与目标正确回显；复制不泄露凭据 |
| AC-10 | 主机模式切回 IP，或切到资产模式 | 下发仅包含当前来源的目标，旧目标不残留 |
| AC-11 | 主机 IP 变化 | 保存前执行快照 IP；重新保存后下发新 IP |
| AC-12 | 重复执行、部分失败、配置下发失败 | 幂等、清理保护和原有补偿行为不回退 |
| AC-13 | 老任务及不支持的新模式入口 | 原执行方式、凭据、结果模型及专用目标规则不变 |
| AC-14 | 企业 JOB 目录含原模型的 `target_model_id` | 主机模式可选择合法 host；旧资产模式仍保留原模型限制 |

## 8. 已知限制与后续事项

1. Nginx 当前脚本使用 `hostname -I` 的第一个地址生成结果 IP。多网卡环境下，连接 IP 与结果 IP 可能不同；本次只保证连接目标来自所选主机快照。
2. CMDB 有主机记录不代表节点在线或软件可采集；真实结果取决于路由、凭据、操作系统和脚本能力。
3. 当前已有资产更新仍按插件结果及任务归属对账，严格定向更新另立需求。后续需要定义多实例匹配、找不到目标、匹配歧义及资产身份变化的处理。
