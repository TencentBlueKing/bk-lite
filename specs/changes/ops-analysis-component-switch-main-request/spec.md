# 运营分析主请求图表开放组件内切换

Status: implemented

## Completion Evidence

## Problem Statement

看板搭建者只能在排行、表格和节点图上打开「组件内切换」。折线、柱状、饼图等同样走主请求的图，参数上即使写了这个标记，查看时也没有控件，请求也不使用卡片上的选择。

同一参数只要开了多选，或者选项查询入参里有引用，配置弹窗就会禁用「组件内切换」。搭建者无法在一张卡里按多个值切换，也无法让这个下拉的候选项跟着别的参数变。

大屏上，标准外观已经有标题，无边框没有标题。现在的切换控件却一律画在图内。仪表盘上的节点图会按卡片里的值请求，使用者却看不到控件。

## Solution

走主请求的图表都可以配置「组件内切换」。自己取数的场景组件和文本不提供这个配置。

查看时，有标题槽就把控件放进标题槽，并且不再在图内画第二份。仪表盘、报表和配置预览沿用已有标题槽。大屏选标准外观时，标题成为标题槽。大屏选无边框时，控件只在卡片内容区画一份。

同一张卡仍然只能有一个组件内切换参数。这个参数可以同时多选，选项查询也可以引用别的参数。卡内多选用一行紧凑下拉，请求带上选中的数组。卡片上正在选的值只供给本卡的选项查询，不写回已保存的参数值，也不进入全局筛选。当前选择为空或不在选项里时，整张卡停止请求并清空这次查看的图。选项还在加载时继续等待。

AI 落盘和已存 JSON 遇到不允许的标记时，去掉 `componentSwitch` 并给出警告，保留参数和其余画布。换到不支持的图表时，该覆盖项上的多选、最大数量和选择器样式一并去掉。

## User Stories

1. 作为看板搭建者，我希望在走主请求的图表上打开组件内切换，从而在这一张卡里更换字符串下拉的取值，而不必做成全页筛选。
2. 作为看板搭建者，我希望场景组件和文本上看不到组件内切换，从而不会配一个改变不了取数的控件。
3. 作为看板使用者，我希望在仪表盘、报表和配置预览里，切换控件出现在标题旁，从而不用在图内找。
4. 作为大屏使用者，我希望标准外观把控件放在标题里，无边框把控件放在图内，从而控件跟着容器外观走。已经能切换的排行、表格和节点图也按这一规则显示。
5. 作为看板搭建者，我希望一张卡只能保存一个组件内切换参数，从而查看时不会出现两个互相覆盖的控件。
6. 作为看板使用者，我希望多选参数在卡内是一行紧凑的多选下拉，请求带上选中的数组，从而一次切换多个值。
7. 作为看板使用者，我希望本卡别的选项查询能用上我正在切的值，同时已保存的参数值和全局筛选保持不动，从而候选项跟着变，配置不被改写。
8. 作为看板使用者，我希望当前一个值都没选中，或选中值已经不在选项里时，这张卡停住并清空，从而不会拿缺省口径去请求。选项还在加载时，我希望卡继续等待，而不是先清空。
9. 作为导入 AI 提案或旧画布的人，我希望不允许的组件内切换被去掉并看到警告，其余画布仍然打开，从而旧盘不会因为一个标记被整份拒绝。
10. 作为看板搭建者，我希望把图表换成不支持组件内切换的类型后，这项覆盖里的多选、最大数量和选择器样式一起去掉，从而不会留下一套已经失效的控件配置。

## Implementation Decisions

本规格取代两条约定。字符串参数多选规格里「多选与组件内切换互斥」不再适用于组件参数。选项查询级联里「查询入参有引用则关闭组件内切换」不再适用。统一筛选栏的多选、空值省略和草稿语义不变。

### 哪些图可以配置

- 允许范围是走主请求的图表。配置里开关是否出现、查看时请求是否改用卡片上的值、控件是否提供，都由同一份允许范围决定。
- 不允许的是自己取数的场景组件，以及没有数据请求的文本。场景组件包括机房 3D、应用 3D、应用拓扑、关联拓扑和网络状态拓扑。
- 统一筛选和数据变量的参数配置不出现组件内切换。数据源设置页不新增这个开关。

### 控件放在哪

- 有标题槽时，控件进入标题槽，图内不再画第二份。仪表盘、报表和配置预览已有标题槽，允许范围内的图都使用它，包括节点图。
- 大屏标准外观的标题成为标题槽。无边框没有标题，也就没有标题槽。
- 没有标题槽时，控件只在卡片内容区画一份，放在图表上方。由卡片外壳画这一份，不要求每种图各自留位置。
- 排行、表格和节点图在大屏上也改为这条规则。标准外观进标题，无边框只在内容区画一份。

### 每张卡一个

- 正式保存和预览都拒绝第二个组件内切换参数。
- AI 落盘和已存 JSON 打开时，保留文档顺序中的第一个候选，去掉其余参数上的 `componentSwitch`，并给出警告。不拒绝整张画布。

### 值和请求

- 三份值分开。已保存的参数值留在配置里。卡片上正在选的值只存在这次查看的内存中。选项列表是另一次查询的结果。
- 组件内切换可以和多选同时为真，也可以和选项查询引用同时存在。配置弹窗不再因为多选或引用禁用、剥掉这个开关。
- 未开多选时，下拉仍是单选，单选按钮仍是分段单选。
- 开了多选时，卡内控件是一行紧凑的多选下拉，放不下的项收成剩余数量。不用分段按钮。参数配置里的表格选择器仍只用于筛选栏和配置表。卡内即使配置了表格选择器，也用这个紧凑下拉。
- 开了多选时，主请求在门闩通过后带上选中的数组，沿用字符串多选的数组形状。不把卡内控件做成单选再包成单元素数组。
- 本卡的选项查询在解析引用时，若引用的是本卡这个组件内切换参数，使用正在选的值，不使用已保存的参数值。这个实时值不写回配置，不写入全局筛选的草稿或已应用值。全局筛选栏继续用自己的查找，不读卡片上的实时值。
- 本卡其他参数已保存的值不因选项变化而改写。查看时今天没有为这些参数另拉选项列表。本规格不新增那条加载，它们的主请求仍发已保存的值。
- 选项查询的环、超过 3 级、拼接引用，仍在保存时拒绝。运行时只解析当前一层。

### 空值和失效

- 选项还在加载时，主请求等待。保留这次查看里已有的选择，不先清空。
- 选项加载失败，上游为空，引用非法，或当前选择不是非空且全部落在选项内时，清空这次查看的选择，停止主请求，并清空这张卡已有的图。不落到选项第一项，不退回已保存的默认值再请求一次。
- 多选一个都没选，与上面的空选择同一处理。
- 清空只影响这次查看的内存值，不写回已保存的参数值。

### AI、已存 JSON 和换图

- AI 落盘和已存 JSON 打开时，图表不在允许范围内的，去掉 `componentSwitch`。多选和选项查询引用本身不再构成去掉的理由。警告与旧字符串列表迁移同一通道，不弹阻塞对话框，不拒绝整张画布。
- 搭建者把图表换成允许范围之外的类型时，该参数覆盖若带有组件内切换标记，则只保留控件类型和选项来源。多选、最大数量和选择器样式一并去掉。数据源定义上的标记不在这次换图里改写。之后若保存到仍不支持的图上，加载规则会去掉抄进来的 `componentSwitch`。

## Testing Decisions

好的测试断言使用者能观察到的结果：开关是否出现、控件在标题还是内容区、主请求是否发出以及 body 里的值、已保存配置有没有被写回、警告是否出现。不断言私有函数的调用次序。

覆盖这些行为。

- 允许范围内的图可以打开组件内切换。场景组件和文本不出现该开关，主请求也不改用卡片上的值。
- 多选和选项查询引用不再禁用该开关。一张卡第二个切换参数在保存和预览时被拒绝。
- 仪表盘、报表、配置预览，以及大屏标准外观，控件在标题槽且内容区没有第二份。大屏无边框只有内容区那一份。节点图在仪表盘标题槽里可见。
- 多选的实时值以数组进入主请求。空选择或失效选择不发主请求。选项加载中不发主请求。
- 本卡选项查询收到正在选的值。已保存的参数值和全局筛选值不变。全局筛选的选项查询收不到这张卡的实时值。
- AI 落盘和导入去掉不允许的 `componentSwitch`，保留多选加引用的合法组合，并产生警告。换到不支持的图表后，该覆盖项失去多选、最大数量和选择器样式。

先验是现有的组件内切换行为脚本、参数输入配置弹窗测试、提案落盘测试、大屏外观测试，以及字符串多选迁移测试。行为脚本里「失效值落到第一项」和「柱状图、机房 3D 一律不能切换」与本规格冲突。实现时改这些断言，使失效值为清空，允许范围按主请求图表计算，场景组件和文本仍为不允许。不把脚本当前的失败当成新的产品行为。

## Out of Scope

- 把场景组件改成走主请求，或把机房 3D 迁回组件内切换。
- 让全局筛选栏读取卡片上的实时值，或把实时值写回配置。
- 为同卡上其他参数新增查看态选项加载，或在请求时丢掉已失效的下游已保存值。
- 改变筛选栏的表格选择器、多选空值省略，或统一筛选上的组件内切换入口。
- 后端筛选快照理解 `componentSwitch`。值的形状仍由字符串和多选决定。

## Further Notes

产品决策里仍把机房 3D 写成组件内切换的消费方。那是迁到统一筛选之前的记录。本规格不恢复那条路径。

字符串多选规格和选项查询级联决策里被取代的两句，留在原文件。本规格落地时再改长期能力里相应的句子，避免两份合同同时指导实现。
