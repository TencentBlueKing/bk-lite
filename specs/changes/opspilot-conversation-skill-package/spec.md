# 对话生成技能包

Status: ready

## Problem Statement

管理员想给智能体加一项可复用的做法时，只能自己准备 ZIP 再导入技能包，然后到配置页勾选。对话里已经把步骤说清楚了，也变不成目录里的一条技能包。导入包还会把文件解到服务本机目录，容器重建后这些文件会丢。

## Solution

有「工具管理-新增」的平台用户，在智能体的 Web 对话、平台对话或配置页技能测试里明确要求做成技能包。服务端先给出四样齐全的成稿，再用现有选择卡请用户确认。点「确认写入」后，新增一条纯文本技能包，分组等于该智能体已经保存的管理分组，内容只在数据库里。刷新配置页后，可以在「添加技能包」里看到它，默认不勾选。勾上之后，它走现有技能包运行时。

## User Stories

1. As a 具备工具管理-新增的管理员, I want 在智能体的 Web 对话、平台对话或技能测试里说明要做成技能包，看过成稿后点「确认写入」, so that 管理分组的技能包目录里多出一条可勾选的技能包。
2. As a 管理员, I want 名称、何时使用的说明、触发词或正文缺了时先被追问, so that 写进目录的技能包勾上后能按步骤使用。
3. As a 管理员, I want 口头答应、点「放弃」或在输入框打字都不写入, so that 只有我点的那张确认卡会把对应成稿放进目录。
4. As a 管理员, I want 刷新智能体配置后在「添加技能包」里看到新包且默认不勾, so that 由我决定哪个智能体使用它。
5. As a 同一管理分组的管理员, I want 在其他智能体的添加列表和工具管理里看到这条包, so that 它和导入的技能包一样可复用。
6. As a 没有工具管理-新增的用户, I want 可以在对话里把内容谈清楚，但看不到确认卡, so that 我不能把技能包写进分组目录。
7. As a 管理员, I want 工作台机器人、嵌入页面、企微、钉钉、飞书、公众号和 API 里提同样的要求也不出确认卡, so that 这一版不会从这些入口写入。
8. As a 管理员, I want 这些管理分组里已有同名包时仍新增加一条，并在确认前看到说明, so that 导入包、内置包和以前生成的包都不会被改掉。
9. As a 管理员, I want 技能测试里还没保存的分组修改不影响新包, so that 新包挂在智能体已经保存的管理分组上。
10. As a 勾选了该技能包的使用者, I want 智能体按正文里的步骤、输入和完成标准做事, so that 工具不够时会说明做不到，而不是拿到一段无法执行的介绍。

## Implementation Decisions

- 产物是现有技能包。纯文本，字段为名称、说明、至少一条触发词、正文。正文写步骤、需要用户提供什么、怎样算做完，写成该管理分组里谁勾上都能照着做的做法。不填写依赖工具，不声明必填变量，不给任何智能体新装工具。
- 不写代码目录，也不写技能包本机解压目录。存储路径为空。重新部署后，数据库里的正文仍是运行时读到的正文。
- 目录中的启用状态为启用，这样现有「添加技能包」列表能列出它。不写入任何智能体的已选技能包。来源记为对话生成，工具管理的详情里显示「对话生成」，不显示成导入或内置。版本固定为 `0.1.0`。包标识每次新生成，不从名称推导。创建人是点确认的平台用户，域与技能包导入相同。
- 分组等于该智能体已保存的全部管理分组。技能测试请求里携带的未保存分组忽略。还没有已保存管理分组时，不出确认卡，并说明先在配置页保存分组。
- 只有用户明确要做成技能包时才进入这个流程。普通问答不出卡，服务端也不主动提议。
- 允许出卡的入口只有三处：智能体 Web 对话、智能体平台对话、配置页技能测试。工作台机器人、嵌入页面、企微、企微机器人、钉钉、飞书、公众号和 API 调用该能力时，说明这一版不能写入，不出卡，不落库。
- 出卡和落库都要求与技能包导入相同的「工具管理-新增」。没有该权限的平台用户，以及外部渠道身份，可以把内容谈清楚，但服务端不出确认卡，也不落库。点确认时再查一次权限；此时已经没有权限，则不写入。
- 成稿由服务端校验。四样缺任意一项，返回缺什么，不出卡。四样齐全后，服务端把这一版成稿的快照存进现有终止式选择的待答标记，并在对话里展示全文。选择卡只有「确认写入」和「放弃」。这些管理分组、同一域里已有同名技能包时，确认前的说明写明确认后会再增加一条。
- 现有选择卡点选后，下一轮收到的是选项文案，和用户自己打出同样的字无法区分。本能力的确认必须另带这张卡的选择标识。只有该标识对应「确认写入」才落库，写入的是标记里的快照，不是模型在下一轮重新组织的文字。输入框里的「好」「可以」「确认」或甚至「确认写入」都不落库。点「放弃」或其他回复使这张卡失效，不落库。用户要改内容时，旧快照作废，重新校验并出新卡。
- 待答标记沿用现有终止式选择的生命周期。过期后再点，不落库，并说明需要重新做成技能包。同一张卡只写入一次。
- 每次确认都新建一条。不覆盖同名包、导入包、内置包或以前对话生成的包。
- 写入成功后的回复给出名称，并说明刷新智能体配置、在「添加技能包」里勾选。勾选之后走现有技能包目录与按需读取正文的运行时。正文不绑定生成时那个智能体的工具；执行时只用当前智能体已经挂上的工具，不够则沿用现有运行时说明做不到。
- 工具管理对这条包仍只能改分组和标签，不能改正文。写错了再生成一条，再删除旧的。
- 模型不能绕过上述校验直接插入技能包。成功、拒绝和失败使用稳定日志模板；不记录正文、选择项全文或凭据。

## Testing Decisions

- 测外部行为，不调用真实模型。最高缝是：准备一份成稿、发出确认卡、用带选择标识的确认完成下一轮，然后检查技能包目录和智能体已选技能包。
- 确认写入后：新增一条启用的对话生成技能包；名称、说明、触发词、正文与快照一致；存储路径为空；依赖工具和必填变量为空；版本为 `0.1.0`；分组等于智能体已保存的全部管理分组；已选技能包不变。再按现有运行时装载时，读到的是库里的正文。
- 拒绝写入：缺任意成稿字段、没有工具管理-新增、入口是嵌入或外部渠道或工作台或 API、智能体没有已保存管理分组、点放弃、输入框打出确认文案、标记过期、同一张卡第二次确认。这些情况都不新增行，已有导入包和内置包不变。
- 技能测试请求里带另一套未保存分组时，新包仍使用数据库里的管理分组。
- 同名包已存在时，确认前的说明包含会再增加一条；确认后是新的包标识，旧行不变。
- 没有权限或入口不允许时，对话可以返回成稿内容，但没有确认卡。
- 先前测试：终止式选择卡（出卡后本轮结束、待答标记被消费）、技能包导入与目录列表（启用包可被添加列表取到、权限与分组）、技能包运行时装载（存储路径为空时使用库内正文）。选择卡点选若要带上选择标识，沿用现有选择卡点选测试补这条行为。
- 日志只断言模板和独立参数，正文与凭据用哨兵值证明未出现。

## Out of Scope

- 工作台机器人、嵌入页面、企微、企微机器人、钉钉、飞书、公众号和 API 中生成技能包。
- 生成后自动勾选到当前智能体。
- 脚本、参考资料、二进制文件，以及把这些文件放到对象存储。
- 覆盖或在工具管理里修改已有技能包正文。
- 声明依赖工具、必填变量，或在生成时给智能体挂上新工具。
- 生成前试跑。
- 用户没有明确要求时，由模型主动提议做成技能包。
- 只属于单个智能体、目录里看不到的私有技能。

## Further Notes

- Grill 共识（2026-10-29）：产物是技能包并只落数据库；纯文本但勾上后必须能走现有运行时；不默认勾选；分组用智能体已保存的管理分组，技能测试里的未保存分组不算；在智能体自己的 Web 对话、平台对话和技能测试中制作；权限与导入相同；先出成稿，现有选择卡点「确认写入」才落库；每次新建；只有用户明确要求才出卡；正文是分组内可复用的步骤。
- 现有选择卡已经改为发出即结束本轮。点选和手输都会变成下一轮用户消息，因此确认必须额外携带选择标识，不能靠文案判断。
