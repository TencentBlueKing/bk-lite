# 运营分析图表按角色选列

Status: implemented

## Problem Statement

运营分析里，不少图表在渲染时写死了列名。搭建者写数据源或查询时，必须把结果改成 `name`、`value`、`time`、`title` 这些规定名字，图才画得出来。日志搜索这类动态列尤其别扭：想画柱状图，得先 `rename` 成 `name` / `value`。

已经能选列的图表也不统一。排行榜、单值、仪表盘、通信关系图、卡片列表各自取字段的方式不同：有的只读字段定义，有的必须点刷新才取数，有的顺带吃左侧预览的结果。问号说明也有的有、有的没有。打开配置时如果自动打取数接口，查询参数常常还没填完，容易报错。

## Solution

每种图保留自己的角色，搭建者从查询结果里选哪一列充当那个角色。数据源按自己的列名返回即可。

折线、柱状、饼图补上维度和数值。多值补上标签和数值。雷达的数组形态补上名称和数值。事件时间线改为选择时间、标题，以及可选的说明、分类、状态、链接。排行榜、单值、仪表盘、通信关系图、卡片列表继续用现在的角色，但名单、刷新和问号收成同一套。

字段名单来自数据源字段定义，再加上一次已经成功的取数里看到的列。打开配置、改查询、改参数都不自动取数。点刷新，或左侧预览已经成功，才更新名单。

## User Stories

1. 作为看板搭建者，我希望日志搜索 `stats by (src_ip) count() as value` 在柱状图里刷新后能选 `src_ip` 和 `value`，从而不必把 `src_ip` 改名为 `name`。
2. 作为看板搭建者，我希望 Prometheus 和已经输出 `name` / `value` 的内置源，折线、柱状、饼图打开就能用，从而不用重配字段。
3. 作为看板搭建者，我希望打开配置、查询还没填完时不会自动取数，从而避免参数不完整就报错。
4. 作为看板搭建者，我希望有字段定义时打开就能选列，没有字段定义时下拉先空并提示点刷新，从而知道列从哪来。
5. 作为看板搭建者，我希望左侧预览已经成功时，字段名单和那次结果一致，点刷新才按当前参数再取一次，从而不会为了填下拉多打一枪。
6. 作为看板搭建者，我希望改查询或参数时已选的列先留着，只有刷新或预览再次成功才换成新名单，从而选择不会在编辑过程中自己消失。
7. 作为看板搭建者，我希望字段定义里标成字符串的计数字段仍能选成数值角色，从而不被类型挡住。
8. 作为看板使用者，我希望数值角色碰到不是完整数字的值时图上是空的而不是 0，文字列则照原文显示，从而脏数据不会被画成真实的零。
9. 作为看板搭建者，我希望多值、雷达数组、事件时间线的必填角色不选就不能保存，折线、柱状、饼图在数据没有列名时仍能只改标题就保存，从而旧图不会因为没有列名而保存失败。
10. 作为看板搭建者，我希望这些图的字段标签旁都有问号，悬停能看到该角色在图上的作用。
11. 作为拓扑搭建者，我希望给节点配单值时，字段选择和仪表盘单值用同一套规则，从而两处不会一个能选、一个必须先刷新。

## Implementation Decisions

- 目标是按角色映射列，不是全产品只提供「维度 / 数值」两个下拉，也不是一张所有图共用的字段大表单。每种图只出现自己的角色。
- 字段名单规则对纳入范围的角色选择器相同：字段定义（有则先展示，标题优先）并上当前样本里探测到的列名。刷新用当前参数再取一次数，只重探列名，不改数据源上的字段定义。不按 string、number、datetime、boolean 过滤。数值角色选到非数字时，配置阶段不拦截。
- 打开配置不取数。无字段定义且还没有样本时，下拉为空，提示点刷新获取字段。已保存的选择仍然显示，不因为名单暂时为空而清掉；此时只改标题再保存，已保存的列不丢。
- 左侧预览已成功时，字段名单复用该样本，不为填下拉再请求一次。一组角色共用一个刷新按钮，放在这组右上角。每个下拉是「标签 + 问号 + 下拉」。点一次刷新，这组下拉一起更新。预览面板已经打开时，同一次结果也更新左边的图；预览没打开时不打开它。
- 改查询或参数时，不立刻清空名单，也不清掉已选列，名单仍是上一次刷新或预览看到的。下次刷新或预览成功后，名单换成这次的结果。新结果里没有、且字段定义里也没有的已选列，再从选择里去掉。不刷新就保存时，仍保存旧列名；新查询里没有这列，运行时按该角色的空值规则处理。
- 问号说明该角色在图上的作用。维度是类目或 X 轴。数值是 Y 轴或排行值。单值和仪表盘是主展示值。其余角色说明自己的槽位，例如通信关系的源、目标、端口、流量，卡片列表的标题和说明，事件时间线的时间、标题等。
- 折线、柱状、饼图新增维度、数值两个角色。下拉不预先显示 `name` / `value`，只有用户自己选过的列才出现在框里。两个都空着保存时，不写入配置，运行时继续用现在的认形状办法，看的是画图已经拿到的数据，不是打开配置时再取的数。折线和柱状优先 `name` + `count`，否则 `name` + `value`，否则成对数组，还认按序列分成好几组的对象。饼图仍是先 `name` + `value`，再成对数组，最后 `name` + `count`。只填了其中一个不能保存。两个都保存之后，只按所选列从对象行取值；行可以是顶层数组，也可以包在 `data` 或 `items` 里。不再回退到成对数组或多条线。
- 成对数组只有折线、柱状、饼图会画。多条线只有折线和柱状会画。因此这三种可以不选列就保存。饼图没有多条线，但因为有成对数组，同样允许不选列保存。
- 多值新增标签列和数值列，二者必填，不选不能保存。下拉还是空时，也要先刷新再选，不能空着保存。未显式保存过映射时，运行时仍认 `label`，没有 `label` 则认 `name`，再加上 `value`。多值的数值可以是文字，原文显示，不套「不是数字就空着」。
- 雷达数组形态新增名称列和数值列，二者必填。只在数据是对象数组时使用。一行里已是多个指标的对象形态，继续用现在的指标列表，不改成这套下拉，也不强迫再填名称和数值。未显式保存数组映射时，数组仍认 `name` / `value`。雷达不画成对数组；多条线形态维持现在的不支持。
- 事件时间线的时间和标题必填，说明、分类、状态、链接可选。未显式保存映射时，仍读现在的这些列名。可选角色不选则该位置为空，时间和标题照常画。单条缺少时间或标题则跳过该条。状态值仍只认 `info`、`warning`、`error`、`success`、`neutral`，其他当成未知。时间不是标准日期时，原文显示。排序配置保持不变。
- 数值角色不是完整数字时按空值处理，不当成 0，配置里不提示。完整数字指有限数字，或整段都是数字的文本（`12` 可以，`1abc`、布尔、空字符串不可以）。折线该点断开，柱状该格不画柱，饼图该块不出现，排行榜保留名字但条长按没有数值，单值和仪表盘显示空。
- 单值和仪表盘仍用树选，可选到嵌套路径。有字段定义时打开即可选，不必先刷新。刷新或预览成功后，样本里的嵌套路径仍按现在的树补上。字段定义继续用于显示名称。拓扑节点上的单值配置走同一套，不单独分叉。
- 排行榜、通信关系图、卡片列表纳入同一套名单、一个刷新和问号。它们已有的必填和可选不变：排行榜的展示和数值必填；通信关系的源、目标、数值必填，服务粒度下目标端口必填；卡片列表标题必填，其余槽位可选。这覆盖卡片列表原先「只读字段定义、不从样本补列」的约定，只改名单来源，不改槽位模型。
- 已挂在看板上、没有人再保存的旧组件，继续按各自现在的认列方式画。数值无法绘制时，看板上不加新的说明文案。

## Testing Decisions

只测外部行为：名单如何组成、什么时候取数、配置保存了什么、给定数据和角色后图上用哪一列。不测下拉组件的内部实现，不靠打开配置时打真实取数接口。

最高接缝是配置提交和图表数据变换，外加字段选择区已经有的交互测试。优先复用这些现成接缝：

- 字段名单：字段定义与样本列合并、标题优先、不按类型过滤、预览样本可复用。
- 配置提交：折线、柱状、饼图两个都空不写入；只填一个不能提交；两个都填才写入。多值、雷达数组、事件时间线的必填角色缺失时不能提交；事件时间线可选角色可缺省；已有排行榜、通信关系、卡片列表、单值的提交契约保持。
- 运行时取值：未映射时折线、柱状、饼图仍认现有形状（含成对数组和折线、柱状的多条线）；映射后只读所选列。多值未映射时仍认 `label` 或 `name` 加 `value`，映射后读所选列，非数字文本仍显示。雷达数组与对象形态分流。事件时间线按所选列读，缺时间或标题的行跳过，未知状态仍为未知。
- 数值空值：不完整数字不画成 0；折线断开、柱状缺柱、饼图缺块、排行榜保留名字。
- 选择器交互：打开配置不取数；无名单时提示刷新；一组只有一个刷新；刷新成功后名单更新，且预览已打开时同一结果更新预览；改查询不清已选列；新样本不含该列时再去掉选择。单值有字段定义时不刷新也能选。问号存在于纳入范围的角色标签上。

## Out of Scope

- 打开配置时自动取数探测字段。
- 所有图表共用的通用字段编辑器。
- 折线多条线的「序列名、横轴、纵轴」映射。用户未显式保存维度和数值时，多条线继续用现在的画法。
- 雷达对象形态的指标列表改造。
- 关系拓扑的 `nodes` / `edges` 契约。
- 场景组件：3D 机房、3D 应用、网络拓扑、关联拓扑。
- 表格和事件表格的列编辑。「重新探测列」仍会重写默认列，不是本需求的下拉刷新。不改表格打开配置时现有的探测行为。
- 配置图表列表里没有的状态时间线和条形仪表。
- 按字段类型灰显或隐藏选项。
- 数值无法解析时的额外提示，包括配置区说明和看板上的新文案。
- 改数据源上的字段定义。

## Further Notes

事件时间线原先要求上游输出固定的 `time` / `title` 等列名。本需求改为可选列，未保存映射的旧组件仍读那些列名。

卡片列表 MVP 曾规定字段选择器只列字段定义、不从预览样本补列。本需求只放宽名单来源，槽位、布局和校验不变。
