# Job 目标使用系统凭据

## 目标与数据

Job 目标保留手填认证，另可绑定系统管理的主机凭据。绑定单位是 Target。执行页、作业模板和定时任务都继续引用目标。节点管理来源的目标使用已有 Agent 通道。

| 目标字段 | 系统凭据模式 |
|---|---|
| credential_source、credential_id | 保存 credential 和仓库稳定 ID |
| IP、云区域、驱动、端口 | 保存在目标 |
| WinRM scheme、transport、证书验证 | 保存在目标 |
| 登录材料 | Linux 从内置 SSH 凭据取用户名与密码或私钥及口令，Windows 从内置 WinRM 凭据取用户名与密码 |

目标绑定要求凭据可见、类型匹配且已启用。切入仓库模式时清空原手填登录字段，事务提交后删除已无引用的旧密钥文件。切回手填必须提供新凭据。列表按页查询可见元数据，停用和失效绑定可在编辑时另选。仓库计数以 job_count_credential_refs 返回直接绑定的目标数，沿用已有的删除、归属变更及超时策略。

## 执行边界

- 已保存目标的原配置可由有目标查看权的用户测试。新增草稿按新增权限测试，修改草稿还校验目标编辑权限。测连只向当前待测配置发起连接，成功与失败都只返回连接状态及受控说明。
- 交互作业保存服务端确定的 username、domain、current_team。重跑按本次操作者重新授权。Worker 使用当前用户授权与目标归属重新检查访问，凭据所有者须为当前团队或活动祖先。登录材料只在执行器调用期间使用。
- Beat 发现仓库目标时，即使存量定时任务治理开关关闭，也会在创建执行记录前锁定和校验任务的单一团队及引用资源。立即执行复用既有的锁内校验。执行快照的团队边界标记随任务记录删除而保留。运行时在同进程按任务团队解析凭据，无需创建人在线，也没有对外开放按团队取密的接口。
- 可信网关以服务端注入的人员和唯一组织建立执行身份。仅自报团队的旧 NATS 请求无法向仓库目标派发。
- 每次派发重新读取绑定。凭据轮换在后续调用生效，停用、失效或越权返回失败。Ansible 无法在同一提交内处理的跨区域或混合驱动仓库目标批次会在派发前明确报错。凭据解析失败有对应目标结果。
- Linux SSH 直连与文件分发传递私钥口令。NATS 执行器在 SCP 分发前解锁带口令的密钥，Job 依据执行器返回的成功标志记录分发结果。Ansible 在独立的任务工作目录里解锁加密密钥，文件从创建起限制为 0600，任务结束清理。脚本和 Playbook 保持原有执行与发布权限。

## 升级与回退

先应用 Job 迁移 0022，再更新 HTTP、NATS、Job Worker 和 Beat。旧记录的凭据身份字段允许为空。使用带口令的 SSH 私钥时，应升级对应区域的 Ansible 执行器以及负责 SCP 分发的 NATS 执行器。上线前保留手填配置；回退旧应用前应先处理已改用仓库的目标并排空在途执行，旧 Worker 不能消费仓库绑定。切回手填需由操作者重新提供登录材料。

## 验证入口

- Job 后端的 test_target_vault_scope_service、test_vault_runner_service、test_target_views 覆盖双团队、轮换停用、测连、派发、重跑、无人值守身份与结果。系统管理 test_credential_ref_count 覆盖引用展示与拦截。
- Web 目标表单集成测试位于 target/__tests__/credentials.test.tsx，校验提交字段、绑定回显、类型切换和手填兼容。
- Ansible 执行器使用真实加密密钥验证解锁、非交互读取和临时文件清理。

## 测试环境验收

2026-11-20 在测试机应用 Job 迁移 0022。通过 Chrome 编辑已有手填目标，先绑定 SSH 凭据，再切换到 Windows 并绑定 WinRM 凭据。两次保存后，列表和重新打开的表单都回显对应名称。系统管理显示「作业 1」，目标接口返回绑定 ID，手填密码和密钥标志均为假。

在隔离 Linux 主机上，使用系统 SSH 凭据测连和执行脚本成功。轮换凭据后，Job 文件分发返回成功，由 Beat 自动触发的一次性任务使用新账号读回文件，目标容器内独立核对内容一致。停用凭据后测连失败，仍有目标引用时删除被拦截。Ansible 执行器使用带口令的私钥通过 SSH 登录，口令错误的任务按预期失败。

在仅允许私钥登录的目标上，Job 通过同一条系统凭据执行 Playbook 和 SCP 文件分发，两项作业均成功，分别核对了 Playbook 写入和 SCP 分发的文件内容。Windows 已覆盖浏览器绑定和后端 WinRM 调用参数；测试环境当时没有可用于真实 Windows 登录的系统凭据。

启用真实迁移的 PostgreSQL 回归有 1241 项通过。两项失败在变更前的相同数据库环境中也可复现，分别是 0013 版本 Worker 向当前表写入时缺少团队边界字段，以及跨组织脚本接口测试期望英文错误文案。Ansible 执行器的 206 项回归和 NATS 执行器的 SSH 测试包通过。
