# 云成本报表完整查询契约

Status: implemented

## Problem Statement

运营分析的云资源成本汇总、费用分布和账单明细需要使用当前用户可见的完整账单与流水集。旧实现固定只读取账单和流水第一页，单页最多 100000 条，却忽略底层返回的真实总数并继续在 Server 内存中聚合。因此第 100001 条起会被静默遗漏，同时单请求的 Python 内存与前 100000 条记录线性增长。

## Solution

在 CMDB 内建立权限感知的 `CloudCostQueryPlan`，由 FalkorDB 与 Neo4j adapter 执行同一份只读报表语义：

- 账单维度筛选、账单实例权限、流水实例权限和计费日期在图查询中一次生效；
- 账单与流水按实际图关系连接，重复关系先去重，避免重复计费；
- 汇总在图内完成费用合计、资源去重计数和日期边界；
- 分布在图内完成分组费用与资源去重计数，Server 仅计算百分比和响应格式；
- 明细在同一次查询快照中完成逐账单聚合、全局稳定排序、精确总数和页切片，排序值相同时使用账单 `inst_uuid` 升序作为稳定键；
- 单次查询固定 30 秒超时，明细每页最多 1000 条；
- Server 不再接收或保存全量账单/流水列表，响应结构保持不变。

## Compatibility

- 保持三个 NATS subject、运营分析数据源名称、筛选参数和响应字段不变；
- `summary.total_cost`、`distribution.total_cost`、`instance_list.total_cost_incurred` 继续按两位小数输出；
- 模糊筛选继续采用大小写不敏感的子串语义；
- 无身份或任一模型权限缺失时继续 fail-closed 返回空数据；
- 未登记的排序字段仍回退到费用倒序，非 `desc` 排序值按既有行为回退为升序；
- 无数据库迁移、环境变量或部署脚本变更。

## Query Budget

- 最大响应行数：明细 1000；汇总 1；分布为实际分组数；
- 关系深度：仅账单与流水直接关联的一跳；
- 查询超时：30 秒，不重试；
- 排序：用户选择字段 + 账单 `inst_uuid`；
- 分页：页码兼容接口，页内结果和精确总数来自同一查询快照；
- Server 内存：汇总 O(1)，分布 O(G)，明细 O(page_size)，不再是 O(min(N, 100000))。

## Testing Decisions

- 单元测试锁定参数化筛选、双模型权限、重复关联去重、字段白名单、稳定排序、单查询总数与切片、超时及跨驱动结果格式；
- Service 回归覆盖空数据、环比、模糊筛选、三种分组、三种排序、分页、零费用和三组件口径一致；
- 100001 条真实 FalkorDB 运行验证汇总与明细不截断，并记录 Server Python 峰值内存；
- FalkorDB 与 Neo4j 分别使用真实临时图库验证相同输入得到相同三类报表响应。

## Out of Scope

- 修改云成本动态模型字段或历史数据；
- 为计费数据新增关系或自动修复缺失关联；
- 修改运营分析画布、组件和数据源配置；
- 增加跨请求结果缓存或物化报表。
