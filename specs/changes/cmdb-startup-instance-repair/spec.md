# CMDB 启动期实例清洗移出启动门禁

Status: implemented

完成证据：sqlite 下相关测试 82 项通过（`test_instance_shape_queries`、`test_instance_shape_repair`、`test_model_init_unique_rule_service`、`test_display_field_backfill_runtime`、`test_uuid_migration_runtime`、`test_migrate_oa_cmdb_instance_uuid_refs`、`test_migrate_cmdb_instance_uuid_refs`，以及模型初始化编排和僵尸主机白名单邻近用例）。启动不再同步扫实例；组织、标量和唯一规则未完成时只投递一次，完成后不再投递。

## Problem Statement

线上每次启动都会跑 `batch_init` 里的 CMDB 初始化。实例一多，启动会把全部实例的完整属性拉进进程：修组织字段、按模型校验唯一规则、把列表字段上的标量包成列表。1 万到 20 万实例，这段等待跟着实例数上涨，端口在清洗结束前开不了。

显示字段回填和 UUID 清洗虽然不挡在 `batch_init` 里面，但每次重启都会在后台把实例再扫一遍。

## Solution

启动过程只做跟模型数量成正比的初始化。实例组织、标量改列表、有变化的唯一规则校验，改到服务起来之后的一次性任务里按页做完。做完把阶段记在数据库里。下次启动发现阶段已完成，就不再投递，也不再扫实例。

不新增每 5 分钟的周期任务。这次投递失败或 Worker 中途停下，下次启动从游标继续。

## User Stories

1. As a 运维人员, I want 实例已经是列表、唯一规则也没变时，重启不再扫实例, so that 10 万到 20 万实例不会把服务启动堵住
2. As a 运维人员, I want 第一次遇到脏数据时，启动先完成，清洗在服务起来后按页做完, so that 健康检查不用等全表清洗
3. As a 运维人员, I want 清洗做到一半进程停了，下次启动从上次的位置继续, so that 不用从头再扫
4. As a CMDB 管理员, I want 种子里的唯一规则和现有规则字段一致时保持原来的规则编号, so that 每次启动不会改写规则并清掉字段缓存
5. As a CMDB 管理员, I want 种子规则和存量实例冲突时保留原规则, so that 启动和后续任务都不会把冲突规则写进去
6. As a 运维人员, I want 显示字段和 UUID 在做完之后不再每次重启全量扫图, so that 后台不会在每次发布后再占一轮长时间

## Implementation Decisions

- 启动期同步保留：种子模型导入、模型上的组织字段修补、字段分组、`_display` 字段定义、字段约束、OID、端口指纹、进程指纹、采集任务团队、节点同步的本地对账。这些不读实例全文。
- 启动期去掉实例组织全表修复，以及 `cmdb_migrate_scalar_to_list` 的同步执行。
- 新增表记录修复阶段：阶段名、游标、是否完成、指纹、结果。完成标记放数据库，不用会过期的缓存。
- 阶段顺序固定为组织修复、标量改列表、唯一规则。前一个阶段完成之前，后一个阶段不查询实例。
- 启动时如果组织、标量或任一唯一规则阶段未完成，只投递一次任务，不注册 crontab。任务持有缓存锁，每页 500，单轮最多 2000 条；没做完就 1 秒后预约自己的下一页。Broker 不可达或任务失败只告警，不让启动失败。下次启动看到未完成再投递一次，从游标继续。
- 阶段完成后，启动不再投递。不抽查。新实例沿用现有保存逻辑。要重做时，人工清掉对应阶段的完成标记。
- 组织修复只处理缺失、空值、空列表和整数，写成默认组织的单元素列表。非空列表不动。非空字符串留给标量阶段。图查询只取节点 id 和组织字段。FalkorDB 用 `typeof`，Neo4j 5 用 `IS ::`。
- 标量阶段在组织阶段完成之后，按模型找出 organization、user、enum 以及类型名带 list 或 array 的字段。值不是空且不是列表时，包成单元素列表。人工执行原来的标量命令时，清掉标量阶段的完成标记并投递同一次性任务，命令自己不扫表。
- 唯一规则在启动期一次取回种子模型，比较有序字段组，不比较规则编号。字段组相同则不查实例、不写、不失效缓存。字段组不同则只把该模型标成未完成并记下指纹。种子不合法仍让模型初始化失败。
- 运行期对一个未完成模型读完规则字段后再决定。无冲突才写入，能对上的字段组保留原规则编号，然后失效该模型字段缓存。有冲突则保留原规则，记下冲突挂起和同一指纹，后续启动在指纹不变时不再扫这个模型。指纹变了才重新进入未完成。
- 一个模型的唯一规则必须看完才能判断冲突，所以这一阶段不受 2000 条预算切开；一轮只处理一个模型。组织和标量仍受 2000 条预算限制。
- 界面导入模型仍同步校验实例，冲突直接报错。字段组相同则不写。写入时同样保留能对上的规则编号。
- 字段分组一次读出相关模型的分组。排序和属性顺序都相同则不保存。未分组字段回写模型的行为保持不变。
- 只补模型 `_display` 定义时，不加载用户表和组织表。
- 显示字段回填的完成状态和游标改存修复阶段表。启动不再强制重扫，也不删除完成标记。定义没有新增时，任务直接返回。某个模型真的写下了新的 `_display` 字段，才把该阶段改回未完成。不带「只处理模型」的人工命令扫完后，把同一阶段标成完成。原有的每 5 分钟任务保留，完成后直接返回，用来接下中途失败，不负责每次重启重扫。
- UUID 图实例和图关联边分开记完成。两边都完成后，清洗命令直接返回，不再分页读实例，也不再把全部关联边装进内存。节点已完成、边未完成时，只做一次边收尾。映射只按本页收集到的数字 id 点查，不再为了已完成的阶段预加载全图。
- 运营分析各阶段都完成后，不再预加载全图 UUID。
- 已经会在完成后直接返回的 PostgreSQL 阶段保持原样。采集结果快照在阶段完成后，只处理更新时间晚于该阶段更新时间的采集任务。
- 自动关联每次重写、OID、两种指纹、采集任务团队、字段约束、节点同步对账，本次不改。

## Testing Decisions

测试只锁对外行为：启动命令叫了哪些子命令、修复阶段表的完成和指纹、分组有没有被保存、图客户端有没有被要求全表读取。

- 模型初始化不再调用实例组织全表修复。规则字段相同不写图。规则字段不同只记未完成阶段，不读取实例。冲突挂起后指纹不变不再取实例；指纹变化会重新进入未完成。
- 组织修复覆盖整数、缺失、空列表和非空列表。组织阶段未完成时，标量阶段不查询。
- 字段分组内容相同时没有保存。
- 只补模型显示字段时不预加载用户和组织。第二次回填在已完成时不扫实例。新增显示字段定义会清掉完成标记。
- UUID 两个图阶段都完成后，不调用全量实例查询和全量边查询。采集快照只处理更新时间更晚的行。
- 邻近用例：`test_display_field_backfill_runtime`、`test_uuid_migration_runtime`、`test_model_init_unique_rule_service`、`test_migrate_display_slice`、`test_migrate_cmdb_instance_uuid_refs`。

## Out of Scope

- 不新增每 5 分钟执行的实例形态修复任务。
- 完成后不做全表抽查。
- 不改自动关联规则的每次重写，不改 OID、指纹、采集任务团队、字段约束和节点同步对账。
- 不把界面导入模型的冲突校验改成异步。
- 不把显示字段回填和 UUID 清洗的既有周期任务删掉。

## Further Notes

实例清洗的总工作量在第一次脏数据上仍然存在，只是离开启动门禁，并且只做完这一次。模型数量从 300 增到 1000，启动仍要读模型定义，时间随模型数而不是实例数变化。
