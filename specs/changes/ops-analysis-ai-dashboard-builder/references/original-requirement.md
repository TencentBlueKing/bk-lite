# AI 对话搭建运营分析仪表盘方案

## 1. 目标

用户在新仪表盘中向 OpsPilot 描述需求。OpsPilot 完成数据源选择、图表和参数配置。方案校验通过后，同一轮把配置套到当前编辑画布并刷新效果。缺必填参数或字段时先问用户，补全并再次校验通过后再套上画布。

AI 应用后的配置进入前端编辑态。用户通过页面原有的“保存”写入数据库，通过“取消”恢复原始配置。

## 2. 首期范围

首期支持运营分析现有的 14 类数据源型组件：

- 趋势与分布：折线图、柱状图、饼图、雷达图、仪表盘
- 指标与排行：单值指标、多值指标、TopN
- 列表与事件：表格、事件表格、事件时间线、卡片列表
- 关系展示：节点关系图、数据源关系拓扑

首期范围不包含网络状态拓扑和 CMDB 关联拓扑等场景组件，这些组件保留原有人工配置方式。

配置能力包括：

- 数据源、图表类型和字段映射
- 固定参数、普通参数和统一筛选参数
- 组件参数和统一筛选器的输入框、组织、静态选项和独立动态选项
- 单选、多选和表格选择器
- 单位、换算系数、精度、阈值和值映射
- 表格列、组件内筛选和操作跳转
- 图表专属配置、自动布局和后续调整

动态选项数据源独立加载，首期不处理选项之间的级联依赖。

## 3. 核心流程

```text
用户描述仪表盘需求
    ↓
page_context 携带当前仪表盘编辑状态
    ↓
拆分数据需求
    ↓
检索数据源并选择候选项
    ↓
生成初步 DashboardProposal
    ↓
补全参数、按需预览并校验方案
    ↓
校验通过后同一轮发送 dashboard_config_apply 事件
    ↓
运营分析页面整体应用配置并渲染
```

### 3.1 读取页面状态

每次发送消息时，WebChat 通过现有 `page_context` 链路自动采集当前页面状态，并随本轮消息发送给 OpsPilot。

仪表盘页面使用现有 `useAiPageContext` 注册状态提供器，直接读取 React 编辑状态。配置快照包含：

- 仪表盘标识、名称及编辑状态
- `layout` 及组件配置
- 筛选器定义和当前筛选值
- `otherConfig` 和刷新周期

页面现有的图表截图、可见指标和表格内容继续作为数据分析上下文。配置快照只保留搭盘所需字段，以 `dashboard-edit-state` 高优先级区段发送。后续调整基于最新页面状态生成下一版完整配置。

### 3.2 拆分数据需求

OpsPilot 将用户需求拆分为独立的数据目标。例如“展示资产总数、类型分布和资产明细”拆分为三项需求，每项包含业务描述、期望数据形态和推荐图表类型。

### 3.3 检索数据源

`searchDataSources(requirements)` 在工具内部读取当前用户有权限的数据源 brief 目录，根据以下信息匹配和排序：

- 名称、描述和标签
- 参数名称及说明
- 返回字段名称、类型及说明
- 数据源声明支持的 `chart_type`

检索包含两类用途：

- `visualization`：为指标、图表和表格选择主数据源
- `parameter_options`：为字符串或选择型参数选择选项数据源

数据源能力目录向 AI 提供参数名称、别名、类型、筛选类型、默认值等基础定义。当字符串或选择型参数需要动态选项时，OpsPilot 根据参数名称、别名、说明和业务语义发起 `parameter_options` 检索。选项数据源可以没有图表类型，但必须声明可用作参数值和显示文本的返回字段。

检索采用关键词、业务同义词和权重评分。每项数据需求返回 3～5 个候选，合并去重后的候选总量控制在约 20 个以内。工具将候选摘要返回给 OpsPilot。

### 3.4 生成和准备方案

OpsPilot 根据候选数据源生成初步 JSON `DashboardProposal`。随后调用 `prepareDashboardProposal`，由运营分析完成参数补全和确定性校验。

数据源参数按以下规则处理：

- `fixed`：使用数据源声明的固定值
- `params`：写入组件参数
- `filter`：生成或绑定页面统一筛选器

必填选项的取值顺序为：

1. 用户明确指定的值
2. 当前页面已有值
3. 数据源声明的默认值
4. 第一个可用选项

动态选项由 OpsPilot 选择选项数据源，并将 `sourceId` 或 `sourceRef`、`valueField`、`labelField` 写入组件参数或统一筛选器的 `inputConfig.optionsSource`。该配置属于页面和组件的二次配置，不写入数据源定义。

`prepareDashboardProposal` 解析方案中明确的绑定，校验选项数据源及字段，加载选项并补全默认值。完整选项列表留在工具内部。选项为空、与用户语义冲突或用户明确要求自行选择时，工具返回待确认项，由 OpsPilot 继续询问。

`prepareDashboardProposal` 校验：

- 组件类型与首期范围
- 数据源存在性和当前用户权限
- 数据源 `chart_type` 与图表类型
- 必填参数和动态选项值
- 声明字段与图表数据契约
- 字段引用、表格列和图表专属配置
- 布局和组件标识

校验通过后返回补全后的最终方案。OpsPilot 保留该 JSON，并在同一轮把它套到编辑画布。缺必填参数时不套用，先把待确认项问完。

### 3.5 数据预览

当数据源返回字段声明不足或字段映射无法确定时，`prepareDashboardProposal` 内部调用数据预览，确认：

- 数据源实际返回结构
- 图表所需字段映射
- 必填参数取值后的查询结果
- 数据形态与图表数据契约的兼容性

首期可不实现自动数据预览，但纳入 AI 搭盘的数据源必须具备完整、准确的参数、返回字段和 `chart_type` 声明。声明不足的数据源暂不进入推荐结果。后续增加预览时，只处理最终选中的数据源，多个预览并行执行。

## 4. 对话说明

方案校验通过并套上画布后，用普通 Markdown 说明已经应用的内容。消息包含：

1. 仪表盘概览
2. 组件标题、图表类型、数据源、字段和核心配置
3. 统一筛选器、参数默认值和选项选择结果
4. 页面布局
5. 已经套到当前编辑画布；页面「保存」才写入数据库，「取消」恢复进入编辑前的配置

示例：

> 计划生成“CMDB 资产概览”，包含 3 个组件和 1 个统一筛选器：
>
> 1. **资产总数**
>    - 图表：单值指标
>    - 数据源：CMDB 资产统计
>    - 展示字段：资产数量
>    - 格式：单位“个”，0 位小数
>    - 参数：绑定页面组织筛选
>
> 2. **资产类型分布**
>    - 图表：饼图
>    - 数据源：CMDB 资产类型统计
>    - 分类字段：资产类型
>    - 数值字段：资产数量
>    - 参数：绑定页面组织筛选
>
> 3. **资产明细**
>    - 图表：表格
>    - 数据源：CMDB 资产列表
>    - 展示列：资产名称、资产类型、IP、所属业务、运行状态
>    - 组件内筛选：资产名称关键词
>    - 参数：绑定页面组织筛选
>    - 分页：每页 20 条
>
> **统一筛选**
> - 新增“组织”筛选器，同时作用于上述 3 个组件。
> - 选项来源于“CMDB 组织列表”数据源，以组织 ID 作为参数值、组织名称作为显示文本。
> - 未指定组织时，先展示第一个可用组织的数据，页面上可随时切换。
>
> **布局**
> - 顶部一行放置资产总数和资产类型分布，资产明细表格占据下方整行。
>
> 已套到当前编辑中的仪表盘。页面上保存后才会写入数据库；要改图表、字段或布局，直接说即可。

语句处理：

- 校验通过：同一轮应用到编辑画布
- 缺必填参数或字段：先询问，补全并再次校验通过后再应用
- “取消”“不要了”：不应用，保持页面原状
- 用户接着要求修改：按新要求更新方案，校验通过后再次应用

## 5. 前端应用

方案校验通过后，OpsPilot 在同一轮通过 AG-UI 发送：

```json
{
  "type": "dashboard_config_apply",
  "payload": {
    "dashboardId": "current",
    "proposal": {}
  }
}
```

应用链路：

1. `GlobalWebchat` 将 `onCustomEvent` 传给 WebChat。
2. WebChat 将 AG-UI 自定义事件转发给页面命令注册器。
3. 仪表盘页面注册 `dashboard_config_apply` 处理器。
4. 处理器校验目标仪表盘和 Schema 版本。
5. 加载方案使用的数据源资源。
6. 一次性更新 `layout`、`filters` 和 `otherConfig`。
7. React 根据新状态创建组件并发起数据查询。

结构应用按整体事务处理：应用前失败时保持原页面状态；应用成功后，单个组件的取数错误由该组件展示。

页面沿用原有“保存/取消”操作和编辑态逻辑。

## 6. 能力声明与工具

### 6.1 组件能力目录

运营分析维护版本化的组件能力定义，内容包括：

- AI 可用的组件类型
- 各组件支持的页面类型
- 必填配置、可选配置和默认值
- 数据形态和字段类型要求
- 组件专属约束

首期使用一份版本化 JSON 能力文档，作为 OpsPilot 的固定上下文。动态能力查询及从前端组件注册表自动生成能力文档首期可不实现；组件能力发生变化时随版本发布。

### 6.2 OpsPilot 工具界面

- `searchDataSources`：由 OpsPilot 实现搜索和排序，数据源 brief 目录由运营分析提供
- `prepareDashboardProposal`：OpsPilot 提供工具适配器；运营分析负责查询组件参数和统一筛选器已绑定的选项数据源、补全默认值、按需预览数据并校验完整方案

页面状态由 `page_context` 自动携带，不属于 OpsPilot 工具调用。数据预览是 `prepareDashboardProposal` 的内部能力。

### 6.3 前端配置入口

仪表盘页面提供统一的 `applyDashboardProposal` 方法，内部复用现有的组件新增、筛选器同步、数据源资源同步和布局处理逻辑。

## 7. 职责划分

### 运营分析

- 通过 `page_context` 提供当前仪表盘编辑状态
- 维护组件能力定义和 JSON Schema
- 提供当前用户有权限的数据源 brief 目录
- 提供数据源的基础参数和返回字段定义
- 执行组件参数和统一筛选器配置的动态选项查询
- 补全参数并执行权限、数据契约和完整方案校验
- 接收并应用 `dashboard_config_apply` 事件
- 创建布局、组件和筛选器，触发数据加载和页面渲染

### OpsPilot

- 识别新建和调整仪表盘的意图
- 读取页面上下文并拆分数据需求
- 检索并选择主数据源、图表和参数配置
- 必要时为参数检索选项数据源并生成动态选项绑定
- 处理缺参、字段不明等必须先问用户的信息
- 生成 JSON 方案和自然语言说明
- 校验通过后同一轮发送应用事件

## 8. 性能控制

- 数据源目录在工具内部匹配，向 OpsPilot 返回候选摘要
- brief 目录按用户和组织短时缓存
- 参数、动态选项和校验集中处理已选数据源
- 多个数据源的选项解析并行执行
- 后续调整复用当前方案、页面状态和已有数据源解析结果

## 9. 技术选型

首期沿用现有 WebChat 和 AG-UI 事件链路。CopilotKit 可用作事件和状态同步的实现参考；OpenUI 和 A2UI 适用的动态交互界面场景不在本方案范围内。
