# OpsPilot 对话将知识沉淀为资料

Status: ready

## Problem Statement

用户在智能体里做完查询分析或排障后，只能把结论留在对话里，不能顺着这次对话变成知识库里的资料，经验飞轮断掉。知识库里已有的结论过时或写错时，同样不能在对话里发起一次修正。

若让对话直接改知识页，会绕开资料构建、来源归并和现有审核。智能体目前只是绑定知识库用于回答，没有「是否允许把对话写进知识库」的配置；一旦允许写，还要能追到是哪个人、对哪个库、写下了哪一篇资料。

## Solution

智能体增加一个默认关闭的开关。打开后，用户在当轮对话里明确要求记下或修正时，系统把模型整理出的知识说明存成该库的一条新文本资料，并自动进入该库现有的资料构建队列。知识页仍只由构建生成或合并；事实冲突和人工编辑过的页继续走现有审核。

能跟这个智能体对话的人都可以写，不再另要知识库编辑权限。外部渠道必须先把发送者对上未禁用的系统用户，否则拒绝。每次成功写入留下可追到个人的操作日志。

## User Stories

1. As a 智能体管理员, I want 在智能体上选择是否允许通过对话修改知识库，且默认关闭, so that 现有智能体不会因为这项能力上线就开始写入。
2. As a 对话用户, I want 在分析或排障后明确说「把这次结论记进知识库」, so that 系统新建一条资料并开始构建，而不是只把结论留在对话里。
3. As a 对话用户, I want 明确指出某条知识错了或过时了并给出新结论, so that 系统再投一条资料，由现有构建去补充或送审，而不是直接改掉旧页。
4. As a 对话用户, I want 智能体只绑了一个知识库时不用再点名, so that 一次明确要求就能写入；绑了多个时，我点名其中一个才写。
5. As a 外部渠道用户, I want 我的钉钉或飞书身份能对上系统用户时可以写下资料, so that 日志上的修改人是这个系统用户；对不上时得到「当前无权限」。
6. As a 审计人员, I want 看到知识库、修改人、资料名称、资料 ID 和正文前 50 个字, so that 我能找到那篇资料并追到个人。
7. As a 对话用户, I want 写入成功时只被告知正在写入、稍候可在知识库看到新知识, so that 我不需要理解构建队列或审核。
8. As a 对话用户, I want 入队失败时被告知写入失败, so that 库里不会留下一条我以为已经在构建的资料。

## Implementation Decisions

会话没有指定测试缝。写入的最高现有缝是对话运行时调用的「对话资料写入」服务：调用方给出智能体、已判定的「用户明确要求」、可选的知识库名称、整理后的标题与正文、以及已解析的系统用户。服务对外只表现为资料是否留下、是否入队、操作日志，以及返回给用户的那句话。不把真实模型的措辞当作测试对象。

### 开关

- 智能体增加布尔字段 `allow_wiki_material_write`，语义为「允许通过对话修改知识库」，默认 `false`。存量智能体迁移后仍为关闭。
- 关闭时不提供写入动作。用户明确要求记下或修正时，回复说明该智能体不能修改知识库，不创建资料，不记成功日志。
- 打开但未绑定任何知识库时，回复说明没有可写入的知识库，不创建资料，不记成功日志。
- 配置仍放在智能体的知识库绑定旁边。绑定列表继续只决定可读写的库范围，绑定本身不表示允许写入。

### 何时写、写什么

- 只有用户在当轮明确要求记下或修正时才调用写入服务。分析结束、排障结束或模型认为「有价值」都不是写入条件。一次明确要求对应一条资料。
- 写入服务在调用方未标明「用户明确要求」，或标题、正文为空时，不创建资料。
- 资料类型为文本。名称是这段知识说明的短标题，正文是模型根据当前对话整理出的知识本身（结论，或「旧结论错了、应改为……」），不是「帮我记下来」这句指令。
- 不修改已有资料，不直接创建或更新知识页。现有「把回答直接存成知识页」的路径不扩展、不作为本能力的实现。

### 写入哪个库

- 只能写入该智能体已绑定的知识库。
- 只绑定一个时写入该库，用户不必点名。
- 绑定多个时，用户必须在这句要求里点名其中一个。名称在去掉首尾空白后与已绑定知识库名称精确匹配；对不上、没说清，或命中多个同名库时，不写入，并请用户指定。不做模糊匹配，不由模型挑选。
- 不能写入未绑定的库。

### 谁可以写

- 本路径不检查 `wiki_list-Edit`，也不检查说话人是否属于知识库团队。知识库管理界面上的新建资料权限不变。
- 平台已登录用户，以及由 API Secret 代表的系统用户，修改人就是该用户。用户已禁用时拒绝。
- 钉钉、飞书等外部渠道只使用这条入站消息上的发送者标识：飞书用发送者 `open_id`，不用退回来的 `message_id`；钉钉用 `senderStaffId`，没有则用 `senderId`。该标识去掉首尾空白后，与未禁用系统用户的 `username` 或 `user_id` 精确相等才算比对成功。
- 标识为空、比对不到、命中不止一个未禁用用户时，都视为无权限。不按邮箱、手机号或显示名猜测，不为渠道账号新增绑定字段。
- 无权限时回复「当前无权限」，不创建资料，不记成功日志。共享访客组织不是个人，同样拒绝。

### 入队与失败

- 资料创建与进入该知识库现有串行构建队列是同一次写入。入队使用的操作者是匹配到的系统用户。
- 入队成功后，回复「正在写入，稍候可以在知识库看到新知识」。不解释队列、审核或旧页是否已被覆盖。
- 入队失败时删除刚创建的资料，不记成功日志，回复写入失败、请稍后再试。不说稍候可以在知识库看到新知识。
- 入队已经成功后，操作日志如果写失败，只记一条警告。资料留在队列里（即使执行器已经把它改成构建中），回复仍是正在写入。不得再删除这份资料。
- 非对话资料的构建规则不变。对话写入在资料上留下只有这条路径能设置的标记；资料创建和批量上传即使把相对路径写成以 `chat/` 开头，或在请求里带上该标记，也写不进去。带标记的资料在进入同一套构建后，只放宽「是不是同一主题」的候选：通用标题不再单独算作具体主题；共享不少于 4 个字的前缀、且两侧多出来的后缀都不超过 4 个字时，仍进入冲突比较；同一入站页的多个同主题比较优先已经有人工编辑的页。审核结论如何落地不变。这样「告警规则配置」和「告警规则说明」不会在普通上传资料里被当成同一主题。来源路径仍只用于构建要求的来源身份。

### 操作日志

- 仅在资料留下且入队成功后记一条创建日志。应用为 opspilot，动作类型为 create，目标类型为资料，目标 ID 为资料 ID。
- 修改人是系统用户的 `username` 与 `domain`。日志至少能查出：知识库 ID 与名称、资料名称、资料 ID、正文前 50 个字（不足 50 字则全文）。
- 追溯以这条操作日志为准。资料上的创建人复用现有维护者字段，不另建渠道身份列。

## Testing Decisions

- 好测试只断言对外行为：开关状态、是否留下资料、资料名称与正文、是否进入构建队列、操作日志字段、返回给用户的话。不断言私有函数调用次数，不驱动真实模型。
- 写入服务：未标明明确要求、标题或正文为空、开关关闭、未绑定知识库、多个库未点名或名称对不上时，资料数为 0 且没有成功日志。只绑一个库时不点名也会留下文本资料并入队。多个库在点名精确匹配后只写入该库。prior art：资料构建队列测试。
- 入队失败：资料不留下，没有成功日志，回复是写入失败而不是「稍候可以在知识库看到新知识」。成功回复就是正在写入、稍候可以在知识库看到新知识。入队成功后操作日志失败时，回复仍是正在写入，资料保持在队列里；状态若已离开待构建，回复同样不是失败，资料不被删除。
- 身份：已禁用用户拒绝；飞书 `message_id`、空发送者、共享访客拒绝并回复「当前无权限」；发送者标识与唯一未禁用用户的 `username` 或 `user_id` 相等时，日志上的修改人是该用户。命中多人时拒绝。prior art：智能体渠道会话测试。
- 日志：成功写入后能按资料 ID 找到记录，并含知识库、修改人、资料名称和不超过 50 字的正文节选。拒绝与入队失败不产生成功日志。prior art：各应用对操作日志字段的断言。
- 回归：本路径不产生由回答直接保存的知识页。构建对冲突和人工编辑页仍进入待审。对话写入留下的资料带有标记；资料创建和批量上传写成 `chat/` 开头的相对路径，或请求里带上该标记，落库后仍不带标记，冲突比较保持上传资料的规则。prior art：对话保存回答测试、资料构建测试。
- 开关：创建智能体时缺省为关闭；更新为打开后再次读取仍为打开。界面在知识库绑定旁提供该开关，用现有智能体设置的组件测试锁住，不引入浏览器端到端。
- 验证沿用仓库约定：server 用 sqlite 跑受影响的 opspilot 测试并 `--no-cov`；改了智能体设置界面时再跑 web 的 lint 与 type-check。

## Out of Scope

- 直接创建、修改或覆盖知识页，以及扩展「把回答直接存成知识页」。
- 改变非对话资料的冲突判定、资料构建和人工审核规则。对话资料只放宽同主题候选，不改变审核如何落地。不用来源路径前缀区分对话资料和上传资料。
- 用户未明确要求时由模型自动入库。
- 写入前再让用户确认一遍整理后的正文。
- 在成功回复里说明队列、审核或旧页尚未改变。
- 按邮箱、手机号、显示名匹配外部用户，或新增渠道账号绑定。
- 通过本路径编辑、删除已有资料。
- 改变知识库管理界面的 `wiki_list-Edit` 与团队范围。
- 个人记忆体的写入。

## Further Notes

- 本变更由一次 grill 会话收敛。成功回复故意不区分「资料已入队」和「知识页已经更新」；冲突或人工编辑页仍可能停在待审，这是已接受的说法，不是实现漏了提示。
- 对话资料写入不授予知识库编辑权限，只绕过本路径上的那两项检查。管理界面的权限边界保持原样。
