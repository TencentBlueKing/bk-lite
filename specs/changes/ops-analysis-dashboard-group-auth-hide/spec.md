# 仪表盘无权分组在查看时隐藏

Status: superseded

本文件里「组织 `hasAuth === false` / 场景 `permission_denied` 决定整组省略」的口径已被模块许可取代。现行判据以 `required_app` 与 `hasAppAccess` 为准，见下文「现行口径」。旧的组织无权与实例 ACL 只保留给组件空态，不再进入 `omitFullyUnauthorizedDashboardGroups`。

## 现行口径

- 数据源可空字段 `required_app` 与 `get_client` 的 app 名对齐。内置 NATS 源在种子 / `init_builtin` 写入：优先 `apps/*/nats` 注册函数所在模块，否则受限前缀（`alert` → `alarm`）。外部源与推不出的源保持空。
- 查看态图表：`required_app` 非空且当前身份没有该 App → 不可见。场景 `relatedTopology` / `applicationTopology` / `networkStatusTopology`：无 `cmdb` 许可则不可见。
- 组内每个组件都因此不可见时，查看态去掉整组并上移。编辑态不裁。不写回存盘布局。
- 普通查看与分享页用 `ClientProvider` 的 `clientData`（`get_client`，含 license 过滤）。
- 订阅渲染 `/ops-analysis/render/execution/<id>` 不挂 `ClientProvider`。`render-input` 返回 `authorized_app_names`，按执行创建者的角色与 license 计算，喂给同一套 omit。列表缺失则渲染失败，不静默全显示或全藏。创建者记录不存在时列表为 `[]`（没有任何模块许可）。
- 复制内置盘后的自定义画布仍引用同一批内置源，不按「是否内置画布」开关。
- 查看态（含分享、订阅）在 `resourcesReady` 且首屏结论已冻结之后，若存盘里原本有组件且每一个组件都因模块不可见（含未分组），画布展示模块许可空态并隐藏盘级筛选条。文案方向是「当前账号缺少相关模块许可，暂无可展示内容」，可附联系管理员，不以「去编辑」为主按钮。只要还有至少一个模块可见组件，就按 §5.2 藏组展示，未分组的模块不可见组件留在原坐标。加载中、lookup 未成功、编辑态、存盘本身没有组件，都不走空态。一期不从布局摘掉未分组组件。整盘空态不挂载这些组件，订阅完成信号直接按空列表发出。

## Problem Statement

仪表盘分组里的图表或场景组件，查看者的组织都无权访问时，分组标题和这些组件仍然占着整行，里面只显示无权限。下面的分组和组件被顶在后面，查看者要先滑过一整段自己看不了的内容。

## Solution

查看仪表盘时，若一个分组里至少有一个组件，且每个组件都无权，则整组不画，下面的分组和未分组组件整行上移。没有开关。编辑态始终画出全部分组。查看态上移不写回保存的布局。分享页、全屏、页面内导出 PDF，以及报告订阅渲染仪表盘时，用同一种无权判断，画面与对应身份打开画布时一致。

## User Stories

1. 作为仪表盘查看者，我希望自己一个组件都无权的分组整组消失、下面的内容上移，从而不必滑过只写着无权限的整段。
2. 作为仪表盘查看者，我希望组里还有任何一个我能看的组件时分组留着，无权图表仍显示无权限，从而不会把还能用的内容一起藏掉。
3. 作为画布编辑者，我希望编辑时始终看到全部分组，保存的坐标仍是编辑布局，从而不会因为自己缺权限而改坏别人的画布。
4. 作为分享链接的查看者，我希望看到的分组和分享者在链接所属组织里能看的范围一致，从而不会比分享者多看到无权分组，也不会把数据源缺失误当成无权限。
5. 作为报告订阅的收件人，我希望渲染出的仪表盘藏掉同一批无权分组，从而邮件里的画面和打开画布一致。

## Implementation Decisions

- 只作用于仪表盘分组。分组新建时占满一行且不能改宽度。查看态从完整 `layout` 派生：去掉「整组全无权」的分组后，再交给现有 GridStack 布局构建（`buildDashboardGridStackLayout` / 等价路径）；保存与编辑提交仍使用完整 `layout`，禁止把省略后的布局 `setLayout` 写回状态后再保存。未分组的无权组件继续占位并显示无权限。空分组留下。组里只要有一个不算无权的组件，整组留下，组内不另做压缩。先去掉无权整组，再应用用户折叠（localStorage）；不要把「省略」写进折叠键。
- 没有新的分组配置，也不改已保存的布局文档。查看态只决定本次渲染省略哪些分组。编辑态不省略。从编辑态保存的仍是编辑布局。
- 数据源与场景的无权结论在首屏网格构建前冻结；仪表盘加载已有的「等数据源同步再画」把场景轻量检查放进同一次等待。本会话内不因晚到的权限结果改结构。组织切换会离开当前页或整页刷新，下次进入重新判断。**编辑态 ↔ 查看态切换时，必须按查看态规则重算省略**（组织/权限结论可复用已冻结值，但省略集合随模式变化）。
- **「存在但无权」通道（普通查看 / 分享 / 订阅必须对称）**：仅靠前端 `checkDataSourceAuth` 不够——现状普通 list 会按组织滤掉他组织源，前端只能当成 missing，按规则 missing ≠ 无权，组隐藏对主路径几乎不生效。因此：
  - 普通查看、分享、订阅渲染加载画布引用的数据源时，凡库里仍在、但当前身份所属组织无权访问的引用，必须返回标识 + `hasAuth: false`（不带名称、参数、字段、命名空间和连接信息）；组织内可访问项显式 `hasAuth: true`；已删除的标识不出现在列表中。
  - 前端相信该字段：分享页与订阅渲染**停止**把列表整表写成 `hasAuth: true`（去掉 `sharedAccess` / `trustBackendAuthorization` 强制 true 的路径，或改为仅在后端未给 `hasAuth` 时的遗留兜底并尽快删除）。订阅渲染须能拿到执行组织（如注入 `execution_team_id` / `selectedGroupId`）或完全信任后端显式 `hasAuth`，并更新既有「整表 true」测试契约。
- 整组省略的「无权」只看模块许可（见文首现行口径）。组织 `hasAuth === false` 与场景实例 `permission_denied` 不进入 omit。轻量检查仍可给组件空态，超时或失败时组件按看得到处理，但不因此藏组。
- 绑定了数据源的图表：`required_app` 为空则不因模块许可不可见。未绑定数据源、数据源已删除，都不算模块无权。查询 403 不参与组隐藏。
- 网络状态拓扑、关联拓扑、应用拓扑在缺少 `cmdb` 许可时整组件不可见。三维机房与三维应用墙仍只在大屏，大屏没有分组，不在本变更里藏组。
- 分享与普通查看使用同一省略判断；分享身份是分享者在链接所属组织中的权限，不是被分享者的当前组织。关联拓扑和应用拓扑的轻量检查以分享者身份、在链接组织下执行。
- 报告订阅渲染仪表盘时，用 `render-input.authorized_app_names`（执行创建者的模块许可）做同一套省略，不调用 `get_client`。页面内导出 PDF 和全屏直接使用当前查看态已经省略后的画面。

## Testing Decisions

测外部结果，不测 GridStack 如何摆放节点。最高接缝是一个纯函数：输入分组归属、每个组件的无权结论、以及当前是编辑还是查看，输出本次渲染要留下的顶层块；保存用的布局坐标保持原样。仪表盘查看、分享和订阅渲染都消费这一个判断。既有邻近以 `buildDashboardSections` / 分组成员测试为参考，**不要**假设存在「折叠后纵向压缩」首屏单测。

- 纯判断要覆盖：组内图表全部因 `required_app` 不可见则整组消失且下方块上移；有一个看得到的组件则整组还在；空分组还在；未分组无权组件还在；编辑态一块不省略；`hasAuth === false` 且 `required_app` 为空不算无权；无 `cmdb` 许可时关联/应用/网络状态拓扑算无权；有 `cmdb` 时场景 `permission_denied` 不算整组无权；编辑↔查看切换后省略集合正确变化。订阅渲染无 ClientProvider 时不抛错，并按执行身份的授权 App 列表省略。资源已就绪且冻结后，存盘每个组件都因模块不可见（含全未分组）时判定整盘空态；资源未就绪、未冻结、编辑态、存盘无组件、仍有任一模块可见组件时不判定。全未分组且部分可见时，无权未分组组件仍留在展示布局。
- 数据源列表（普通查看若改了 API、分享、订阅）：组织之外但记录仍在的引用返回 `hasAuth: false` 且没有名称和连接字段；组织之内返回 `hasAuth: true`；已删除的标识不出现。前端不再整表强制 true。
- 场景轻量检查：关联拓扑、应用拓扑及其分享委托；检查结果与正式查询的 `permission_denied` 一致，响应里没有拓扑正文；分享会话使用分享者与链接组织；`not_found` 与查询失败不是无权。
- 订阅渲染：断言执行身份的组织进入上述同一个判断，且渲染态能出现 `hasAuth: false`，不另测像素。

## Out of Scope

- 给查看者或编辑者一个开关。
- 隐藏未分组组件，或在仍可见的分组内部藏掉单个无权图表并压缩空位。
- 用数据源查询的 403、网络状态拓扑的局部过滤、三维应用墙里某一条告警曲线无权来隐藏分组。
- 为大屏、报表建立分组，或隐藏大屏上的三维机房和三维应用墙。
- 把查看态上移后的坐标写回布局。

## Further Notes

三维机房若将来能放入仪表盘分组，沿用「整组件 `permission_denied` 才算无权」；三维应用墙放入时仍算看得到。那不是本变更的实现范围。
