## Problem Statement

大屏搭建者在编辑态里拖组件、改样式、改数据或恢复一版快照之后，退不回刚才那一步。现在只能点取消，整次编辑回到进入时的正式画布。拓扑编辑有撤销和恢复，大屏没有。

## Solution

编辑态提供撤销和恢复。它们只作用于这一次编辑里、点「保存」会写成正式大屏的那份内容：组件、画布尺寸与背景、装饰、统一筛选字段。一次手势记一步，最多 50 步。历史是一条线，撤销后再做新动作，被撤掉的步骤不能再恢复。快照仍是现在的「存一版 / 恢复」；存一版不动撤销，恢复整份换成那一版，并且这一下可以撤销回去。

## User Stories

1. 作为大屏搭建者，我希望把刚才的添加、移动、缩放、删除、改样式或应用数据撤回去再恢复，从而试错不必取消整次编辑。
2. 作为大屏搭建者，我希望同一次拖拽、缩放或连续输入只占一步，从而撤销对得上我做的那一下，而不是每个像素或每个字符。
3. 作为大屏搭建者，我希望编辑工具栏最前面有撤销和恢复，暂时不能用时灰掉，并用 `Ctrl+Z` 撤销、`Ctrl+Y` 恢复，从而不用在菜单里找。
4. 作为正在改样式或位置的搭建者，我希望第一次撤销退回开始输入前的值，从而受控输入框里也能整段退回。
5. 作为正在筛选条或弹窗里输入的搭建者，我希望快捷键不动大屏历史，从而不会误撤画布。
6. 作为数据配置还没应用的搭建者，我希望撤销前先确认丢掉未应用的修改，从而应用时不会把旧表单盖回已经撤过的画布。
7. 作为大屏搭建者，我希望撤销或恢复后选中这一步涉及的那个组件；不针对单个组件的步骤保持当前选中，从而看得到刚回来的内容。
8. 作为大屏搭建者，我希望撤销后再改一笔时，原先能恢复的步骤消失，从而历史不会分叉。
9. 作为大屏搭建者，我希望「存一版」不影响撤销，「恢复」可以再撤回到恢复前，从而快照和刚才那几步各管各的。
10. 作为查看者或分享页使用者，我希望看不到撤销和恢复，快捷键也不生效，从而只读大屏不会被改。

## Implementation Decisions

- 只做运营分析大屏编辑态。仪表盘、拓扑、架构图、报表、网络拓扑不跟。不修改拓扑现有的撤销实现。
- 撤销文档等于点保存和存一版时那份内存工作拷贝：组件、画布尺寸与背景、装饰、统一筛选字段。选中、检查器页签、未应用的数据表单、预览用的筛选值、刷新、全屏和分享不进文档。
- 进入编辑时历史为空。保存正式大屏、取消编辑、切换大屏时清空。刷新后历史消失；未保存的编辑仍按现网从正式大屏重新开始，快照仍须手动恢复。
- 历史线性，最多 50 步，超出丢最早的一步。撤销后的新手势截断恢复分支，包括把尚未结束的连续输入再改掉。
- 一步等于一次完成的手势。添加、复制、删除、图层、应用数据配置、确认筛选字段、画布设置、居中、换预设、组件内网络状态拓扑的节点拖完、折点松开、切换布局、重置布局，各记一步。同一次缩放结束时成对出现的尺寸和位置合成一步。同一字段上的连续文本、数字或取色替换当前未关闭的一步，直到失焦或开始另一个手势。
- 样式和几何字段写入草稿时，未关闭的一步留在栈顶并随输入更新。编辑态快捷键撤的是这份历史：第一次撤销回到聚焦前的值并关闭该步，再按恢复则回到刚输入的内容。焦点在弹窗或筛选条时，快捷键不碰历史。工具栏按钮与快捷键使用同一套确认和选中规则。
- 数据配置有未应用修改时，撤销和恢复走现有的未保存确认。确认后丢掉未应用表单再应用历史；取消则文档和历史都不动。
- 应用一步之后的选中：该步只涉及一个组件且组件仍在，则选中它。本来就选中它时，检查器页签保持不动，表单显示恢复后的内容。选中因此换成另一个组件时，回到样式页。画布设置和筛选字段这类不针对单个组件的步骤保持当前选中。组件被这一步去掉时，清空选中并关掉数据面板。
- 「存一版」不改画布，也不入撤销历史。「恢复」先走未应用数据确认，确认后整份替换内存工作拷贝，并记成一步。恢复后当前选中的组件还在则保持选中，已经不在则清空选中并关掉数据面板。不新增检查点，不改变现有快照条数上限。
- 撤销回到与正式大屏一致的内容时，是否有未保存修改仍按现有比较，不另做脏标记。
- 按钮只在编辑工具栏出现，放在画布设置、全屏预览、刷新、筛选这排图标的最前面：先撤销，再恢复。不能撤或不能恢复时禁用。悬停提示写出对应快捷键。查看态和分享态不渲染按钮，快捷键不响应。内置大屏沿用现网，不能进入编辑。
- 用大屏文档的前后内容记录历史。不复用拓扑那套图元操作日志，也不把它的折点记录、合并写入或撤销防抖搬过来。

## Testing Decisions

好测试只断言搭建者看得到的结果：做完手势后文档是什么、撤销和恢复后文档与选中变成什么、按钮能不能点。不锁历史数组、定时器或内部合并标记。

接缝用大屏编辑会话对文档的转移，这是现有布局、图层和复制纯函数之上的最高缝。拓扑撤销测试只说明「批量删除要合成一步」这种粒度，不作为实现模型。

- 会话：移动、添加、删除各是一步；同一次缩放的尺寸和位置是一步；同一字段连续输入是一步，换字段或开始拖拽后另起一步；撤销后再编辑不能恢复；第 51 步丢掉最早一步；筛选确认和恢复快照各是整份一步；存一版不改变历史；选中规则与「组件被去掉则清空选中」成立。
- 编辑器：按钮在图标排最前，不可用时禁用；快捷键在编辑态生效，焦点在筛选条或弹窗时不改文档；数据配置未应用时取消确认则文档不动，确认后历史才生效。

先验：大屏布局、图层、复制和视口规范化测试，画布设置与检查器面板测试，以及画布快照规格里「恢复只替换编辑器内存」的行为。

## Out of Scope

- 其他运营分析画布的撤销和恢复
- 修理拓扑撤销里的折点、数据合并或快捷键抢输入
- 把撤销历史写入快照、正式大屏或刷新后的会话
- 改变「存一版」的条数、权限或 YAML
- 字符级撤销、多选，以及撤销刷新、全屏、分享和预览筛选值

## Further Notes

拓扑撤销挂在图实例的增删改事件上，大屏编辑内容已经是一份可保存文档，所以按文档前后内容记录。拓扑里有几处不能照搬：折点的前后坐标被记成同一份；节点数据恢复是合并而不是替换；撤销后短时间的连按会被丢掉；快捷键在输入框里也会撤图。本变更不修这些。
