# Stargazer 发布公平调度与终态释放

状态：done（第二阶段实现及本地验证完成；现有 lint 环境限制和生产复验边界见验收报告）

## 事故证据与边界

新日志单 Worker 曾有 7 个运行、3838 个目标，目标槽位和 Payload 上限均为 160。
本轮可对齐的 cmdb_47 汇总为：254 个目标，采集成功 82、失败 172；发布确认 61、失败 12、未知 9。
日志不包含 192.168.198.*，不能把这组统计直接当作该网段的逐 IP 对账。
JetStream deadline 497 / rejected 495 是累计计数，不是本轮损失；成功 PubAck P99 不能证明失败消息的 broker 延迟。

## 修复契约（用户已授权实施）

1. 保留 `enqueue → receipt` 和逐目标流式发布；不等待整个采集任务结束。
2. **用户后续确认：排队与发送预算分离。** 默认 Run 的 `PUBLISH_TOTAL_TIMEOUT=120` 改为单目标累计活动发送预算，只统计连接/SDK 发送、ACK 及其有限重试。并行消息按活动时间并集计时；准入、编码等待、信贷等待、chunk 回队不主动消耗预算，下一 chunk 沿用剩余额度。等待信贷期间如果该目标另有消息正在等 ACK，该 ACK 的活动时间仍正常计时。Run 不再从 enqueue 时起套一个 120 秒绝对截止。
3. 默认 NATS 链路从 Writer 独占 50 个结果，改为有界单目标 chunk 轮转。每个 quantum 不超过单调用信贷窗口，完成后回到共享队尾，让新来的小结果也能获得发送机会。4 个 Writer 负责调度，不被 ACK 等待占住；每个 Payload 最多一个活动 quantum，最多 120 个，消息在途仍受全局 256 条/32MiB 信贷限制，编码线程仍为 2。
4. 每个结果的编码游标、数据引用、回执和 Payload 额度由发布器持有；终态先关闭游标并清理引用，再释放额度，不再等慢结果结束。
5. 发布器管理重试并持有唯一 payload：轮次元数据写入在发送前进行有限幂等重试（沿用目标发布 max_attempts，默认 2 次；准备阶段独立最多 30 秒），失败归为未发送失败；验证/编码错误归为永久失败。连接建立失败但尚未调用 SDK 发送，不归为未知。已调用 SDK 但未确认、或此前 chunk 部分成功，仍归为未知。Run 不再拿已释放的 payload 二次重试。
6. 首次发送时间只记录一次，位于取得信贷且连接就绪后的 SDK 调用前。分别保留入队、首次发送前等待、编码准入/执行、元数据准备、信贷等待、累计活动发送、端到端时长。信贷等待与同目标在途 ACK 可重叠，各阶段 P99 不可相加。失败原因与所在阶段分开；累计未确认不解释为 broker 拒绝。
7. 保持一行一消息、subject、稳定消息 ID、轮次元数据及回调协议。不改 SNMP 探测、部署参数及已有 Server 错峰工作。
8. 回执按完成事件进入有界汇总队列，不由前 4 个慢回执占住所有汇总 worker。Publisher 接收结果后，Coordinator 返回仅有采集摘要的 Pending，使 Scheduler/Executor/Sink 都不再保留托管 payload。
9. 编码提交前以 2 个额度限制线程池任务积压；逐条检查取消信号。小结果复用完整验证时的编码，缓存按实际字符串内存加引用开销限制在每目标 900KB；超限回退原有完整验证 + 有界重编码，不新增无限全量缓存或落盘队列。单结果原有 100000 行、64MiB 和单行上限不变。

## 排队、兼容及关闭语义

- 默认 NATS Run 队列不按时间淘汰；容量满时背压采集，不是无限堆积。排多久由发布额度和 broker ACK 的恢复速度决定，不等价于 CMDB 消费速度；PubAck 不证明已经入库。
- `PUBLISH_QUEUE_TIMEOUT` 暂保留解析以兼容既有配置，默认协作式 NATS 链路不再用它淘汰排队目标。外部注入的旧式 publisher 仍遵守其原接口；显式传入底层 `deadline=` 的工具调用保留绝对截止语义，不能用于默认 Run 的排队淘汰。
- 显式开启的 Core NATS fallback 同样使用累计发送预算和首投标记，但成功语义仍是原有 Core flush，不冒充 JetStream PubAck 或 CMDB 入库确认。
- 显式 Run 取消/租约失效/停机仍可终止等待；“无排队超时”不是无限重试或永不响应关闭。
- shutdown 的 grace 是排空宽限，不是可强杀 Python 线程的硬保证；宽限到达后协作取消。编码线程真正停止前保留额度，不提前宣布释放；单个不响应取消的外部阻塞调用仍可能延长 join，独立进程不在本次范围。
- 回滚通过回退整组 Agent 变更，恢复旧队列包含在绝对截止中的行为；无消息 schema、Server、数据库或部署配置迁移。

## 测试接口与验收

已确认测试接口：BufferedResultPublisher enqueue/receipt、ResultDeliveryCoordinator finish、JetStreamPublishWindow publish，以及真实发布链路到外部 JetStream SDK 替身。

- TDD：公平性、结果终态与实际引用释放、重复发送时间戳、托管重试异常逐项先红后绿。
- 并发、慢 ACK、截止前后、部分确认、取消及 shutdown：无重复终态、无额度泄漏、无任务泄漏。
- 用户后续明确要求按已降载配置测试：7 个运行 / 3838 个合成目标 / **120** 活跃槽位与 Payload / 4 个 Writer / 全局 256、单调用 64 条信贷；新版使用 120 秒累计发送预算。日志中的 160 仅作为历史事故证据，不作为本次验收参数。
- 快速压力用例与真实 120 秒截止实验分开报告，不拿缩短时间的结果冒充生产重放。
- 输出成功/失败/未知、耗时、首次发送前等待、吞吐、额度峰值与回收情况；不得保证 128 个可达 IP 全部入库，生产仍需采集端和 CMDB 消费端对账。
- 通过共享 CollectionScheduler + TargetCollectionExecutor + RunResultSink 的真实 7 轮基准，验证 120 槽位峰值、大小混合、慢 ACK、信贷耗尽/恢复、实际等待超过 120 秒和 3838 个终态；只替换外部探测、采集插件和 SDK，不冒充真实 SNMP/NATS/CMDB 重放。旧 producer 基准保留用于同口径历史比较。
- shutdown 取消 await 后，编码线程未真正退出前不得释放 Payload；终态异常保留身份与异常链但清理帧局部变量，防止 traceback 延长大结果生命周期。

## 非目标
