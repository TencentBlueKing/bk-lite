# 日志告警策略查询语句字段联想

Status: implemented

## Problem Statement

日志搜索页已经支持基于当前日志分组和时间范围联想字段名、字段值，但日志告警策略的
“查询条件”仍是普通文本输入。配置人员必须记忆字段路径和值，且策略页当前在日志分组
回填前便请求字段，导致新增、编辑场景中的展示字段、分组字段和聚合条件也可能拿不到
正确的字段目录。

## Solution

将日志搜索页的智能查询输入整理为日志域内唯一的 `LogQueryInput` 模块，由日志搜索页与
关键字/聚合告警策略表单共同使用。模块保持自由文本输入，同时在所选日志分组和时间范围
内提供字段名、字段值候选，负责光标位置替换、值转义、防抖、请求取消和上下文缓存失效。

告警策略页在表单日志分组确定后再加载最近 15 分钟的字段目录，并把同一目录提供给查询
联想、展示字段、分组字段和聚合条件。无日志分组、无近期日志或候选请求失败时，不得阻断
手工输入和策略保存。

## Interaction Decisions

- 聚焦空查询片段时展示当前范围内的字段；继续输入后按包含关系过滤字段名。
- 选择字段后在当前光标位置替换字段片段并补充 `:`，随后加载该字段的值候选。
- 字段值最多请求 50 条；按前缀匹配、包含匹配、命中数和长度排序。
- 选择字段值后使用双引号包裹，并转义反斜杠、双引号和换行。
- 候选打开时 Enter 优先确认候选；无候选时日志搜索页 Enter 执行搜索，策略页不提交表单。
- 切换日志分组或时间范围时立即清理候选、缓存并取消旧请求；旧响应不得覆盖新上下文。
- loading、无匹配字段、无匹配值均在下拉中提供文字反馈，不依赖颜色表达状态。

## Explicit Non-goals

- 不新增 LogsQL 操作符、函数或布尔关键字联想。
- 不新增查询语法校验、格式化或服务端保存前试运行。
- 不新增字段 Schema 注册表；候选仍来自 VictoriaLogs 当前时间窗内的实际日志。
- 不修改日志策略存储结构、扫描语义或后端查询接口。

## Acceptance Criteria

1. 日志搜索页与关键字/聚合告警策略页使用同一个查询输入模块，候选和插入行为一致。
2. 新增与编辑策略均在日志分组确定后加载正确字段，空分组不发字段/字段值请求。
3. 字段和值可通过鼠标或键盘选择，并在表达式当前光标位置正确替换。
4. 字段值请求携带当前日志分组和时间范围，特殊字符保存为合法的带引号值。
5. 快速切换日志分组或时间范围时不显示旧候选，卸载后不更新状态。
6. 无近期日志、无候选或接口失败时仍可手工填写并保存合法策略。
7. 亮色、暗色、长字段名、loading、empty 状态可读，输入 focus 状态保持 Ant Design 语义。

## Testing Decisions

- 通过 `LogQueryInput` 的公开界面做 Vitest 交互测试，不导出内部解析函数作为测试入口。
- 覆盖受控值、Form 回填、光标替换、字段值请求/转义、键盘、上下文失效和过期响应。
- 单独测试策略字段目录在空分组、编辑回填、分组切换、取消请求和失败场景的行为。
- 保留日志策略 payload 既有测试，并运行类型检查、Lint 与 Log Family Storybook 验证。

## Implementation Evidence

- 日志搜索页和告警策略表单已统一使用日志域 `LogQueryInput`，原搜索页私有实现已移除。
- 策略字段目录在表单日志分组变化后请求，显式使用最近 15 分钟窗口并取消旧请求。
- Vitest 覆盖鼠标/键盘选字段、值请求与转义、空分组、分组切换取消，以及策略字段目录
  的加载和过期响应隔离。
- 日志策略 payload 回归、TypeScript、范围 Lint 与 Log Family Storybook 静态构建通过。
