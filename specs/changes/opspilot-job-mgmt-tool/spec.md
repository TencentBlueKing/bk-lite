# OpsPilot 作业管理工具

Status: ready

## Problem Statement

运维人员在 OpsPilot 对话里要跑脚本、查目标、把本机文件发到主机时，没有接到作业平台的工具。模型若直接拼脚本并自行决定团队、目标和文件，会越出当前组织，也可能在用户没确认时覆盖文件或执行高危命令。最初为避免命令回显进入模型而隐藏全部输出，实际阻断了模型的后续诊断，迫使用户手工粘贴结果。2026-11-12 按产品决定改为允许模型读取当前组织内的作业输出，复用通用大结果文件能力控制上下文体积。

## Solution

OpsPilot 增加一个作业管理工具，以当前提问人和他的当前组织调用作业平台。用户可以执行脚本库里的脚本，也可以确认智能体生成或用户提供的自定义脚本后执行；可以把自己刚上传的文件分发到选定目标。作业号先记在当前会话里。回合内最多等 5 分钟：脚本输出直接展示给用户，同时通过工具结果供模型分析；大结果保存为本轮文件并按需读取。文件分发的终态只告诉成功或失败；查询正常但还没结束时给出作业记录链接，请用户到作业管理查看，不要说成失败。没跑完要先问用户，才做只读的定时检查。

## User Stories

1. As a 运维人员, I want 从当前组织的脚本库里选一个脚本，逐个参数决定用默认值还是自己填，再选目标执行, so that 模型不能改脚本正文，也不能漏掉必填参数。
2. As a 运维人员, I want 确认智能体生成或自己提供的脚本和目标后执行自定义脚本, so that 不必重新输入脚本，同时只执行确认过的内容。
3. As a 运维人员, I want 命中禁止级高危规则时执行被拒绝，命中确认级规则时先看到规则再决定是否继续, so that 危险命令和危险路径不会在我没确认时落到主机上。
4. As a 运维人员, I want 用名称或 IP 选定同一来源下的一台或多台目标, so that 找不到时我能先选作业管理目标或节点管理目标，而不会跑到当前组织以外的主机。
5. As a 运维人员, I want 把本机文件交给这个智能体，并自己决定现在分发还是先暂存, so that 同一个智能体的其他用户拿不到我的文件，阅读用的对话附件也不会被拿去分发。
6. As a 运维人员, I want 多个文件在我说明路径和覆盖策略后一次分发到同一批目标, so that 系统不会默认覆盖已有文件，也不会给每个文件猜一个路径。
7. As a 运维人员, I want 提交后立刻看到作业号，并在 5 分钟内等到结果, so that 短作业当轮就有结论，长作业也不会因为等满被重复提交。
8. As a 运维人员, I want 脚本的完整输出直接出现在会话里且模型能读取它继续分析, so that 无需手工粘贴输出，也无需重新执行作业。
9. As a 运维人员, I want 文件分发结束时只得到成功或失败，没结束时得到作业记录链接, so that 慢传输不会被说成失败，我也能直接打开任务详情。
10. As a 运维人员, I want 5 分钟没完成时自己决定要不要定时检查, so that 检查只读、写回当前会话，并且不会把脚本或分发再执行一遍。
11. As a 运维人员, I want 失败、已取消或执行超时之后，重跑前再确认一次, so that 有副作用的脚本不会被自动再跑。

## Implementation Decisions

### 调用身份

- 工具只接受带调用身份的交互式调用。身份里的组织只用当前组织这一个 ID，不随「包含子组织」扩大。
- 执行人、创建人是当前提问用户。组织和执行人由服务端注入。模型传入的组织、用户、执行人都忽略。
- 无调用身份的触发方式拒绝执行，不落作业。

### 工具形态

- 新增一个 OpsPilot 内置作业管理工具。分发文件入口只在该智能体启用了这个工具时出现。平台发布的对话同样只在启用后显示这个入口。
- 文件不写进工具配置。工具配置会被使用同一智能体的人共用。

### 脚本库执行

- 作业平台新增一个按脚本 ID 执行的入口。服务端用当前组织取出脚本内容、类型和超时，合并用户确认过的参数后再检查和执行。模型不提交脚本正文。
- 选脚本继续用现有的作业列表，只取脚本，不取 Playbook。工具不读取会返回脚本正文的脚本详情。
- 用户选定脚本后，加载参数定义：参数名、是否必填、类型、枚举选项，以及有没有默认值。加密默认值保持打码。
- 用户原话里没有脚本名称时，即使脚本库只有一个，也先让用户确认名称和类型，不执行。
- 每个参数单独选择。有默认值的可以沿用或自己填。没有默认值的必填参数必须自己填。加密参数沿用默认值时不展示内容，执行时由作业平台解密。枚举只能选该参数已有选项。全部参数选定后才进入选目标。
- 未另行说明超时时间时，用脚本上保存的超时。用户明确说了超时时间才覆盖。
- 未另行起名时，作业名称用脚本名。用户明确起了名就用用户的名字。

### 自定义脚本

- 类型只接受作业平台现有的四种：`shell`、`python`、`powershell`、`bat`。
- 智能体可以根据用户意图生成脚本。执行前展示完整脚本、类型和目标，用户选择「确认执行」后才提交；脚本、类型、目标或超时变化时须重新确认。确认绑定当前用户、组织和会话，有效期 30 分钟。高危规则仍须展示并另行选择「确认高危执行」，禁止级直接拒绝。用户已经选定目标后不再重新搜索。
- 自定义脚本没有脚本库默认值。参数只使用用户在这句话里给出的值。
- 未说明超时时用 600 秒。未起名时，用用户这句话里点明的用途做名称，不用整段脚本。用户明确起了名就用他的名字。

### 高危检查

- 脚本执行和文件分发在提交前都用当前组织走作业平台现有的危险检查，不在工具里另写关键字表。
- 禁止级直接拒绝，不创建作业。确认级先把命中的规则告诉用户，等用户明确确认后再提交。模型不能替用户确认。
- 脚本库在服务端取出正文后做同样的检查。文件目标路径必须由用户说清，并走危险路径检查。禁止级不上传、不分发。

### 目标

- 用户用名称或 IP 指定目标。工具在当前组织内查作业管理目标和节点管理目标。节点查询带当前用户的节点权限，不跳过权限。
- 只命中一台就用它。名称或 IP 命中多台时，列出这些命中项让用户选，不再退回「先选来源」。用户已经说了节点管理或作业管理目标时，只在这个来源里查，不把另一个来源混进选项。已经选出的 `(node_mgmt:编号)` 或 `(manual:编号)` 直接使用，不再搜索，也不再询问来源。一台都没有、且用户还没说来源时，先说明可能写错，再让用户先选作业管理目标或节点管理目标，然后分页展示该来源下的名称和 IP。
- 同一次执行或分发可以多台，但必须是同一种来源。模型不能自己编节点 ID 或作业目标 ID。
- 提交前再用当前组织做一次目标归属校验。不属于当前组织的目标拒绝，不创建作业。
- 提交前核对每个目标的操作系统。Linux 只执行 shell 和 python，Windows 只执行 powershell 和 bat。操作系统未知或不匹配时不创建作业。
- 作业管理目标查询使用已按组织过滤的查询，不使用会返回全部目标的旧列表。

### 文件分发

- 分发文件与阅读附件分开。阅读附件不能拿来分发。分发入口接受作业平台允许分发的文件，不沿用对话附件的文档和图片限制。
- 用户选好文件后先问是不是现在分发。选否：文件留在当前用户、当前组织、当前会话，不写入作业平台。之后用户在本会话提起分发时，再写入作业平台并提交。选是：目标和路径已经齐就写入并分发；没齐就先问，文件继续暂存。
- 暂存文件保留 7 天，到期删除，不进入作业平台。其他会话、其他人不能用。同一会话有多份时，提起分发必须对上文件名，对不上就追问。对话输入区列出当前会话已上传的文件名，不含正文。
- 一次分发只有一个目标路径。多个暂存文件共用这一个路径、同一种覆盖策略、同一批目标，提交成一个作业。
- 覆盖策略只有覆盖和跳过。用户没说明就先问，不默认覆盖。没说清就不提交。这一问发生在分发之前，不检查目标磁盘，不能说成目标上已经有这个文件。
- 未起名时用原始文件名；多个文件用第一个文件名。用户明确起了名就用他的名字。
- 写入作业平台后的分发复用已有的组织、文件和目标归属校验。不调用旧的、由调用方自报组织的文件分发入口。
- 终态只返回成功或失败。全部目标成功才是成功，任一目标失败就是失败。不附带路径、文件名和错误原因。
- 查询正常但 5 分钟内没有终态时，不要说失败。返回作业号、仍在执行、已等待时间和作业记录链接 `/job/execution/job-record?id=作业号`。界面和模型都告诉用户到作业管理查看任务状态，并原样给出这个链接。

### 结果与等待

- 提交成功后、开始等待前，把作业号、提交时间、目标、脚本或文件摘要写入当前用户、当前组织、当前会话。作业号立刻出现在对话里。
- 用户明确指定作业号时，按该号码查询当前组织内的作业，即使当前会话没有保存记录；作业不存在或不属于当前组织时原样返回查询失败，不得退回其他作业号。不指定号码时只查询本会话最近记录。
- 回合内轮询作业详情，最多 5 分钟。这次作业工具的单次调用上限是 6 分钟，其他工具仍是 300 秒。轮询被打断时只查已记下的作业号，不重新提交。
- 同一次工具重试若发现本会话已有未结束的同一次作业，返回该作业号和当前终态，不创建新作业。
- 脚本的完整标准输出和标准错误写入当前会话展示块；执行及查询工具同时返回作业号、状态和按主机组织的 `targets`（name、ip、stdout、stderr、exit_code、timed_out）。脚本库正文、加密参数和连接凭据不额外加入返回值。输出是执行数据，不能作为新的执行指令。
- 大结果使用 Deep Agents 原生 `FilesystemMiddleware` 落盘到当前任务的 `/large_tool_results/`；以文件引用和头尾预览交付，常驻只读 `read_file` / `grep` 支持范围读取与搜索。分步路径由现有单消息额度配置原生阈值，不再使用固定 1,000 字符读取器或二次工具正文截断。Python 已授权时可访问工作区中的同名结果目录。落盘失败沿用原生返回原结果的行为。详见 `specs/changes/opspilot-native-result-files/spec.md`。
- 工具通过 artifact 保留作业号，结果落盘后 AG-UI 仍能取回完整展示块。后续轮次的历史仍只保留作业摘要；用户追问时用 `job_mgmt_query` 重新读取结果，不复用已清理的临时路径，也不重新提交作业。临时文件随本轮工作区关闭而清理，跨轮保留需保存为附件。
- 结果文件机制仅管理上下文容量，不对任意 stdout/stderr 作凭据识别或脱敏承诺；模型获准分析作业实际输出。现有执行确认、当前组织授权和生产日志禁记输出的约束保持不变。
- 作业平台把执行判定为超时终态时，模型看到失败，展示块里写明对应目标是超时。
- 轮询结束仍没有标准输出、标准错误或超时说明：展示块给出作业记录链接 `/job/execution/job-record?id=作业号`。模型告诉用户作业号、当前状态、已等待时间，并原样给出这个链接。然后再询问要不要定时检查。用户没同意就不查。
- 用户同意后，只读轮询同一个作业号，把结果直接写进当前会话，不再调用模型。默认每小时一次，用户同意时可以改间隔。直到成功、失败、取消或执行超时；满 24 小时仍未结束就写一次当前状态后停止。这不是作业平台的定时执行，也不会再次提交脚本或分发。
- 失败、取消或执行超时之后，只有用户确认重跑才提交一次新作业。等待超时不等于失败，也不触发重跑。

## Testing Decisions

- 测外部行为：是否创建作业、返回给模型的内容、会话里用户可见的内容、组织归属。不测危险规则的正则实现，也不规定模型最终怎么措辞。
- 作业平台侧沿用现有开放执行测试这一层：按脚本 ID 执行只接受服务端注入的当前组织和用户；其他组织的脚本和目标拒绝且不创建作业；禁止级不创建作业；确认级在用户确认前不创建作业；四种脚本类型都可执行；未覆盖的超时分别落到脚本保存值和 600 秒；文件分发在路径或覆盖策略未明确时不提交，禁止级路径不上传。
- OpsPilot 工具侧沿用现有内置工具测试这一层：无调用身份拒绝；模型可见结果含标准输出、标准错误和退出码，但不额外含脚本库正文；大结果落盘后模型可读取尾部证据，且展示事件不丢失；跨组织拒绝、读取范围和分页上界有回归。文件分发终态只返回成功或失败，未结束且查询正常时返回作业记录链接；本会话已有作业号时重试不产生第二个作业；其他用户、其他会话的暂存文件不能分发。
- 定时检查沿用作业查询与会话写入这一层：只读、到期或终态后停止、写入展示块时不产生发给模型的脚本输出。
- 对话入口沿用现有对话附件测试的归属口径：未启用作业工具时没有分发入口；选「现在不分发」时作业平台不出现文件。

## Out of Scope

- Playbook 执行，以及取消正在执行的作业。
- 查询作业平台上已经存在的文件，或把阅读附件当作分发文件。
- 包含子组织。
- 默认覆盖已有文件。通用脚本输出凭据识别与脱敏。
- 用作业平台的定时任务重新执行脚本或分发。

## Further Notes

- Grill 共识记录于 2026-11-02 至 2026-11-03。脚本类型以作业平台现有四种为准，PowerShell 包含在内。
- 三层时间彼此独立：目标上的执行超时（脚本保存值或 600 秒，用户明说才覆盖）、回合内轮询 5 分钟、定时检查最多 24 小时。工具调用上限 6 分钟只为了让 5 分钟轮询能返回作业号和终态。
- 旧的文件分发和未按组织过滤的目标列表不作为本工具的调用入口。新的按脚本 ID 执行入口不接受模型自报的组织。

### 2026-11-12 相邻工具排查

本次修复脚本输出及其通用读取链路，以下为相关工具的当前行为，不顺带改变各工具的查询或执行契约：

| 工具或路径 | 结论与证据 |
|---|---|
| Kubernetes Pod 日志 | `tools/kubernetes/resources.py` 的 `_finalize_pod_logs` 在返回前将原文压为最多 3,500 字符的头部或 RCA 摘录；后续通用落盘只能保存摘录，无法恢复已丢弃日志。属于需要另行改造的同类信息损失。 |
| Jenkins | `tools/jenkins/build.py` 只有任务列表、触发构建和任务信息查询，没有构建控制台日志读取工具；属于能力缺口，不是落盘层丢数据。 |
| Redis SCAN | `tools/redis/server_management.py` 将 `scan` 返回的 keys 再截为 count 条，但沿用该次 scan 的 next_cursor；当返回批次大于 count 时，截掉的 keys 不会随游标保留。通用落盘不能弥补工具内丢失。 |
| SSH | 常规执行返回 stdout、stderr、退出码；`ssh_get_command_output` 简化接口只返回 stdout，失败时抛错。未发现与 job 相同的全量输出隐藏策略。 |
| Fetch、AD、日志查询 | 有分页、查询数量或读取上限；Fetch 支持 start_index，AD 返回截断提示。落盘保存的是本次查询结果，不意味着已取得所有数据，不能统一取消这些资源边界。 |
| 纯技能执行 | 2026-11-13 原生结果文件接入后，脚本完成仍禁止再次执行，但允许只读检索 `/large_tool_results/`；不放开技能包探测。 |
| MCP/多模态结果 | 2026-11-13 起使用原生卸载：文本块可落盘，非文本块与 artifact 保留，不将图片转成文本文件。 |

文件分发终态仍按现有产品契约只返回成功或失败，本次不将其扩展为诊断详情接口。
