# 网络状态拓扑布局编辑与持久化

Status: done

## Problem Statement

运营分析仪表盘与大屏中的网络状态拓扑组件，节点位置每次都由算法重新计算。运维人员即使拖动了节点，刷新后也会回到自动布局，无法保留自己整理过的拓扑视图；连线也不能手工拉成折线，复杂并行关系时可读性不足。现有工具栏只有适配视口与切换布局模式，缺少「重置布局」这一明确恢复入口。

## Solution

为网络状态拓扑组件支持可持久化的布局整理。在仪表盘/大屏**画布编辑态**下，用户可直接拖动实例节点与连线折点；几何变更实时写回该组件实例草稿，点击页面「保存」后落库，刷新后仍按保存结果渲染。工具栏提供「重置布局」。在**非画布编辑态**（查看态），节点仍可临时拖动以便看清拓扑，但折点不可编辑，临时摆放不落库。

## User Stories

1. As an 运维人员, I want 在画布编辑态直接拖动实例节点, so that 整理后的位置可随页面保存保留
2. As an 运维人员, I want 在画布编辑态拖动连线折点形成折线, so that 并行连线与交叉关系更容易阅读
3. As an 运维人员, I want 在页面点击「保存」后刷新仍看到我整理过的节点位置与折线, so that 整理结果不会因刷新或重新打开而丢失
4. As an 运维人员, I want 在组件右上角工具栏点击「重置布局」, so that 我可以清空当前布局模式下的手工调整并回到该模式的算法布局
5. As a 查看者, I want 在非画布编辑态也能临时拖动节点, so that 即使编辑者保存的布局不易阅读，我仍可本地摆放后更清晰地查看
6. As an 运维人员, I want 不同仪表盘或大屏组件实例各自保存自己的布局, so that 同一拓扑查询参数在不同画布上可以有不同摆放
7. As a 查看者, I want 非画布编辑态下不能编辑折点、临时摆放也不会被保存, so that 不会误改共享布局
8. As an 运维人员, I want 切换布局模式时看到该模式的算法或该模式已保存的手工几何, so that 不会把其它模式的摆放错误套到新模式上；切回原模式仍能看到原模式整理结果

## Implementation Decisions

- 改动范围限于运营分析中的网络状态拓扑场景组件（scene widget），不改造独立的网络拓扑编辑页产品能力；后者仅作为节点拖拽与边折点编辑的既有参考。
- 布局数据按组件实例持久化，落在该组件 `valueConfig` 下的网络状态拓扑配置中，随仪表盘或大屏 `view_sets` JSON 一起保存与回填；不新增后端专属表或专属 API。
- 运行时拓扑节点与连线仍由现有网络状态拓扑查询接口提供；布局只覆盖几何，不改写拓扑结构、告警状态或端点关系。
- 配置扩展字段约定如下：
  - `layoutMode`：可选；**新建或未写入时**缺省视为 `hierarchical`。切换布局模式会写入该字段；打开/刷新组件时**恢复上次的 `layoutMode`**（与对应 mode 桶一并回填），不会每次强制回到层级
  - `layoutByMode`：按布局模式分桶的手工几何；每桶可含 `nodePositions`（节点 id → `{ x, y }`）与 `linkVertices`（连线 id → 折点数组）
  - 旧扁平 `nodePositions` / `linkVertices` 仅读兼容：归入当时 `layoutMode`（缺省 hierarchical）对应桶；新写入不再输出扁平字段
- 布局编辑不设组件内「编辑布局」开关：父级画布处于可编辑上下文且非分享模式时（画布编辑态），节点与折点可直接拖动并写回草稿；否则为查看态。
- 工具栏在画布编辑态提供「重置布局」；**不提供「保存布局」或「编辑布局」**。既有缩放、适配视口、导出、刷新、布局模式切换保留。
- 查看态：节点可临时拖动（仅本地 ephemeral，且只作用于当前 mode；切 mode 丢弃 ephemeral），折点不可编辑；画布编辑态：节点与折点可编辑并写回**当前 mode 桶**，不允许端点重连或改写拓扑关系。
- 节点移动、折点变更、重置布局、切换布局模式（画布编辑态）直接更新父级草稿中的该组件实例 `valueConfig`；用户点击仪表盘/大屏页面「保存」时，随整页 `view_sets` 一次性落库。
- 几何拖拽不得触发画布 `fitView` / 全量 `initData` 重建；身份结构变化才重建，几何变更只原地 patch，并在折点拖拽结束后恢复平移与节点可拖。
- 未点页面「保存」前离开或刷新，布局草稿与画布其他未保存改动一样丢失，行为与现有草稿模型一致。
- 渲染顺序：先按当前 `layoutMode` 做算法布局，再应用 `layoutByMode[layoutMode]` 中仍存在的节点位置；边路径上，该 mode 桶内用户保存的 `linkVertices` 优先于自动并行边偏移；无手工折点时继续使用现有并行边逻辑。
- 切换布局模式：只切换并持久化 `layoutMode`，渲染目标 mode 的算法结果 + 该 mode 桶（若有）；**不丢弃**其它 mode 的几何；无需确认弹窗（切模式不是清空）。再次打开组件时恢复该已保存的 `layoutMode`，而非重置为层级。
- 「重置布局」仅清空**当前** `layoutMode` 对应桶中的 `nodePositions` 与 `linkVertices`，留在当前 mode，其它 mode 桶不动；是否最终落库仍取决于用户是否点击页面「保存」。
- 运行时拓扑变化时：只对仍存在的节点/连线 id 应用已保存几何；消失的 id 在下次几何写回时自然剔除；新增节点/连线使用算法位置与自动边路径，直到用户再编辑。
- 通用网络拓扑 X6 画布层以可选回调与开关扩展节点移动、边折点变更与重置按钮，避免把场景组件业务逻辑硬编码进通用画布。
- 组件配置提交与回填路径须透传新增布局字段，避免配置弹窗保存时把已有几何冲掉。
- 本变更不要求后端 migration；若后续要对 `view_sets` 内部 schema 做严格校验，可作为跟进项，不阻塞本规格。

## Testing Decisions

- 好测试只验证外部行为：给定配置与拓扑数据，渲染/覆盖后的节点坐标与边折点是否符合契约；几何写回/重置后配置形状是否正确；编辑态开关是否控制可交互性。不锁定 X6 内部事件名或 DOM 结构。
- 优先复用现有最高接缝：
  - 布局覆盖纯函数（已有节点位置覆盖能力）与边几何优先级解析函数
  - 组件配置提交/合并函数，确保布局字段被保留与重置
  - 现有网络状态拓扑并行边单测风格（Node test runner 下的纯函数测试）作为 prior art
- 若父级草稿配置回写接缝可测，补充「拖拽/重置写回实例草稿配置」「页面保存后刷新回填」相关行为测试。
- 不强制本阶段做完整仪表盘/大屏 E2E；手动验收覆盖：编辑态拖拽、页面保存后刷新回填、重置、分享只读、仪表盘与大屏各一实例互不串扰、确认工具栏无「保存布局」。

## Out of Scope

- 工具栏「保存布局」按钮或组件内单独落库动作
- 独立网络拓扑编辑页的功能增强或行为变更
- 拖线改端点、新建/删除节点或连线、改写运行时拓扑结构
- 跨组件实例、跨仪表盘/大屏的全局共享布局
- 为布局持久化新增后端模型、migration 或专用 API
- 分享模式、只读访客下的布局编辑
- 自动布局算法本身的重写（仅复用并覆盖结果）
- 把布局编辑能力推广到其他运营分析组件

## Further Notes

- 「点击保存」统一指仪表盘/大屏页面级「保存」；布局几何与画布其他改动共用同一草稿与落库时机。
- 「默认层级」仅指新建或尚未写入 `layoutMode` 时的初始值；已保存实例打开时恢复上次布局模式。
- 布局编辑入口文案（例如「编辑布局」/「完成」）与图标可在实现时按现有工具栏风格选定，不另开产品访谈。
