# 用工作台智能体替换智能体模板

Status: implemented（2026-11-10）

## Problem Statement

智能体模板目录里是一批通用助手，例如编程、文案和周报。运维人员真正会反复用到的，是已经随工作台内置的 Kubernetes 助手和 Postgres DB 助手。模板目录和工作台各说各话，从模板创建也带不走巡检提示词和对应的内置工具。

## Solution

模板目录只保留这两条内置模板。从模板创建出一个普通智能体，带上该工作台智能体的巡检提示词，并挂上对应的内置工具。连接参数和大模型留空，由用户自己配置。换目录由一条新的手动命令完成，不写数据迁移，这版也不放进启动初始化。启动初始化里原来的 `init_llm` 调用注释掉，启动不再播种旧模板。工作台和它已经绑定的内置智能体保持原样。

## User Stories

1. As a 智能体管理员, I want 模板目录里只有 Kubernetes 助手和 Postgres DB 助手, so that 我按运维场景挑选，而不是在一批通用助手里找。
2. As a 智能体管理员, I want 用 Kubernetes 助手模板直接得到带巡检提示词、并挂上 Kubernetes 内置工具的普通智能体, so that 不用从空白智能体重写巡检说明。
3. As a 智能体管理员, I want 用 Postgres DB 助手模板直接得到带巡检提示词、并挂上 Postgres 内置工具的普通智能体, so that 数据库巡检也可以从同一目录开始。
4. As a 智能体管理员, I want 新智能体不带工具连接参数，也不带大模型, so that 我在自己的环境里重新填写集群、数据库和模型。
5. As a 智能体管理员, I want 当前组织已经有同名智能体时，新智能体自动叫「原名 副本」，再冲突则叫「原名 副本2」「原名 副本3」, so that 一键创建不会因为内置智能体同名而失败，也不用先改名。
6. As a 平台运维, I want 手动执行一条新命令后模板目录只剩这两条，并且可以重复执行, so that 我先在本地确认目录，再决定是否放进启动流程。
7. As a 平台运维, I want 启动初始化不再调用 `init_llm`, so that 验证之后的下一次启动不会把通用模板写回来。
8. As a 工作台用户, I want 已有的内置工作台和已经创建的智能体保持可用, so that 更换模板目录不影响正在运行的巡检。

## Implementation Decisions

- 模板是另建的目录记录，不是工作台正在使用的内置智能体。工作台仍绑定原来的内置智能体。模板记录只标记为模板，不标记为内置，避免工作台初始化把同名模板当成自己的智能体。
- 目录只有两条。Kubernetes 助手使用该工作台主智能体的巡检提示词，技能类型为计划执行，工具名为 Kubernetes 内置工具。Postgres DB 助手使用该工作台主智能体的巡检提示词，技能类型为基础工具，工具名为 Postgres 内置工具。介绍沿用工作台配置里的说明，目前与名称相同。
- 模板内容以发版时的工作台定义为准，不复制库里内置智能体上已经填好的连接、模型或其他运行配置。工具只记录名称，连接参数为空，大模型为空。模板不归属某个组织，模板列表仍对能查看智能体的人全部可见。
- 新增管理命令 `init_skill_templates` 替换模板目录：删掉全部模板记录，再写入这两条。不写数据迁移。已经创建的普通智能体、内置工作台和它绑定的内置智能体都不是模板记录，不受这次删除影响。重复执行结果仍是这两条。
- `init_skill_templates` 不加入启动初始化。在 `batch_init` 的 OpsPilot 初始化里注释掉 `init_llm` 调用，不删除 `init_llm` 命令本身。启动因此不再删除模板，也不再写入通用模板。还没执行 `init_skill_templates` 时，库里已有的模板保持原样。
- 继续使用现有的模板列表和一键创建，不新增接口。使用模板时提交巡检提示词、技能类型、介绍、当前组织，以及按名称挂上的内置工具。创建请求里已经带了提示词时，保留这份提示词。没有带提示词的空白创建仍写入现在的默认提示词。
- 新智能体是普通智能体。工具连接参数为空，大模型为空。温度、建议问题、问题改写和对话历史沿用空白创建的现有默认，不照搬工作台内置智能体上的开关。对话历史因此是开启的。
- 名称在当前组织内唯一，规则不变。提交前先看当前组织：名称可用就用模板名；被占用则用「原名 副本」；仍占用则用「原名 副本2」「原名 副本3」，依此递增。内置智能体和模板同名时，默认组织里的第一次创建会落到「副本」。
- 工具标识在用户创建智能体时按名称对应到当前环境的内置工具。命令播种时只记工具名，不写工具实例编号，也不写连接参数。内置工具视为始终存在且不能删除，创建流程不处理工具缺失。

## Testing Decisions

测模板目录和「使用模板」产生的智能体，不测巡检提示词的措辞，也不测 Kubernetes 或 Postgres 工具的执行。

最高缝是这条新命令、模板列表和智能体创建接口。使用模板仍是现有创建接口上的一次提交。附近已有模板列表测试，以及创建时写入默认提示词、拒绝同名的测试。直接调用 `init_llm` 的现有测试保持通过，因为它测的是命令本身，不是启动是否调用它。

- 执行新命令之后，模板只有 Kubernetes 助手和 Postgres DB 助手，提示词与发版定义一致。再执行一次，仍然只有这两条。同名的普通智能体和内置智能体还在。
- 启动初始化不调用 `init_skill_templates`，也不调用 `init_llm`。不跑 `init_skill_templates` 时，已有模板记录保持不动。单独执行 `init_llm` 时，它仍按原来的通用助手种子替换模板。
- 模板列表只返回这两条，不返回普通智能体。
- 用模板创建：保存巡检提示词、对应技能类型和介绍；挂上指定名称的内置工具且连接参数为空；大模型为空；组织是当前组织；对话历史按空白创建的默认开启。
- 不带提示词的空白创建仍得到现在的默认提示词。
- 当前组织已有模板同名智能体时，依次得到「原名 副本」「原名 副本2」。提交一个仍然重名的名称时，创建继续拒绝。

## Out of Scope

- 改动内置工作台、它的流程，或它绑定的内置智能体。
- 把 Web 应用巡检助手、以及三个工作台里的数据汇总智能体放进模板目录。
- 把工具连接参数、大模型，或工作台上已经填过的运行配置复制到新智能体。
- 内置工具不存在时的失败提示或降级。
- 创建前让用户改名，或创建后自动进入智能体设置。
- 回写已经从旧模板创建的智能体。
- 用数据迁移替换模板目录。
- 把 `init_skill_templates` 加入启动初始化。
- 删除 `init_llm` 命令。这版只注释启动里的调用。
- 保留被接口标成模板的其他智能体。执行这条命令时会随全部模板记录一起删除。

## Further Notes

- 对齐来源是本次 grill-me。换目录用 `init_skill_templates` 在本地验证，确认后再决定是否接入启动。`init_llm` 仍可手工执行；手工执行会按原来的通用助手种子删掉全部模板再写回，本地验证时不要再跑它。
- Web 应用巡检的提示词写死了特定站点和占位账号，所以这版先不进入模板目录；对应工作台继续按原初始化存在。
- Kubernetes 和 Postgres 的连接表单在工具参数为空时仍然可以打开，用户创建后再填写。
- 验证：上述 pytest 路径 47 passed 后，又补了模板列表和启动不改已有模板的断言，`test_init_skill_templates.py` 与启动调用测试 4 passed。前端 `pnpm exec vitest run src/app/opspilot/utils/__tests__/templateSkill.test.ts` 4 passed。
