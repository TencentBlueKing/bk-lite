# OpsPilot 内置 PPT Master 技能包

Status: ready

## Problem Statement

智能体要做可编辑的演示文稿时，平台没有内置的 PPT 技能包。用户说「做一份 PPT」要么得不到原生 PPTX，要么被现成的文本转幻灯片附件盖掉。上游 PPT Master 还要求工程文件跨轮还在，而现在每轮沙箱结束就删掉。

## Solution

把 PPT Master v6.7.2 作为内置技能包放进技能包目录，由管理员勾到需要的智能体上。用户说出 PPT 相关触发词后，智能体按该技能包生成或修改原生 PPTX。工程留在本对话的工作目录里，供下一轮确认和改稿。每轮导出成功都新增一个下载附件，第一份一定是 `<工程名>_v1.0.pptx`。做不到的能力直接说明，不改道。

## User Stories

1. As a 智能体管理员, I want 在技能包目录里直接选用内置的 PPT Master, so that 不用自行导入，也不会让每个智能体都带上做幻灯片的流程。
2. As a 对话用户, I want 说「做一份 PPT」就得到可下载的原生 PPTX, so that 结果是一份真正的演示文稿，而不是一段大纲。
3. As a 对话用户, I want 在同一对话里接着确认方案或改某一页, so that 不必把上一轮的页面再描述一遍。
4. As a 对话用户, I want 每次导出都留下一份新附件，并且第一份名为 `<工程名>_v1.0.pptx`、之后为 `_v1.1`、`_v1.2`, so that 我能区分先后版本。
5. As a 对话用户, I want 已经上传并解析好的 PDF 正文被当作资料, so that 做 PPT 不必再装一套 PDF 转换库。
6. As a 对话用户, I want 在要求旁白、生图、抓网页、网页上改 SVG 或按页面截图重建时得到明确拒绝, so that 系统不会假装已经做完。
7. As a 平台运维, I want 对话工程放在所有 server 副本共享的持久卷上，下载文件放在现有对象存储, so that 换副本或重建容器后，改稿和下载都还在。

## Implementation Decisions

- 只做内置技能包，出现在技能包目录中。不写入每个智能体的已选技能包，管理员自行勾选。
- 包内容为 PPT Master v6.7.2 的 skill-only 发布，整包原样放入内置技能包源。不收录示例稿，不修改技能正文，不跟踪上游 main。升级时再改一次版本。
- 播种时在技能包记录上写入触发词：`ppt`、`pptx`、幻灯片、演示文稿。这些词不写回技能正文，以免破坏上游完整性检查。
- 执行约定与现有内置技能包相同：系统提示只放目录，正文按需读取，脚本在沙箱中执行。两处只针对本包的例外：物化后的技能正文必须是上游原文；纯技能步不得禁止读取正文点名的流程文档。
- 生成原生 PPTX 所需的 Python 包预装在主服务解释器中，并随镜像固定：`python-pptx`、`PyYAML`、`Pillow`、`XlsxWriter`、`openpyxl`、`skia-pathops`、`uharfbuzz`。问答时不再按技能包依赖文件安装。不预装 `PyMuPDF`、`edge-tts`、`google-genai`、`curl_cffi`、`flask`。
- 对话中的 PDF 以已解析正文为准。执行说明要求不要运行技能包自带的资料转换入口，也不要安装 `PyMuPDF`。
- 普通生成、创建模板、修改已有原生 PPTX 按技能包自己的路由走。旁白、AI 生图、网页抓取、SVG 网页编辑器、按页面截图重建，停下来说明当前不做，不安装对应依赖，也不改走另一条路线。
- 技能目录只读，不当工作目录。每轮沙箱仍是临时目录，结束即删。工程放在本对话的持久工作目录下的 `projects/<工程名>/`。同一对话的后续轮次复用它。对话删除时删除该工作目录。不跨对话、不跨用户保留，也不在别的对话复用刚创建的模板。
- 本地工作目录放在已被忽略的技能数据目录中，按对话 ID 分目录。线上只把这块工作目录挂成所有 server 副本共享的持久卷。技能包留在镜像内，沙箱继续用临时目录。
- 每轮导出成功后，在清理沙箱之前，把该工程 `exports/` 里修改时间最新的 `.pptx` 登记成一份新的工作流附件，不覆盖上一份。文件进入现有工作流附件所用的私有对象存储。命中本包的这一轮不规划文本转幻灯片的附件工具。
- 下载名的前缀是工程名。该工程还没有附件时，丢掉导出文件名自带的版本，一定登记为 `<工程名>_v1.0.pptx`。之后再导出按现有附件规则递增为 `_v1.1`、`_v1.2`。版本字母用小写 `v`。

## Testing Decisions

测用户可见行为，不测上游脚本内部，也不把完整性检查的实现细节当成测试对象。

最高缝是现有内置技能包播种、按用户消息命中技能包，以及工作流附件的登记与编号。附近已有内置技能包播种测试、技能包命中测试、附件版本号测试，以及「生成文件」时注入文本转幻灯片工具的规划测试。本变更沿用这些缝：

- 播种后目录中出现该内置包，触发词能让「做一份 PPT」命中，且技能正文未被改写。
- 该工程第一次登记的下载名是 `<工程名>_v1.0.pptx`，即使导出文件名里已有别的版本。再次导出新增 `_v1.1`，上一份仍在。
- 命中本包时，规划结果不包含文本转幻灯片附件工具。
- 要求旁白、生图、抓网页、SVG 编辑或按截图重建时，回复说明不做，且不触发依赖安装。
- PDF 资料使用对话中已有正文，不调用技能包自带的 PDF 转换脚本。

## Out of Scope

- 把该包默认写入每一个智能体。
- 旁白、AI 生图、网页抓取、SVG 网页编辑器、按页面截图重建。
- 安装或分发 `PyMuPDF`、`edge-tts`、`google-genai`、`curl_cffi`、`flask`。
- 跨对话复用模板或工程。
- 跟随上游 main 自动升级。
- 用文本转幻灯片附件工具重写本包导出的原生 PPTX。
- 收录上游示例稿。

## Further Notes

- 上游技能的完整性检查读取技能正文的版权、许可证、仓库地址和赞助信息。物化时若把正文收成只剩名称和短说明，脚本会直接失败。因此本包必须保留原文。
- `PyMuPDF` 为 AGPL-3.0，且只服务于技能包自带的 PDF 路径。对话上传文件已由现有 MarkItDown 解析，所以不把该库放进镜像。
- 对齐来源是本次 grill-me。版本钉在 2026-10-17 发布的 v6.7.2。
