# 七个平台采集凭据与连接参数闭环

状态：代码与本地协议回放验证完成；真实平台验收待提供测试实例。

## 需求与边界

OpenStack、SmartX、ManageOne、FusionCompute、Nutanix HCI、InCloud Rail、Azure 的手动凭据及系统凭据引用，必须经过页面、保存、秘密解析、NodeParams、HTTP 接纳、异步执行器，到达真实采集器。端口和证书校验不能仅保存却不生效；认证失败或核心资源接口失败不能报告成功。

复用系统管理已有 `cloud/openstack`、`cloud/platform_api`、`cloud/oauth_client` 类型。身份字段由凭据管理保存；端口、协议、范围和厂商连接选项由任务保存。引用凭据不复制秘密到任务，运行时解析后通过环境变量下发。手动模式沿用现有加密存储。

## 字段设计

| 插件 | 系统凭据字段 | 任务连接选项 | 脚本约束 |
| --- | --- | --- | --- |
| OpenStack | 用户名、密码、用户域名称 | Keystone 端口（默认 5000）、协议、校验证书、项目 ID（可选） | Keystone v3 系统级认证，枚举项目并换取项目令牌；账号需具备现有脚本所需系统/项目及计算、存储读取权限。项目 ID 是采集筛选，不代替系统级权限。优先使用服务目录中的 Nova/Cinder/Neutron 地址，未返回目录时保留历史服务端口。 |
| SmartX | 用户名、密码 | 端口（默认 443）、协议、认证来源（默认 LOCAL） | 证书校验保持强制开启；选择已有凭据仍可配置认证来源。 |
| ManageOne | 用户名、密码 | 端口（默认 443）、协议、校验证书、区域（可选）、API 版本 | 当前 CMP 驱动支持 8.2.0。可填完整运维面地址；根域名配合区域转换为 `oc.<region>.<host>`。 |
| FusionCompute | 用户名、密码 | 端口（默认 7443）、协议、校验证书、用户类型、API 版本（默认 8.1） | 登录按原脚本计算密码摘要，版本进入 Accept 头。 |
| Nutanix HCI | 用户名、密码 | 端口（沿用页面默认 443）、协议、校验证书 | REST Basic Auth；实际端口以目标部署配置为准。 |
| InCloud Rail | 用户名、密码 | 端口（沿用页面默认 443）、协议、校验证书 | 登录取得会话后查询虚拟机；实际端口以目标部署配置为准。 |
| Azure | 应用 ID、客户端密钥、租户 ID | 订阅 ID | 公有云固定 OAuth/ARM HTTPS 端点，强制证书校验；移除不生效的端口、协议和 TLS 开关。应用须有目标订阅资源读取权限。 |

其他五个私有平台的证书校验默认开启，明确关闭时才传 `verify=False`；SmartX 不允许关闭。完整 URL 的协议优先于协议选项，任务显式端口优先于 URL 端口，URL 路径保留。

## 实现

- 前端创建、编辑和凭据引用保留厂商选项；后端验证单凭据、连接参数和 Azure 必填范围。
- NodeParams 把连接参数送到请求；ManageOne CMP 驱动接收完整端点和 TLS 选项。
- 七个采集器实现现有异步契约，同步 HTTP 放入 `asyncio.to_thread`；不修改执行器契约。
- 修复认证失败返回空成功、部分核心资源接口失败被吞掉的问题。
- OpenStack 原有网络对象 best-effort 行为保留，不把整体成功解释为每个模型都已完整采集。
