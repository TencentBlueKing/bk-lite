# 告警规则统一多值匹配

> 2026-09-10：当前契约以 [最新实施文档](../alert-rule-types/implementation-plan.md) 为准，已获确认并实施，完成本地验证；[最新测试报告](../alert-rule-types/business-matching-test-results.md)。本文保留为旧版本记录；历史别名、来源 ID 下拉及复杂文本关键词方案不再作为实施依据，标量多候选以最新矩阵为准。

状态：方案已确认，已完成实现与本地验证；尚未部署。
日期：2026-09-09。

## 目标与范围

把已经确认的多值标签交互推广到相关性规则、告警分派、屏蔽策略、告警丰富、告警处理。
覆盖五个页面现有匹配字段，并把监控源接入五个入口；不把所有 JSON 字段自动开放成筛选字段。
匹配值多选不等于业务字段变成数组，不改 Event/Alert 标准字段的持久化类型。

## 探索时的代码证据（下述映射缺口已在本轮修复）

| 入口 | 实际匹配对象 | 前端 | 后端 |
| --- | --- | --- | --- |
| 相关性规则 | Event；周期聚合、缺失检测、即时旁路 | settings/correlationRules/components/matchRule.tsx | aggregation/strategy/matcher.py、instant_matcher.py |
| 告警分派 | Alert | settings/components/matchRule.tsx | common/assignment.py → MonitorSourceRuleMatcher → RuleMatcher |
| 屏蔽策略 | Event | settings/components/matchRule.tsx | common/shield.py → MonitorSourceRuleMatcher → RuleMatcher |
| 告警丰富 | 入库前事件字典 | settings/components/matchRule.tsx | enrichment/engine.py → enrichment/matcher.py |
| 告警处理 | Alert 的匹配字典 | settings/actionRules/components/matchRule.tsx | action/engine.py → action/matcher.py（复用 enrichment.matcher） |

前端还存在 components/alarm-match-rule 和 alarmMatchRuleRuntime，但当前五个正式页面没有使用它们；不能只改 Storybook 组件以为正式页面已接通。

已核实的不一致：

- 分派已有 level 数组输入，其他入口仍主要是单值输入。
- 通用 ORM RuleMatcher 的 eq/ne 数组是 IN/NOT IN；相关性要求显式 in/not_in；丰富/处理的 eq 会把数组转成字符串。这三种不能互换。
- 分派后端映射缺 resource_name/item，屏蔽缺 source_name/service/location/resource_name/item，但对应页面展示了这些选项。
- 丰富允许 content，但标准事件模型字段为 description；规则字典需要显式别名。
- 分派/相关性前端 source_id 选择值来自 AlertSource.id；屏蔽后端 source_id 映射 source__source_id；丰富上下文也是 AlertSource.source_id（业务字符串）。同名字段的身份语义不一致。
- action/payload.py 未投影 push_source_ids；source_id 只取第一条关联事件，不能据此宣称覆盖 Alert 的全部告警源。
- 丰富在 Event 实例化前执行，push_source_id 的兜底补全在后续 add_base_fields；新增丰富监控源条件需要把相同归一化事实提前提供给匹配上下文。
- AlertBuilder._resolve_standard_fields 对 source_name/resource_id/resource_name/resource_type/item 使用唯一值归约，成员取值不一致时置 None；不是列表。
- 现有正则、空值和历史别名在匹配器之间也有差异，不能借改控件静默重解释旧规则。

## 字段分类与交互

| 字段 | 当前数据形态 | 新交互与操作 |
| --- | --- | --- |
| 级别 | 单值枚举；事件与告警使用各自级别目录 | 已有选项多选；属于任意一个、不属于任何一个 |
| 告警源（ID/名称） | Event 单个来源；Alert 名称为单值快照，ID 由关联事件读取 | 多选下拉，显示名称并附身份；保留旧 key 的原含义，新增统一主键身份 source_pk |
| 资源类型、对象实例、资源名称、指标 | 单值字符串；Alert 聚合时可能为空 | 多值标签；完整值属于任意一个、不属于任何一个；保留已有文本操作 |
| 服务、位置 | Event 单值字符串，Alert 无此顶层字段 | 相关性/屏蔽/丰富支持多标签；分派/处理不增加不存在的顶层选项 |
| 标题 | 单值文本 | 多个完整标题精确匹配；文本包含任意关键词、全部关键词、不包含任何关键词；正则 |
| 内容/description | 单值长文本 | 多关键词匹配；正则；不把整段正文默认拆成标签 |
| Event.push_source_id | 单值字符串 | 相关性/屏蔽/丰富支持多标签候选值，任意/排除 |
| Alert.push_source_ids | 字符串列表 | 分派/处理支持包含任意一个、包含全部、不包含任意一个 |

级别/告警源复用已有选项接口，其余未建立目录的字段支持自由输入；不虚构候选目录。
完整值匹配与文本关键词匹配分别展示，避免“包含”同时指集合成员和子串。
同组 AND、组间 OR 继续保持；字段切换清空不兼容条件，兼容的多值操作符切换保留标签。
单个值仍用一枚标签；重复值去重；空数组、空白值、过多值、非法正则在原行提示。
分隔规则按字段区分：枚举/ID 可批量分隔；标题等可能含逗号的完整文本默认回车提交，不能无条件按逗号切割。
正则保持单输入，表达式中的逗号不能拆分。
策略列表摘要、详情回显、编辑、保存和中英文文案一起更新。

其他真实集合需要区分：

- Event.assignee/team、Alert.operator/team 是列表，但尚不在五个页面的普通匹配选项中。本轮不因为 JSON 类型而自动新增人员/组织过滤能力。
- Alert.monitor_objects 是对象列表，不能直接拿整个对象与字符串标签比较；如开放须定义明确的叶子投影。
- labels/tags/enrichment 是对象，叶子可能是标量或列表。已有 enrichment 路径规则需兼容；不凭一条样本猜测所有动态字段的类型。

## 已确认的聚合多对象边界

本轮“资源名称选择 a、b”首先表达当前资源名称属于候选集，不修改旧字段的快照语义。
如果要求对一个聚合告警中的全部成员资源进行匹配，应另加“关联事件·资源名称/对象实例/资源类型/指标/告警源”等明确命名的集合字段，并在分派和处理共同提供。
这些集合从关联事件批量投影，不能仅从 monitor_objects 读取，因为该快照仅覆盖有 monitor_id 的部分创建事件，也没有全部标准字段。
它属于额外的匹配范围，不应静默替换原 resource_name 等 key；多个关联字段是否要求同一成员事件满足，也需要显式定义。
本轮已确认只完成现有字段多候选值、监控源真实列表和告警源主键关联；不新增关联事件资源字段。

## 统一规则契约

保留现有 match_rules 二维数组和 key/operator/value 结构。
新操作符使用明确名称，避免改写历史 eq/ne/contains/in 的含义：

| 新 operator | 允许字段 | value | 语义 |
| --- | --- | --- | --- |
| any_of | 标量、基本值列表 | 非空数组 | 标量属于候选集；列表与候选集有交集 |
| none_of | 标量、基本值列表 | 非空数组 | 字段存在且非空，标量不在候选集；列表无交集 |
| all_of | 基本值列表 | 非空数组 | 包含全部候选值，允许额外成员 |
| text_any | 有文本匹配能力的字段 | 非空字符串数组 | 文本包含任意关键词 |
| text_all | 有文本匹配能力的字段 | 非空字符串数组 | 文本包含全部关键词 |
| text_none | 有文本匹配能力的字段 | 非空字符串数组 | 文本不包含任何关键词 |

新集合操作对 missing/null/空列表不命中，否定条件也如此；数字 0 是有效值。
精确字符串区分大小写、保留 001 与 1 的区别；文本关键词不区分大小写。
上限：每条规则最多 20 组、合计 100 条条件；每个新多值条件 1–50 项，每项最多 256 个字符。不把列表转成字符串做子串匹配。前端标签去重，后端允许重复候选值但不改变命中语义。
旧操作符按原上下文读取和执行；只在等价已证明时迁移为新操作符。
新增 source_pk 明确表示 AlertSource 数据库主键，候选值为规范的正整数 ID 字符串（如 "12"，拒绝 "0012"）；UI 显示名称及 #ID，旧 source_id 保持原有语义。其他普通字段仍保留 "001" 与 "1" 的区别。
相关性即时/缺失检测禁止空监听范围等策略约束，由调用方继续维护。

## 实现结构

1. Alerts 内部字段目录：声明场景、字段身份、基数、值类型、操作符、选项来源、ORM 路径和内存取值方式。静态目录生成前端类型/配置，动态选项继续走原接口；避免新增通用 schema 平台。
2. 一个前端条件编辑模块：五个入口传场景配置，复用已确认卡片/标签交互。保留各页面其他表单、聚合维度、丰富绑定、动作参数的专属行为。
3. 一个规则语义模块：校验/编译条件，提供内存判断与 QuerySet 过滤两个适配方式。旧匹配器逐步变为上下文适配，不各自实现新操作符。
4. 标量与文本优先下推 Django ORM；真实 JSON 列表在已限定组织/时间/状态的候选集中按批次读取所需字段。关联集合使用 ORM 子查询或批量投影，不依赖连接行上的简单取反来表达“全部不属于”。
5. 所有写入接口共享同样的合法性校验。未知字段/不支持操作符不能被删掉后扩大 AND 组；保留现有无效组失败关闭行为。
6. 不改分派先后顺序、屏蔽执行顺序、丰富 Provider 查询协议、Action 触发时机及幂等、通知/作业投递流程。

## 完整性与链路测试

- 字段目录完整性：五个页面每个可选字段都有校验、取值、执行支持；不支持的场景不能出现该字段。
- 语义矩阵：标量/列表 × any/all/none × 命中/不命中/缺失/空值；文本任意/全部/排除关键词；0、数字字符串、大小写、重复值、超限与非法值。
- 同一规则夹具分别运行 ORM 与内存适配器；相关性周期/即时结果一致。
- 五个正式页面分别覆盖新增、编辑、单值历史回显、多值保存、切换操作符、清空/校验、AND/OR 与摘要；跨控件包装测试到真实请求参数。
- 相关性：多级别/多源筛选 → 周期聚合、即时建警、缺失检测监听范围，包含越界事件不被选中的反例。
- 屏蔽：事件多值候选命中 → SHIELD → 不进入即时/周期建警；同批其他事件继续。
- 丰富：标准化事件匹配 → 仅命中事件查询 Provider → 写入 enrichment → 下游可读取；来源身份与正文别名一起验证。
- 分派：Alert 字段/监控源列表命中 → 实际负责人/通知目标按现有规则产生；不重复分派。
- 处理：Alert 匹配字典 → ActionExecution → mock 外部执行边界；重复触发不重复执行。
- 跨链路：接入 → 丰富 → 屏蔽 → 聚合/即时 → 分派 → 动作；包含命中、部分命中、全未命中和历史规则样本。
- 双组织候选隔离、批次边界、候选数量和查询次数验证。SQLite 验证语义，生产数据库验证 JSON/关联查询差异；无法运行的检查明确记录。

## 实施顺序

1. 确认字段/操作矩阵及关联事件范围；记录旧规则兼容契约。
2. 接通共享语义与字段目录，用完整性测试暴露并修复现存字段映射缺口。
3. 五个正式页面共同接入多值交互及保存校验。
4. 补齐全部执行适配、历史兼容、链路测试和浏览器验收，再交付。

## 实施落点与发布

- `server/apps/alerts/utils/rule_fields.json` 是字段目录事实源；运行 `node web/scripts/generate-alarm-rule-fields.mjs` 生成前端目录，`--check` 检查同步。
- `utils/rule_catalog.py` 统一五个序列化器的规则校验和 ORM 字段映射；`utils/multivalue_rules.py` 提供新操作符的内存语义与 ORM 编译。历史操作符继续由原匹配器执行。
- Alert 监控源匹配复用已有有界候选批次；告警源排除用关联 `Exists` 子查询，避免把“存在一个未排除源”误判成“所有源均未排除”。Action 字典提供全部关联源主键。
- 丰富匹配前补齐 `source_pk`、`content` 和与 Event 入库一致的监控源兜底值；只用于上下文的别名不写入 Event 模型。
- 五个正式页面复用 `settings/components/matchRule.tsx`，相关性和处理保留场景薄封装。操作符宽度和下拉宽度独立；标签区自动换行，说明置于条件下方。标题/正文和正则中的逗号不拆分。
- 保留旧规则原操作符和数据形态，包括历史 `in` 数组；切换兼容的新多值操作符保留标签，切换到单值操作符时仅保留单项候选值，否则清空并要求填写。
- 告警处理列表摘要显示本地化字段、明确的多值操作符和完整候选数组；Tooltip 保留完整规则。
- 发布先更新 API 服务和所有规则执行 Worker，再更新前端，防止旧 Worker 读取到不支持的新操作符。本轮多值能力没有新增数据库迁移；此前监控源能力的 `0031_alert_push_source_ids` 仍是前置条件。
- 回滚到旧 Worker 前须先停用或转换新操作符规则，不能只回退前端；现有旧规则无需批量迁移。
