# 告警监控源

> 2026-09-10：本文保留监控源存储和既有验证记录；规则操作符及五入口交互以 [最新实施文档](../alert-rule-types/implementation-plan.md) 为准，新方案已获确认并实施；[最新测试报告](../alert-rule-types/business-matching-test-results.md)。下文操作符与入口范围为初版历史记录。本次告警源排除恢复事件不改变监控源的存储维护范围。

## 目标与契约

告警中心把 Event.push_source_id 提升为 Alert.push_source_ids，界面统一称为「监控源」。
Alert 保存 JSON 字符串列表，按关联事件原值去重、排序，忽略空值，保留 default 与数字字符串的原始身份。
列表仅由事件关联流程写入，接口只读；普通聚合创建/追加、即时告警及恢复/关闭事件关联均维护该集合。
无关联事件的合成告警默认为空列表。更新字段不改变指纹、分派时机或已分派告警的责任人。

## 匹配与页面

- 分派规则 key 为 push_source_ids，屏蔽规则 key 为 push_source_id；两处均显示「监控源」。
- 每条条件输入一个字符串；等于/不等于按原字符串精确比较，包含/不包含及正则不区分大小写。
- 正向条件任一成员满足即命中，否定条件要求非空且全部成员不满足；空列表均不命中。
- 条件独立执行，继续遵循组内 AND、组间 OR；非法条件不能被忽略而扩大匹配范围。
- 仅为这两个规则入口提供字段选项；不扩展其他配置页面的共享默认字段。
- 两套详情基础信息均显示列表，支持换行、展开、复制，空值显示 --；列表、Incident 告警和关联告警响应带上字段。
- 现有分派策略按创建时间依次执行，成功后不再执行后续策略；仍未分派的告警沿现有任务重试。

## 实现边界与验证接口

沿前述方案和用户验收要点，验证聚合构建公开入口、即时派发入口、恢复关联入口、分派/屏蔽执行入口、序列化与关联告警查询接口，以及前端详情/条件编辑器用户交互。
按纵向切片先写失败回归，再补实现；额外覆盖列表匹配的五种操作符、AND/OR、空值、数字字符串、输入错误和重复执行。
列表匹配仅物化本批候选对象的主键与监控源，不把 JSON 文本当字符串搜索，不增加数据库方言专属查询。
普通聚合、恢复关联和历史回填在事务内协调 Alert 行锁，避免并发更新丢失来源。
历史回填使用独立 ORM 命令、稳定主键游标、预览和重跑；不放进启动或 schema migration，不产生分派/通知副作用。
未分派历史告警回填后，仍可能由既有兜底任务按新规则匹配。

## 发布与历史数据

本次仅修改代码，没有对业务数据库执行迁移或回填。部署时先应用 schema migration，再启动包含新字段的服务与任务进程。
独立提交的迁移 `0031_alert_push_source_ids` 直接依赖已发布的 `0029_alert_event_enrichment_meta`，不引入通知模板依赖。工作区其他未提交迁移仍保留原有串联关系，后续提交它们时须重新核对完整迁移图。

在配置好目标数据库环境的 `server/` 目录执行：

```bash
uv run python manage.py migrate alerts
uv run python manage.py backfill_alert_monitor_sources --dry-run --batch-size 200
uv run python manage.py backfill_alert_monitor_sources --batch-size 200
```

中断后可用输出的 `last_id` 作为 `--after-id` 续跑；全量重跑也幂等。未回填的旧告警显示 `--`，监控源分派条件不命中；新事件追加时也会刷新该告警全部关联事件的来源。回填不修改告警状态和更新时间，不直接发送通知，但既有待分派重试任务可使用回填结果。
