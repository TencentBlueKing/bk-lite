# 容量超额

Status: implemented

## Problem Statement

CMDB、监控和日志的许可还在有效期内时，实际用量可以超过已购容量，系统却只在许可页展示用量并发阈值提醒。客户无法区分「还在观察」和「已经限制新增与修改」，也没有一条按天计算、可恢复的容量状态。许可到期已经会整段拒绝模块接口，这次不能和容量超额混成一套规则。

## Solution

为 CMDB、监控、日志各维护一条容量状态：正常、观察期、已限制。每天计算一次。第一次发现用量超过额度时进入 30 个自然日观察期，期内权限不变。期满仍超额，则在返回给该模块的权限列表里去掉新增和修改，查看和删除保留。下一次计算发现用量回到额度内，权限恢复。已有采集、接入和处理继续运行，不丢数据，不因许可删除已有数据。许可过期仍按现有逻辑整段拒绝模块接口。

## User Stories

1. As a 许可管理员, I want CMDB、监控、日志在用量超过已购容量后进入 30 个自然日观察期, so that 客户有时间扩容或清退，期间系统仍可正常使用。
2. As a 许可管理员, I want 观察期从某次每日计算第一次发现超额的那天起算，并在之后某次计算发现用量回到额度内时解除, so that 删除或扩容不要求当场生效，恢复也不用等人重新登录。
3. As a 许可管理员, I want 观察期满后仍超额时，该模块的新增和修改从权限列表中消失，查看和删除仍在, so that 用户不能再扩大使用，但可以自己删除对象把用量降下来。
4. As a 超级管理员, I want 容量限制同样作用在我查询到的全量菜单上, so that 超管不能绕过新增和修改限制。
5. As a 运维人员, I want 已有采集、监控自动纳管和日志接入在限制期间继续运行, so that 已有链路不中断、已有数据不丢失、也不被许可自动删除。
6. As a 日志运维人员, I want 在日志已限制时仍能删除采集实例, so that 可以停掉后续采集；已入库日志不因这次删除而消失。
7. As a 许可管理员, I want 用量查询失败时容量状态保持不变, so that 一次统计故障不会被当成用量已经归零并提前解除限制。
8. As a 许可管理员, I want 许可过期的行为保持不变, so that 到期后的整模块拒绝不会被 30 天观察期削弱。
9. As a 登录用户, I want 许可进入现有提醒窗口，或 CMDB、监控、日志处于观察期或已限制时，在全局顶栏右侧看到许可提醒, so that 不用打开许可页也能知道快到期或容量超额。
10. As a 许可管理员, I want 在许可页立即重算 CMDB、监控和日志的用量, so that 不用等到次日计算就能看到当前已用和额度。

## Implementation Decisions

- 只新增容量超额。许可过期继续按有效期把许可标为过期；模块不再被任何生效许可覆盖时，该模块 HTTP 接口整段拒绝。容量状态机不处理过期。
- 范围是已有用量接口的三个模块：CMDB、监控、日志。告警无容量计数，作业按单次任务目标上限处理，都不进入这套状态。
- 每个模块一条容量状态，取值为正常、观察中、已限制。记录观察起始日、观察截止日（起始日起 30 个自然日）、最近一次成功测到的用量和额度、最近计算时间、最近一次用量不可用的错误类型。
- 额度是所有生效许可中该模块容量相加。CMDB 与监控比较实例总数和节点额度总数，日志比较磁盘占用和容量 GB。额度小于等于 0 视为未配置容量，不进入判断，与日志容量提醒在总额为 0 时不发送一致。
- 用量查询必须能区分「测到了」和「失败」。失败时不得把已用量写成 0，也不得迁移状态，只记录失败。
- 状态在完整计算，以及停用、过期后的快照重判时迁移：
  - 正常且已用超过额度 → 观察中，记下起始日和截止日。
  - 观察中且已用回到额度内 → 正常，清空观察期。再次超额重新计算 30 天。
  - 观察中且已到截止日并且仍超额 → 已限制。已限制期间不再重新给予 30 天。
  - 已限制且已用回到额度内 → 正常。
- 查用量的完整重算只在每天 09:15、许可页「重新统计」和导入许可。导入许可这次仍当场重算，怎么改还没定。删除实例、停采集、改配置当时不触发计算。「重新统计」重算 CMDB、监控、日志并写回容量状态，再返回模块摘要。它需要许可管理的查看权限。这不是缺行补算，会重算已有行。节点明细里的「刷新明细」只重取当前模块的用量明细，不写容量状态，成功后提示明细已更新。
- 停用和过期先改许可状态，再按还在生效的许可重加该模块额度。快照里已有已用时不查用量，用这份已用做上面的判断，已用、最近计算时间和用量失败记录保持不动。没有容量行，或行在但已用为空时，只查一次该模块的实际用量。测到了就写入已用、剩余许可总额和最近计算时间，清空用量失败记录，再做状态迁移。测失败时不把已用写成 0，也不迁移状态；没有行仍不插入，已有空行只更新额度。同一模块再判一次结果不变。
- 打开许可页时，已有快照只读，不重算用量。模块摘要发现 CMDB、监控或日志还没有容量行时，只对缺行的模块补算一次：测量成功才插入快照，额度为 0 也写入；测量失败不插入，下次摘要还可再试。已有行不在摘要里重算，已用为空也一样。顶栏不补算。
- 权限过滤发生在返回前，不修改角色上已保存的菜单勾选，也不把滤掉之后的结果写入权限缓存。模块处于已限制时，该模块返回的菜单里，操作名（菜单名第一个 `-` 之后）以 Add 或 Edit 开头的项去掉，Setting 也去掉。View、Delete、Execute 保留。超管拿到的全量菜单走同一过滤。写接口由 `LicenseCapacityGuardMiddleware` 按 `LICENSE_CAPACITY_WRITE_PERMISSIONS` 拦截新增和修改，超管不例外；未列入的路径不拦，删除、查询和采集写入不列入。不改 `HasPermission` 的超管放行。菜单和写接口拦截可用环境变量 `LICENSE_CAPACITY_RESTRICT_DISABLED` 关闭：变量存在且值为 `true`（忽略大小写和首尾空白）时不拦截。变量不存在，或值不是 `true`，超额限制照常生效。关闭后仍计算并在许可页和顶栏展示容量状态，只是不再从权限列表去掉新增和修改、也不在中间件拒绝写操作。
- 日志角色权限不是整模块只有 View 和 Operate。菜单里名为 Operate 的只有事件下的告警（`alert_list-Operate`），表示处理告警，容量已限制时保留。其余写操作已经拆开：策略、日志分组是 Add、Edit、Delete；日志接收是 Edit、Delete；接入列表是 Setting；接入配置是 Add。这些 Add、Edit、Setting 与 CMDB 一样从返回列表去掉，Delete 和 View 保留。
- 采集任务、监控自动纳管、日志已有写入不经过这道用户权限过滤，继续更新已有对象，也可以写入新实例。不因容量状态丢弃数据或删除已有数据。限制期间用量仍可能上涨；涨回去后仍要等下一次计算才恢复。若先恢复再次超出，重新进入观察期。
- 监控用量维持现有口径：未删除且已启用的收费实例才计入。发现对账把实例标成停用后，下一次计算自然不再计入。不为停用再做许可特判；用户主动停用属于修改，已限制时随 Edit/Setting 一并不可用。用户主动把监控数量降下来的操作是删除。
- 日志删除采集实例只停止该路后续采集，不删除已入库日志。日志用量下降来自扩容，或 VictoriaLogs 自身保留期使磁盘占用下降。日志模块不新增手动删除已入库日志的能力。
- 模块摘要和三个用量接口返回容量状态、观察起始日、截止日、剩余天数、最近用量和额度。许可页在用量旁显示观察期剩余天数或已限制新增和修改。已用或额度为空，或额度小于等于 0 时不画用量条；已用为 0 且额度大于 0 时显示 `0 / 额度`。节点已用和额度按四舍五入显示为整数，日志占用按 GB 四舍五入到两位小数，不补零。是否画出用量条以取整前的快照为准。
- 模块摘要对 CMDB、监控、日志附带模块级提醒阈值。阈值来自该模块自己的提醒配置，不返回对象级覆盖。log_memory 只保留日志额度，不返回提醒的模式、阈值、渠道和人员。许可页卡片用这个阈值。打开该模块的「提醒设置」才请求完整提醒配置；保存后用保存结果更新卡片上的阈值，不重新请求模块摘要。
- 许可页首屏同时等待许可列表和模块摘要，到齐后一起展示。注册码在打开添加许可时请求。历史许可在打开历史时请求。默认提醒、单条许可提醒、节点提醒和日志提醒第一次打开时请求全局提醒、渠道和人员。CMDB 或监控的节点明细只请求该模块的用量接口，抽屉里的刷新只更新该抽屉，成功后提示明细已更新。日志没有节点明细。重新统计期间模块区显示卡片骨架，成功后提示统计数据已更新。
- 状态迁移打一条稳定模板日志，带模块、原状态、新状态、用量和额度。这次不发送进入观察期、剩余 7 天、已限制或解除的渠道通知。
- 全局顶栏右侧、通知铃铛左侧放许可提醒。没有快到期，也没有观察期或已限制时不出现。鼠标悬停展开详情。不占一整条横幅，也不放进通知铃铛。这次不从浮层跳到许可页。
- 快到期沿用许可卡片的提醒窗口：跟随默认或单许可自定义的提醒天数。剩余天数大于等于 0 且小于等于该天数时列入，到期日当天仍算快到期。不改到期判定、不改提醒天数、不改整模块拒绝。
- 容量只列入观察中和已限制，读已算好的状态、剩余天数、最近用量和额度。这次请求不调用过期同步，也不重算用量。
- 已登录用户都能读取，不要求许可管理的查看权限。响应只有有效期和容量事实，不含许可密钥、被许可方、注册码。社区版没有许可模块时，请求失败则顶栏不出现提醒。
- 顶栏许可提醒只在壳层挂载时请求一次。导入许可后后端仍查用量并重算。停用和过期在快照已有已用时只调整额度；没有已用时查一次该模块用量。许可页会重新拉数，已挂载的顶栏不自动刷新；要看最新提醒需整页刷新。这次不补推送或轮询。

## Testing Decisions

- 好的测试锁住外部行为：状态迁移、权限列表里还有哪些操作名、新增/修改被拒绝而删除仍成功、用量失败时状态不变、过期许可仍整段拒绝。不断言内部查询次数。
- 状态机用冻结日期覆盖四类迁移和「起始日起第 30 个自然日」的边界。用量不可用时状态与上次成功测到的用量保持不变。
- 权限测试覆盖普通用户和超管：已限制时 Add、Edit、Add Associate、Edit Model、Setting 不在返回列表中，View、Delete、Execute 仍在。角色保存的菜单勾选不被改写。解除后的下一次查询恢复 Add 和 Edit，不等待权限缓存过期。
- 禁用超额限制：`LICENSE_CAPACITY_RESTRICT_DISABLED` 不存在，或值不是 `true` 时，已限制仍过滤权限并拦截写接口。值为 `true` 时权限列表仍含新增和修改，容量写接口中间件不拒绝，许可页和顶栏仍返回已限制。
- 容量写接口中间件：已限制且路径命中 `LICENSE_CAPACITY_WRITE_PERMISSIONS` 时超管和普通用户均 403；未命中的删除、查询放行；观察中或开关关闭时放行。
- 日志在已限制时，策略、分组、接收、接入配置上的 Add、Edit、Setting 不在返回列表中，对应的 Delete 和 View 仍在；告警的 Operate 仍在。删除采集实例成功。
- 观察期内上述写操作仍成功。导入一张提高额度的许可后，紧接着的计算能解除已限制。过期路径的整模块拒绝保持现有测试语义。
- 前端只断言许可页根据返回的容量状态展示剩余天数或已限制，不把状态计算放进页面。
- 顶栏接口：观察中和已限制列入，正常不列入；提醒窗口内的生效许可列入，窗口外和已过有效期的不列入；响应不含密钥、被许可方、注册码；没有许可查看权限的登录用户仍可读取；这次请求不触发过期同步和容量计算。
- 模块摘要缺行补算：没有容量行且测量成功时写入已用、总额和状态，超额从当天进入观察期；测量失败不插入；已有行即使已用为空也不重算，错误类型保留；额度为 0 的成功结果仍写入；顶栏读取不触发补算。
- 停用和过期：快照已有已用时不调用用量测量，额度等于剩余生效许可之和，已用仍是快照。已用超过新额度时从正常进入观察期；回到额度内时解除观察或已限制；新额度小于等于 0 时回到正常。没有容量行或已用为空时查一次用量：测成功写入已用和剩余许可总额并完成上述迁移，总额不采用用量接口返回的额度；测失败不把已用写成 0，没有行不插入，已有空行只改额度并保留错误类型。未覆盖的模块快照不变。
- 重新统计：三个模块都被重算，摘要返回写入后的已用和额度。它走每日计算，不走缺行补算。没有许可查看权限时接口拒绝，且不重算。
- 顶栏前端只断言空数据不展示、仅快到期或观察期为预警色、任一模块已限制为失败色。

## Out of Scope

- 改变许可过期的判定、邮件提醒和整模块拒绝。顶栏只读取现有提醒窗口。
- 告警容量口径，以及作业平台按单次任务目标数拦截。
- 在采集、自动纳管或日志写入链路上拒绝新实例。
- 按专用节点或单个模型分别判定超额。
- 删除或停用当时立即重算并恢复权限。
- 为日志中心增加手动删除已入库日志或配置保留期。
- 把过滤后的权限写回角色或权限缓存。
- 导入或停用许可后自动刷新已挂载的顶栏许可提醒。
- 容量超额的渠道通知：进入观察期、观察期剩余 7 天、进入已限制、解除各发一次。

## Further Notes

- 需求原文把告警中心列在持续占用模块中。告警目前没有容量字段和用量接口，本规格明确不覆盖。
- 日志磁盘能否自己下降，取决于 VictoriaLogs 进程是否配置了保留期。本规格不把该配置当成日志模块的产品功能。
