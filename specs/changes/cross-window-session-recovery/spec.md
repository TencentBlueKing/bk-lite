# 跨窗口登录态恢复

Status: proposed

## 问题

BK-Lite 用户可能同时打开多个控制台窗口。当前任一窗口中的受保护请求返回
401 后，该窗口会独立展示登录遮罩；在其中一个窗口重新登录成功，只会刷新该
窗口。其他窗口既收不到恢复通知，也不会重新获取 NextAuth session，必须手动
刷新才能关闭遮罩。刷新会卸载当前页面，可能丢失尚未提交的表单、抽屉和编辑器
内容。

## 目标

任一同源窗口重新登录成功后，所有已打开窗口都应原地恢复认证并关闭登录遮罩，
不刷新页面、不重新加载业务数据，并保留尚未提交的前端状态。

## 行为契约

- 有效登录态下的受保护请求返回 401 时，仅在发生失效的窗口展示登录遮罩。
- 任一窗口重新登录成功后，向所有同源窗口广播“认证可能已恢复”事件。
- 广播只表达状态变化，不携带 token、用户信息或其他凭据。
- 每个接收窗口必须自行重新获取 NextAuth session；只有取得有效 session 后，
  才更新本窗口认证状态、API token、会话失效门闩并关闭登录遮罩。
- 发起登录的窗口也通过相同恢复流程更新 session，不使用
  `window.location.reload()`。
- 恢复过程不重新挂载页面，不主动刷新业务数据，保留表单、抽屉、弹窗、分页、
  编辑器及其他未提交的 React 状态。
- 会话失效后已经失败或被阻止的业务请求不自动重试；保存、删除、执行任务等写
  操作不得自动重放。
- 登录恢复只解除后续受保护请求的暂停。用户再次主动提交时，使用当前最新页面
  状态创建新请求。
- 恢复成功后每个可见窗口最多展示一次提示，明确此前失败的操作需要重新提交。
- 接收窗口无法取得有效 session 时，继续保留登录遮罩和请求暂停状态，不误报
  恢复成功。

## 实现决定

### 1. 窗口间信号

- 使用 `BroadcastChannel` 作为同源窗口间的主要通知通道。
- 使用 `localStorage` 的 `storage` 事件作为不支持 `BroadcastChannel` 时的
  兼容兜底。
- 事件包含协议版本、随机事件 ID 和发生时间，用于兼容演进和单窗口去重。
- 模块只暴露订阅恢复事件、发布恢复事件和释放资源的小接口；认证上下文不直接
  理解两种浏览器传输的细节。
- 本窗口不依赖浏览器是否回送自己发布的消息；登录成功处理函数必须显式进入与
  接收窗口相同的本地恢复流程。

### 2. 本地恢复

- `AuthProvider` 负责恢复编排，通过 NextAuth `useSession()` 提供的更新能力
  重新读取当前 session。
- session 有效后，再原子完成本地 token 更新、`sessionExpired` 状态重置和
  登录遮罩关闭，避免遮罩已经关闭但请求仍使用旧 token。
- API 客户端继续从更新后的 session/AuthContext 获取 token，不从跨窗口事件
  直接接收 token。
- 同一窗口同时收到重复事件或本地恢复仍在执行时，共用一个进行中的恢复过程，
  不重复读取 session、不重复提示。
- 组件卸载时关闭 BroadcastChannel 并移除 storage 监听。

### 3. 请求边界

- 会话失效门闩保持现有 fail-fast 语义：失效期间新的受保护请求在客户端被
  阻止，避免连续产生 401。
- 恢复成功后只重置门闩，不保存、排队或回放失败请求。
- GET 请求也不自动刷新，因为配置详情查询可能覆盖正在编辑的本地草稿。
- 460 强制退出语义不变，不参与可恢复的跨窗口 401 流程。
- 登录、认证探测、分享 prepare 等既有忽略路径保持现有语义。

## 异常与竞态

- 广播表示“应重新验证”，不表示接收窗口可以直接信任已恢复；共享 Cookie 或
  NextAuth session 才是认证事实来源。
- 旧 token 发出的在途请求若在恢复后才返回 401，不得重新打开登录遮罩。沿用
  请求发起时 session identity 与当前 identity 的比较，忽略旧身份的迟到响应。
- 恢复失败允许用户在当前或其他窗口再次登录；后续新的恢复事件必须能够再次
  触发验证。
- localStorage 兜底键只保存非敏感事件信封；写入失败不影响支持
  BroadcastChannel 的正常路径。
- 新打开窗口通过正常初始化认证检查取得当前 session，不依赖收到历史广播。

## 验证

- 多个窗口同时展示登录遮罩时，在一个窗口登录后，其余窗口无需刷新即可关闭。
- 发起登录的窗口也不调用 `window.location.reload()`。
- 恢复前后未提交表单、打开的抽屉和编辑器内容保持不变。
- 恢复期间失败的 GET、POST、PUT、PATCH、DELETE 均不自动重放。
- 恢复后的新请求使用新 token。
- session 更新失败时保留遮罩和会话失效门闩。
- 重复恢复事件只进行一次并发 session 更新并最多提示一次。
- BroadcastChannel 不可用时，storage 事件仍能触发其他窗口恢复。
- 旧身份的迟到 401 不会在新 session 生效后重新打开遮罩。
- 460 强制退出和既有认证忽略路径行为不回归。
