# CMDB 服务树

Status: approved

## Problem Statement

系统 → 应用 → 主机已是监控、僵尸机和 3D 应用墙的主线，但 CMDB 里它只是普通关联，没有独立工作台。现有「应用拓扑」按跳数展开成五带资源图，中间件、库、机柜都会进来，无法承担分配、转移和按路径导入。蓝鲸用业务拓扑把组织树做成左树右表，但主机只能进一个模块，和 Weops X 的多归属原则冲突。

## Solution

在应用系统详情与「应用拓扑」并列增加 **服务树**：左树只放应用系统 / 业务分组 / 应用，右侧列表承载主机与结构操作。组织脊柱保持单父，主机对应用保持多对多。第一期只改 CMDB 与运营分析。

## User Stories

1. As an 运维人员, I want 在应用系统详情打开服务树并按左树选择节点, so that 组织主线和五带资源图分开
2. As an 运维人员, I want 在系统与应用之间插入自定义模型并在服务树上按模型名新建节点, so that 没有自定义模型时不出现额外分组按钮
3. As an 运维人员, I want 选中应用后把已有主机分配上去, so that 一台主机可以同时挂多个应用
4. As an 运维人员, I want 把勾选的主机从当前应用转移到任意可见应用, so that 只换当前这条边、其它挂靠保留
5. As an 运维人员, I want 把勾选的主机从当前应用解除挂靠, so that 主机资产和其它应用上的挂靠都还在
6. As an 运维人员, I want 按「系统 / 分组 / 应用 / 主机」批量导入导出, so that 缺的分组和应用能按路径创建、对不上的主机该行失败
7. As an 运营分析使用者, I want 系统下主机和 3D 部署树沿服务树展开并画出分组, so that 插层后不会漏主机

## Implementation Decisions

- 服务树不是第二套归属库。存储仍用模型实例和关联；新增内置模型「业务分组」。`system contains application`（1:n）与 `application run host`（n:n）保留。分组相关 contains 为 1:n，分组最多自嵌套两层。
- 应用在服务树上只有一个父（系统或某一分组）。主机只挂在应用上，不挂系统或分组。
- 入口只在应用系统详情，Tab 名「服务树」；现有「应用拓扑」与 CMDB 应用专题仍是五带资源图。展示为左树右表，主机不进左树。右侧只展示主机，不展示子节点表。选中系统或分组：其下主机只读汇总；选中应用：可分配、转移或解除挂靠。切换节点时先清空主机再加载。树上不硬编码「新建业务分组/应用分组」；只有用户在应用系统与应用之间配置了自定义模型（contains 路径）时，才出现「新建{该模型名称}」。
- 分配：增加应用运行于主机的边，不拆其它边。添加主机弹窗后端分页、可搜索，勾选跨页保留。转移、解除挂靠只作用于右侧勾选的主机。写操作只校验组织树，不重建带主机的整棵树。转移只拆当前选中应用上的边，目标为当前用户可见的任意应用（可跨系统）。转移目标应用下拉展示「应用系统 / 应用」。解除挂靠只拆当前应用这一条边，主机资产和其它应用挂靠保留。写入时使用模型目录里实际的 run 关联 ID，不写死 `application_run_host`。
- 树上默认可新建、重命名应用；主机不在树上新建。自定义中间层节点的新建按钮读取该模型名称。分组有子则不能删。删除应用只删应用实例和树上的边，主机资产保留。第一期不做拖拽改挂。
- 导入一行 = 已有主机 + 路径列（系统、分组、二级分组可空、应用、主机标识）。空分组列 = 应用直挂系统。缺分组/应用则创建；主机按现有唯一规则匹配，对不上该行失败。语义是分配不是覆盖。导出是同一张表的反向。
- 「系统下有哪些主机」在 CMDB 服务树和运营分析中沿 `系统 → 业务分组* → 应用 → 主机`。3D 部署树画出分组。第一期不改监控等其它模块；不得把旧两跳展开函数偷偷改成新语义。
- 展示参考：`docs/design/product-decisions/cmdb-service-tree-preview.html`。

## Testing Decisions

- 好测试只验证：混深路径展开、应用单父、主机多归属、分配不加拆、转移只拆当前边、解除挂靠只拆当前勾选边、导入创建缺失分组/应用且拒绝未知主机、有子分组不可删、删应用保留主机、运营分析沿分组展开、其它模块仍走旧两跳。
- 约定接缝：服务树展开、分配/转移/解除挂靠、导入路径解析、应用系统详情 Tab、服务树中间层新建按钮（无自定义模型则不出现，有则读取模型名称）、运营分析 3D/系统下主机查询。
- Prior art：`application_system.py` 两跳展开、`application_run_host` n:n、`system_contains_application` 1:n。

## Out of Scope

- 把 CMDB 应用专题默认改成服务树
- 监控等其它模块跟新口径
- 拖拽改挂、空闲机、在树上新建主机、把任意模型标成服务树节点但不在系统-应用 contains 路径上
- 用服务树替换五带应用拓扑
- 主机在一个应用下的独占归属

## Further Notes

- 工作名「业务分组」；若产品文案改为「集群」需同步术语，不改变模型职责。
- 不要把蓝鲸「一台主机一个模块」带进 Weops X。

## Completion Evidence

已实现并通过约定接缝测试。

- 域：混深展开、旧两跳不变、分配不加拆、转移只拆当前边、解除挂靠只拆当前勾选边、导入按路径创建缺失分组/应用且拒绝未知主机、同名应用按路径区分、有子分组不可删、不可见节点不进树。
- 种子：内置模型 `biz_group` 与 1:n contains 关联；系统拓扑主题含 `service_tree`。
- API：应用系统详情服务树 CRUD / 分配 / 转移 / 解除挂靠 / 导入导出；转移目标不可见返回 403。
- Web：应用系统详情 Tab「服务树」左树右表；主机不进左树；无左导航入口、无拖拽改挂。默认不展示新建分组按钮；自定义模型出现在系统-应用 contains 路径上时，按钮文案为该模型名称。
- 运营分析：3D 部署树画出业务分组（应用平面后一排）；系统下主机沿服务树展开。僵尸机报表沿既有 NATS `list_host_uuids_for_systems` / `list_monitored_hosts_for_systems` 使用新展开器。
- 验证：`server` 聚焦 pytest 91+ 通过；web vitest：treeModel、relationships 隔离、3D architecture。
