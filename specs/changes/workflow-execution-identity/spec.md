# 编排中心定时执行身份

定时节点在发布时绑定当前登录账号与一个执行组织。编辑时账号只读，组织选择器默认当前组织；后端从认证上下文取得账号，并校验所选组织。已发布节点展示该版本绑定的账号。以定时入口调试时按调试用户和所选组织执行，可在发布前验证身份。调试流程和重新调试按钮旁显示本次调试账号与组织，切换调试入口时，确认弹窗中的身份提示随之更新。其他人启停流程时继续使用原版本的绑定，重新发布时由本次发布人重新绑定。

## 执行与权限

- 调度器在每次新执行前检查账号状态、可用组织、流程执行和实例操作权限。重复的调度按既有幂等键复用执行。授权失败时停止本次启动。
- 执行记录保存实际账号、域、执行组织及单组织调用身份。执行记录的查看权限仍由流程归属决定。OpsPilot 工具以执行身份调用目标模块，记忆读写使用执行组织可见的空间，个人空间绑定执行账号，组织空间绑定执行组织。
- 编排中心的定时、NATS 和 Webhook 自动执行在 OpsPilot 工具审批中归为无人值守；表单运行沿用交互式审批。
- OpenAPI 使用网关注入的真实调用者和其有权操作该流程的一个组织。平台模块通过 `apps.rpc.workflow.invoke_nats_workflow(request, trigger_id=..., subject=..., event=...)` 发起带用户身份的 NATS 调用。接收端验签并校验目标组织、主题和流程权限，托管通知按系统事件执行。
- 升级前发布的版本缺少执行组织，沿用原调度方式，重新发布后绑定个人身份。只有带已验证执行身份的自动流程可以访问个人记忆和需要调用者身份的工具。

流程包导入和导出会移除账号与组织绑定。部署需应用 workflow 的 0005 数据库迁移，并同时更新编排 Worker、调度器和 NATS 发送与接收服务。托管通道和用户调用使用各自的签名用途。关闭旧版共享密钥回退的部署沿用现有编排内部事件签名密钥。
