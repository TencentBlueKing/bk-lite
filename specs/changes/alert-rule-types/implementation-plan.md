## 4. 统一匹配契约

保留 match_rules 二维数组及 key/operator/value 结构；同组 AND、组间 OR。字段目录分别记录实际值类型、值基数、条件 value 类型、场景和取值方式。

| operator | 条件 value | 语义 |
| --- | --- | --- |
| eq / ne | 单字符串 | 完整字符串相等/不等 |
| contains / not_contains | 单字符串 | 文本连续子串包含/不包含 |
| re | 单字符串 | 仅矩阵明确开放的字段支持正则 |
| any_of | 非空字符串数组 | 标量属于候选集；集合与候选集有交集 |
| all_of | 非空字符串数组 | 仅集合使用，包含全部候选项，允许额外成员 |
| none_of | 非空字符串数组 | 标量不在候选集；集合与候选集无交集；实际值必须有效且非空 |

级别界面显示“包含/不包含”，保存 any_of/none_of，值为当前场景合法枚举代码数组。单候选也用长度为 1 的数组；不把数组包装为 eq 或字符串 contains。

精确名称、ID 字符串、集合成员匹配区分大小写；文本包含及保留的正则沿现有不区分大小写语义。空白实际值视为空；文本输入不因逗号、星号或百分号变成数组或通配符。ORM 与内存结果通过同夹具核验，不以数据库默认排序规则代替业务契约。

最多 20 组、合计 100 条条件；数组 1–50 项，每项最多 256 字符。标签去除输入首尾空白、忽略空标签、按完整字符串去重，保留内部空格。不按逗号自动分割告警源名称，名称中的逗号是名称的一部分。文本单输入保留原文。

空候选数组是非法配置；缺失/null/空白实际值/空列表是有效执行中的“不命中”。非法字段、非法类型和非法操作符导致整条规则不命中，不能忽略坏条件而放宽范围。API 拒绝非法保存；ALL 与 FILTER 模式沿原入口契约，FILTER 未完成不能当作 ALL。

## 5. 告警源关联查询（方案 1）

### 5.1 来源集合的唯一定义

对 Alert，来源集合为其关联 Event 中 `action != EventAction.RECOVERY` 的非空 `source.name` 去重结果；使用 ORM 的 exclude 与枚举常量实现。恢复排除依据 Event.action，不依据 Alert 是否已恢复，也不依据来源名称猜测。

- 已恢复 Alert 的原产生事件仍参与；恢复事件始终不贡献来源名称。
- 本次仅排除 recovery，不额外排除 closed 事件。
- 同名的不同 AlertSource 按同一个名称处理；比较和详情去重口径一致。
- 规则保存名称，不解析成 ID；允许保存当前尚不存在的名称，之后新接入同名来源可以命中。
- 改名后按最新关联名称匹配，规则标签不自动改名；该选择不提供不可变历史名称快照。
- 停用/软删除不凭选项目录丢弃已关联来源名称；硬删除导致 Event 级联删除时集合随之变化。不增加软删除来源选择接口。
- Alert.source_name 保持现有数据库类型和通知/绑定用途，不改 JSON；source_names 仅为派生查询/响应数据，不做回填或第二份持久化。
- Event 场景使用该 Event 的来源名称；恢复排除约束针对 Alert 集合，不擅自改变 Event 入口原有生命周期处理范围。

示例：产生事件 A、A、B 加恢复事件 C，集合为 `[A,B]`。

| 条件 | 结果 | 原因 |
| --- | --- | --- |
| 包含任一 [B,C] | 命中 | B 来自产生事件 |
| 包含任一 [C] | 不命中 | C 只来自恢复事件 |
| 包含全部 [A,B] | 命中 | 两个名称齐全 |
| 包含全部 [A,C] | 不命中 | 恢复事件不补齐 C |
| 不包含 [C] | 命中 | 有效集合非空且无 C |
| 不包含 [A,C] | 不命中 | 有 A 即不能通过排除 |
| 仅关联恢复事件时，任意条件 | 不命中 | 有效集合为空，否定也不命中 |

### 5.2 ORM、内存和执行时机

任一使用关联 Exists；不包含使用“存在有效来源 AND 不存在命中候选来源”。全部使用命中的去重名称计数等于去重候选数，或等价的逐候选 Exists。必须在同一关联子查询中限定 Alert、非恢复和有效名称，不能简单对连接行取反，也不能统计 Event 数代替名称数。

从已有组织/状态/时间/会话限制后的 Alert QuerySet 继续过滤，不从全量 Event 查询扩大范围。所有新集合取值走同一内部来源解析逻辑；列表按页/批次读取，动作一次评估按需读取并复用，不逐规则重复查询。

告警处理当前基于字典匹配，必须提供相同 source_names 集合；丰富发生在入库前，必须从已解析的接入来源对象提供 source_name。规则上下文与动作参数、Provider 入参、通知变量分开，临时字段不得写入 Event 构造参数。

新增关联 Event 后按实际评估时的数据判断。沿用待分派重试、既有 Action 触发和幂等机制；不新增“来源变化”触发、不自动重分派、不撤销已执行动作。异步动作按 Worker 实际读取时的关联状态匹配，非触发瞬间快照。不得跨执行缓存来源集合造成追加/改名后陈旧。

### 5.3 详情和列表一致性

详情只读响应提供 source_names 字符串数组，按名称去重并稳定排序，空集合显示 `--`。告警详情页、详情抽屉以及复用该基础信息的关联告警路径同步接线，不能仅改 Storybook。

告警列表的“告警源”筛选同步使用名称标签和相同关联范围，多个名称默认任一匹配。新筛选参数使用 source_names，与旧 source_name 参数区分；不静默重新解释原有对外 API 参数。通知模板、动作绑定中 source_name 的既有协议保持原行为。

监控源 push_source_ids 继续保留原持久化及恢复/关闭关联维护契约；本次“排除恢复事件”不扩展到监控源。
