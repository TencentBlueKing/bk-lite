# APM 列表视觉治理

## 背景

APM 的自动高度页面曾直接使用面向固定高度工作区的 `CustomTable`。该组件会根据父容器计算表体高度并将分页绝对定位；当父容器没有明确高度时，表体被压缩为最小高度，产生内部滚动、行截断、分页悬浮和列表贴边。其他原生 Ant Design 表格又各自声明密度和列宽，造成同一模块内表头、正文、分页与留白不一致。

## 设计决定

- APM 二级导航已经标识当前页面，路由壳不再重复渲染标题、图标和说明卡。页面内容直接进入筛选、摘要或业务工作面；路由标题仍以仅供辅助技术读取的 `h1` 保留语义层级。
- 应用卡中的服务数与告警数都是下钻入口：服务数进入已按当前应用筛选的服务视角，告警数进入告警列表；两者均使用可聚焦的真实链接，并提供明确的无障碍名称。
- APM 自动高度列表统一使用 app-local `ApmDataTable`，继续组合 Ant Design Table，不修改 shared `CustomTable` 及其 OpsPilot 等消费者。
- 列表只保留一层 `ApmSurface` 边框和 16px 内边距；表格自身无边框、无独立圆角，依靠二级表头背景和 Ant Design 行分割线建立层级。筛选区、列表标题和表格之间使用 16px 间距，不让表格贴住承载面四边，也不形成卡片套卡片。
- 直接控制同一结果集的搜索、筛选、统计和操作栏必须与表格或视图共用一个 `ApmSurface`。普通列表使用 16px 间距，画布型视图使用 1px 分割线；不得把条件区和结果区拆成两个相邻卡片。
- 普通资源列表的表头默认统一左对齐；指标型表格可显式让表头跟随列语义，确保文本左对齐、状态居中、数值与操作右对齐，表头与正文共享同一视觉轴线。数字列使用 tabular figures。
- 列宽只用于状态、数值和操作等稳定窄列。名称、服务、资源等主信息列参与剩余宽度分配，并使用省略与 Tooltip 保护长文本。
- APM 工作区在小于等于 `1920px` 时占满可用宽度，超宽屏以 `1920px` 为最大内容宽度并居中，避免主信息列或百分比列在 4K 视口被无意义拉长。
- 响应式按任务优先级隐藏次要列，而不是强制 `scroll.x`：窄屏保留实体身份、关键状态和操作；时间、组织、趋势与次要指标逐级在 md/lg/xl/xxl 展示。
- 分页默认 20 条，提供 10/20/50/100，显示总数；小屏隐藏总数字样并使用精简页码。
- 查询结果不创建隐式表体滚动。只有日志、命令和明确固定高度的工作区允许局部滚动。

## 覆盖范围

- 服务目录、服务详情调用链与 SLO、服务拓扑依赖列表、SLO 列表。
- 调用链明细与聚合、端点及端点样本、Trace 属性、错误分组列表。
- 告警、策略、应用管理、应用详情下属服务、接入实例。

## 验收

- APM 二级页面不出现重复介绍卡，首屏直接展示可操作内容；文档结构仍存在唯一页面级 `h1`。
- 应用卡的服务数可通过鼠标或键盘进入当前应用的服务列表，且不误触应用详情卡片。
- 3840、1920、1440、1024、768、375px 下页面无整页横向滚动，表头与单元格列边界一致；3840px 下工作区宽度不超过 1920px。
- 普通资源表的表头统一左对齐；指标表的数值、状态和操作表头必须与对应正文对齐。
- 直接查询列表只出现一圈承载面边界，筛选条件和查询结果在同一工作面内连续排列。
- 自动高度列表完整展示当前页数据，不出现约 160px 的隐式表体滚动区。
- 列表四周至少保留 16px 桌面留白，且只出现外层承载面边框；375px 下单元格横向 padding 收敛至 8px。
- 亮暗主题下表头、边框、hover、固定列和分页均使用语义 token。
- loading、empty、error、长中英文资源名、数字列和行操作均通过页面或 Storybook 契约验证。
