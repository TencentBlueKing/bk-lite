# OpenAPI 网关调用写入审计日志

Status: complete

## Problem Statement

第三方用个人密钥或系统密钥打 OpenAPI 网关时，控制台审计页看不到这些调用。现有网关只在进程 INFO 里打 `openapi_access`（身份、钥匙、method、path、状态、耗时、body 的 sha256），运维可以搜日志，审计员不能在「审计日志」里按组织和钥匙筛、也不能导出。操作日志只覆盖控制台里的增删改执行，登录日志只覆盖登录，都对不上「哪把钥匙调了哪个网关接口」。

## Solution

在平台设置的审计日志页增加第三个页签「API调用日志」。网关在内部 invoke 与外部 ForwardAuth 结束时，把一次调用已识别的身份、钥匙、认证时刻组织和 HTTP 摘要写入独立的调用日志表（不落入参、出参、sha256）。查询与导出对标登录日志：只读、可筛、可导出 Excel；进页仍用审计日志查看权限。有该权限的人看到全部调用，不按当前组织裁剪。进程 INFO `openapi_access` 维持冻结模板，与本表并存。

## User Stories

1. As an 具备审计日志查看权限的管理员, I want 在审计日志页看到「API调用日志」页签, so that 网关调用与操作日志、登录日志在同一入口。
2. As an 审计员, I want 按时间、用户、密钥类型、接口类型和成功/失败筛选调用, so that 能回答「哪把钥匙以哪个用户身份调了哪条路径、网关放行还是拒绝」。
3. As an 审计员, I want 列表看到方法加路径、源 IP、成功/失败和错误码, so that 扫一眼能读懂这一跳，不用再打开详情。
4. As an 具备审计日志查看权限的审计员, I want 看到全部组织的调用, so that 系统密钥代其他组织的用户调用时不会因为当前组织而被藏起来。
5. As an 审计员, I want 用户名为空的调用同样出现在列表里, so that 认不出主体的乱试、以及系统 Token 命中但没有已校验用户的调用不会从审计里消失。
6. As an 审计员, I want 过期钥匙被继续使用时仍能对上那把钥匙（和个人令牌的绑定用户/组织，或系统 Token 的系统 ID）, so that 「这把已知钥匙还在被谁用」查得到。
7. As an 审计员, I want 按当前筛选或勾选行导出 Excel, so that 可以交付合规材料。
8. As a 网关调用方, I want 写调用日志失败时接口响应不变, so that 审计落库不会拖垮或打断 OpenAPI。

## Implementation Decisions

- 主职责是密钥追溯与合规，不是排障、用量统计或钥匙生命周期。钥匙的创建、编辑、删除仍只写操作日志。
- 新建独立调用日志模型与只读查询/导出接口，不塞进操作日志。权限位复用审计日志查看，不新增权限。
- 记录范围：内部统一 invoke 的一切终态（含认证失败）；外部 ForwardAuth 视图的一切终态（放行 200、认证失败、`SCOPE_DENIED` / `ROLE_REQUIRED` / `TEAM_OUT_OF_SCOPE` 等 403、快照查无服务的 404）。不记录 `_me`、`_docs`。本表只识别个人密钥与系统密钥。
- HTTP 状态码是网关回给调用方的状态码。ForwardAuth 的 200 是「允许 Traefik 反代」，不是上游业务 200。上游 502/超时仍在 Traefik，不进本表。库列名 `http_status`。
- 不存请求入参、响应正文、`request_sha256`。GET query 与 Forwarded URI 上的 query string 都丢掉。进程 INFO 继续按冻结访问日志模板打 sha256，本表不搬那一列。

### 身份：用户名空与钥匙未识别是两件事

可见性不按组织裁剪。钥匙是否识别看钥匙字段是否为空，与用户名是否为空相互独立：系统 Token 已命中但 acting 头缺失时，用户名为空、钥匙字段有值，这一行仍然进列表。

写入规则：

- 凭据类型、钥匙 ID、钥匙名称、系统 ID：**哈希已经命中钥匙行就照填**，不因最终 401/403 清空。系统 ID 只在系统密钥上填写。
- **用户名、组织 ID 只在用户通过校验后才落列**（用户存在且启用）。请求头里未经校验的 acting 值不写进这两列，与「身份从凭据推导、不信任入站头」一致。因此「acting 用户不存在 / 未启用」落成用户名为空 + 钥匙字段有值；「组织越权」（用户已校验、只是不在该组织）仍带用户名，组织 ID 记此次 acting 组织。这两类行都进列表。本表不存 domain。
- 凭据不是一把已命中的个人密钥或系统密钥时（缺 Bearer、形态不匹配、哈希查无此行含过期/禁用、JWT 或其他凭据）：用户名、凭据类型、钥匙 ID、钥匙名称、系统 ID 都空。仍写一行，HTTP 状态码按网关实际返回填写。
- 存储哨兵一律空字符串 / SQL NULL，不用 INFO 模板里的 `-`。展示层再渲染 `--`。钥匙名称、系统 ID 空串；钥匙 ID、组织 ID 用 NULL。

### 过期钥匙的审计身份（网关认证的附带改动）

个人令牌 `find_by_api_secret` 与系统 Token `find_live_by_secret` 都带活行条件（未过期；系统 Token 还要求 `enabled=True`）。认证成功路径**保持这个口径**：过期或禁用的钥匙仍然 401，不能变成可调用。其它入口（含 opspilot 直查个人令牌）不放宽。

活查失败后，网关认证再按哈希查一次**含过期、系统 Token 含已禁用**的行，只用于填 `AuthenticationFailed.identity`。响应仍是无效凭据；调用日志能对上那把钥匙。个人令牌过期且绑定用户仍存在时，用户名/组织来自钥匙行（用户已是行上的绑定主体，不是入站头）。系统 Token 过期/禁用时填钥匙字段与系统 ID；acting 用户仍须通过校验才落用户名，未带到已校验用户则为空。

### 表字段

查询维全部是列，不把 HTTP 摘要做成唯一 JSON 存储。类型约定：

| 列 | 类型 | 空值 | 筛 |
|---|---|---|---|
| 创建时间 | DateTime，索引 | 否 | 时间范围 |
| 源 IP | GenericIPAddress | 解析失败为 `0.0.0.0` | 否（列表展示，不筛） |
| 用户名 | CharField(100)，索引 | 无已校验用户时 `''` | 有 |
| 凭据类型 | CharField(16)，choices：`api_token` / `system_token` | 未识别凭据时 `''` | 有（个人密钥 / 系统密钥） |
| 钥匙 ID | 可空正整数，不建外键 | 未识别钥匙为 NULL | 否（导出） |
| 钥匙名称 | CharField(128)，对齐个人/系统钥匙 `name` | 未识别或空名为 `''` | 否（列表展示名称，导出） |
| 系统 ID | CharField(32)，列名 `system_id`，对齐系统密钥的 `system_id` | 非系统密钥必须为 `''` | 否（导出） |
| 组织 ID | 可空正整数，不建外键 | 见下 | 否（列表展示组织名称，导出为 ID，列名「认证时组织」） |
| 接口类型 | CharField(16)，列名 `api_kind`，choices：`internal` / `external` / `''` | 目录未命中为 `''` | 有 |
| 方法 | CharField(10) | 外部转发方法头缺失为 `''` | 否（导出，列表合成「接口路径」） |
| 路径 | CharField(512) | 外部 URI 头缺失为 `''` | 有（包含匹配，顶栏「接口路径」） |
| HTTP 状态码 | PositiveSmallIntegerField，列名 `http_status` | 否 | 有（成功 / 失败，不按精确码；列表不展示数字） |
| 错误码 | CharField(32) | 成功为 `''` | 否（列表展示，成功为 `--`；同时导出） |

- **系统 ID 检查约束**：`credential_type = system_token` 时 `system_id` 非空；其余凭据类型（含未识别）时 `system_id` 必须为空。这是钥匙属性快照，不是「被调系统」。
- **接口类型只在一处判定**：路径对上内部注册表端点写 `internal`，否则对上外部服务注册表写 `external`，都对不上写空。不记录请求走了 invoke 还是 ForwardAuth。

- 源 IP 与操作日志一样走 `ipware.get_client_ip`。ForwardAuth 回调上 Traefik 会带 `X-Forwarded-For`，因此能拿到真实客户端 IP，不要用回调对端的 Traefik 地址冒充调用方。
- **组织 ID**：仅在用户已校验时，取长度为 1 的组织集合那一个。个人密钥为绑定组织；系统密钥为已校验用户之上的 acting 组织。多个或零个都为空，不取第一项。acting 头缺失或 acting 用户未通过校验时为空。列表按这个 ID 显示组织名称，导出仍写 ID。本列不决定列表可见性。
- 不单存服务名。路径已经包含 `/openapi/{version}/{service}/...`。
- 内部方法与路径取本次 Django 请求（`request.path` 不含 query）。外部路径取 `X-Forwarded-Uri` 去掉 query 后截断到 512；外部方法取 `X-Forwarded-Method`，**缺失时写空字符串，不回落成回调自身的 GET**。不记 ForwardAuth 回调 URL。
- 错误码取网关 envelope 的冻结码（`AUTH_INVALID`、`SCOPE_DENIED`、`PERM_MISSING`、`ROLE_REQUIRED`、`TEAM_OUT_OF_SCOPE`、`NOT_FOUND` 等）。成功为空。
- `response` 在收尾时仍为 `None`（视图在拼出 envelope 之前抛错）：仍写一行，`http_status=500`，`error_code=INTERNAL_ERROR`，身份与路径按当时已有的值填写。不跳过。
- 不加耗时、响应大小、详情 JSON。第一版不做 TTL；以后按时间全局清理只用创建时间，不必预留过期列。

### 索引

本表按每次网关调用一行写入（外部请求还多一行 ForwardAuth），高于操作日志。至少：

- `(username, -created_at)`（按用户名筛选）
- `(credential_type, token_id, -created_at)`（个人密钥与系统密钥的数字 ID 会撞，不能只按 `token_id`）

### 可见性与写入

- 有 `audit_log-View` 的人看到全部调用记录，不按当前组织、也不按超管身份裁剪。用户名为空的行同样可见。日志上的组织不决定列表里出不出现；列表展示组织名称，导出写组织 ID。
- 列表列：时间、用户名、组织、源 IP、密钥类型、密钥名称、接口路径（方法 + 路径，单行省略）、接口类型（内部接口 / 外部服务；空则 `--`）、结果、错误码。密钥类型只显示「个人密钥」或「系统密钥」，认不出的凭据为 `--`。系统密钥在类型下方用小字标出「系统ID:xxx」。密钥名称只显示名称，空则 `--`。钥匙 ID 不进列表，只入库和导出。结果只显示「成功」或「失败」，不展示 HTTP 状态码。错误码单独一列直接展示，成功或没有错误码时为 `--`。没有操作列，也不再提供详情。源 IP 只展示，不提供筛选。顶栏按密钥类型筛选，并按接口路径包含搜索。
- 顶栏筛选：用户名、接口路径（路径包含）、密钥类型（个人密钥 / 系统密钥）、接口类型、结果（成功 = `http_status < 400`，失败 = `http_status >= 400`）、时间。不提供钥匙名称筛选，不提供精确状态码输入框。
- Excel 导出列：时间、源 IP、用户名、认证时组织、凭据类型、钥匙 ID、密钥名称、系统 ID、接口类型、方法、路径、HTTP 状态码、错误码。不含服务名，不含入参/出参。HTTP 状态码只入库、进 Excel，不进列表。
- 写入发生在 invoke 与 ForwardAuth 视图的收尾处：同进程 ORM 插入，失败隔离，不改变已生成的响应。对标同进程操作日志写入，不走 NATS 操作日志 RPC，也不走异步队列。
- 页签顺序：操作日志、登录日志、API调用日志。文案为「API调用日志」。
- 本变更不把调用日志暴露为 OpenAPI 网关端点。

## Testing Decisions

好测试只锁对外行为：一次网关调用之后表里有没有行、控制台按组织和身份能看见什么、导出内容、以及写库失败时 HTTP 契约不变。不锁辅助函数名或内部调用链。不把入参、出参、令牌明文、sha256 断言进表字段。存储列不得出现 INFO 模板的 `-` 哨兵。

写侧接缝用现有网关 HTTP 测试方式（内部 invoke 与 ForwardAuth）：

- 认证通过的个人密钥 invoke：`api_kind=internal`，方法、路径为调用方请求，凭据类型与钥匙/单一组织 ID 符合身份，系统 ID 为空。不写服务名列。
- **过期个人密钥**（绑定用户仍存在）：401，行上有 `api_token`、钥匙 ID/名称、绑定用户名与组织；调用仍不可成功。现有活查语义不变。
- **过期或已禁用的系统密钥**：401，行上有 `system_token`、钥匙 ID/名称、系统 ID；acting 用户未通过校验则用户名为空。
- **禁用个人令牌 owner**（钥匙仍在有效期内、`authenticate` 失败但活查命中）：401，行上有钥匙与绑定用户名。
- **系统 Token 缺 acting 头或 acting 头畸形**：401，用户名为空，钥匙字段与系统 ID 有值。
- **系统 Token acting 用户不存在或未启用**：401，用户名为空（不写头里的字符串），钥匙字段有值。
- **系统 Token 组织越权**：403 `TEAM_OUT_OF_SCOPE`，行上有已校验用户名与此次 acting 组织。
- **未知凭据**（缺 Bearer、形态不匹配、哈希查无任何行、JWT 或其他非个人/系统密钥）：用户名与凭据类型、钥匙字段、系统 ID 皆空。命中目录时接口类型仍按路径填写。
- 系统 ID 约束：系统密钥且系统 ID 为空、或非系统密钥但系统 ID 非空，数据库拒绝写入。
- ForwardAuth 放行、403、404 都写入。命中外部服务时 `api_kind=external`，目录未命中时为空。方法与路径来自转发头而不是回调 URL；缺 `X-Forwarded-Method` 时方法为空串；URI 带 query 时路径不含 query；`http_status=200` 不表示上游成功。
- `_me`、`_docs` 不写本表。
- 收尾时响应尚未生成：仍有一行，`http_status=500`，`error_code=INTERNAL_ERROR`。
- 写库抛错时 invoke / ForwardAuth 仍返回原来的成功或错误体与状态码。
- 表字段与 INFO 日志中均不含令牌明文、请求正文、响应正文。

读侧接缝对标登录日志 / 操作日志的 ViewSet 测试（当前组织 cookie、只读 list、Excel 导出）：

- 有 `audit_log-View` 的非超管看得到全部调用，包括其他组织用户的行和 `username = ''` 的行。列表不按当前组织裁剪。
- 顶栏筛选只接受用户名、接口路径、密钥类型、接口类型、成功/失败、时间。成功命中 `http_status < 400`，失败命中 `http_status >= 400`。列表展示源 IP，但不提供源 IP 筛选。错误码在列表单独一列展示，成功为 `--`。导出列含「认证时组织」、凭据类型、钥匙 ID、密钥名称、系统 ID、接口类型、方法、路径、HTTP 状态码、错误码；不含服务名，不含入参/出参。列表结果不展示 HTTP 状态码数字。

前端行为用与现有审计页相同的方式锁页签、筛选和导出入口；不测样式像素。

## Out of Scope

- 改冻结的 `openapi_access` INFO 模板，或把 sha256 搬进控制台
- 记录 `_me`、`_docs`、provider 拉取
- 耗时、请求 ID、上游状态码
- 单存服务名
- 把 JWT 记成一种凭据类型（打进来的 JWT 按未识别凭据记）
- 入参、出参、请求体、query 原文
- 把调用日志写入操作日志表，或经 NATS 操作日志 RPC
- 用量统计、按组织不同保留期、法律保留、软删
- 新的审计权限位
- 把本表暴露为 OpenAPI 网关接口
- 密钥发放/吊销以外的操作日志改动
- 放宽 `find_by_api_secret` / `find_live_by_secret` 让过期钥匙可以认证成功

## Further Notes

网关规范里「网关负责认证、审计、路由」的审计，在本变更前只落到进程日志；本表是把它接到控制台审计页。后端工程规格禁止完整 payload 进入**日志**；本表不存入参是产品选择，不是那条日志红线自动覆盖存储。

列表不按当前组织裁剪。组织列展示认证时刻的组织名称：个人密钥是钥匙绑定组织，系统密钥是已校验的 acting 组织。导出仍写组织 ID。
