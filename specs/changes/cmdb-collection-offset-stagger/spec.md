# CMDB 周期采集错峰（collection_offset）

Status: implemented

实现与验证结果见 [validation.md](validation.md)。

## 已确认范围

- 本期仅主机 `host_info`、网络设备 `snmp_facts`、网络拓扑 `snmp_topo`；其他插件不分配、不下发偏移、不参与占位。
- 用户的「每 N 分钟」语义不变，不新增表单字段。偏移是周期相位，忙时是预计占用时间，两者不混用。
- 只对新建周期任务启用；存量不回填、不批量重推，但有效存量通道按现有偏移（缺失为 0）参与计算。
- 网络设备和启用的拓扑分别占位，设备先分配，拓扑避让；拓扑沿用现有周期规则，推荐设备周期 × 5。
- 首次与手动立即采集不等待偏移；本期不改 Stargazer 接纳、排队和 429 行为。

## 分配算法

输入：通道身份（任务 ID + 通道类型）、周期、目标数、已有通道；输出：固定偏移与估计忙时。

- 选资产按实例数，IP 范围按地址数，不展开地址列表。设备与拓扑目标数一致。
- 忙时分档：1–64 为 5 分钟，65–255 为 10 分钟，256–1024 为 15 分钟，1025+ 为 20 分钟。这些不是周期或偏移步长，不再压缩到周期的一半。
- 候选为 `[0, cycle)` 的整数分钟。评分依次比较长期同刻触发频率、忙时重叠、由近到远的启动间隔；并列优先保留合法原偏移，其余按通道身份的稳定顺序选择。
- 使用最大公约数计算周期关系，不展开 7 天触发列表，不使用任意大权重。同评分相位折叠、同周期/相位/忙时通道合并计数，不做候选采样。跨周期边界与忙时长于周期的估计负载均计入。
- 允许不可避免的冲突，不阻止保存。例如整数分钟偏移无法消除 30/31 分钟周期的长期同刻触发。策略不保证容量、运行不重叠或全局最优。

## 插件接入与执行范围

集中登记三个插件的任务模型、通道角色、偏移键、周期与启用字段，保存和渲染共用登记，不在各调用方复制白名单。后续已有 Telegraf 周期插件增加登记和契约测试即可接入；特殊目标口径按实际需要扩展，不预建插件框架。

当前 CMDB 没有可靠的接入点到 Stargazer 容量池映射，首期三个插件的有效通道共同参与分配，不按接入点或组织盲目隔离。这可能使独立容量上的任务互相避让，但不会遗漏跨接入点共享负载。后续有真实映射再缩小查询与锁范围，不从用户 params 接受容量池标识。

## 保存与生命周期

- 主机/设备：`params.collection_offset_seconds`；拓扑：`params.topology_collection_offset_seconds`。
- 字段由服务端持有，新建忽略用户值，编辑从已保存任务恢复，防止表单覆盖或遗漏。
- 无关编辑和下发重试保持偏移；已启用错峰任务修改周期、接入点或重新启用周期时重新评估受影响通道，评分相同优先保留原值。
- 已启用错峰任务新增拓扑时分配；关闭拓扑不占位，重新开启重新评估。存量未启用错峰任务的编辑不补偏移。
- 不重排其他任务。目标规模变化影响后续占位估计，不自动重排当前任务。
- 读取占位、分配和保存在同一事务内，复用 `UniqueWriteLockService` 的独立命名锁；更新在锁内重读并重新检查权限。锁不覆盖提交后的 RPC；锁竞争或数据库失败沿现有错误路径反馈，不静默归零保存。
- 配置采集表单、扫描生成（复用保存入口）、节点同步自动生成的主机任务均接入；节点同步刷新 params 时同样保留偏移。
- 提交后复用已有配置下发、首次采集与补偿；重试使用落库偏移。

## 配置与兼容

- 仅支持插件的周期配置渲染 `collection_offset = "Ns"`，满足 `0 ≤ offset < interval`；缺失或非法按 0 渲染。其他插件不新增该字段。
- Telegraf one-shot 允许读取含偏移的周期配置，转换成一次性 HTTP input 时不转发偏移，保持立即执行和原安全限制。
- 不改启动、部署或调度器。需实测 Telegraf 版本兼容及启动/重载时序。
- 回退本次代码恢复旧模板，残留 JSON 偏移不影响旧代码，不自动重推存量。NodeMgmt one-shot 消费端与 CMDB 渲染端同版本发布，或先升级消费端。

## 功能测试与完整性验收

已确认测试接口：`assign_offset` / `assign_many`、任务保存/编辑、最终节点配置、一次性采集执行入口。

1. 算法：同周期、大网段、双通道混合周期、互质周期、相位容量耗尽、短周期长忙时、跨边界、确定性与原偏移保留。
2. 独立 oracle：小周期完整枚举对照选择结果；性能记录覆盖 31/37/41 与千通道，不用脆弱的耗时断言。
3. 范围：三插件正例、其他插件负例、关闭拓扑、未来登记插件复用保存/渲染。
4. 功能：落库与配置偏移一致、周期及其他 params 不变、客户端覆盖无效、无关编辑/周期变更/新增拓扑、存量无回填、其他任务不变。
5. 完整性：事务回滚、锁竞争、提交后下发失败与重试、权限拒绝、双通道配置身份和周期对应、首次立即执行。
6. 回归：网络双通道、节点配置、首次采集和 one-shot 的鉴权/资源限制/失败行为。
7. 实际 Telegraf：配置接受、周期触发、重启/重载相位。环境缺失时记录未验证项，不以模板测试代替。
