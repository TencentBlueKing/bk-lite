# CMDB 数据治理：重复性检测与孤岛检查

Status: implemented

日期：2026-11-05  
来源：2026-11-04《CMDB 数据治理：重复性检测与孤岛检查》需求说明与两份交互原型，以及随后的设计讨论。  
六条数据口径和前端交互已于 2026-11-06 确认，并按 `implementation.md` 落地。

## Problem Statement

企业版 CMDB 已经能按日计算完整性和新鲜度健康度，并在运营分析里看比例和趋势。模型管理里没有「看问题 → 修问题」的工作台，算重和关系缺失也没有检查路径。录入时唯一规则会拦住新的冲突，已经存在的重复仍然留在库里，没人集中处理。

## Solution

在现有日更健康度上增加重复性检测和孤岛检查。配置仍放在模型管理：重复规则是模型上的新 Tab，孤岛是关系上的必连开关。结果进入新的「管理 / 数据治理」页。唯一规则的写入拦截保持不变，它拦不住的存量冲突自动出现在同一张问题清单里，类型为唯一性冲突。

治理页按检查路径筛问题，并跳到对应配置或处置抽屉。处置沿用现有实例编辑、重采、建边；重复组可以忽略；孤岛由人选择目标实例后建边。

## User Stories

1. As a 模型管理员, I want 在模型上单独配置单字段或联合字段的重复检测, so that 允许录入的重复会被发现，又不会和写入拦截搅在一起。
2. As a 模型管理员, I want 已被唯一规则占用的字段不能再选进重复检测, so that 同一字段不会被两套检查各报一遍。
3. As a 模型管理员, I want 在关系上打开必连, so that 源实例缺少这条边时能被找出来。
4. As a 资产维护人, I want 在数据治理页按完整性、新鲜度、重复、孤岛查看问题, so that 知道该去补字段、改重复，还是补关系。
5. As a 资产维护人, I want 打开重复组后编辑实例或忽略本组, so that 已知可保留的重复不必每天再出现。
6. As a 资产维护人, I want 在孤岛抽屉里选择目标实例并创建这条关系, so that 补边不用先离开问题本身。
7. As a 资产维护人, I want 唯一规则已经存在的冲突出现在治理清单里, so that 历史脏数据有入口，同时新的冲突写入仍然失败。
8. As a 资产维护人, I want 只看到自己组织范围内的问题, so that 治理页不会露出无权实例的名称。

## Implementation Decisions

数据口径和前端交互已确认。实现见 `implementation.md`。

### 检查路径

四条路径并列，治理页不另做规则引擎。

| 检查路径 | 配置位置 | 写入时 | 问题对象 |
|---|---|---|---|
| 完整性 | 模型属性的关键属性 | 不拦截 | 缺少关键属性的实例 |
| 新鲜度 | 模型属性的时效性 | 不拦截 | 超窗未核实的实例 |
| 重复 | 模型「重复性检测」Tab | 不拦截 | 同一规则下比较值相同的一组实例，至少 2 条 |
| 孤岛 | 模型关系的必连开关，默认关闭 | 不拦截 | 缺少该必连边的源实例 |

唯一性冲突沿用现有唯一规则，页面交互不改。它在治理清单中单独标记，出现在「全部」和「重复」筛选下，不单独占一张指标卡。

模型详情 Tab 顺序：属性、关系、唯一规则、重复性检测、自动关联规则、自定义采集。

### 重复规则

- 一条规则选择一个或多个字段。单字段按该字段值分组。联合字段要求所选字段全部相同才成组。
- 要同时盯序列号和主机名时，配置两条规则，各自出问题组。
- 参与比较的任一字段为空，该实例不进入这条规则。
- 非必填字段可以参与。规则条数不受「每个模型最多 3 条额外唯一规则」限制，也不占用该配额。
- 不可选：`inst_name`、组织、历史单字段唯一、额外唯一规则已占用的字段，以及附件、图片、表格、密码、枚举、标签、布尔。候选列表里禁用，并说明「已被唯一规则占用」或对应的类型原因。
- 比较值复用唯一规则的规范化。命中只进治理清单，不阻断创建、编辑、导入、采集写入。
- 之后再保存唯一规则时，字段若已属于某条重复规则，保存失败，并提示先删除对应检测规则。删除字段或把字段改成不可比较类型时，重复规则与唯一规则一样拒绝。
- 重复规则存在模型上，结构与唯一规则相同：服务端生成 `rule_id`，前端只提交字段列表。接口形态对齐现有模型唯一规则接口，由企业版提供。

### 孤岛

- 必连是模型关联上的开关，默认关闭。不必连的关系不参与治理。关系约束（1:1 / 1:N / N:N）仍只在创建实例边时生效。
- 一条必连关系产生孤岛，需同时满足：源模型和目标模型都至少有一个实例；某条源实例没有这条关系的边。
- 目标模型一个实例都没有时，这条规则不产生孤岛。
- 只检查源实例。不要求连到某一个具体目标实例，不做按字段匹配的预期配对，不把互相有边但连不上枢纽的整团当孤岛，不检查目标侧悬挂。
- 源模型和目标模型相同时，沿用同一口径：模型里已有实例，且该源实例没有这条边，就记为孤岛。

### 健康度

计算仍走现有日更任务，不改为打开页面时全量重算。

- 整体健康度 = 通过全部已适用检查路径的资产占比。
- 模型具备关键属性、时效字段、重复规则，或作为源的必连关系时，才进入健康度分母。某条路径没有配置时，该路径视为通过。
- 重复组中的实例、孤岛实例，以及已经进入分母的模型上的唯一性冲突实例，都不算完全健康。
- 每个模型都有内置 `inst_name` 唯一。仅因唯一规则存在，不把模型拉进分母，避免改写现有健康度基数。这类模型的唯一性冲突仍然写入问题清单。
- 指标卡：整体健康度、完整性、新鲜度为百分比；重复为未忽略的问题组数；孤岛为未处理的源实例数。卡片标注快照日期。
- 被忽略且成员未变的重复组不拉低健康度。
- 同一重复组按模型全局计一组。按组织看指标时，组内任一成员属于该组织，该组计入该组织的组数。

### 问题清单

日更快照继续保存聚合分数。实例级问题另存问题行，供治理页筛选，不把实例列表塞进快照 JSON。

一行一个问题对象，包含：检查路径、模型、规则标识（重复规则、唯一规则或模型关联）、分组键、成员实例、成员组织、展示摘要、状态（待处理 / 已忽略）。摘要只保留字段名、比较值、缺失属性或缺失关系，不保存整份实例。

唯一性冲突复用现有唯一比较器，把规模至少为 2 的组写成独立类型，不并进重复规则的结果。

清单读取最近一次快照日的问题行。服务端按资产组织范围过滤。重复组在模型内全局分组：当前用户至少能看见一名成员时，该组出现在清单中；看不见的成员只显示数量，不显示名称。

处置成功后，清单可以立即关掉对应问题行：忽略立即关闭；建边成功后关闭对应孤岛；编辑后只重读这一组的比较字段，不再相同则关闭。指标卡仍显示上次日更的数字，页面说明指标截至某日，已处理项会从清单消失，比例次日重算。

### 忽略本组

忽略记录规则、分组键和成员指纹。日更时指纹未变，该组不再出现，也不拉低健康度。组成员增减，或比较值变化，抑制失效，问题重新出现。修改重复规则的字段集合后，该规则上的旧忽略失效。

组内仍有当前用户看不见的成员时，不能整组忽略。忽略写入操作日志。

### 处置与权限

- 完整性：编辑、重采。
- 新鲜度：编辑、重采、确认仍有效。确认仍有效只追加一条不改字段值的核实记录，日更把它算进新鲜度。
- 重复：打开实例、编辑、忽略本组。
- 孤岛：在抽屉中选择有权限的目标实例并创建该关系，或跳到资产详情的关联关系页。不自动建边。
- 批量修复只覆盖完整性和新鲜度。任一目标缺少权限时，整批失败。
- 读清单和读指标复用资产组织范围，服务端再次过滤。编辑、重采、建边复用现有实例和关系权限。

页面结构、跳转和抽屉以《数据治理交互原型》《重复性检测》为准，细节见「前端交互」。落到现有模型页时，保留现有表格和弹窗，只增加原型里的新列、新 Tab 和新说明。

## 前端交互

对照《数据治理交互原型》和《重复性检测》。原型里的假顶栏（配置管理 / 监控 / 告警）用现有应用壳，不新做。控件用现有 Ant Design 和模型页组件，颜色用语义 token。

### 数据治理页

入口在侧栏「管理」下，与「模型管理」并列，名称为「数据治理」。页内只有这一屏，不再套「问题清单」子菜单。原型里的子项点击后仍是同一页。

页标题下保留一行说明：指标截至某日；已处理的问题会从清单消失，比例在下次日更后更新。原型顶部那条蓝色长说明是给评审看的路径解说，正式页不放。

五张指标卡横排，可点击，选中时主色描边：

| 卡片 | 数字 | 点击后的清单 |
|---|---|---|
| 整体健康度 | 百分比 | 全部路径 |
| 完整性 | 百分比 | 只看完整性 |
| 新鲜度 | 百分比 | 只看新鲜度 |
| 重复数据 | 问题组数 | 重复，并带上唯一性冲突 |
| 孤岛 | 问题实例数 | 只看孤岛 |

百分比沿用运营分析已有阈值：大于等于 70 为成功色，大于等于 30 为警告色，更低为危险色。重复组数大于 0 用警告色，孤岛数大于 0 用危险色，为 0 用正文色。没有快照时数字为「—」，说明尚未完成日更。再点当前卡片不取消筛选；看全部要点「整体健康度」。

指标卡下面一张问题清单卡。栏头左侧是「问题清单」和当前条数胶囊，右侧是「配置规则」和「批量修复」。栏头下是筛选行，从左到右：模型、组织、检查路径、搜索。模型和路径默认「全部」。搜索匹配问题对象文案和实例名。换筛选后从第一页重新取数。表格分页沿用现有列表，默认 20 条。原型没有画分页。

清单列与原型一致：检查路径、模型、问题对象、详情、处理。整行和「处理」打开同一抽屉。路径标签：完整性为信息色，新鲜度和重复为警告色，唯一性冲突和孤岛为危险色。问题对象示例：

- 重复：`序列号 = SN8821`，详情 `2 条实例`
- 唯一性冲突：`内网IP = 10.0.12.8`，详情 `3 条实例 · 来自唯一规则`
- 孤岛：`web-13 缺少 属于 业务`，详情 `业务侧已有 41 个实例`
- 完整性：`web-07 缺少关键属性 负责人`
- 新鲜度：`web-04 内网IP 超过 90 天未核实`

勾选框只在检查路径为完整性或新鲜度时出现。「批量修复」在其他路径、或没有勾选时禁用。完整性批量只有「重新采集」。新鲜度批量是「重新采集」和「确认仍有效」。任一目标无权限则整批失败，并指出无权限的实例。

「配置规则」：

- 重复：进入筛选中的模型的重复性检测 Tab。模型仍是全部时，按钮禁用，提示先选择模型。
- 孤岛：进入该模型的关系 Tab。清单已经按某条关系筛过时，关系表定位到该行。
- 完整性、新鲜度：进入该模型的属性 Tab。
- 全部：按钮变成菜单，三项为属性、重复性检测、关系。未选模型时禁用。

空筛选结果用表格空态「当前筛选下没有问题」。指标卡仍显示。

从模型页问题组数、孤岛数点进来时，带上模型、路径，以及规则或关系，筛选直接落在对应问题上。

### 处置抽屉

右侧抽屉，宽 520，点遮罩关闭。没有「保留选中，删除其余」。

**重复。** 眉题 `重复 · 主机 · 检测规则「序列号」`，标题 `序列号 = SN8821`。下面两行键值：冲突实例数、规则名。再往下是组内实例表：名称、组织、更新时间。名称进资产详情。看不见的成员不进表，表下写「另有 N 条不在当前权限范围」。底部「忽略本组」在左，「打开实例」在右。打开实例进入当前点中的那条资产详情；还没点名称时，打开第一条可见实例。有不可见成员时「忽略本组」禁用，并说明不能整组忽略。抽屉底部保留一句：不阻断写入；这里可以打开实例编辑，或忽略本组。

**唯一性冲突。** 眉题和表格与重复相同，规则名写成 `唯一规则 · 内网IP`，详情带来源说明。不提供「忽略本组」。只保留「打开实例」。冲突要靠改字段消除，忽略会把仍会挡住写入的数据藏起来。

**孤岛。** 眉题 `孤岛 · 必连关系「主机 属于 业务」`，标题 `web-13 未连接到业务`。中间一行：源实例用危险描边，中间写缺少的关系，右侧是目标模型及已有实例数。下面两行键值：判定是「两边模型都有实例，源实例没有必连边」；不报的情况是「目标模型一个实例都没有」。然后是「补关系」下拉，只列有权限的目标实例。底部「打开实例关系页」进该资产的关联关系页，「创建关系」在未选目标时禁用。建边若撞上 1:1 / 1:N / N:N，用现有错误提示，抽屉保持打开。

**完整性。** 列出缺少的关键属性。主按钮「编辑实例」。该实例能重采时，另给「重新采集」。

**新鲜度。** 列出超窗字段和档位。按钮为「确认仍有效」和「编辑实例」；能重采时再给「重新采集」。确认仍有效不改字段值。

处置成功后关闭抽屉，该行从清单消失。指标卡数字不变，直到下次日更。

### 模型详情

沿用现有模型头和 Tab，不改成原型里的另一套头。Tab 顺序：属性、关系、唯一规则、重复性检测、自动关联规则、自定义采集。

**唯一规则。** 表格、新建、编辑、删除、最多 3 条都不动。现有提示下补一句：存量冲突会出现在数据治理，类型为唯一性冲突。本页不加治理开关。

**重复性检测。** 版式与唯一规则页相同：上方说明、右上「新建」、下方表格。说明文案：「单字段或联合字段（全部相同才算重复）。已被唯一规则占用的字段不可选。空值不参与比较。」列：检测规则、类型、问题组、操作。一个字段显示「单字段」，多个字段显示「联合字段」，名称用 `主机名 + 机房`。问题组是链接，如 `7 组`，进治理页并筛到该规则。操作为编辑、删除。删除沿用现有二次确认。没有 3 条上限，新建不因条数禁用。

新建和编辑用与唯一规则相同的多选弹窗。可选字段正常显示；不可选字段禁用，原因直接写在选项上，占用字段的原因是「已被唯一规则占用」。原型里的逐行名单用这个多选表达，不另做一套名单。至少选一个字段才能确定。

**关系。** 保留现有名称、源模型、目标模型、约束、类型、删除和批量删除。在约束和类型之间加「必连」「孤岛数」。必连是开关，切换后立即保存；无编辑模型权限时禁用；失败则开关回到原状态并提示。未开启时孤岛数为灰色「不检查」。已开启时数字为链接，进治理页并带上这条关系。当前模型是目标侧时，开关改的仍是这一条关系，数字仍是源侧孤岛数，列标题用提示说明。表格上方加说明：约束仍只在创建实例关系时生效；打开必连后，两边都有实例而源实例没有这条边，记为孤岛。

**属性。** 不把属性页换成原型那张只读四列表。在现有属性列表增加「关键属性」「时效性」两列，在现有属性弹窗里配置。关键属性是是否，时效性是未设置、及时、不频繁更新、基本不变。基本不变不参与新鲜度。这是完整性、新鲜度的配置入口，也是治理页「配置规则」跳来的地方。

## Testing Decisions

只断言外部行为：分组结果、是否拦截写入、健康度分母、问题是否出现、权限过滤后的可见成员、忽略后的消失与再现。

优先测纯计算，与现有健康度核心测试同一层：

- 单字段与联合字段分组；任一空值不入组；组规模小于 2 不产生问题。
- 唯一规则占用字段不能保存为重复规则；反向保存唯一规则时也不能占用重复规则字段。
- 重复命中不阻断写入；唯一规则仍然阻断写入。
- 目标模型没有实例时不产生孤岛；有实例且源实例无边时产生孤岛；已有边不产生孤岛。
- 无治理配置的模型不进入健康度分母；配了重复规则或必连后进入；唯一性冲突单独不扩大分母，但在已纳入模型上使实例不算完全健康。
- 忽略后指纹不变则问题消失且不拉低健康度；成员变化后问题回来。
- 看不见部分成员时清单隐藏其名称，并拒绝整组忽略。
- 确认仍有效不改变字段值，并刷新新鲜度。

日更任务只验证它调用上述计算并落快照与问题行。页面测试验证指标卡筛选、配置规则跳转、问题组数和孤岛数回跳、四类抽屉的按钮，以及唯一性冲突抽屉没有忽略。不重复计算口径。

## Out of Scope

- 模糊查重、跨模型查重、自动合并、自动删除。
- 任一字段相同即重复。
- 按属性匹配的预期配对缺边，以及图连通意义上的孤岛团。
- 目标侧悬挂。
- 修改唯一规则的写入语义、条数上限、必填限制和页面交互。
- 自定义健康度公式或阈值。
- 归档、僵尸资产退役。
- 运营分析看板本期增加重复、孤岛指标。指标仍读现有健康度查询；看板跳转到治理页可后续再接。
- 新增对外 OpenAPI。治理页走现有 CMDB 管理接口。

## Further Notes

落地前，日更健康度只有字段级计数，没有实例级问题行，也没有数据治理页。本期补上问题行、确认仍有效的核实记录，以及属性上的关键属性和时效性配置。

### 已确认的数据口径

2026-11-06 确认：

1. 问题清单用独立问题行，由日更任务写入；指标卡继续用快照，已处理项当天从清单消失，比例次日重算。
2. 唯一性冲突进入清单。已纳入治理的模型上，冲突实例不算完全健康。只有内置名称唯一、没有其他治理配置的模型，不进入健康度分母。
3. 跨组织重复组只要能看见一名成员就出现；看不见的成员只显示数量。看不见全部成员时，不能整组忽略。
4. 后补的唯一规则不能占用已经用于重复检测的字段。
5. 运营分析本期不增加重复和孤岛指标。
6. 忽略本组后，成员和比较值都没变，则离开清单且不拉低健康度；有新实例撞上同一组值，或比较字段被改掉，问题重新出现。

### 已确认的前端取舍

屏幕流程按两份原型。下面几处是原型落到现有页面时的取舍，2026-11-06 已确认。

1. 侧栏只加「数据治理」一项，不加「问题清单」子菜单。
2. 不增加面包屑。原型顶部的蓝色路径解说不进正式页，只留指标截至日期和清单消项的说明。
3. 治理页筛选放在清单卡内、按钮在栏头右侧，顺序与原型一致。百分比颜色用运营分析已有的 70 / 30 阈值。
4. 批量修复只在完整性、新鲜度下可用，并出现勾选框。完整性批量只有重新采集；新鲜度批量是重新采集和确认仍有效。
5. 检查路径为「全部」时，「配置规则」是属性 / 重复性检测 / 关系菜单，且必须先选中一个模型。原型在未区分路径时直接去属性。
6. 唯一性冲突抽屉不提供忽略，只打开实例。重复抽屉才有忽略本组。
7. 重复规则的选字段用现有唯一规则那种多选弹窗，禁用项带原因。不另做原型里的逐行名单。
8. 关系表在现有列之间插入必连和孤岛数，不改掉现有的类型列和删除。
9. 属性仍用现有列表和弹窗，增加关键属性、时效性。不换成原型那张只读表。
