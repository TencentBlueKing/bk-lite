# 飞书、企微与蓝鲸登录未匹配时可选创建用户

Status: implemented — 2026-10-23。目录接口成功才建号，字段为空也建；超时或失败不建号。`test_login_auth_unmatched_create` 8 passed。

## Problem Statement

系统管理员配置飞书、企业微信或蓝鲸登录时，未在本平台找到对应用户就只能拒绝登录。微信登录认证已经可以选择「创建用户」，并在未指定组织时把新用户放进 `OpsPilotGuest`，从而走进控制台首次登录的建组织流程。飞书、企微和蓝鲸的管理表单不提供这个选择，保存接口也会拒绝企微和蓝鲸的创建动作。管理员无法让这三家的首次访问者用同一套方式进入平台。

## Solution

飞书、企微、蓝鲸的登录认证绑定与微信一样提供「拒绝登录 / 创建用户」。新建这三家绑定的默认仍是拒绝，管理员改成创建后，未匹配用户按微信同一套规则建成本平台用户：不填写默认组织，进入 `OpsPilotGuest`。飞书登录响应里已有姓名；企微和蓝鲸只在确实要创建、且本地还没有这个人时，再取一次姓名。目录接口成功就建号，姓名、邮箱、手机为空时显示名用已确认的身份值。目录接口超时或失败时登录失败，不建号。

## User Stories

1. As a 系统管理员, I want 在飞书、企微、蓝鲸的登录认证绑定里选择未匹配时拒绝或创建用户, so that 可以决定首次访问者是必须事先同步，还是登录时直接建号。
2. As a 系统管理员, I want 新建飞书、企微、蓝鲸绑定时默认拒绝, so that 未改配置前仍保持「先同步、后登录」。
3. As a 选择了创建的外部用户, I want 首次登录进入 `OpsPilotGuest`, so that 控制台弹出建组织流程，而不要求管理员在绑定上再填一个组织名。
4. As a 绑定仍为拒绝的外部用户, I want 本地没有账号时登录失败并留在本平台登录页, so that 未授权的人不会被自动建号。蓝鲸沿用现有 cookie 入口，登录页不出现蓝鲸按钮。
5. As a 已经同步过的用户, I want 登录只匹配现有账号, so that 显示名、邮箱、手机、组织和角色不被这次登录覆盖，也不为了姓名再请求一次外部目录。
6. As a 选择了创建、但目录成功返回里没有姓名的用户, I want 账号仍然建成, so that 显示名可以先用已确认的身份值。目录接口超时或失败时登录失败，不建号。

## Implementation Decisions

- 管理端登录认证绑定表单对微信、飞书、企微、蓝鲸展示未匹配动作。切换到飞书、企微或蓝鲸实例时，动作为拒绝；切换到微信时仍默认为创建。提交创建时保留该动作，不再改写成拒绝，默认组织提交空值。
- 表单不提供默认组织输入。创建且绑定上的默认组织为空时，微信、飞书、企微、蓝鲸都加入 `OpsPilotGuest`。绑定上已经保存了默认组织名称时，使用该组织。其它提供方保持「创建必须填写默认组织」。
- 保存绑定允许飞书、企微、蓝鲸使用创建，包括默认组织为空。企微外部身份字段仍只能是 `userid`。蓝鲸外部字段与平台字段仍只能是 `username`。飞书的外部字段选择保持现状，默认 `user_id`。
- 登录匹配和创建仍走统一的登录绑定流程。先核对外部身份并在本地查找用户。已有用户只更新登录时间，不改资料。
- 未找到用户且动作为拒绝时，登录失败，不建用户。蓝鲸的启动兑换同样遵守这条绑定：拒绝时不写本平台会话；创建且未匹配时建用户并签发会话。蓝鲸绑定继续不出现在登录页列表。
- 未找到用户且动作为创建时再补姓名，然后建用户。用户名取外部匹配字段的值。显示名取外部用户的 `name`，没有则用用户名。微信显示名仍取 `nickname`。邮箱和手机有则写入。角色沿用微信首次创建用户的默认角色集合。
- 飞书同一次登录认证已经带回 `name`、邮箱和手机，不为创建再发请求。
- 企微身份核对仍用「获取访问用户身份」，只得到 `userid`。仅在要创建且本地无此人时，再请求「读取成员」，把 `name`、邮箱、手机写入外部用户。不改成网页授权的敏感信息接口，也不改扫码范围。
- 蓝鲸身份核对仍用登录 `get_user`，只得到用户名。仅在要创建且本地无此人时，再按该用户名请求用户管理的单用户读取，把 `display_name` 映射为外部用户的 `name`，邮箱和电话映射为邮箱、手机。
- 详情接口成功就建用户。返回里有姓名、邮箱、手机就写入；这些字段为空时仍建用户，显示名回落为企微 `userid` 或蓝鲸用户名。详情接口超时或失败时登录失败，不建用户，并记一条 warning。日志不包含凭据、token、授权码或响应正文。

## Testing Decisions

测外部行为，不锁死私有请求函数的拆分方式。最高缝是「保存登录认证绑定」和「用该绑定完成一次登录」。

- 保存绑定：飞书、企微、蓝鲸可以保存创建且默认组织为空；企微仍拒绝非 `userid` 的外部字段；蓝鲸仍拒绝非 `username` 的外部字段和平台字段；微信创建且组织为空的现有保存结果不变。
- 用绑定登录：动作为拒绝且本地无用户时不建用户。动作为创建且本地无用户时，用户进入 `OpsPilotGuest`，显示名来自外部姓名，角色与微信首次创建一致。本地已有用户时不改资料。绑定上已有默认组织名称时加入该组织，而不是 `OpsPilotGuest`。
- 企微和蓝鲸的详情请求只出现在「动作为创建且本地无用户」的登录里。飞书创建不产生第二次目录请求。详情接口成功但姓名为空时仍建号，显示名等于身份值。详情接口超时或失败时不建号，登录失败，日志不含凭据和响应正文。
- 管理端表单：飞书、企微、蓝鲸展示未匹配动作，提交创建时动作保持创建、默认组织为空；不渲染默认组织输入。微信新建绑定仍默认创建。已有的登录认证表单行为脚本继续作为这条契约的前序测试。

## Out of Scope

- AD 与内置账号的未匹配动作。
- 登录页上的蓝鲸按钮、跳转蓝鲸或蓝鲸回调本平台。
- 登录时更新已有用户的显示名、邮箱、手机、组织或角色。
- 改变微信的扫码方式，或改变 `OpsPilotGuest` 触发首次登录建组织弹窗的既有判定。
- 用户同步的拉人范围、字段映射和调度。
- 企微「获取访问用户敏感信息」，以及为拿到 `user_ticket` 修改扫码授权范围。

## Further Notes

本规格替代企业微信变更规格里「未匹配创建只留给微信」，以及蓝鲸内置集成规格里「未匹配动作锁定为拒绝、登录不创建用户」。两处的默认仍是拒绝；只有管理员把绑定改成创建后才建号。实现时同步改这两处表述，避免和本规格冲突。

企微「读取成员」要求该成员处于应用可见范围。蓝鲸单用户读取要求应用具备用户管理权限。这两种接口失败都让登录失败，不建号。接口成功但没有姓名、邮箱、手机时仍建号，显示名用已确认的身份值。
