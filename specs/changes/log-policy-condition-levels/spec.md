# 日志聚合策略 · 条件卡与级别表

Status: implemented

## Problem Statement

聚合策略把「统计什么」和「有多严重」写在同一张条件卡的触发行里。两条以上、全部满足时，级别其实是跨条件合成的（取最轻的一档），页面却让每条条件各填一套警告 / 错误 / 严重。档位没对齐要到保存才报错。前置式的门槛（本窗至少多少条、去重至少多少个）没有单独的角色，只能再占一套阶梯，把级别算脏。

监控多指标和 APM 告警条件已经是另一套版式：上面用字母卡片定义每个数，下面一张表按级别分行、按条件分列。日志要接上这套版式，同时保留日志自己的统计、字段、比较和对照。

## Solution

聚合策略的规则分成两段。

**条件定义。** 每条条件一张卡，按顺序标 `a`、`b`、`c`。卡上写统计、字段、类型、比较和对照。类型只有「常规」和「前置条件」。前置条件的比较符和数字写在这张卡上，并提示「不参与级别，不满足就走恢复」。前置条件只能是当前值，不能做变化量或变化率。

**告警条件。** 一张表。行是严重、错误、警告，列只放常规条件。格子里是比较符和数字。同一常规条件的三档共用一个比较符：改一格，整列一起变，并保持严格单调。全部满足时，某一档必须每一列都填上，告警级别取各常规条件命中档里较轻的一档。任意满足时，格子可以留空（表示这条条件没有这一档），命中后取较高的一档；任意满足不能带前置条件。

全部常规条件都要命中，并且全部前置条件都要通过，才告警。一个分组仍然只开一条告警。关键字策略保持单级别，不出现这张表。

## User Stories

1. As a 日志策略作者, I want 常规条件的严重、错误、警告排成一张表, so that 我能看出某一档要每一列都达到。
2. As a 日志策略作者, I want 前置条件的比较符和数字留在它自己的卡片上, so that 「去重至少 20 个」读成一句，而不会变成另一套级别。
3. As a 值班人, I want 前置没过时不新开告警, so that 流量不够的窗口不会单独升起一个级别。
4. As a 日志策略作者, I want 打开旧的聚合策略时每条条件都当作常规条件, so that 不用做数据迁移也能继续编辑。
5. As a 日志策略作者, I want 任意满足时每列可以缺某一档, so that 「计数过线或耗时过线」仍然能取较高的那一档。

## Implementation Decisions

- 只改聚合策略。关键字策略的级别单选、命中条数、人工关闭保持原样。条件上不出现类型和级别表。
- 条件增加可选角色 `role`：`regular`（常规）或 `guard`（前置条件）。缺省、空字符串和旧数据都视为 `regular`。不新增模型列，不迁移。
- 至少一条常规条件。可以没有前置条件。不新设条数上限。
- 前置条件只保留一个比较符和一个数值，不写 `thresholds`。比较方式锁定为当前值；从变化量或变化率切成前置时，对照清空。函数仍按现有规则要字段、分位或占比分子。
- 常规条件继续用 `thresholds: [{level, value}]`，`value` 仍镜像最轻一档。比较符仍是条件上的一个 `op`，不是每一档各有一个。`>` `>=` `<` `<=` 多档必须严格单调。`=` `!=` 以及旧的 `in` `nin` 只允许一档。
- 全部满足时，各常规条件启用的级别集合必须相同。这个约束改由表格结构保证：添加或删除一档，作用于每一列；某一档有空格就不能保存。保存失败的文案说明「这一档还没填完」，不再只说「级别必须一致」。
- 任意满足时不接受前置条件。表单不提供这个类型；已有前置时切到任意满足，保存被拒绝，并提示先去掉前置或改回全部满足。任意满足下，常规条件的级别集合可以不同，空格表示该条件没有这一档，每条至少一档。
- 判定：先算每条条件自己的命中。前置条件命中与否不产生级别。全部满足时，全部常规条件都命中且全部前置都通过才触发，级别取常规条件命中档的最轻者。任意满足时，任一常规条件命中即触发，级别取命中档的最高者。没有常规条件命中则不触发。
- 前置未通过等于本窗该分组不满足：不新开告警，也不把活动告警的级别降下来。`recover_after` 有值时，这一窗计入连续不满足；没有开启自动恢复时，活动告警保持，与现在「条件没中」相同。查询失败、对照失败仍是既不计数也不清零，不要把前置未过记成查询失败。
- 告警取值取第一条常规条件的算出值，跳过排在它前面的前置条件。策略 `alert_level` 仍由常规条件里启用的最高档推导，前置不参与。
- 试算、通知正文和告警详情把前置单独写出来（过或没过，以及它的比较符和数字），不把它画成级别档。常规条件仍逐档标出命中档。
- 表单两段的标题用「条件定义」和「告警条件」。条件卡的字段顺序是统计、字段、类型、比较、对照；前置卡在比较之后是「门槛」，下面一行说明「不参与级别，不满足就走恢复」。级别表的行序是严重、错误、警告。列头是字母、统计名和单位。全部满足时表下说明「行是级别，列是条件。级别取较轻的一档。」任意满足时改成「任一条件达到即告警，级别取较高的一档。空格表示这条条件没有这一档。」
- 新建聚合策略：一条常规条件，级别表先有严重、错误、警告三行空值，至少填完一整行才能保存。空行不写出。字母从第一条就显示，加第二条时版式不变。
- 同一列的比较符控件可以画在每个格子里，但状态只有一个。不做成每格独立运算符。原因：每格各写各的会让严重档用大于、警告档用小于，单调阶梯不再成立。

数据契约（旧条件没有 `role`，读入即常规）：

```json
{
  "query": "level:ERROR",
  "group_by": ["host"],
  "rule": {
    "mode": "and",
    "conditions": [
      {
        "role": "regular",
        "func": "count",
        "field": "_msg",
        "compare": {"kind": "absolute"},
        "op": ">",
        "thresholds": [
          {"level": "warning", "value": "10"},
          {"level": "error", "value": "50"},
          {"level": "critical", "value": "200"}
        ],
        "value": "10"
      },
      {
        "role": "guard",
        "func": "count_uniq",
        "field": "user",
        "compare": {"kind": "absolute"},
        "op": ">=",
        "value": "20"
      }
    ]
  }
}
```

## Testing Decisions

测保存进去和扫描出来的行为，不测表格的像素。

- 聚合条件校验：缺省角色等于常规；至少一条常规；前置拒绝阶梯、拒绝变化量和变化率；全部满足时常规档位必须填齐；任意满足拒绝前置、允许各列档位不同；单调和单档运算符的旧规则仍在。
- 扫描判定：两条常规加一条前置。前置通过且两条分别命中错误和警告时，告警级别为警告。前置未通过时不触发。前置未通过在开启自动恢复时计入连续不满足，查询失败时不计入。任意满足不看前置，取较高档。告警取值来自第一条常规条件，不来自前置。
- 旧载荷：没有 `role` 的条件保存、扫描、通知与升级前一致。
- 表单：切到前置后级别表去掉这一列，门槛出现在卡上；切回常规后门槛回到表里。全部满足下清空某一档的一格，保存被拒绝。任意满足下该空格可以保存。
- 试算和通知：前置有单独的过或没过，不出现在级别档列表里。

已有的阶梯校验测试、扫描纯函数测试、条件编辑器测试和试算测试是同一接缝，在上面补用例，不新开一套引擎。

## Out of Scope

- 关键字策略的多档级别和前置条件。
- 每一档各自一个运算符，以及按级别路由通知。
- 级别回落、恢复滞回、有状态的连续计数。
- 本规格不改自动恢复的状态机。前置未过只是多了一种「本窗不满足」。
- 给日志新设条件条数上限，或去改监控、APM 编辑器里前置数字的位置。
- 公式编辑器，以及 `in` / `nin` 的数据迁移。
