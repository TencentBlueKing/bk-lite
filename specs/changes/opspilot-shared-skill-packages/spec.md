# 技能包同域共用

Status: implemented

## Problem Statement

技能包导入或生成之后，只有分组对得上的当前组能在工具管理和智能体的「添加技能包」里看到它。技能包上没有各组自己的口令。同一域、同一包标识、同一版本本来就只有一行，再导入会覆盖这一行。分组只让别的组挂不上同一个技能包。MCP 的地址和令牌写在 MCP 自己的记录上，不能跟着放开。

## Solution

同一域里，已经能查看工具管理的用户，无论当前组是哪一组，都能看到该域的全部技能包，并把它挂到自己的智能体上。技能包和内置工具的分组不再决定目录里谁能看见。内置工具的编辑框不再改分组。MCP 仍按分组筛选和编辑。智能体设置页回写时，目录里没有的内置工具保留，目录里没有的 MCP 去掉。同一包标识和同一版本的再次导入仍覆盖这一行，所有已经挂上这一行的智能体都使用覆盖后的内容。删除一条非内置技能包后，各组都不再能用它。

## User Stories

1. As a 能查看工具管理的管理员, I want 在组 2 看到组 1 导入或生成的技能包，并把它加到组 2 的智能体上, so that 同一套做法不用按组再导一次。
2. As a 管理员, I want 各组填在智能体上的技能包参数仍留在各自的智能体里, so that 共用技能包不会把别的组填过的密码交给我。
3. As a 管理员, I want 再次导入同一域、同一包标识、同一版本时更新这一行, so that 已经挂上这一行的智能体用到新的说明和文件。
4. As a 管理员, I want 导入同一包标识的另一个版本时新增加一行, so that 还挂着旧行的智能体不会被换到新版本。
5. As a 有工具管理删除权限的管理员, I want 删除一条非内置技能包后各组都失去它, so that 我知道这是在删共用的那一行，而不是只从本组拿掉。
6. As a 管理员, I want 内置技能包仍然不能删除, so that 共用目录不会把内置包删掉。
7. As a 管理员, I want 编辑技能包时只改标签, so that 我不用再为技能包选一个分组。
8. As a 组 2 的管理员, I want 组 1 的 MCP 仍不出现在工具管理和智能体的 MCP 选择里, so that MCP 的地址和令牌继续留在原来的分组。

## Implementation Decisions

- 技能包的列表、详情、修改和删除按调用者的域过滤，不再按分组过滤，也不再按工具权限里的实例或分组规则过滤每一行。域相等才可见。域为空的旧行不对有域的调用者展示。
- 工具管理的查看、新增、编辑、删除权限保持原样。没有查看权限的用户仍然拿不到技能包目录。
- MCP 继续按当前分组过滤。内置工具对各组可见，编辑时忽略提交的分组。技能包和它们共用同一个权限键，放开技能包时不能放开 MCP 的行级范围。
- 技能包模型上的分组字段保留，不做删列，也不回填旧数据。访问路径不再读取它。导入、本地导入和对话生成可以继续写入这个字段。修改接口收到分组时忽略，不据此隐藏技能包。
- 工具管理里技能包和内置工具的编辑不再展示、也不再要求分组。MCP 的新建和编辑仍要求分组。智能体「添加技能包」使用同一份技能包列表，不再单独按分组筛一次。
- 同一域、同一包标识、同一版本再次导入时，覆盖这一行的名称、说明、清单和磁盘文件。智能体保存的是这一行的数字标识。覆盖后，挂着这个标识的智能体读到新内容。另一版本新增加一行，旧标识仍指向旧内容。
- 删除非内置技能包时删除这一行及其存储目录。内置技能包的删除请求仍拒绝，行还在。
- 技能包参数继续存在智能体上。密码的加密和掩码不变。技能包列表不返回任何智能体填过的参数值。
- 运行时仍按智能体保存的技能包标识加载启用的技能包，不读分组。本变更不改加载条件。
- 对话生成技能包的确认卡仍按原条件出现，包括智能体要先有已保存的管理分组。确认后写入的技能包对同域各组可见。本变更不放宽出卡条件。

## Testing Decisions

- 只断言调用方能观察到的目录、覆盖、删除和 MCP 隔离。不断言分组字段的内部写法。
- 最高缝是技能包的列表、导入、修改、删除，以及工具列表。准备两条同域技能包，分组分别写成调用者的当前组和另一个组。当前组的列表必须同时包含这两条。另一域的技能包不得出现。
- 同包标识、同版本再次导入后，两组列表都看到新说明，智能体保存的那个数字标识读到新内容。另一版本出现新的一行，旧标识的说明不变。
- 修改请求带上另一个分组后，原当前组的列表仍能看到该技能包。
- 另一组中有删除权限的用户删除非内置包后，两组列表都没有它，对应存储目录也不再保留。内置包的删除仍被拒绝，行还在。
- 技能包列表的响应里不出现智能体技能包参数中的密码哨兵。
- 当前组为 2 时，分组只有 1 的内置工具仍出现在工具列表中，MCP 不出现，响应里没有 MCP 令牌。智能体上已经保存、但这次目录没有返回的内置工具，回写后仍然保留。目录里没有的 MCP 回写时去掉。
- 先前测试：内置技能包在空分组下仍可见、内置包不可删除、技能包导入覆盖同一标识、技能包参数掩码。其中「其他分组的自定义包不可见」改为同域可见。

## Out of Scope

- 去掉 MCP 的分组字段，或迁移旧的分组数据。
- 同一包标识按组各存一份。
- 放宽对话生成技能包的出卡条件。
- 为跨组删除增加新的确认文案。现有删除确认保留。
- 工作流直接挂载技能包。

## Further Notes

- 2026-11-24 的后续结论是内置工具不按分组隔离，编辑框也不再改分组。MCP 仍按分组筛选和编辑。智能体设置页回写时，目录里没有的内置工具保留，目录里没有的 MCP 去掉。技能包不按分组过滤。
- 本规格取代「对话生成技能包」里「只有同一管理分组能在目录里看到这条包」的可见性。那份规格里的出卡条件、权限和「每次新建一条」不在这里改。
- 完成证据：`TestSharedSkillPackageCatalog` 与 `TestBuiltinSkillPackageVisibilityAndDelete`。同域其他分组的技能包出现在列表中，另一域的不出现。其他分组可以改标签，提交的分组不生效。其他分组删除后行和存储目录都没有。同一版本再次导入后两组列表看到新说明，另一版本是新行。技能包列表不含智能体密码。当前组为 2 时，分组只有 1 的内置工具仍在工具列表中，MCP 不在，令牌也不出现。拒绝删除时不再清理存储目录。
