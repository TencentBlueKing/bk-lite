# 关联拓扑声明嵌入（告警详情第一实验）

Status: implemented

## Problem Statement

BK-Lite 按已售模块交付，监控详情那种「关联拓扑 / 日志 / 告警」拼在同一页的一体化，不能再靠模块之间编译期互相引用页面实现。运维处置告警时，想判断出事对象周围还有谁、是不是也在告警，现在只能离开告警中心去 CMDB 翻关系，而且资产详情那张关联拓扑没有实时告警叠层。运营分析已经能把 CMDB 邻居和告警合成一张只读图，但还没有按「先声明、再被别人加载」的方式交出去。要求的第一实验是：运营分析先做出这件可引用的关联拓扑，放到告警中心去验证这条链路。

## Solution

运营分析声明一件只读「关联拓扑」小组件：圆心是当前 CMDB 资产实例 UUID，邻居与资产详情关联拓扑同一份，节点上叠该资产所关联监控实例的当前活跃告警（数量 + 最高级别）。对外契约只有 `{ instUuid: string }`；组件自取邻居与告警叠层，不认识告警单据，不接收模型 ID 或 UUID 列表。

告警中心在活动告警详情抽屉增加「关联拓扑」Tab：先探测组件已声明，再从本条告警快照 `monitor_objects` 解析非空 `cmdb_id`。零个硬指针则不出 Tab；一个则直接传入；多个不同 UUID 时由告警 Tab 内切换圆心，每次仍只传当前这一个 UUID。权限针对当前选中圆心，经运营分析拼图（邻居 NATS 带 `user_info`）判定，失败留在图内，不作为 Tab 显隐条件。告警中心不串邻居和告警数据，也不直接引用运营分析内部实现或 HTTP 路径。本变更只验收这一条实验链路。

## User Stories

1. As an 正在处置告警的运维人员, I want 在告警详情里看到「关联拓扑」Tab 并打开出事对象的邻居图, so that 不必先跑去 CMDB 才能判断是孤点故障还是周围也在告警。
2. As an 运维人员, I want 一条告警挂了多个已联动 CMDB 的对象时能切换圆心再看图, so that 详情里列出的每台资产都能看自己的邻居，而不是只看到其中一台、也不把多台画进同一张多圆心图。
3. As an 运维人员, I want 图上的点和边与该资产在 CMDB 关联拓扑里看到的一致, so that 两处说的是同一套关系，而不是另一套跳数或过滤。
4. As an 运维人员, I want 每个节点用角标显示当前活跃告警数量和最高级别, so that 一眼能看出邻居此刻是否也病了。
5. As an 运维人员, I want 这条告警对不上已联动的 CMDB 资产时根本看不到该 Tab, so that 不会打开一张没有圆心的空图，也不会按 IP 或名称误认资产。
6. As an 运维人员, I want 运营分析未声明该组件时告警详情也没有该 Tab, so that 没装或不提供该能力时页面不会出现打不开的入口。
7. As an 运维人员, I want 当前圆心我看不见时仍能看到该 Tab 并在图内得到失败（可刷新重试）, so that 唯一圆心和多个圆心的入口一致，告警中心也不必为了藏 Tab 去打运营分析 HTTP。
8. As an 运维人员, I want 资产存在但一个邻居都没有时仍能打开 Tab 并看到「暂无关联」, so that 空邻居和「没联动 / 没权限 / 未声明」不会混成同一种失败。
9. As an 运维人员, I want 未关联监控的邻居不要被画成「零告警 / 全绿」, so that 我不会把没接监控当成健康。

## Implementation Decisions

- 本变更只交付实验链路：运营分析可声明的只读关联拓扑 + 告警中心活动告警详情抽屉加载。界面文案与声明展示名均为「关联拓扑」。产品上这是实例中心的邻居健康图，告警中心只是第一消费方；不是「告警单拓扑」，不把当前告警 ID 传入组件。运营分析本实验不把该件挂进自己的画布；声明给别人用就是这一刀的产品用法，不为了「本模块也有页面宿主」而进盘。
- 声明组件的最小契约：`props` 仅为 `{ instUuid: string }`。禁止模型 ID、告警 ID、`instUuid[]`。多值列表属于宿主，不属于组件。模型 ID 由 CMDB 在邻居查询内部解析；调用方不必认识 CMDB 模型。`resource_type` 是监控对象类型，不是 CMDB `model_id`，不得拿来当圆心。
- 告警中心解析圆心的唯一规则：只读本条告警已有快照 `monitor_objects[].cmdb_id`（按集合既有顺序去重）。这是事件期硬指针，不现场反查 `MonitorInstance`，禁止按名称、IP、云区域或 `resource_id` 猜测去碰 CMDB。零个非空 `cmdb_id` 不出 Tab。一个则无选择器、直接传入。多个不同 UUID 时，告警 Tab 内用已有 `resource_type：resource_name` 切换，每次加载组件仍只传当前选中的那一个 UUID；没有 `cmdb_id` 的对象不进选择器。禁止静默取第一个、禁止组件内下拉、禁止一张图多个圆心。
- Tab 入口与当前圆心权限分开：
  1. 运营分析已声明该组件可被其他模块引用（模块级，与这台资产有没有邻居无关）；未声明则不出 Tab。
  2. 本条告警快照至少有一个非空 `cmdb_id`；否则不出 Tab。
  3. 权限针对**当前选中的**圆心，经运营分析拼图判定（内部走 CMDB 邻居 NATS，带 `user_info`；无权或不存在与空邻居必须可区分）。告警中心不调用需要 `model_id` 的 CMDB HTTP 做预检，不自己串邻居和告警，也不为 Tab 显隐预打运营分析 HTTP。圆心无权 / 不存在：Tab 仍出现（已声明且有硬指针即可），图内失败可刷新重试。越权由拼图接口拒绝，不靠藏入口。
- 公共池最小契约是硬依赖，本变更必须具备：稳定声明 key、探测「已声明」、按需加载、入参 `{ instUuid: string }`。告警中心禁止编译期 import 运营分析页面组件，禁止 iframe 打开运营分析全页来冒充嵌入。实现不得把运营分析业务组件搬进 `src/components`（shared 禁止反向依赖 `@/app/*`）。声明走系统层 `appCapabilities`：运营分析在 `capability.ts` 导出 `RelatedTopologyWidget`，并登记进 `catalog.ts`；告警中心用 `useAppCapability('ops-analysis')` 按已售模块权限探测并按需加载。未授权该 App 即视为未声明。不另建运行时注册表。
- 邻居与资产详情「关联拓扑」同一算法、同一默认深度（现有按 UUID 的轻量拓扑查询，含权限裁剪）。不另做一跳过滤，不按「是否告警」删点。无权邻居不出现。运营分析禁止为这件新能力新增长对 CMDB `InstanceManage`（或同等内部服务）的进程内直连；CMDB 补一条带 `user_info` 的邻居 NATS（入参实例 UUID，不强制调用方传模型），身份与 org 校验与现有 CMDB NATS 一致，不经 OpenAPI 网关对外暴露。
- 告警叠层与网络状态拓扑同一口径：节点先经已有 `cmdb/get_monitor_ids_by_inst_uuids` 得到 `monitor_id`，再经已有 `monitor/query_latest_active_alerts` 取当前活跃告警（监控中心 `status=new`）。角标为该监控实例的 `count` 与最高级别；超过 99 显示 99+。已关闭 / 已恢复不叠。无 `monitor_id` 的节点无角标，且不得表现为 count=0 的健康态。有 `monitor_id` 且 count=0 也无角标。不在节点上挂告警标题列表；本变更不做点节点跳转，也不做角标弹层。
- 整合发生在运营分析：一次查询入参圆心 UUID（及当前用户身份），出参邻居图 + 各节点告警汇总。内部编排 CMDB 邻居 NATS 与上述两条已有契约。告警中心只加载组件并传当前 `instUuid`，不自己串三边、不在告警页再编排数据源。组件只读渲染；抽屉宽度不足时用缩放 / 适应画布，不当验收失败。
- 空邻居（圆心有权限、图为零关联）返回成功空图，由组件展示「暂无关联」。CMDB / 监控契约失败时：Tab 已出现则图内可重试错误，不得把失败画成全绿或编造邻居。
- 本变更不把该件登记为运营分析画布上的 `topologyMap` / 场景组件，也不接统一筛选。画布通用关系拓扑与网络状态拓扑维持原状。不改造 CMDB 可编辑关联拓扑。进盘（单值实例筛选绑定同一个 `{ instUuid }`）另开变更。

## Testing Decisions

好测试只锁对外行为：给定身份与圆心 UUID 时，Tab 是否出现、邻居是否与 CMDB 轻量拓扑一致、角标是否只反映当前用户可见的监控活跃告警、无硬指针 / 未声明是否都不出 Tab、已声明且有硬指针时唯一圆心无权仍出 Tab 且失败留在图内、空邻居是否仍出 Tab 且文案为暂无关联、多个 `cmdb_id` 时是否由宿主切换且组件每次只收到一个 UUID。不锁画布内部事件名、不锁 X6 DOM、不锁 LLM、不把「页面上看起来像不像」当单测。

最高接缝优先：

- CMDB 邻居 NATS：对齐现有 `get_monitor_ids_by_inst_uuids` 的权限测试风格——无权或缺失的圆心要让调用方能区分失败；有权时邻居集合与轻量拓扑查询一致；不要求调用方传模型 ID。
- 运营分析拼图：对 NATS / 数据源取数打桩，断言一次查询的出参含邻居与节点 `count` / 最高级别；无 `monitor_id` 与 count=0 的表现不同；禁止新测试依赖运营分析 import CMDB 内部管理类。
- 声明与探测：key 已声明 / 未声明时探测结果；告警详情在「已声明 + 至少一个非空快照 `cmdb_id`」才把关联拓扑列入 Tab；告警宿主不得硬编码运营分析 HTTP 路径；唯一 `cmdb_id` 且圆心无权时 Tab 仍在，失败由图内错误承担；多个 `cmdb_id` 时 Tab 在，组件调用入参始终是单个 UUID。
- 告警解析：只读 `monitor_objects[].cmdb_id`；全空或全 `null` 不出 Tab；一个则无选择器；多个不同 UUID 出现切换且选项文案来自 `resource_type` / `resource_name`；不得把选择器或数组入参写进组件契约测试。
- 角标口径复用监控 `query_latest_active_alerts` 与关系拓扑已有的 count / 级别语义（含 99+），不重测监控 NATS 全量历史，只锁本组件合并规则。

手测（不替代单测）：打开一条已与 CMDB 联动且当前用户有资产读权限的告警，抽屉出现「关联拓扑」，图与该资产详情关联拓扑的点边一致，告警中的邻居有角标；打开未联动的告警，无此 Tab；唯一圆心无权时仍有 Tab，图内为失败可刷新；运营分析未声明时无此 Tab；一条告警多个已联动对象时能切换圆心，每次图仍是单实例邻居。

## Out of Scope

- 网络状态拓扑进池或按模型替换本 Tab
- CMDB 基础信息、变更记录、告警列表小件、监控关键指标、日志进池
- 监控实例详情那一排 Tab（产品上仍可以是用户以后第一次看见这张图的主场，本变更不改监控页）
- CMDB 资产详情作为主宿主（可编辑关联拓扑旁再挂只读图；若两 Tab 都叫「关联拓扑」需另开变更拆名）
- 点节点跳转、角标弹层、按当前告警 ID 过滤或高亮除圆心以外的语义
- 按 IP / 名称补全 `cmdb_id`、打开页面时现做身份匹配、现场反查监控实例补写 `cmdb_id`
- 组件入参多个 UUID 或模型 ID；一张图多个圆心；组件内对象下拉
- 将本组件登记进运营分析画布 / 统一筛选 / 场景组件（含「为了本模块也有使用方而进盘」）
- 将新 NATS 经 OpenAPI 网关对外暴露
- 把运营分析存量的 CMDB / 监控进程内直连（网络状态拓扑、应用 3D 等）一并拆掉
- 新问答 UI、仪表盘页面问答（另一份变更规格）

## Further Notes

- 「可以加载」是模块声明，不是「这台资产有没有邻居」。没有圆心是绑定门；当前圆心无权是该圆心的权限门，失败留在图内，不回头关掉 Tab。二者都和声明门分开。
- 角标里的活跃告警是监控中心 `status=new` 的监控告警，与告警中心单据不是同一套。处置中的这一条告警中心记录只决定人站在哪，不进入图的过滤条件。圆心节点按当前传入的 `instUuid` 高亮即可。
- `cmdb_id` 来自既有推送 / 同步回写后落在告警对象快照上的值，本变更不负责补写历史实例，也不在打开详情时回查监控。
- 第一档公共组件目录（网络状态拓扑、CMDB 基础信息与变更、告警列表、监控指标、日志、监控详情拼装）仍是后续要加的清单，不构成本规格完成定义。
