# 事故影响拓扑

Status: implemented

## Completion evidence

日期：2026-11-09。

- CMDB：给定种子和假边，上一跳、桥接、截断和看不见的实例符合口径。模型目录查询失败时不返回一张用默认层级猜出来的图。超过 200 个去重种子不打开图。
- 事故接口：查看权限、种子求交、无 NATS 订阅者时 `relation_status=not_purchased` 且仍然发起调用、超时或结果失败时 `unavailable`。告警侧不引用 CMDB 服务。失败日志保留脱敏 traceback，不写入异常正文和种子 UUID。
- 页面：表格、甘特、影响拓扑可切换。同一 UUID 合成一个节点，颜色取更小的 `level_id`。未绑定对象不连线。未购买时只显示说明。关系不可用或种子变化后的旧桥接不继续展示。
- 验证：server 上这三组测试 33 项通过；web 上拓扑纯函数、视图和事故详情隔离测试 15 项通过。使用 sqlite 内存库，没有启动整套中间件。

## Problem Statement

事故详情能看到这起事故里的告警（表格、甘特），告警上也有 `monitor_objects[].cmdb_id`。缺的是一张影响拓扑：这些告警对象按 CMDB 里真实存在的关系连在一起，看出谁挂在谁下面、哪些对象只是因为被多个告警对象共用才出现。事故里的告警是小集合，打开详情时按这批 UUID 查即可。

## Solution

事故详情的告警 Tab 增加第三种视图「影响拓扑」，与表格、甘特并列，不新开 Tab。图由当前告警列表上的 CMDB 对象组成。两端都是告警对象的「运行于」「关联」直接连上；两个及以上告警对象共用的上一跳拉进来当桥接。只有一个告警对象时不拉上一跳。没绑定 CMDB 的对象单独成点。没购买 CMDB 时视图仍可打开，页面说明原因，不报错。

主机、应用、Nginx、MySQL 只是原型里的例子。参与连线的是任意 CMDB 模型上的 `run` 与 `connect`。

## User Stories

1. As a 事故处理人, I want 在告警 Tab 的表格、甘特、影响拓扑之间切换, so that 不用离开事故详情就能看到对象关系。
2. As a 事故处理人, I want 同一 CMDB 对象的多条告警合成一个节点，颜色取最严重级别, so that 图上的对象数量和严重程度可信。
3. As a 事故处理人, I want 两个告警对象没有直接边、但共用同一个上一跳时，把这个上一跳画成桥接, so that 能看出它们为什么落在一起，即使上一跳自己没有告警。
4. As a 事故处理人, I want 只有一个告警对象时图上只有这个点, so that 这张图不会变成以单台为中心的资产拓扑。
5. As a 事故处理人, I want 点一个告警对象只看它自己的告警，点桥接节点看经由它连上的告警对象, so that 能从关系回到这起事故里的告警。
6. As a 事故处理人, I want 没绑 `cmdb_id` 的告警单独成灰点且不连线, so that 未进 CMDB 的对象不会被误连。
7. As a 未购买 CMDB 的用户, I want 打开影响拓扑时看到未购买说明而不是报错, so that 表格和甘特仍然可用。
8. As a 已购买 CMDB 的用户, I want CMDB 暂时查不到时仍能看到告警对象, so that 关系失败不挡住事故详情。

## Implementation Decisions

### 视图

- 告警 Tab 的分段切换扩展为表格 / 甘特 / 影响拓扑。三个视图共用当前告警列表。搜索、关联告警、解除告警保持可用；这些操作改变列表后，影响拓扑按新列表重查。
- 当前视图是影响拓扑时，工具栏提供「刷新拓扑」，重新拉取关系。关联或解除成功后的现有刷新同样会更新图。
- 画布只读。节点按应用拓扑层级从上到下排列：系统、服务、主机、应用服务、基础设施，没有层级的放在下面。未绑定 CMDB 的点分开摆放，不连线。点击停在本页侧栏，不跳转到资产详情。
- 节点颜色用该对象上最严重告警的现有级别颜色。`level_id` 更小为更严重。同一条告警上的同一个 UUID 只计一次。条数是命中该 UUID 的告警条数，不是事件数。
- 桥接节点没有告警，用单独样式并标明「桥接」。未绑定对象为灰色孤立点，标签用资源名称。没有 `monitor_objects` 的告警用资源名称或标题成一个灰点。同一个展示名不合并。一条告警同时有已绑定和未绑定对象时，已绑定对象进关系图，未绑定对象另成灰点。
- 图例表达三件事：告警节点颜色跟随级别、桥接、未绑定。不把级别写死成只有严重和警告。
- 侧栏：告警对象展示名称、命中的告警，以及它在本图中的关系（一端名称、关联名称、另一端名称）。桥接节点展示经由它连上的告警对象和这些对象上的告警。
- 空态：事故没有告警时与表格空态一致。告警都没有 `cmdb_id` 时只显示灰点，并提示未绑定 CMDB。有 UUID 但没有可用关系时只显示点，不弹错误。

### 种子

- 种子是当前列表里、当前用户在这起事故中可见的告警的 `monitor_objects[].cmdb_id`。模型不限。
- 页面把当前列表中的 UUID 子集交给事故接口。服务端与这起事故的可见告警种子求交，交集之外的 UUID 丢弃。不传子集时使用全部事故种子。
- 未绑定对象不发给 CMDB，由页面本地画成灰点。

### 事故接口

`POST /alerts/api/incident/{id}/impact_topology/`

权限沿用事故详情的查看权限。告警服务不引用 CMDB 的服务或 HTTP 接口，只通过 CMDB 的 RPC 客户端调用新的 NATS 方法 `incident_impact_topology`，并带上当前用户身份。

成功响应始终是 HTTP 成功。`relation_status` 决定页面怎么画：

| relation_status | 含义 | 页面 |
|---|---|---|
| `ok` | 关系已返回 | 合并告警级别与灰点后画图 |
| `not_purchased` | NATS 没有该订阅者 | 说明未购买 CMDB，不画图，不弹错误 |
| `unavailable` | 已发出调用但超时或失败 | 用告警快照把点画出来，提示关系暂时查不到，不弹错误 |

不在调用前检查本进程是否安装了 CMDB，也不为「有没有购买」做额外查询。没有 CMDB 时该方法不会注册，NATS 无订阅者会立即返回；事故接口把这个结果记为 `not_purchased`。超时和其他调用失败记为 `unavailable`。

响应体：

```json
{
  "relation_status": "ok",
  "message": "",
  "truncated": false,
  "nodes": [
    {
      "inst_uuid": "",
      "inst_name": "",
      "model_id": "",
      "model_name": "",
      "layer": "service",
      "role": "seed",
      "found": true
    }
  ],
  "links": [
    {
      "src_inst_uuid": "",
      "dst_inst_uuid": "",
      "model_asst_id": "",
      "asst_id": "run",
      "asst_name": "运行于",
      "parent_inst_uuid": ""
    }
  ]
}
```

`role` 为 `seed` 或 `bridge`。`layer` 使用应用拓扑层级：`system`、`service`、`host`、`appService`、`infrastructure`、`none`。实例不存在或当前用户看不见时，对应种子仍在 `nodes` 里，`found` 为 false，不带边。`message` 在 `not_purchased` 与 `unavailable` 时给人看，走告警现有文案。

去重种子超过 200 个时 `truncated` 为 true，只回种子 UUID，不查实例、不查边。页面提示关系未展开，并用告警快照显示这些点。

### CMDB 查询

NATS `incident_impact_topology` 只接受种子 UUID 和用户身份。按这批 UUID 批量查询 `asst_id` 为 `run` 或 `connect` 的关联边，每条边至少一端是种子。不逐个实例做 BFS，不使用网络设备闭集拓扑，也不使用资产详情那种单中心按跳数展开。

`belong`、`group`、`install_on`、`contains` 不参与。因此应用系统包含应用、主机关机柜、网卡归属不会进图。

上一跳只在这两个关联类型上判断，两端模型不限：

1. 两端都有层级，且层级不同：更高的一层是上一跳。从高到低是系统、服务、主机、应用服务。`infrastructure` 和 `none` 不参与这场比较。
2. 同层，或至少一端没有层级：`run` 的上一跳是边的目标端（运行于的落点）；`connect` 的上一跳是边的源端（发起关联的一端）。

纳入：

- 两端都是种子：保留这条边。种子自己属于基础设施层时，点保留；它与另一个种子之间的 `run` / `connect` 也保留。
- 上一跳不是种子，且它是至少两个种子的上一跳：把这个对象作为 `bridge` 拉入，只保留它连向这些种子的边。
- 只有一个种子以它为上一跳：不拉入。
- 只向上拉上一跳。种子的下级若不是种子，不拉入。
- 非种子的基础设施层对象不拉入，连向它的扩展边丢弃。当前用户看不见的上一跳同样不拉入，相关种子保持无这条边。

超过 200 个去重种子时，CMDB 直接按截断返回，不再查边。

实例可见性沿用 CMDB 按用户身份计算的组织与实例权限。看不见或不存在的种子不让整次请求失败。

### 页面合成

页面用告警列表给种子补级别、条数和名称，用 CMDB 的节点与边补关系和桥接。CMDB 不返回告警级别。桥接节点的名称用 CMDB 返回的实例名。`found` 为 false 时，种子名称回落到告警快照。

## Testing Decisions

好的测试看对外结果：给定种子和关联边，返回的节点、边、桥接和截断是否符合口径；事故接口在无订阅者、超时、越权 UUID 下的 `relation_status` 与成功状态码；页面把同一 UUID 合成一个节点、未绑定对象不连线、未购买时只展示说明。

- CMDB：用假边锁定上一跳与桥接，不依赖整张真实图。覆盖两台主机共用一个应用、两台虚拟机共用一台主机、任意模型的 `run` 共用一个落点、`connect` 的源端当上一跳、同层 `run` 以目标端为上一跳、单个种子不拉上一跳、两端都是种子的边直接保留、`contains` 与 `belong` 不出现、非种子基础设施不成为桥接、看不见的上一跳不返回、查不到的 UUID 为 `found: false`、超过 200 个种子时 `truncated` 且不查边。
- 事故接口：沿用事故查看权限；请求 UUID 必须属于这起事故的可见告警；无 NATS 订阅者时成功且 `relation_status` 为 `not_purchased`，并且没有预先查询购买状态；超时或其他 RPC 失败时成功且为 `unavailable`。断言告警侧只通过 CMDB RPC 客户端调用 `incident_impact_topology`。
- 页面：三种视图可切换；同一 UUID 合并且级别取更小的 `level_id`；未绑定对象是孤立点；`not_purchased` 展示未购买说明且不弹错误；`unavailable` 仍显示快照节点。纯函数覆盖种子合并与图合成，页面测试只锁视图切换和这三种状态的展示。

Prior art：CMDB 关联边的批量查询与应用拓扑展开测试、事故详情的权限与告警列表测试、告警快照对象的纯函数测试、NATS 无订阅者时接口仍成功的处理。

## Out of Scope

- CMDB 归属索引、告警接入时的多跳遍历、服务与 CI 的摊平表
- 以单台 CI 为中心的资产拓扑、网络接口拓扑
- APM 调用链、日志相关作为边
- 在这张图上新建、修改或删除 CMDB 关系
- 按拓扑自动合并或拆分事故
- 把影响拓扑做成运营分析组件
- 调用前探测 CMDB 是否安装或已购买，以及为此增加缓存
- 对外 OpenAPI 暴露这条查询

## Further Notes

- 原型里的主机、Nginx、MySQL、应用用来说明层级和桥接，不是模型白名单。原型把子对象上的告警算进主机节点；实现只统计打在该 UUID 上的告警。
- `model_asst_id` 的形式是 `{源模型}_{asst_id}_{目标模型}`。需求说明里的 `host_run_*` 是「主机上面跑着谁」的说法，库里的落点边通常是 `{对象}_run_host`。实现按 `asst_id` 判断，不按某几个模型 ID 写死。
