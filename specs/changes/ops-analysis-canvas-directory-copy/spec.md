## Problem Statement

运营分析里挂在 Directory 下的画布（仪表盘、大屏、拓扑、架构图、报表、网络拓扑）名称在各自类型表上全局唯一，不按目录隔离。用户无法把一份画布复制到另一个目录；即便手工再建一份，同名也会被唯一校验拦住。内置画布只读，也不能另存成可编辑的用户副本。

## Solution

在侧栏画布「⋯」菜单提供「复制」：弹出选择目标 Directory 与组织 `groups`，服务端生成一份同类型新画布。内容（布局、组件、筛选、类型既有配置）与原件一致且可独立编辑；名称按请求语言自动加后缀并通过全局唯一校验；副本不继承内置身份。原件保留在原目录（复制，不是移动）。

## User Stories

1. 作为有新建画布权限的运营分析用户，我希望把树上的画布复制到另一个（或同一个）可见目录，从而在新位置得到可独立编辑的副本且原件仍在。
2. 作为用户，我希望复制时不必手改名称，系统按我的界面语言自动加后缀并在冲突时递增，从而连续复制多次仍能保存成功。
3. 作为用户，我希望在复制弹窗里选择目标目录与组织可见范围，且组织选项受目标目录链约束，从而不会把画布扩到目录不允许的组织。
4. 作为只能查看内置画布的用户（具备目标类型新建权限），我希望能把内置画布复制成普通用户副本，从而在保留平台种子的同时得到可编辑拷贝。
5. 作为无目标目录可见性或无对应 `AddChart` 权限的用户，我希望复制被拒绝并有明确提示，从而不会误以为拷贝成功。
6. 作为正在查看某画布的用户，我希望复制成功后仍停留在当前打开的源画布，侧栏不改选到副本，从而选中态与打开内容保持一致。

## Implementation Decisions

### 范围与对象

- 覆盖六类画布：Dashboard、Topology、Architecture、Screen、Report、NetworkTopology。类型不变；不提供跨类型复制。
- 复制的是画布资源本身，不是 Directory，也不是画布内单个组件（组件级复制是另一变更）。
- 不做跨组织租户/跨 domain 复制；组织边界仍由现有 `groups` 与当前组织上下文表达。

### 入口与交互

- 入口：侧栏画布节点「⋯」→「复制」。内置画布（非内置 Directory）同样提供「复制」；内置 Directory 本身不提供复制入口。
- 弹窗必选：目标 Directory、`groups`。不展示、不编辑即将生成的名称。
- 目标 Directory 可为与源相同的目录；若目标为内置 Directory，前端排除且后端拒绝。
- 默认 `groups`：当前组织（须属于目标 Directory 链允许集合）。不考虑源画布的 `groups`。切换目标目录时收敛已选组织并限制可选项，使 `groups ⊆ 目标目录链上的 groups`（与现有 Directory 链可见性规则一致）。
- 成功后：Toast（可用服务端返回的新名称）→ 关闭弹窗 → 刷新目录树 → 展开目标 Directory；**不**选中副本、**不**导航打开副本；保持当前已打开的源画布。

### 权限

- 源画布：当前组织下可见即可（含内置只读可见）；不要求源上的 `EditChart`。
- 目标 Directory：当前组织下可见，且非内置。
- `current_team` cookie 必须是请求用户真实加入的组织（与 list/retrieve 一致）；禁止仅凭伪造 cookie 冒充其他组织完成可见性判断。
- 功能权限：对目标画布类型具备与新建相同的 `AddChart`。
- 无权限：前端隐藏或禁用入口；后端返回明确错误（可见性不足 vs 无新建权限 vs 无权访问该团队），禁止静默成功。

### 命名与唯一性

- 用户可见的唯一冲突字段是各类型表上的全局 `name`。不存在单独的用户侧 Key 字段需要加后缀。
- 服务端按本次请求已激活的语言生成名称：`{源名}-{文案}`；仍冲突则 `{源名}-{文案}2`、`3`…（不出现裸 `1`）。文案经 gettext（中文「副本」、英文 `copy`）；未知语言回退 `copy`。
- 超长时先截断源名再拼后缀，保证落库名称不超过字段上限且仍唯一。
- 不与 YAML 导入的 `_copy` 机器命名强行统一；不智能剥离源名上已有的「副本/copy」后缀（拷贝副本可出现叠后缀）。
- 前端不预生成最终名称；以接口返回为准。

### 副本内容与身份

- 深拷贝类型既有内容字段（如 `view_sets`、仪表盘 `filters`、`other`、`refresh_interval`、描述等以各类型现有模型为准）。组件内 DataSource 只保留引用 id，不克隆 DataSource / 连接 / 凭据。
- 清空 `is_build_in` 与 `build_in_key`；副本不得被后续内置初始化认领为种子对象。
- `created_by` 等维护信息记为当前操作者；时间戳按新建生成。
- 不克隆分享链接、报告订阅、执行/渲染快照、个人草稿检查点等外围资源。
- NetworkTopology：服务端将 `base_url` 与已存储 token 安全拷贝到新行（不向浏览器回传明文 token）；清空运行态缓存类字段；`view_sets` 等配置照常深拷贝。

### API 与模块边界

- 在各类画布既有资源接口上增加「复制」动作（或等价的统一画布复制接缝），请求体至少包含目标 `directory` 与 `groups`；响应返回新对象标识与最终 `name`，供 Toast 与树刷新。
- 复用现有 Directory 链 `groups` 校验与画布新建权限模型；复制路径必须走与新建同等的组织子集校验。
- 名称生成与唯一性保证在服务端完成；并发撞名时按同一后缀算法继续寻找可用名或等价安全重试，不得把裸唯一约束错误抛给用户当最终文案。

## Testing Decisions

- 只测外部行为：复制后原件仍在、新对象落在目标 Directory、名称唯一且语言后缀正确、内置标记被清除、改副本内容不影响原件、`groups` 越界与内置目标 Directory 被拒绝、无 `AddChart` / 源不可见被拒绝、伪造 `current_team` cookie（用户未加入该组织）被拒绝、外围资源未跟随、NetworkTopology 副本可使用连接且 token 不出现在响应中。
- 最高接缝优先：各画布类型的复制 API（认证用户 + 权限/组织上下文），而不是只测私有命名辅助函数。命名与 gettext 语言分支用同一 API 接缝加语言激活覆盖。
- 前端：侧栏内置/普通画布菜单出现「复制」；弹窗提交成功后的树刷新与「不切换选中/不打开副本」行为；无权限时入口不可用。优先复用侧栏与画布 CRUD 相关既有测试风格。
- Prior art：画布新建时的 Directory + `groups` 校验测试；YAML 导入 rename 冲突测试（仅作唯一性递增参考，后缀文案以本变更为准）；内置画布只读与导出菜单测试；NetworkTopology 创建/更新时 token 脱敏测试。

## Out of Scope

- 将名称唯一性改为「仅 Directory 内唯一」。
- 跨组织租户或跨 domain 复制。
- 克隆 DataSource、命名空间或连接凭据（NetworkTopology 画布自身 token 除外）。
- 克隆分享、订阅、快照、草稿检查点。
- 复制进内置 Directory。
- 弹窗内名称预览或改名；复制成功后自动打开或选中副本。
- 画布内组件级复制、跨类型复制、移动（剪切）语义。

## Further Notes

- 与「画布数据组件复制」变更正交：本变更复制整份画布资源到 Directory；组件复制仅作用于编辑态草稿内的单个数据组件。
- 内置生命周期能力不变：种子仍靠 `build_in_key` 原位同步；用户副本无 `build_in_key`，不会被 init 覆盖认领。
