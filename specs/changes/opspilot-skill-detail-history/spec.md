## Problem Statement

智能体可以按渠道独立发布，会话也已经按「渠道绑定 + 外部用户」落在智能体会话里。管理员打开智能体详情只能改设置和发布，看不到不同发布入口、不同人实际聊了什么。本人历史只出现在 Web 对话页，且接口按会话主人隔离；别人的记录会 403。排障和抽查只能去各渠道里问当事人，或误以为工作台机器人「会话日志」能覆盖智能体直连发布。

## Solution

在智能体详情左侧、发布之后增加「历史」。该页沿用详情现有的智能体管理权限，不另做可见性。管理员看到本智能体仍存在的会话表，可按具体渠道绑定、人、时间筛选，并按会话标题搜索。点开一行用抽屉只读回放该会话全文（复用对话页消息渲染）。不能代聊、不能从这页删除。用户在对话页删除会话仍是物理删除，管理员也看不见。

## User Stories

1. As a 智能体管理员, I want 在智能体详情左侧看到「历史」, so that 不必离开管理页就能抽查已发布渠道上的真实对话。
2. As a 智能体管理员, I want 一张会话表按最后更新倒序列出标题、时间、用户、渠道和数量, so that 能扫清「谁、从哪条入口、最近问了什么」。
3. As a 智能体管理员, I want 按具体渠道绑定和用户筛选, so that 测试入口和生产入口不会混在一起，也能按人找到会话。
4. As a 智能体管理员, I want 能对上平台账号的人显示姓名或用户名、对不上的显示渠道原始 ID, so that 表上的「用户」可以认，而不是一串 UUID。
5. As a 智能体管理员, I want 点开「详情」在抽屉里只读回放气泡和工具过程, so that Web 渠道落库的 AG-UI 事件仍然可读，又不会误发消息。
6. As a 仅有使用组织资格的人, I want 打不开这页、也调不到跨人会话接口, so that 别人的对话不会因为「能用这个智能体」就被看见。
7. As a 渠道对话用户, I want 自己在对话页删除会话后管理员历史里也不再出现, so that 「删除后无法恢复」对管理侧同样成立。

## Implementation Decisions

### 入口与权限

- 入口只加在智能体详情左侧菜单，文案「历史」，排在「发布」之后。不进入工作台详情，也不替代 Web 对话页的个人历史。
- 页面权限与渠道发布配置相同：智能体 `skill_setting` 查看 + 当前用户对该智能体有管理组权限。不新增独立权限点。使用组织成员若无管理组权限，不能打开详情，也不能调用本变更的管理接口。
- 现有「当前用户会话列表 / 消息 / 删除」接口保持主人隔离，不得改成返回全员数据。管理侧另开只读接口，鉴权对齐渠道绑定 CRUD 的「是否有权管理该智能体」，不要复用 Web 对话页那组登录用户接口。

### 数据与时间

- 数据源仍是智能体会话与消息，不新建会话表，不做合规留存，不改用户删除为软删除。列表只包含库里还在的会话；用户删除或删除智能体/渠道绑定后的级联删除，管理侧同样没有这些行。
- 「最后更新」以会话行的 `updated_at` 为准。每次追加消息都要刷新该时间，否则 24 小时窗会漏掉标题已定、仍在继续的会话。排序默认最后更新倒序。
- 已停用但未删除的渠道，其历史仍列出，筛选下拉里也要出现。已删除的渠道绑定随现有级联带走会话，本变更不改外键。

### 管理只读接口

- 列表：必填智能体 ID；可选具体渠道绑定 ID、人关键字、开始/结束时间、标题关键字、分页（默认每页 10）。时间空表示不限。标题搜索只匹配会话标题（含展示用回退标题所依据的已存 title 字段），不扫消息正文。
- 列表行至少返回：会话 ID、标题、渠道绑定 ID、渠道类型、渠道名称、外部用户标识、展示用「人」、创建时间、最后更新时间。标题空时展示「新会话」，与对话页一致。
- 「人」筛选同时匹配外部用户标识，以及能解析到的平台用户 `display_name` / `username`（含 `username@domain` 历史形态）。解析规则：系统用户 UUID 或 `username@domain` 能命中系统用户则用 `display_name`（空则 `username`）；企微/钉钉/公众号等解析不到的保持原始 ID。不做人员通讯录，不列出从未在本智能体聊过的组织成员。
- 消息：按会话 ID 返回该会话全部消息，形状对齐现有用户侧历史消息（角色、内容、时间），以便前端直接走历史消息渲染。调用者必须能管理该会话所属智能体；不校验「是不是会话主人」。不提供管理侧删除、代聊或发消息。

### 前端

- 主区是会话表，不是对话页左右栏，也不是按渠道类型的页签。列顺序为：渠道、用户、标题、创建时间、更新时间、数量、操作。标题、渠道、用户均为独立单行显示，多余内容截断省略隐藏（`truncate`）并在鼠标悬停时提供 Tooltip 全文查看，保持表格行高均匀规整。操作列「详情」打开抽屉。表格贴内容高度，不出现表体横向/纵向滚动条。
- 顶栏筛选全部靠右，顺序为渠道绑定下拉（类型 + 名称，可清空=全部）、用户搜索、刷新。不提供时间筛选和标题搜索。
- 抽屉复用对话页历史消息渲染（含 AG-UI 气泡与工具过程）。宽度撑大至 1000px；使用已有展示模式，去掉输入框、发送、上传、清空、新会话。不提交选择/审批，不发起 SSE。抽屉 body 移除外层 padding，滚动容器占满宽度，滚动条贴紧抽屉最右边缘，内部消息区保留舒适内边距。
- 中英文案与智能体详情其它页签一致；菜单项挂在智能体详情权限树下，随父级权限，不单独开菜单权限。

### 可观测与安全

- 生产日志只记智能体 ID、渠道绑定 ID、会话 ID、筛选类别和分页，不写消息正文、用户原话或凭证。
- 本接口是产品内管理能力，不作为新的对外 OpenAPI 网关端点。

## Testing Decisions

- 好测试只锁外部行为：谁能列出/打开谁的会话、筛选项是否按绑定而不是类型、标题搜不到正文、默认时间窗与排序、删除后管理侧消失、用户侧接口仍 403 跨人。不锁抽屉内部 React 状态或私有 helper 调用次数。
- 最高接缝是管理只读 HTTP：有管理组权限的人能看到本智能体各渠道、各人的会话；无管理组权限（含仅使用组织、其它智能体管理员）得到 403；按渠道绑定 ID 过滤不会串到同类型另一条绑定；人关键字能命中展示名和原始 ID；标题关键字命中 title 不命中仅存在于消息正文的词；时间窗按刷新后的最后更新过滤；消息接口跨人可读但管理侧没有删除/发送。对标现有智能体渠道会话的主人隔离用例，在其旁增加管理侧对照，而不是改掉那组断言。
- 追加消息必须刷新会话最后更新：同一会话在标题写定之后再聊一轮，应进入最近 24 小时列表。用户删除会话后管理列表与消息均 404/空。回归：原用户会话列表仍不含他人会话，他人读消息仍 403。
- 前端接缝：详情左侧在发布之后出现「历史」且带上智能体 ID；表列与工作台对话日志对齐；顶栏仅渠道和用户筛选且成组靠右；点「详情」打开只读抽屉且无发送入口。对标智能体详情 layout 与发布页的组件测试，不要求浏览器 E2E。

## Out of Scope

- 管理员代聊、以对方身份续写，或从历史页删除会话。
- 把用户删除改成软删除，或做合规审计留存。
- 搜索消息正文、轮次列、按渠道类型页签、对话页式左右栏。
- 人员通讯录、组织成员全量下拉。
- 工作台机器人会话日志与统计、把智能体会话并进 Bot 历史表。
- 新的 RBAC 权限点、对外 OpenAPI 暴露、导出。
- 删除渠道后仍保留会话（维持现有级联）。

## Further Notes

- 渠道发布规格里「下线渠道后历史仍可查」指停用未删的绑定；本页是该承诺的管理面。停用渠道拒绝新对话，但本页仍能打开旧会话。
- 这与工作台「会话日志」不是同一张表：那边是 Bot/ChatFlow 轮次日志，这边是智能体直连发布的 `SkillConversation`。
- 对齐会话结论：管理员详情只读；表对齐工作台对话日志列；筛选仅具体渠道绑定 + 用户且靠右；人可解析则显示名否则原始 ID；抽屉复用对话渲染；用户物理删除后双方都看不见。
