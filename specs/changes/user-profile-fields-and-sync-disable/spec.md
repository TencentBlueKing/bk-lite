# 用户标准属性、自定义字段与禁用映射

Status: implemented

## Problem Statement

系统管理员同步企业目录时，平台用户只有用户名、展示名、邮箱和手机号。工号、职位、职级、直属上级、在职状态和账号有效期无法保存，也无法从目录映射进来。不同企业还需要少量自己的档案项，但这些项不应该变成新的授权条件。

人还在目录里时，同步会把本地禁用清掉，管理员手动停用的账号会在下一次同步后重新可登录。平台没有单独的外部禁用接口可读；外部源里的禁用状态只可能出现在管理员填写的字段映射中。

## Solution

用户增加一组封闭的标准档案，并在用户管理下提供全目录统一的自定义字段。在职状态只用于展示和筛选。登录是否放行仍看现有的 `disabled`、临时锁定、密码有效期，再加上账号有效期。

禁用不拆成人工禁用和同步禁用，不新增字段。同步只有在该同步源的字段映射里把某个外部字段对应到平台禁用时，才按这个外部字段的值更新 `disabled`。没有这项映射时，同步不改 `disabled`。

目录对账保持现状：成功名单里没有、且属于该同步源的用户仍然删除。展示名、组织、邮箱、手机号以及新档案的更新和跳过规则保持现在的比较方式：没有变化就跳过，来源空值不覆盖已有值。

## User Stories

1. As a 系统管理员, I want 在用户档案里维护直属上级、在职状态、职位、职级、工号和账号有效期, so that 企业目录里的常用身份信息能在平台上看到和筛选。
2. As a 系统管理员, I want 直属上级指向另一名平台用户且可以留空, so that 汇报关系可查，但不会因此让下级获得上级的权限。把自己或成环的上级保存时会被拒绝。
3. As a 系统管理员, I want 按未设置、在职、离职筛选用户, so that 能查看人员状态。在职状态不阻止登录。
4. As a 系统管理员, I want 把账号设为永久有效或指定到期时间, so that 到期后该用户不能再通过本地登录、外部登录、已有会话或个人 API 令牌访问。个人令牌自己的过期时间仍然生效。
5. As a 使用系统令牌的调用方, I want 令牌不因创建人账号到期而失效, so that 系统集成不跟着个人账号周期中断。以到期或被禁用的用户作为 acting user 时，这次访问被拒绝。
6. As a 系统管理员, I want 启用和禁用继续只改现有的 `disabled`，临时锁定和密码有效期保持原有作用, so that 账号停用、锁定和密码过期不被新的账号有效期取代。
7. As a 系统管理员, I want 在字段映射里把一个外部字段对应到平台禁用, so that 外部源提供的禁用状态写到现有 `disabled`。没有这项映射时，同步不改本地禁用。
8. As a 系统管理员, I want 定义全目录统一的文本、数字或日期字段, so that 各同步源映射同一套扩展档案，而不是每个目录各定义一套。
9. As a 系统管理员, I want 已有值或已被同步映射的字段不能改类型、不能删除, so that 历史值和映射不会指向另一种含义。停用前必须先解除映射；停用后历史值还在，但不能再填写，同步也不再写入。

## Implementation Decisions

- 标准档案加在现有用户上，不拆成「基础信息」和「职务信息」两个模型。新增字段为：直属上级、在职状态、职位、职级、工号、账号有效期。职位、职级、工号是文本，不是「员工 / 组长」这类枚举。不新增 `manual_disabled` 或 `sync_disabled`。
- 在职状态只有未设置、在职、离职。已有用户迁移后为未设置。本地新建且未填写时也是未设置。它不参与登录判断，目录中消失也不会把它改成离职。
- 直属上级是可空的平台用户引用。不能指向自己，不能沿上级链回到自己。保存形成自指或环时，这次保存失败。它不写入角色、组织或数据权限。
- 账号有效期要么永久，要么一个到期时间。已有用户迁移后为永久。到期判断发生在后续鉴权，不用定时任务把用户改成禁用。到期时间到点后，本地登录、外部登录、已有会话的后续鉴权和个人 API 令牌都拒绝。个人令牌自身的过期时间继续有效，两个条件都要通过。系统令牌不因创建人到期或被禁用而失效。acting user 到期或 `disabled` 为真时拒绝该次访问。
- 禁用只有现有的 `disabled`。管理员的启用和禁用只改它。临时锁定和密码有效期的判定不变。已有用户的 `disabled` 保持原值，不做拆分迁移。
- 同步不调用外部源的禁用接口，也不从固定属性名猜测禁用。平台字段标识是 `disabled`。只有 `field_mapping` 里出现这个标识，并且对应的外部字段名非空时，才读取该外部值。没有这项映射时，成功名单里的用户也保持本地 `disabled`，包括现在同步会把仍在目录中的用户写成未禁用的行为。
- 映射到的外部值去掉空白后，`true`、`1`、`yes`、`disabled`、`禁用` 写成禁用；`false`、`0`、`no`、`enabled`、`启用` 写成未禁用。比较忽略大小写。空值不覆盖。其他值跳过该字段，用户仍留在成功名单，整批不因此失败。
- 用户同步的成功名单仍是：拉到了用户名，并且归属检查通过。没有用户名的跳过。本地手工用户和其他同步源的用户记为冲突，不更新。某一批失败时不对账。
- 全部批次成功后，属于本同步源、且用户名不在成功名单里的用户仍然删除。成功且目录为空时，该同步源下已有用户仍按消失删除。运行记录继续用删除人数表示对账结果。
- 成功名单内的比较方式不变。展示名和组织有变化才更新。邮箱、手机号、职位、职级、工号只有来源给出非空值且与本地不同才更新，空值不覆盖。没有上述变化、也不需要按映射更新禁用时，跳过写入。
- 标准档案和平台禁用进入现有字段映射。直属上级按平台用户名匹配。来源空值不改变本地上级。匹配不到、指向自己或会成环时，本轮不改上级，该用户仍留在成功名单。在职状态只接受未设置、在职、离职；账号有效期只接受永久或可解析的到期时间。无法识别时不改该字段，不因此把用户移出成功名单，也不让整批失败。
- 自定义字段在用户管理下以「用户字段」维护，全目录一份定义。每个字段有名称、标识、类型、说明。类型只有文本、数字、日期。标识保存后不可改，且不得与标准档案标识重名，包括用户名、展示名、邮箱、手机号、直属上级、在职状态、职位、职级、工号、账号有效期、禁用。取值挂在用户上。各同步源把外部属性映射到字段标识。
- 名称和说明可以改。任一用户已有该字段的值，或任一同步源仍映射该字段时，不能改类型，也不能删除。停用时若仍有映射，拒绝停用，由管理员先解除映射，不自动解除。停用后保留已有值，用户表单不再接受填写，同步不再写入；用户详情仍展示该历史值。已停用的字段不能被选为新的映射目标。文本超长时按现有档案字段的长度上限截断。数字或日期无法解析时跳过该字段，用户仍算成功。
- 用户详情展示标准档案和自定义字段的已有值，停用字段为只读。用户列表提供在职状态筛选。用户的新增和编辑、用户字段的新增、编辑和停用，沿用用户管理现有操作日志。
- 拉取 AD、企业微信、飞书、蓝鲸目录时，仍不按在职或离职过滤，也不按外部禁用状态过滤。消失组织仍归档。删除同步源时仍删除该源用户并归档其组织。

## Testing Decisions

测外部行为，不锁死私有函数怎么拆。最高缝是一次完整用户同步、一次登录或令牌鉴权，以及用户字段的保存接口。

- 用户同步：沿用现有同步服务测试里「成功名单、冲突不领取、空邮箱不覆盖、批次失败不对账、目录消失即删除」的缝。没有把外部字段映射到 `disabled` 时，成功名单中的用户保持本地禁用，同步不把它写成未禁用。映射存在且外部值能识别时，`disabled` 改成对应结果。外部值为空或无法识别时不改 `disabled`，用户仍在成功名单。来源空的职位、职级、工号、上级不覆盖本地值。上级匹配不到或成环时用户仍在成功名单，上级不变。无法识别的在职状态、账号有效期、数字和日期同样不改该字段。
- 鉴权：本地登录、外部登录、会话的后续请求和个人 API 令牌，在 `disabled` 为真或账号到期时拒绝。个人令牌自身已过期时，即使用户账号仍有效也拒绝。系统令牌在创建人到期或被禁用时仍可通过；acting user 到期或 `disabled` 为真时拒绝。在职状态为离职、临时锁定和密码过期的现有判定不被这次改写：离职仍可登录，锁定和密码过期仍拒绝。
- 用户字段：标识保存后不能改；与标准档案或 `disabled` 重名被拒绝。有值或有映射时改类型和删除被拒绝。有映射时停用被拒绝，解除映射后可以停用。停用后同步和用户保存都不再写入该字段，已存值在详情中仍可读。无值且无映射时可以删除。
- 迁移：已有用户的在职状态为未设置，账号有效期为永久。已有用户的 `disabled` 不变。

## Out of Scope

- 用这些档案或自定义字段做角色、组织继承、数据权限或授权条件。
- 微信号、QQ、入职日期，以及枚举、多选等更多字段类型。
- 按在职或离职过滤外部目录的拉取结果。
- 把目录消失解释成离职，或把目录消失改成禁用、保留用户。
- 新增人工禁用字段或同步禁用字段，或单独调用外部源的禁用接口。
- 改变消失组织的归档方式，或改变删除同步源时删除其用户的行为。
- 把新档案加入对外 OpenAPI 的用户列表契约。
- 用定时任务把到期用户写成禁用。

## Further Notes

这次对齐替换原先「禁用拆成人工禁用和同步禁用」以及「目录消失的用户保留并打上同步禁用」。同步禁用指外部源里该用户的禁用状态，并且只通过管理员填写的字段映射读取。

直属上级、在职状态、账号有效期和禁用的同步映射失败只跳过对应字段。用户是否进入成功名单仍只看用户名和归属检查。

## Completion

主工作区在 `master`。标准档案、自定义字段和账号有效期沿用已复制的实现。禁用只保留现有 `disabled`，没有 `manual_disabled` 或 `sync_disabled`。字段映射写到 `disabled` 且外部值能识别时才更新；没有映射、空值或无法识别时保持本地禁用。目录中消失的用户仍然删除。

验证通过：`test_user_profile_sync.py`、`test_user_field_catalog.py`、未映射时重新出现的用户保持本地禁用、登录对禁用、离职和账号到期的判定。`test_reconcile_deletes_stale_users_instead_of_disabling_them` 仍会走到现有对账锁，失败点和当前 master 的对账实现一致。
