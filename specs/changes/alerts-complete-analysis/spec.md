# 告警分析完整读取

状态：已实现并验证

## 问题

用户要求分析全部活动告警时，`alerts_list_alerts` 只返回一页，模型可能把前 100 条作为样本结束。大结果落盘后的预览也不能代表全部记录。

## 行为

- `alerts_list_alerts` 默认 `fetch_all=true`，从第一页以每页 100 条连续查询，逐页沿用调用者身份与筛选条件。
- 成功结果包含 `count`、`items`、`complete=true`、`retrieved_count`、`pages_fetched`。`complete` 表示本次分页记录齐全，不表示事务快照。
- 最多 1000 条、10 页、1 MiB JSON。总数变化、重复 ID、分页缺失、RPC 失败或超限均返回失败，不返回部分明细，不自动改为抽样分析。
- 显式 `fetch_all=false` 保留单页查询，返回 `complete` 与 `next_page`。只有第一页包含全部匹配记录时，单页结果才完整。
- NATS 列表按创建时间和唯一主键倒序，避免相同创建时间导致分页顺序不确定。原授权范围和每页上限不变。
- 工具说明要求读取完整文件再分析。已启用 Python 时，读取 JSON 并校验记录数后聚合，不能把文件预览或匹配行数当成全部数据。
- 已绑定的 Python 工具在执行步骤中保持可见，避免规划只选择查询工具后无法分析落盘文件。未绑定时不注入 Python，总结阶段仍关闭工具。
- 执行指引明确文件工具的虚拟路径与 Python 相对路径，并要求各维度完整分组的合计与读取总数一致。同一指标跨对象类型时合并计数或完整列出各类型，未知值单列。
