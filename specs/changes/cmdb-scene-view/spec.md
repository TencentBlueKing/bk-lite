# CMDB 场景视图

Status: done

## Problem Statement

运维人员经常要按场景看资产，例如「测试环境的主机和物理服务器」，而不是先选一个模型再筛选。现有资产列表和已保存筛选都绑在单个模型上；跨模型搜索只支持关键词，不能保存条件，也不能把同一个视角分享给组织和全员。

## Solution

在 CMDB「视图」下增加「场景视图」：用户先选模型范围，再按标签切数据，保存为一条活查询。打开时按当前用户的实例权限重新计算。个人默认可建；有权限可组织内只读分享；管理员可发全局只读场景。结果以按模型分表为主，附匹配总数和按模型数量，支持一次导出多 Sheet Excel。

## User Stories

1. As an 能看资产的运维人员, I want 先选多个模型再选标签并保存为个人场景, so that 我能反复打开「测试环境的计算资产」这类视角而不用每次重选模型
2. As an 运维人员, I want 标签之间可选 AND 或 OR 且默认 AND, so that 我既能切交集场景，也能偶尔做并集
3. As an 运维人员, I want 打开场景时看到匹配总数、按模型数量和有命中的分表, so that 我知道这次切出来一共多少、各模型多少
4. As an 运维人员, I want 分表列跟各模型资产列表的展示列走、行只读并点进现有详情, so that 场景负责找人，改数据仍走原来的资产页
5. As an 运维人员, I want 某个模型 0 条时不占一块、全 0 时看到没有匹配的实例, so that 空结果像搜索而不是坏掉的空表
6. As an 有组织共享权限的人, I want 把场景设为组织只读分享, so that 同组织的人打开同一个视角
7. As an 管理员, I want 创建全局场景并出现在「全局」分组, so that 全员能找到标准视角，但不被自动钉到「我的」
8. As an 打开共享或全局场景的人, I want 不能改原件、只能另存为自己的, so that 团队视角不会被别人改乱
9. As an 运维人员, I want 在同一导航列表里按「我的 / 组织 / 全局」分组看到我能看见的全部场景, so that 不用切 Tab 找视图
10. As an 运维人员, I want 一次导出当前权限下全部命中、按模型分 Sheet 的 Excel, so that 我能把这一个场景带走

## Implementation Decisions

- 场景是独立持久化对象，不复用 `cmdb_saved_filters` / 个人 user_configs。那套按模型隔离且无法做组织/全局分享。
- 查询定义包含：名称、模型 ID 列表、标签列表（`key:value` 字符串）、`tag_match`（`and` | `or`，默认 `and`）、可见范围（`personal` | `organization` | `global`）、组织 ID（仅组织共享必填，取创建时当前组织）。
- 活查询：按打开者身份、逐模型调用现有实例列表查询。AND 把每个标签做成必须命中的标签条件；OR 把标签放进同一 `list_any[]`。权限参数与资产列表相同（组织权限 + 创建人）。不新造图查询语言。
- 无标签字段或实例未打上所选标签，结果就是 0 条，响应不带原因码或原因文案。count 为 0 的模型从结果中省略。
- 列表接口返回当前用户可见的全部场景（个人：创建者是我；组织：可见范围是组织且组织在用户组织范围内；全局：全部）。分组标题由前端排，空组不渲染。
- 读、执行、导出、创建个人场景：挂现有 `asset_info-View`。组织共享的发布/改可见范围：新动作权限 `asset_views_scene-Org Share`（默认不给 normal，给 CMDB admin）。全局的创建/改/删：超管或 CMDB admin 角色。共享与全局场景对非创建者只读；另存为始终生成个人场景。
- 菜单：一级「视图」下新增「场景视图」，权限继承 `asset_info`；父级「视图」仍落地资产总览。路由为独立页 `/cmdb/views/scene`，不要并进现有 `[viewType]` 专题工作台（那套依赖实例焦点选择器）。
- 分表列读取打开者在该模型上的展示列配置，没有则回落到模型默认展示列。行点击进现有资产基础信息。
- 导出复用现有按模型实例导出能力，在场景执行结果上打包成一个工作簿、每模型一 Sheet；只包含 count > 0 的模型；范围为当前用户权限下的全部命中，不是当前页。
- 第一版不经 OpenAPI 网关对外暴露。内部 API 即可。
- 生产日志只用 CMDB logger；INFO 只记录场景保存/分享/导出终态（ID、可见范围、模型数、命中总数），不写标签值、实例列表或权限映射。

## Testing Decisions

- 好测试只验证外部行为：保存的条件、AND/OR 命中、权限过滤后的数量、0 条模型被省略、可见范围隔离、只读与另存、导出 Sheet 集合。不锁定图客户端 Cypher 或前端 DOM 层级。
- 约定接缝（由现有 CMDB 测试风格推断，不再另开访谈）：
  - 场景查询服务：mock `InstanceManage.instance_list`，断言逐模型条件、permission_map 传入、省略 count=0 的模型、汇总 total
  - 场景 HTTP API：个人 CRUD、preview/execute 响应形状、组织/全局可见性与 403、另存归属
  - 导出服务：给定各模型命中，断言工作簿 Sheet 名与「无命中不出 Sheet」
  - 前端菜单脚本：zh/en 子项、URL、`withParentPermission`；列表分组纯函数：空组消失、顺序为我的→组织→全局
- Prior art：`test_instance_service_graph_mock.py`（instance_list + fake_graph）、订阅规则序列化/权限测试、`web/scripts/cmdb-views-hub-menu-test.ts`

## Out of Scope

- 公共大表、饼图、维度切换、点图再筛选
- 组织、负责人、状态等标签以外的场景条件
- 跨模型批量编辑/删除
- 共享/全局场景的协作编辑
- 空结果原因文案（无标签字段 / 未打标 / 无权限分开展示）
- 全局场景自动钉到「我的」
- 指定人/角色分享
- 经 OpenAPI 网关对外暴露场景 API
- 标签全局词表治理

## Further Notes

- 「分享」只分享查询定义。两个用户打开同一场景，命中数可以不同，产品不解释原因。
- 创建顺序是产品契约：先模型范围，后标签。标签候选项来自所选模型上已有的标签字段选项并集，不另建词表。
- 与一级专题视图（网络拓扑、机房机柜等）并列，不替换它们，也不复用其实例选择器壳。
