# Windows Bat 作业的位置参数

## 执行约定

快速执行、模板、定时任务沿用 Job 的参数数组和执行记录格式。服务端在派发 Bat 前还原有序值列表，按下列路径传递。

| 目标 | 传递方式 |
|---|---|
| Windows 手动目标 | Ansible 执行器通过已加密保存、查询时脱敏的 `extra_vars.bklite_secret_bat_args` 接收参数，通过 WinRM 标准输入交给固定的 PowerShell 启动程序，再由该程序为本次 `cmd.exe` 子进程设置环境。 |
| Windows 纳管节点 | NATS 执行器通过可选 `bat_args` 数组接收参数，在本次 `cmd.exe` 子进程的环境中传递。 |

用户脚本通过 `%1`、`%2` 等原生位置参数读取值，含空格和空字符串的值保留为独立参数。用 `%~1` 取去除外层引号的值。两条路径均关闭延迟展开，使用固定变量引用启动脚本。输入中含内嵌双引号、ASCII 控制字符或无效 Unicode 时显式失败；命令长度按 UTF-16 码元受 `cmd.exe` 上限约束。无参数的调用省略参数字段，沿用原路径。

## 发布与回滚

先升级 Windows 节点上的 NATS 执行器和承接 WinRM 请求的 Ansible 执行器，再升级 Job 服务端。带参脚本在执行用户正文前检查执行器标记，遇到忽略新字段的旧执行器会报错。无数据库迁移。回滚时先回滚服务端，再回滚执行器；旧服务端恢复此前忽略 Bat 参数的行为。

## 验证

已用真实 Windows 分别验证 WinRM 文件执行和节点执行器的原生启动。覆盖两个中文参数、中间空值、带空格的路径、字面百分号和批处理元字符。WinRM 验证还检查了 `SHIFT`、脚本文件名、指定的非零退出码及临时文件清理。
