# OpsPilot 工具、技能与 MCP 标签筛选

Status: ready

## Problem Statement

智能体要挂的工具、技能包和 MCP 已经很多。管理员在智能体里挑选时，只能整表翻找；工具管理页也只有 MCP 用一组固定六类标签做下拉筛选。内置工具的标签要么是空的，要么在同步时被写成「其他」，和实际用途对不上。技能包只有一个来自包清单的分类，不能当多标签用。

## Solution

给内置工具、技能包、MCP 各自一套标签。内置工具和内置技能包的系统标签由系统维护，用户可以再加自己的标签，但不能删系统标签。用户导入的技能包和 MCP 只有用户标签。

工具管理页的三个视图，以及智能体里选择工具、技能包、MCP 的三个弹层，顶部都用同一套筛选：标签可点亮，没点亮就显示全部，点亮多个是「命中任一」。有搜索框时，关键字再在标签结果里收窄。

## User Stories

1. As a 智能体管理员, I want 在选择工具、技能包或 MCP 时按标签点亮筛选，并同时用关键字收窄, so that 不用在整张列表里翻找。
2. As a 智能体管理员, I want 一个标签都没点亮时看到全部，点亮多个时看到命中任一标签的项, so that 筛选是在缩小范围，而不是要求同时具备所有标签。
3. As a 智能体管理员, I want 被标签或关键字藏起来的已选项仍然保持选中, so that 筛选不会把已经勾上的工具、技能包或 MCP 弄丢。
4. As a 工具管理员, I want 在工具管理页用同一套标签筛选内置工具、技能包和 MCP, so that 管理和挂载时的找法一致。
5. As a 工具管理员, I want 给内置工具和内置技能包只改分组和标签，且系统标签去不掉, so that 我能按自己的叫法补充筛选，又不会改掉系统给定的分类。
6. As a 工具管理员, I want 给 MCP 和自己导入的技能包自由添加、复用和删除标签, so that 标签词能在同一类里逐渐对齐，而不必先建一套标签库。
7. As a 工具管理员, I want 系统再次同步内置工具或重新播种内置技能包时，系统标签换成新的、我加的标签还在, so that 升级分类不会清掉我的补充。

## Implementation Decisions

### 三套词表

- 内置工具、技能包、MCP 的标签互不混用。筛选条和输入提示都只取当前这一类里已经出现的标签。
- 不设「内置」这个标签。内置与否仍用现有的分段和内置标记区分。
- 技能包清单上的 `category` 继续只做展示和关键字搜索，不进入标签，也不在播种时抄成标签。

### 系统标签与用户标签分开存

- 内置工具、内置技能包各存两份：系统标签、用户标签。对外展示时合并，同一个词只出现一次。
- 用户导入的技能包和 MCP 只有用户标签，系统标签为空。
- MCP 上已经保存的旧六类标签（搜索、通用、运维、媒体、协作、其他）整份视为用户标签，保留，允许之后改掉或删除。新建 MCP 不再从这六类里必选，标签可空。
- 内置工具上由同步写成的「其他」以及旧六类，视为旧系统标签。同步时丢掉，改写成下面的新系统标签，不并入用户标签。
- 用户标签按用户输入保存。去掉首尾空白，丢掉空词，同一份里去重。筛选按保存后的词精确匹配。系统标签用稳定标识，界面按当前语言显示文案。

### 内置工具的系统标签

标签打在工具集上（一张卡，例如 MySQL、Kubernetes），不打在工具集内部的每条子命令上。一个工具集可以有多个系统标签。

| 系统标签 | 工具集 |
|---|---|
| 监控告警 | monitor、alerts |
| 日志 | log |
| 资产 | cmdb |
| 数据库 | mysql、oracle、mssql、postgres、redis、elasticsearch |
| 容器 | kubernetes、kubernetes_data_collection |
| 发布 | jenkins |
| 主机与身份 | ssh、shell、activedirectory |
| 检索 | duckduckgo、fetch、github、browser_use、agent_browser |
| 通用 | current_time、python、attachment_file、ops_analysis_dashboard |
| 平台应用 | cmdb、monitor、alerts、log、ops_analysis_dashboard |

平台应用与该工具集自己的领域标签同时存在。例如 CMDB 同时是「资产」和「平台应用」。

### 内置技能包的系统标签

- 系统标签按包写在播种数据里，不从 `category` 推导。
- 当前仓库里的内置技能包 `kubernetes-configuration` 系统标签为「容器」。
- 以后新增内置技能包时，在其播种数据里写系统标签；没有写则系统标签为空，用户仍可加用户标签。

### 同步与重新播种

- 内置工具再次同步、内置技能包再次播种时：系统标签整组替换为当前定义；用户标签保持不变。
- 不把 `tags` 整段覆盖成只剩系统标签。
- 系统标签与用户标签撞同一个词时，存储仍分开，展示只留一个。

### 编辑

- 入口在工具管理页，点单个内置工具或内置技能包进入编辑。
- 内置工具、内置技能包只允许改分组和用户标签。名称、描述、地址、包正文和 `category` 保持不可改。分组沿用现有的组织分组字段。
- 系统标签在编辑界面展示且不可删除。用户标签可增可删。
- MCP 仍用现有的新建和编辑表单，标签改为可空的自由多选。用户导入的技能包同样从工具管理页点开编辑，可改分组和标签，标签全部可删；不改包正文。
- 输入标签时列出当前这一类已经用过的词供点选，也允许输入新词。不另做标签管理页。提示来自当前列表，不新增标签字典接口。
- 写权限沿用工具列表现有的编辑权限，不新增权限点。

### 筛选

- 工具管理页的内置工具、技能包、MCP 三个视图，以及智能体里三个选择弹层，使用同一套筛选规则。
- 三个选择弹层都提供搜索框。工具管理页沿用现有搜索。
- 筛选条列出当前这一类里真实出现过的标签，系统标签和用户标签混在同一条里，不分成两组。没出现过的词不展示。
- 没有点亮任何标签且搜索框为空：显示全部，包括没有任何标签的项。
- 点亮多个标签：命中任一标签即留下（系统标签或用户标签都算）。没有任何标签的项在此时不出现。
- 关键字在标签结果之上再收窄，匹配名称和描述。只点标签、或只输入关键字时，只按那一边筛。
- 切换「工具 / 技能包 / MCP」，以及重新打开选择弹层：点亮的标签和关键字都清空。清空的是筛选条件，不清空智能体里已经选中的工具、技能包或 MCP。
- 在同一次选择里，被筛掉的已选项保持选中，底部已选数量把它们算进去。关掉筛选后勾选状态还在。

筛选在客户端对已加载列表完成。列表接口返回系统标签和用户标签，供界面合并展示并区分哪些不能删。服务端负责写入约束和同步时的替换，不新增按标签查询的接口。

## Testing Decisions

好的测试锁住外部行为：写入后系统标签与用户标签各自是什么、同步之后各剩什么、筛选后看见哪些、已选项是否还在。不锁存储字段名或组件内部状态。

服务端用现有的工具同步命令测试、内置技能包播种测试，以及技能工具与技能包更新接口测试，作为最高缝。覆盖：

- 内置工具同步后系统标签等于上表，旧的「其他」不在用户标签里；同步前用户标签在同步后仍在。
- 再次同步会替换系统标签，不覆盖用户标签。
- `kubernetes-configuration` 播种后系统标签为「容器」。
- 更新内置工具或内置技能包时，去掉系统标签被拒绝，用户标签和分组可以改，名称等其余字段不变。
- MCP 与用户导入技能包的标签可空、可增删；MCP 旧六类标签落在用户标签上。

客户端把三处列表共用的筛选规则测一次：未点亮显示全部、多标签命中任一、关键字再收窄、无标签项只在未点亮时出现、切换类型清空条件但不清空已选。选择弹层再补一条：被筛隐藏的已选项仍计为选中。先前例如工具选择弹层的纯逻辑测试，以及技能设置相关组件测试。

## Out of Scope

- 把技能包 `category` 变成标签，或让它出现在筛选条上。
- 单独的标签管理页、跨类共用词表、名为「内置」的标签。
- 给工具集内部的单条子命令打标签。
- 改智能体运行时如何调用已挂上的工具或技能包。
- 改知识库页面的自由标签。
- 改用户导入技能包的正文、清单或导入流程。

## Further Notes

内置工具的系统标签以工具集标识为准，与卡片上的展示名无关。展示名随语言变化，筛选匹配用系统标签标识和用户输入的原词。
