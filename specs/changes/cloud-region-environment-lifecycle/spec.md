# 云区域环境生命周期交互

## 目标

云区域环境页必须区分平台内置的默认云区域与用户创建的非默认云区域，并区分首次部署、运行健康和后续维护，避免已经正常运行的默认环境继续暴露部署表单。

## 行为契约

- 默认云区域由 BK-Lite 安装流程统一部署和维护。控制台只展示组件健康状态、刷新和排障说明，不允许修改代理地址、生成部署脚本或重新部署。
- 非默认云区域全部组件尚未部署时，页面展示“确认代理地址 → 生成并复制脚本 → 执行后刷新状态”的首次部署流程。
- 非默认云区域部署后展示只读部署摘要；重新部署沿用当前生效地址，变更代理地址走独立维护流程。
- 代理地址变更先写入待生效地址。部署脚本使用待生效地址构造，但不得提前覆盖当前地址或相关环境变量。
- 用户确认已在新代理主机执行脚本后，平台必须再次确认 `stargazer` 与 `nats-executor` 均为已部署且健康，才允许把待生效地址切换为当前地址；失败或取消时旧地址继续生效。
- 当前代理健康协议只按云区域固定实例名响应，不能证明响应来自新代理。因此本轮切换同时要求用户显式确认脚本已执行；未来若代理回报部署批次标识，可将该确认升级为自动验证。
- 部署阶段与健康状态分别返回。部署阶段至少包含 `system_managed`、`not_deployed`、`partially_deployed`、`deployed`；健康状态至少包含 `normal`、`abnormal`、`unknown`。
- K8s 当前没有本地可执行部署能力，但必须保留独立的 K8s 部署跳转入口。入口应明确说明企业版能力并跳转至 BK-Lite 官网，不得改变或伪装成容器部署生命周期中的可执行步骤。

## 接缝

- `CloudRegionSerializer` 返回 `is_default`、`deployment_state`、`health_state`、`pending_proxy_address`。
- `POST /node_mgmt/api/cloud_region/{id}/stage_proxy_address/` 暂存非默认区域的新地址。
- `POST /node_mgmt/api/cloud_region/{id}/activate_proxy_address/` 在用户确认且组件健康后切换地址。
- `POST /node_mgmt/api/cloud_region/{id}/cancel_proxy_address/` 放弃待生效地址。
- `POST /node_mgmt/api/cloud_region/deploy_command/` 对默认区域拒绝生成；对非默认区域优先使用待生效地址，但不修改当前配置。
- 前端环境页只消费详情接口的领域状态，不从 URL 查询参数推导部署状态或代理地址。

## 验证

- 默认区域无法生成部署脚本、暂存或切换代理地址。
- 待生效地址生成的脚本使用新地址，数据库中的当前地址和环境变量保持不变。
- 双组件未全部健康、缺少用户确认或没有待生效地址时无法切换。
- 成功切换后当前地址及相关环境变量原子更新，待生效地址清空。
- 页面覆盖默认区域、首次部署、已部署正常、已部署异常和地址待生效状态。
- 默认与非默认区域均可进入 K8s 部署说明并安全跳转至 BK-Lite 官网；切回容器部署后原有生命周期状态不丢失。
- 刷新按钮具有可访问名称；状态不只依赖颜色表达；亮暗主题均只消费语义 token。
