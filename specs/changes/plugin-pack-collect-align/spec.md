# 探针包单槽覆盖与采集配置对齐

Status: ready

## Problem Statement

运维导入新探针包后，已接入实例的采集任务不会自动按新模板重下发。操作者需要知道哪些任务还停在旧内容上，并在不升级节点二进制、不覆盖手改配置的前提下，把未手改任务对齐到当前包。当前实现已打通导入提醒与一键对齐，但日常入口不容易发现待对齐实例；导入后的「去节点」落不到对应采集器；升完二进制也没有回到采集配置；撤销路径容易和「恢复内置」混淆；资产页操作列过挤。

## Solution

探针包目录只保留一份当前内容。导入覆盖目录，不自动重下发。资产页按内容指纹提示可升级，操作者可选择把采集配置对齐到当前包。有待更新任务时，导入成功页只给配置对齐入口；本次 artifacts 有写入时才说明新配置仍跑节点上现有采集器程序。不自动给节点装新程序。节点列表日常展示采集器可更新；换程序仍走安装/更新组件。集成列表日常展示待对齐实例数。退路写明是再导入上一份 zip。手改配置默认不覆盖；要对齐必须明确放弃该探针在该实例上的全部手改后再重渲染。

## User Stories

1. As a 平台运维, I want 导入探针包后看到可升级实例并跳到资产页, so that 我能按需把运行中的采集任务对齐到当前包，而不是被自动改配置。
2. As a 平台运维, I want 在资产页看到当前下发版本和目标包版本, so that 我能确认这次对齐会把任务从哪一版收到哪一版。
3. As a 平台运维, I want 对未手改任务一键按当前包重生成并下发采集配置, so that 接入参数保留，配置文件按新模板重生，节点二进制不被这次操作安装或升级。
4. As a 平台运维, I want 手改任务默认不被一键覆盖, so that 我改过的采集文件不会在对齐时丢掉。
5. As a 平台运维, I want 对已手改任务明确选择「放弃手改并升级」, so that 该探针在该实例上的全部采集配置被丢掉并按当前包重渲染，可升级提示可以结束。
6. As a 平台运维, I want 导入成功且有待更新任务时只看到更新采集配置, so that 日常闭环是改任务配置。若本次 artifacts 有写入，再看到「新配置仍跑旧程序」的说明，而不是并列去升节点。
7. As a 平台运维, I want 恢复内置后只被引导去对齐采集配置, so that 我不会被带到节点页去处理这次并未改动的二进制。
8. As a 平台运维, I want 导入写坏时再导入上一份 zip 来退回目录, so that 我不需要产品提供版本库或快照撤销。
9. As a 无实例 Operate 权限的导入者, I want 导入仍能成功且对齐时无权限实例被跳过, so that 包目录更新不会越权改别人的采集任务。
10. As a 平台运维, I want 节点列表日常看到可更新的采集器, so that 我不用等导入页带着 query 进来才发现。换程序仍走安装/更新组件，不新增升级接口。
11. As a 平台运维, I want 采集器程序安装或更新完成后被提醒回资产页对齐采集配置, so that 我不会以为装完程序采集任务就已经是新包。
12. As a 平台运维, I want 在集成列表看到哪些插件还有待对齐实例, so that 我不必只靠导入成功页才能发现可升级。
13. As a 平台运维, I want 打开「可升级」过滤后空表有说明, so that 我知道当前对象没有待对齐实例，而不是接入丢了。
14. As a 平台运维, I want 产品内写明退路是再导入上一份 zip、恢复内置不是撤销, so that 我不会用错恢复内置。

## Implementation Decisions

- 目录是单槽：插件只保留当前 `pack_version` 与内容指纹。导入覆盖，版本号只用于展示和确认，不是可切换版本库。
- 可升级判定看采集配置已应用指纹是否等于当前包指纹，不看上报正常/失联，也不表示节点上采集器程序可更新。资产页「可升级」只表示配置指纹。
- 对齐接口按实例列表重渲染未手改配置；可选 `monitor_plugin_id` 限制探针。新增 `discard_hand_edited`：为真时对该实例 × 该探针下全部采集配置跳过手改护栏并清手改标记。
- 一键对齐抽旧配置和环境变量再套新模板。新模板缺参按空值生成并标成功。写库即成功，不等节点在线。
- 手改保存默认不 acknowledge 新包指纹，避免「去编辑」误清可升级。
- 导入成功页有 stale 时默认只给配置对齐入口（1 个对象直达资产页，2 个及以上去集成列表）。节点程序入口仅在本次 `artifacts[].action` 为 `created`/`overwritten` 时以次要说明出现；全是 `skipped` 则不提节点。不按舰队 `upgradeable` 出入口，不导入即自动升节点。恢复内置成功页只给配置对齐。
- 程序说明里的去节点 URL 仍带采集器名称，以及可回跳资产页的对象/插件。节点页读取该查询参数，说明采集器程序与采集配置是两件独立的事；安装/更新完成页在带了回跳参数时提供去资产页入口。节点列表只要 `versions` 里采集器 `upgradeable` 就展示名称和可更新版本，不依赖导入 query。控制器可升级筛选维持原语义，不加采集器可升级筛选。安装组件文案为安装/更新组件，与覆盖安装同一条 `installCollector` 路径。
- 插件列表在当前页结果上批量附带操作者可见的 `stale_instance_count`；集成卡片用它做日常发现，点进资产页并打开可升级过滤。计数失败不得打断列表。
- 资产页「可升级」过滤为空时说明这不是接入丢失，并提供关掉过滤的出口。
- 覆盖导入警告、导入说明和恢复内置确认都写明：退路是再导入上一份 zip；恢复内置回到产品内置，不是撤销最近一次导入。
- 导入成功、恢复内置成功、集成列表 stale 提示用「更新采集配置」/「去查看待更新配置」。资产页操作仍叫「升级探针」，且只表示重下发采集配置。需要提节点时写「采集器程序（在节点上）」，少用「节点二进制」。恢复内置后的待对齐提示说的是当前内置内容，不是「新探针包」。
- 资产页操作列只保留查看、编辑和当前主升级动作；去编辑、配置、移除收入更多菜单。
- 无权限实例按条 skip。批量上限 200，超出截断并提示。结果用汇总 toast；剩余未对齐继续出现在「可升级」过滤里。
- 第一次给插件打上包指纹时，从未 stamp 的存量实例全部进入可升级。
- 自定义探针、仪表盘和告警策略不进入这套对齐流。

## Testing Decisions

- 测外部行为：默认对齐仍跳过手改配置；`discard_hand_edited` 会重渲染并清手改标记；导入成功页有 stale 时只有配置入口；`hasCollectorProgramChange` 区分 skipped 与 created/overwritten；多对象收口到一个配置按钮；程序说明里的去节点 URL 带采集器；恢复内置成功页没有去节点；插件列表在授权范围内给出 stale 计数；计数失败时列表仍返回；节点列表不依赖导入 query 也能展示采集器可更新。
- 测模块：采集配置更新服务、插件列表富化、资产页手改出口与空态、导入成功页页脚、节点列表可更新发现。
- 优先复用现有采集配置更新服务的单测风格（构造配置对象与返回结构，不测私有调用次数）。本地验证用的测试默认不纳入 commit。

## Out of Scope

- 探针包版本库、实例钉版本、按版本回滚、服务端保留上一份导入快照。
- 导入或撤销时自动重下发采集配置。
- 节点离线待重试队列、独立对齐审计、后台任务与进度条。
- 把导入权限和对齐权限打通。
- 自定义 SNMP / 自建探针改模板并进可升级。
- 随包自动迁移仪表盘或告警策略。
- 预检新模板必填参数。
- 按采集器名称在服务端过滤节点列表（节点页用说明和回跳闭环，不改现有控制器可升级过滤语义）。
- 导入后自动给相关节点安装新采集器程序。
- 一个按钮同时装程序并重下发采集配置。
- 用节点可升级冒充资产页「可升级」。
- 为导入成功页查询舰队 `NodeComponentVersion.upgradeable`。
- 新增独立「升级组件」接口（与安装同路径）。

## Further Notes

已锁定原则：

1. 目录单槽，导入覆盖；版本号只是展示。
2. 退路是再导入上一份 zip。
3. 混跑长期允许，未对齐不算故障。
4. 导入/撤销都不自动重下发。
5. 一键不覆盖手改；出口是「放弃手改并升级」，作用于该实例 × 该探针的全部配置。
6. 导入成功有 stale 时只推更新采集配置；不自动升节点。程序有变更时写清新配置仍跑旧程序。
7. 新模板缺参也照样渲染并标成功。
8. 第一次打指纹，未 stamp 存量全部可升级。
9. 离线写库即成功，不做待重试。
10. 导入权限和对齐权限拆分。
11. 不做独立对齐审计。
12. 批量结果用汇总 toast，剩余看「可升级」过滤。
13. 恢复内置只引导去对齐配置，不去节点。
14. 自定义探针不进这套可升级流。
15. 指标/仪表盘/策略不随包自动迁移。
16. 节点列表日常展示采集器可更新；程序变更说明可带采集器去节点。装完或更新程序后再提醒对齐采集配置。
17. 集成列表日常展示待对齐实例数；可升级过滤空态要说明原因。
18. 产品内写明退路；恢复内置不是撤销导入。
19. 资产页「可升级」/「升级探针」只表示采集配置指纹，不表示节点上采集器程序可更新。
