# vCenter 采集归属修复

Status: implemented — 本地自动化验证完成，真实 VC 验收待执行

## 已确认范围

修复同一 VC 可通过不同根实例重复建任务，以及根资产归属为空时被新任务单独接管的问题。
以本地代码为准，不部署、不重启、不修改真实任务与资产。

- 同一根 UUID，或同一采集网络范围内规范化地址和端口相同，视为同一目标。
- 后端保存拒绝重复目标；已纳管的原任务仍允许正常编辑。
- 存量重复任务在任何写图前检查整个 VC 的归属，以现有资产所有者为准，不按任务 ID/创建时间选赢家。
- 混合所有者或无法确定唯一原任务时明确拒绝，不抢占根或子资源。
- 根实例按 UUID 解析；先更新根，根失败不写子资源。改名不能生成第二份根。
- 成功纳管根记录采集来源键；删除任务后仍保留，用于同端点新任务复用原根及关系，保留 UUID。
- 不自动合并或删除重复根实例。IP/域名别名指向同一真实 VC 的识别不在端点匹配证明范围。
- 普通非 VC 采集与扫描/拓扑共享调用保持原行为。

## 验证入口

沿用已授权的服务/生命周期测试入口：任务保存 serializer/service，实际 RegisteredCollect runner → 插件/对账/Management → 有状态图适配器，及任务删除清空归属。
SQLite 测试数据库，不连接真实 VM/FalkorDB 或执行设备采集。补充同端点别名、原任务编辑、跨网络同 IP、根失败、根改名、删除重建等行为测试。

## 实现

- `VmwareCollectionScope` 统一任务保存查重和同步前的归属判定。保存通过已有数据库写锁串行化查重与创建/更新；同步按来源串行化预检与写图。
- 任务保存来源键，历史任务通过根 UUID 和地址候选查询兼容。地址比较规范化大小写、域名尾点和 IPv6 压缩/展开形式；网络范围优先采集接入点的云区域，无区域时按接入点区分。
- 有重复任务时，图中已有资产只能证明一个当前任务的归属；无所有者或多个所有者均返回明确冲突。
- `collect_vmware` 在任何写图前检查根及本轮命中的所有子资源，冲突作为更新失败保存到任务详情，不走新增唯一性失败路径。
- 根按 UUID 或已记录的来源键定位，先更新根；根失败不写子资源。根不执行差集删除；子资源继续使用原任务范围的清理逻辑。
- 根的内部 `vc_source_key` 加入采集可写字段，避免被图库属性白名单过滤；任务删除清空归属时保留该标记。子资源 `self_vc` 与指向 VC 的关联统一使用原根名称。
- 非 VC 采集继续使用原通用流程。未修改前端、数据库表结构及真实环境数据。

## 边界与历史数据

- 地址不同但实际指向同一 VC（例如 IP 与 DNS 别名）不自动推断；本次未引入远端 vCenter UUID 探测。
- 已有重复任务不会自动删除。原所有者有证据时可继续同步并补齐根归属；其他重复任务被拒绝。无所有者或混合归属需要先处理重复任务。
- 来源标记在根首次成功同步后写入。尚未写入标记的历史根，换任务应选择原根 UUID；不会根据历史重复根的名称猜测并自动合并。已有标记时，从同端点另一个根入口也复用原根及关系。
- 根失败阻断子资源，不代表对整个图库提供跨模型事务回滚；子资源写入失败仍沿用现有逐项失败与重试语义。
