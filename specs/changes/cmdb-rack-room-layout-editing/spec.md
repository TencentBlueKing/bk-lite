# CMDB 机房机柜布局编辑

Status: implemented

## Problem Statement

机房俯视图和机柜正视图目前只能看布局，不能在图上登记。运维要在机房某个格子放一台机柜、或在某个 U 位放一台设备时，只能去资产列表新建、再手工填位置并建关联，空机房甚至没有格子可点。已经放错的对象也不能从布局里拿下来，只能改实例字段，容易漏改关联或误删台账。

## Solution

在现有机房俯视图、机柜正视图上提供有权限的布局编辑：点空格/空 U 可新建或选择已有实例，系统自动写入位置并建立关联；已占用对象仍先打开现有抽屉，可「移出布局」——只拆关联、清位置，不删实例、不改其它字段。已在其它机房/机柜的对象在选择列表里灰色展示，点击则新开详情页，由用户自行解关联。

## User Stories

1. As an 有资产新增权限的运维人员, I want 在空机房的默认网格或已有机房的空格上新建机柜, so that 第一台柜也能直接从俯视图登记，且位置由点击的格子写入
2. As an 有资产编辑权限且对目标机柜有 Operate 的运维人员, I want 在空格上选择尚未上架的机柜并放置, so that 不用重复录入，系统自动填位置并建机房到机柜的关联
3. As an 运维人员, I want 选择列表里已在其它机房的机柜显示为灰色, so that 我能发现它在哪，又不会误绑到两个机房
4. As an 运维人员, I want 点击灰色机柜时新开浏览器页打开其详情, so that 我可以自己去解除原关联，回来后再放置
5. As an 有相应权限的运维人员, I want 在机柜空 U 上新建或选择允许的设备模型并指定高度, so that 设备出现在正确的 U 段，且与机柜建立包含关系
6. As an 运维人员, I want 保存时若 U 段超出机柜或与已有设备重叠则被拒绝, so that 布局不会出现无法解释的重叠
7. As an 有资产编辑权限且对实例有 Operate 的运维人员, I want 在已打开的机柜/设备抽屉里确认后移出布局, so that 关联被拆掉、位置被清空，台账实例仍在
8. As a 仅有查看权限的人员, I want 继续点已占用对象看详情，但空格不可点、也没有移出, so that 不会误改布局

## Implementation Decisions

- 布局仍读写现有 CMDB 实例与关联，不另存一套图纸。机房格子的位置来源与只读视图一致：机柜只维护 `location`（如 `A03`，字母为列、数字为行）；画布用的行/列由 `location` 解析得出，放置与移出都不写 `row`/`col`。设备位置为 `rack_u_start`；`u_size` 是设备高度，放置时可填，移出时保留。
- 机房→机柜使用现有 `run` 关联；机柜→设备使用现有 `contains` 关联。放置时若该关联已存在于当前机房/机柜（例如侧栏未定位对象），只补位置；否则创建关联并写位置。
- 提供专用布局变更接口（放置 / 移出），在一次请求内完成权限校验、占用冲突校验、实例创建或更新、关联创建或删除。不要让前端串多个通用创建/关联接口，以免写到一半失败。
- 放置机柜：目标格必须空闲（无已定位机柜，冲突格不可放置）。只写入 `location`，并保证机房→机柜 `run` 关联。
- 放置设备：点击的 U 为起始位，`u_size` 由表单提供（新建默认 1；选已有用已有值，没有则默认 1）。占用区间 `[start, start+size-1]` 必须完全落在机柜 `u_count` 内，且不与已放置设备重叠。写入 `rack_u_start`/`u_size`，并保证机柜→设备 `contains` 关联。
- 允许上架的设备模型仅限已有 U 位字段且与机柜有包含关联定义的内置模型：`switch`、`router`、`firewall`、`loadbalance`、`physcial_server`。`host` 等没有 U 字段的模型不出现在新建/选择中。
- 新建复用现有资产新建表：机柜固定模型 `rack`；设备先选上述模型再出该模型标准表。位置与起始 U 由点击位置预填且不可改。组织等必填项走模型表单，可从当前机房带默认组织，但不在布局接口里放宽模型校验。
- 选已有的候选：
  - 可放置：未关联到任何机房的机柜，或已关联到**当前**机房但尚未有效定位；未关联到任何机柜的允许模型设备，或已关联到**当前**机柜但尚未分配起始 U。
  - 灰色不可放置：已关联到**其它**机房的机柜，或已关联到**其它**机柜的设备。点击灰色项用新标签页打开该实例详情，布局接口不得替用户拆掉原关联。
- 移出布局：删除当前机房/机柜与该实例之间的那条布局关联，并清空对应位置字段（机柜只清 `location`；设备仅 `rack_u_start`）。不删除实例，不改名称、组织、类型、`u_size` 等其它字段。机柜移出时，柜内设备关联与 U 位保持不变。
- 机柜内点击设备打开的右侧抽屉只读展示该设备模型的 CMDB 属性（空值显示 `--`），不允许编辑。页头已有的名称与 U 位不在列表里重复。完整编辑走「查看完整实例详情」。
- 空机房不再因「无机柜」而整页空白：有编辑相关权限时渲染与现网一致的默认网格（至少 12 列 × 6 行）；已有机柜时空格同样可点。网格随已放置机柜的最大行列增大。本期不加「加一行/加一列」。
- 已占用格子/U 位的点击行为保持只读查看（机柜进正视图，设备开现有抽屉）。有移出权限时，在该抽屉/详情条提供「移出布局」，二次确认后提交。
- 权限对齐资产列表，后端与前端同时执行：
  - 查看布局：资产查看，且对当前机房/机柜实例有查看权限（沿用现有只读接口）。
  - 新建并放置：资产新增。
  - 选已有放置、移出布局：资产编辑，且对**被放置或被移出的那台**机柜/设备实例有 Operate。
  - 无对应权限：空格不可点，不展示移出；越权请求返回禁止。
- 保存成功后刷新当前俯视图或 U 图。占用冲突、越界、无权限、模型不允许等失败返回明确错误，不部分落库。

## Testing Decisions

- 好测试验证外部行为：给定机房/机柜与候选实例，放置是否写入正确位置与关联、是否拒绝占用/越界/越权；移出是否只拆关联并清位置、实例仍在且其它字段不变；灰色判定是否按「关联到其它容器」而不是仅看位置字符串。不锁定 SVG/DOM 结构。
- 最高接缝优先：
  - 布局变更纯决策（可否放置、占用区间、灰色 vs 可选、移出后字段集合）做成与 IP 视图手工登记类似的服务层单测
  - 视图层补权限与错误码（无新增/无编辑/无 Operate/冲突格）
  - 前端用现有 CMDB 脚本测试风格锁定：默认可点空格、允许的设备模型列表、移出不清 `u_size`、灰色项走新开详情而不是布局拆关联
- 已有机房/机柜只读组装测试保留，并补「空机房仍能给出可点击网格所需的空布局」相关行为（前端默认行列，后端允许对无机柜机房执行放置）。
- 不强制本阶段做完整浏览器 E2E。手动验收：空机房放第一台柜、选未上架柜、灰色跳详情、点 U 放 2U 设备、重叠拒绝、抽屉移出后实例仍在资产列表。

## Out of Scope

- 拖拽改位、同一机房内挪格子、加行加列
- 在布局里删除实例
- 主机（`host`）及其它无 U 位字段的模型上架
- 移出时拆掉柜内设备或改写 `u_size`
- 布局接口代用户解除「其它机房/机柜」上的原关联
- 3D 机房大屏上的对等编辑
- 单独的「布局编辑」权限点

## Further Notes

- 机柜模型 id 为 `rack`，机房为 `server_room`；物理服务器模型 id 保持存量拼写 `physcial_server`。
- 「未定位」机柜继续出现在现有侧栏提示中；它们属于当前机房的可放置候选，不是灰色项。
- 文案（新建/选择已有/移出布局/确认）实现时按现有 CMDB 中英文案风格补齐，不另开产品访谈。
