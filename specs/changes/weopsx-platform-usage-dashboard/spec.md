## Problem Statement

平台已有 CMDB、监控、日志、告警、节点、作业、系统管理，但缺少一张「平台自己用得怎么样」的总览。交付与运维需要在运营分析里一次看清各模块纳管了多大盘子、模块内闭环了多少，而不是跳多个应用拼数。这不能做成进程 CPU 监控，也不能在 CMDB 与监控尚未完全关联时用跨模块覆盖率制造假成效。

## Solution

在运营分析新增一张内置工作台仪表盘「WeOpsX 平台使用」：顶栏展示平台级此刻库存，下方按模块分行展示规模与模块内成效（比率 / TopN）。运营分析只做可视化与目录可见性；事实与取数鉴权仍在各业务模块。指标尽量复用或扩展现有模块统计 NATS，缺失的再补；画布用现有单值、比率（gauge）与 TopN 组件，不新做皮肤，也不做领导大屏。

## User Stories

1. As an 交付或运维人员, I want 打开运营分析即可看到 WeOpsX 各模块的规模与模块内成效, so that 不用跳多个应用拼数。
2. As an 交付或运维人员, I want 在这张盘的统一筛选里切换组织与时间窗, so that 不用离开画布就能按所选组织看库存、按所选时间窗看告警与闭环类指标。
3. As an 模块负责人, I want 在本行看到本模块库存与 TopN, so that 能判断哪些对象最吵、哪些策略几乎不响。
4. As an 运维人员, I want 某模块出数未就绪时该行仍保留但组件为空或「暂无数据」, so that 盘结构稳定且能看出哪块尚未接上。
5. As a 平台使用者, I want 只能看到当前组织与权限允许的业务数据, so that 目录能看见数据源不等于能看到其他组织的库存与告警。

## Implementation Decisions

### 总原则

- 以运营分析内置画布交付，经 `init_builtin_canvases` 初始化；视觉与布局对齐示意稿，实现只用现有 widget（单值、gauge、TopN）。
- 规模 = 此刻库存；成效 = 模块内比率 / TopN。活跃（DAU 等）不做。跨模块比值不做；谁持有关联键，谁出比率或排行。
- NATS 返回扁平字段供 `selectedFields` / TopN 字段绑定；跨模块「信封」只作指标清单约定，不要求运行时嵌套 JSON。
- 各模块可并行；画布可先接已就绪模块，未就绪模块保留行，组件空或「暂无数据」。
- 不经 OpenAPI 网关对外暴露这些用法统计 NATS。

### 画布统一筛选（验收必达）

- 内置盘必须配置**组织**与**时间**两套统一筛选，打开即可用（对齐验收「组织筛选与时间筛选可用」）。
- **时间筛选**：类型为既有 `timeRange`；默认近 7 天。库存类组件**不**绑定时间；告警产生、闭环、吃窗 TopN **绑定**时间统一筛选。默认 TopN N=10。
- **组织筛选配置走现有统一筛选三件套**（与时间同类，不开特例链路）：
  1. 画布 `filters` 增加一条：`key` 与数据源参数名均为 `organization`，类型 `string`，`inputConfig.control: organization`（组织树控件；旧 `inputMode: organization` 只读兼容）；
  2. 本盘凡出数所用的数据源均声明同名 `organization` 可筛选参数；
  3. **所有出数组件**绑定该组织统一筛选（换组织整盘重刷；个别平台目录类字段若本身不分组织，数值可能不变，但请求仍带选中组织）。
- **组织选项来源**：组织树控件选项来自当前登录用户会话中的组织树（用户有权看到的组织；不是另拉一套全平台目录数据源）。
- **默认值与展示**：打开盘时默认 = 用户**当前工作组织**；控件展示该组织的**真实名称**，不展示「默认组织」字样。内置 YAML **不写死**组织 ID；由运行时填入当前工作组织。
- **不可清空**：组织筛选必须始终有且仅有一个选中值，不允许清空后变成「未选/全平台」。
- **与全局工作组织同步**：用户在系统顶栏切换全局当前组织时，本盘组织筛选与已绑组件取数一并跟随变化。
- **取数语义**：画布选中的 `organization` 作为**本次查询的组织上下文**。运营分析取数时以该选中组织驱动组织上下文；模块再按该用户在该组织下的权限过滤。仅改全局登录组织、却不在本盘提供组织统一筛选，**不满足**本验收项。

### 权限与组织（硬约束）

- **两层语义不得混用**：运营分析目录 / 内置数据源的 `groups` 只控制谁能看见、选用画布与数据源；**取数范围必须由各模块按组织上下文 + 用户权限自行鉴权过滤**。目录可见 ≠ 数据可见。
- 取数路径与现有内置源一致：运营分析注入 `user_info`、下发含 `organization` 在内的筛选参数后调用模块 `rest_api`；模块内复用该模块已有的授权 queryset / permission map，不得另开「平台使用专用旁路」。
- **组织筛选与鉴权的关系**：可选组织已被用户组织树收口。取数以选中组织为上下文（并遵守 `include_children` 等既有规则）；模块仍按该用户在该组织下的实例/告警等权限过滤。越权伪造组织 ID → 空成功或零值，不得出数。
- **禁止超管取数旁路**：超管也不能靠本盘组织筛选看到自己本不该看的组织业务数据；计数与排行仍按组织上下文与模块权限规则收敛。
- 无组织、无权限或授权构造失败时：返回与现有统计接口一致的空成功或零值 schema，不得泄露其他组织的实例、告警、节点、作业或用户。
- 新建或扩展的每一个用法相关 NATS，验收必须包含：选中有权组织有数、换无权/他组织为空或零、无权限为零/空；TopN 不得出现无权对象；切换组织筛选（及跟随全局工作组织切换）后结果随之变化。
- 复用现有接口时：沿用该接口既有组织语义（例如监控总览中部分「平台目录」计数若本就全平台一致、不做组织收窄，平台使用盘绑这些字段时不擅自改成另一套口径）；**新增的租户数据字段与排行必须做组织/权限收窄**，并响应画布组织筛选。
- 运营分析画布侧不做跨模块除法，也不在前端用多源原始数拼「看起来像覆盖率」的跨模块比率。

### 数据源复用与扩展策略

- **CMDB 规模**：复用现有 CMDB 总览统计；在其上**追加**采集覆盖标量（至少关联 1 条采集任务、且与当前有权实例求交后的实例数、实例总数、占比）。只加字段、不改旧字段含义；不给该源增加时间参数。
- **CMDB 按分类/模型实例 Top**：复用现有实例 Top NATS；目录名改为「CMDB 实例排行（按模型/分类）」；参数 `group_by` 展示为「排行维度」（`model` / `classification`），**默认按模型**以保护现有 CMDB 内置盘。按分类时对分类下模型实例数加总再排序。
- **监控规模**：复用现有监控中心总览统计对应字段（对象、实例、指标目录条数、策略等）；不给该源增加时间参数，不塞吃窗 TopN。
- **监控告警实例排行**：新建一个 NATS + 一个数据源；参数选择模式——「告警数量最多的监控实例」或「已配策略且告警最少（含 0）」。画布两个 TopN 组件用固定参数钉死两种模式。排序单位是监控实例；计数为画布时间窗内产生的告警条数。已配策略口径按需求原文：策略启用、实例落在策略 source 范围，对象级策略则该类型下实例均算覆盖。由监控模块出数（告警挂在监控实例上）。
- **日志**：无现成用法总览则新建——一个总览（采集实例、提取规则、告警规则、已绑定资产占比），一个告警规则 Top（时间窗内该日志告警策略产生告警最多）。已绑定 = 采集实例已关联资产即可。
- **告警未关闭**：复用告警快照统计的活跃/未关闭字段；快照继续忽略时间窗。
- **告警接入源数**：复用告警源配置类统计中的源总数（配置快照，不受窗影响）。
- **告警闭环率**：扩展告警期间统计——窗内产生沿用现有新增告警计数；窗内关闭 = `updated_at` 落在半开时间窗且状态属于已关闭集合（与今日状态摘要同款）；闭环率 = 关闭 / 产生，分母为 0 则为 0。只加字段，旧期间字段与旧画布绑定不变。**不得**写入快照统计。
- **接入源事件 Top**：复用现有告警源事件 Top（必填时间窗，按事件数）。
- **相关性聚合规则命中 Top**：新建 Top 数据源；时间窗内仅统计落在 `AlarmStrategy` 的关联/聚合规则 `rule_id` 产生的告警条数作为命中次数，降序 TopN。非策略 `rule_id` 不入榜。
- **节点**：新建总览（节点总数、采集器数、云区域数、在线/总数）与云区域节点数 Top（节点管理云区域，非 CMDB 地域；此刻库存，不吃时间窗）。
- **作业**：新建总览——作业数、模板数，以及时间窗内成功执行 / 总执行（执行记录可按窗聚合，能力已具备）。
- **系统管理**：新建一个总览——组织数、用户数、通知渠道数，以及已启用渠道 / 已配置渠道。**组织数** = 选中组织及其下级节点数（不含归档；不跟随 `include_children`）；用户数 / 渠道仍按选中组织上下文（并遵守 `include_children`）。普通通知渠道（`Channel`）无独立启停字段，产品口径为**已配置即已启用**；即时通讯渠道按 `enabled` 计。

### 画布

- 顶栏六个平台级此刻数字：CMDB 实例、监控实例、监控指标、日志采集实例、未关闭告警、节点——分别绑各模块库存字段。
- 下方每个模块单独一行。CMDB 行保留分类/模型/实例、采集覆盖率与分类 Top（不放「已挂采集」单值与模型 Top）；告警行库存三卡加宽后与两个 Top 分行；作业/系统管理行卡片加高与节点行对齐。
- 统一筛选栏同时提供组织（`organization`）、时间；**所有出数组件绑组织**；库存不绑时间，吃窗成效绑时间。
- 内置数据源登记与生命周期遵循现有内置画布/数据源约定；新建内置源组织名单语义与现网一致（空名单全员可见目录，取数仍走模块鉴权）。

## Testing Decisions

只测外部行为：字段口径、时间窗半开区间、组织统一筛选三件套与取数上下文、授权过滤、空/零值 schema、复用扩展不破坏旧画布所选字段、数据源与内置画布可初始化。

接缝（优先现有最高层）：

- 各模块 NATS handler：有权组织有数、无权/他组织为空或零、时间窗边界、TopN 不含无权对象（对齐各模块现有 `test_nats_*` / 告警 period·snapshot 测试风格）。
- 扩展旧接口：旧字段值与忽略时间（快照）行为回归；新字段仅在授权范围内计算，并响应组织上下文。
- 监控排行模式参数：两种模式候选集与排序方向正确；未授权实例不出现。
- 运营分析：内置盘 `filters` 含 `organization`（组织树、不可空）与时间；出数数据源均声明 `organization`；全部出数组件绑定组织；打开盘默认当前工作组织名称；跟随全局工作组织切换；`source_api` / 画布定义可解析；`init_builtin_canvases` 可创建该盘（对齐现有 builtin canvas 测试）。
- 不测真实前端 E2E 点选，不测领导大屏，不做跨模块集成假覆盖率。

## Out of Scope

- 领导大屏、投屏、轮播
- APM、OpsPilot、运营分析自身用量
- 监控覆盖率、CMDB「已推监控」、告警 `inst_uuid` 回跳率
- DAU、按人活跃、平台用量数仓
- 许可用量（另立项）
- 为平台使用盘新做一套 widget 皮肤或专用布局引擎
- 改写告警快照统计使其认时间窗或承载闭环率
- 运营分析侧聚合多模块原始数做除法

## Further Notes

- 组织与目录产品记忆：内置数据源可见性与「目录不替代下游鉴权」见运营分析内置数据源组织可见性相关决策；本变更遵守同一边界并在用法统计上显式验收。
- 告警期间 vs 快照分家既有规格继续有效；闭环率落在期间统计是该分家的延续，不是例外。
- 采集覆盖分子 = 采集任务挂载钥匙与当前用户有权 CMDB 实例求交后的去重实例数；分母仍为有权实例总数。
- 闭环率公式未封顶（关闭可多于新增）；画布 gauge 刻度 `gaugeMax: 200` 以容纳超过 100% 的展示。
