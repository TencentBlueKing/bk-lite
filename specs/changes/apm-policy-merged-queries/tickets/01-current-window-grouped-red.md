# 01 — 当前窗按目标分组取回 RED

Status: ready

Blocked by: None

**What to build:** 一条展开出 N 个入口目标（端点 × 版本 × 实例）或 N 个依赖目标的策略，一轮评估的当前窗只发常数次
VictoriaTraces 查询；判断、证据曲线、目标状态与逐目标查询一致；超上限退回逐目标；分组查询失败按现有查询失败处理。

- [ ] telemetry store 新增按目标维度分组的 RED 汇总与趋势读取（入口与依赖各一），保留去重口径、慢请求/Apdex、
      唯一 Span 上限与截断检测；内存实现同步提供，供测试与本地使用
- [ ] 评估器在一个子任务内先批量取回当前窗，再分发给各目标；Top 操作结果与现状一致且不随目标数增长
- [ ] 超上限时本轮退回逐目标路径；分组查询失败时全部目标记查询失败并整轮重试
- [ ] 试算 / 预览走同一路径
- [ ] 等价性测试（全部端点、指定端点、版本、实例、依赖）、查询次数为常数的测试、适配器 LogsQL 形状测试、
      超上限与失败测试
- [ ] `server/apps/apm/tests` 在 sqlite 下通过

## Notes

- 多条件策略已有窗口级缓存，合并后仍需保持“同一窗口只查一次”。
