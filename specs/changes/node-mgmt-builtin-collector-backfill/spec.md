# 新内置采集器补齐已纳管节点预置配置

Status: implemented

对应需求：p398_798。

## Problem Statement

内置采集器只在平台初始化时写入采集器目录。预置默认配置只在节点首次纳管时生成。目录里新增采集器之后，已经纳管的节点没有这份配置，新探针不能随心跳拉走。

## Solution

`import_collector` 新插入带默认模板、且 `controller_default_run=True` 的内置采集器时，在同一事务写入补齐记录。事务提交后清掉采集器目录 ETag，并投递运行期任务。没有补齐记录时不投递，也不清 ETag。启动期投递失败不阻断启动；每 5 分钟的定时任务继续领取待处理记录。处理中超过 15 分钟没有结束的记录收回待处理，这次收回不计入失败次数，避免进程中途退出后永远停在处理中。旧执行写回时必须带上领取时的锁时间，锁已被新执行替换则丢弃写回。

补齐只创建缺失的预置配置，沿用首次纳管的操作系统、CPU 架构、容器节点和模板渲染规则。已有预置配置、自定义配置和同名配置不改写。单次最多处理 2000 个节点，用游标续跑。单节点失败不影响其他节点；一整轮扫描出现失败则从头再试，连续 5 轮无完整成功后停止。配置绑定后由现有 ETag 失效让 Sidecar 按自己的心跳拉走，不额外下发启动或重启。

## Implementation Decisions

- 更新或删除已有采集器不触发补齐，避免升级时重写存量预置配置。
- 不在 `batch_init` 里扫描节点。
- 不调用 `Sidecar.create_default_config`。那条路径会检查并更新节点上全部默认采集器的预置配置，仍只用于首次纳管和 `repair_node_config`。
- 手工修复命令保持原样，可作为自动重试停止后的入口。
