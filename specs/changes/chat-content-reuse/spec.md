# 智能体测试窗口与平台聊天内容复用

## 问题与行为

同一回答在测试窗与平台窗的表格、代码、报告、引用和审批信息不一致；平台历史会丢失实时卡片，重生成会截断历史并丢失原附件。

| 对比项 | 原有差异 | 本次处理 |
| --- | --- | --- |
| Markdown | 测试窗使用 MarkdownIt；SDK 使用另一组 Markdown 组件，表格、字体、代码高亮样式不同 | 共用解析、清理和排版；表头完整显示，宽表内部滚动 |
| 业务内容 | 测试窗具有报告、Diff、下载、引用和进度组件；SDK 多数仅隐藏或降级为文本 | 迁移现有组件并接入平台消息 |
| 人工确认 | 平台审批和选择另有简化实现，参数、理由、多选等表现不一致 | 共用审批与选择组件，仍由各入口提供已认证请求 |
| 历史回放 | SDK 主要恢复文本和工具信息，结构化卡片不能完整还原 | 实时、两边历史共用 CUSTOM 事件转换；历史操作只读 |
| 再次生成 | SDK 截断选中回答后的消息，只重发文本 | 共用原问题定位，追加重试并保留原图和文件，不消耗当前草稿 |
| 流式边界 | SDK 正常 EOF 和异常提前断流没有明确区分 | 保留已有回答并显示中断；继续沿用已有停止与流所有权机制 |
| 细节状态 | IME、上下文用量和规划步骤各有实现 | 共用纯逻辑，保留工具步骤归属、失败原因与延迟事件处理 |
| 引用图片 | 测试窗通过 Wiki API 重签媒体地址；SDK 原先没有完整引用查看能力 | 引用正文、签名加载与共用媒体地址规则接入平台 |

两个入口现在消费 `web/packages/chat-content` 的同一份源码：Markdown 与清理策略、审批/选择/报告/引用/进度组件、结构化事件状态转换、规划步骤、上下文用量、IME Enter 判断和重生成的原问题定位。

- 重生成统一在末尾追加一轮，保留当前历史与原附件；平台不消耗用户尚未发送的草稿。
- 实时和历史对结构化 CUSTOM 事件使用同一转换逻辑；历史审批/选择仅展示，不恢复失效的操作。
- 平台意外 EOF 保留已收到的回答并明确标记中断，主动停止仍由已有 StreamLifecycle 隔离。
- 测试窗的工具 HTML 继续走原有允许列表；平台普通回答不启用原始 HTML。共享排版不放宽平台原有的 HTML 边界。

## 所有权与接入

公共包放在 `web/packages`，因为主站 Docker 的上下文只有 `web/`。主站通过 pnpm workspace 引用；WebChat Core/UI 通过本地 file 依赖引用。两者保留独立构建与 React peer。SDK 将公共包作为构建期依赖，运行时代码打入 JS，公开类型声明一并生成到 dist；消费者无需安装私有包或访问仓库相对路径。npm 的本地 file 依赖使用安装快照；修改公共源码后在 `webchat` 执行 `npm ci` 刷新，再运行构建。源码只在公共包维护。WebChat 浏览器产物仍由既有 sync-web-public 脚本同步。

主站将公共包纳入 Next `transpilePackages`，workspace 生成器始终保留该依赖。无 DOM 的服务端渲染先输出转义文本，浏览器挂载后再增强为 Markdown，不跳过 HTML 清理。

`ChatContentProvider` 只提供翻译、配置详情请求、引用内容读取和审批提交；认证、组织上下文、渠道配置、页面上下文、会话持久化仍归入口所有。公共包不得导入 Next 页面、主站登录 Context 或 app API。

保留各入口的流传输适配、工具调用展示外壳与窗口布局，不将整个聊天页面做成大量模式开关的公共组件。

调试窗的草稿配置、模型选择与调试信息，平台窗的渠道选择、上下文采集与会话历史属于不同职责，继续保留。两边的工具分组外壳及业务卡片相对正文的排列方式还没有合并；本次统一内容能力和状态契约，不宣称两个完整页面像素一致。

## 验证

主站聊天集成测试从同一组事件验证实时转换、测试窗历史、平台历史，覆盖卡片单独回答、重复事件、引用、选择结果和规划步骤；同时验证 Markdown 表格/高亮/HTML 清理、审批参数与理由、过期选择。SDK 验证重生成保留历史与原图/文件、按帧更新、停止与异常 EOF。主站既有规划步骤脚本、SDK 类型检查、SDK 构建与静态产物同步纳入交付检查。

2026-11-12 验证结果：

- SDK `npm test` 全量 202 项通过，包括独立发布包 ESM/CJS 安装加载、公开声明不依赖私有包以及附件专项；正式构建和浏览器产物同步通过。
- 公共内容、无 DOM 服务端渲染与 Wiki 媒体测试共 14 项通过；下载安全、规划步骤与失败原因、报告和选择相关脚本通过。
- 主站类型检查通过；智能体设置页通过 Turbopack 定向生产编译（compile 模式，不代表全站生成或部署）。
- SDK 全量 lint 和主站改动范围 lint 均无错误，保留既有警告；workspace 生成脚本回归通过。
- 组件预览检查亮暗主题、940px 与 390px 视口，表格和代码样式一致、无容器溢出；未进行真实登录和模型端到端联调。
- 主站既有聊天组件测试仍有 8 项失败：6 项发送函数参数断言过期、2 项缺少图标 mock；用修改前组件代码复现了相同失败，未将它们计作通过。
