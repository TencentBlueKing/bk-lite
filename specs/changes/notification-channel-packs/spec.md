# 企业版通知渠道包

状态：实现中，未提交。通知渠道不使用集成实例的核验状态。告警模板和流程通知类别仍选不到新渠道。

## 已定行为

企业版沿用现有 Provider zip 上传。上传请求先带用途 `integration` 或 `notification_channel`，按用途进入对应校验路径。一个通知渠道包注册一种渠道，渠道首页多一张卡片，卡片下的实例是 `Channel`。告警和流程按渠道实例发送，不直接调用包。

用途不写入 `UploadedProviderPack`。集成类型列表从已加载的 manifest 计算用途。加载失败的行用途为空。

进程重新加载没有上传请求。注册已入库的包时，manifest 含 `notification_channel` 就走渠道包规则，否则走集成包规则。这只用于重启后的加载，不替代上传时的显式选择。

## 上传两路

共用检查只覆盖压缩包：不超过 10MB，拒绝绝对路径和 `..`，必须是带 `__init__.py` 的 Python 包。

`integration` 保持现有规则。要求 `adapters/client.py` 和 `adapters/base_connection.py`。能力属于登录、用户同步或 IM。带 `notification_channel` 则失败。标识不能与内置 Provider 目录名相同。

`notification_channel` 要求 `adapters/send.py`，不要求上述两个身份包文件。manifest 只能有一条能力，键为 `notification_channel`，并写明 `delivery` 为 `template` 或 `body`。模板类再写 `parameter_mode` 为 `ordered` 或 `named`。`adapter_key` 以 `{包标识}.` 开头，`adapter_path` 指向包内发送适配器。标识不超过 30，并躲开内置渠道类型、内置 Provider 目录名和 `im_notification`。包内不放页面、密钥和新依赖。试加载失败不入库。

替换请求也带用途。旧包能读出用途时，本次选择必须与它一致；读不出时，新包只按本次选择的路径校验。已有渠道实例时，读得出原包就必须保持相同 `delivery`；读不出原包则拒绝替换。同一个标识不能在两类包之间更换。替换不改已有渠道的配置。

缺少 `purpose` 的上传保持现有集成包行为，避免已有调用方中断。

## 渠道实例

`Channel.channel_type` 列保持原有 `choices`。序列化器按普通字符串接收，只接受内置类型或当前已加载的通知渠道包。包未加载时不能新建。不为这一列增加迁移。

地址、密钥和模板 ID 来自包的实例字段。`secret` 字段加密存储，读出时脱敏。提交空值或当前掩码保留原密文。模板类只登记变量声明，最多 20 条，每行可保存 `test_value`。`named` 登记参数名。`ordered` 只登记槽位，不登记参数名。正文类不登记变量。测试值只给页面测试用，正式发送不用已保存的测试值。

卸载通知渠道包时统计 `Channel.channel_type` 等于该标识的行。还有实例则 409。集成包仍统计集成实例。

## 发送

内置类型的正式发送保持现有分支。其余类型查找已加载的通知渠道包。包不在注册表中就失败，不调用包。配置不全、密钥解不开、模板声明不合法，也在调用包之前整次失败。模板类收到的 `template_params` 只放行省略、空对象、空数组、JSON 对象和字符串数组；其他 JSON 在进包之前整次失败。对象的键、数组长度和空值由渠道包检查，并通过返回的 `reason` 告诉调用方。正式发送不看测试发送的结果，也不使用已保存的测试值。`retryable` 为 false。

正文类测试发送仍使用固定英文，忽略请求里的标题和正文。标题是 `[{渠道名}] Test Message`，正文是 `This is a test message from channel '{渠道名}'. Receiver: {接收人}`。模板类测试发送用渠道上已保存的 `test_value` 组装 `template_params`；没有登记变量时传空对象或空数组。邮件和机器人仍使用各自原来的文案。内置短信和语音的测试发送不改。

模板类按接收人调用包。发送入口仍接收标题和正文，但不把它们填进模板。真正使用的是当次 `template_params`。省略时，`named` 传空对象，`ordered` 传空数组。平台确认用户资料里有电话，并把原值传给包。没有电话的接收人跳过并写明原因，其他人继续。包返回 `accepted`、`rejected` 或 `unknown`，以及 `request_id`。包无法使用该号码时返回可见原因。内置短信和语音仍只接受大陆 11 位号码。

正文类一次调用，传入解密后的配置、标题和正文。`template_params` 可以不传，传了也不使用。

任一接收人未被受理，整次结果为失败。已受理或未知不自动重发。手动重发必须再次调用包。不新增发送台账。流程通知原子不在这次改动里。

`send` 签名：

- 模板类：`send(config, phone, template_params) -> {"status", "request_id", "reason"}`
- 正文类：`send(config, title, content) -> {"status", "request_id", "reason"}`

`template_params` 是 JSON 对象或字符串数组。平台不把它渲染成 `{name, value}` 列表。

## 界面

集成类型上传弹窗先选用途再选文件。替换时用途固定为当前用途且不可改。列表增加用途列。确认文案按用途使用集成实例或渠道实例。

新建集成实例的类型列表排除通知渠道包，直接提交这种标识也拒绝。`notification_channel` 不进入集成中心能力筛选。

通知渠道首页为每个已加载的通知渠道包追加一张卡片，名称用包的 `name`。表单渲染包的实例字段。模板类再加和内置短信相同的参数表：具名模式显示参数名，顺序模式显示槽位，每行有测试值，不显示标题、正文或固定文字来源。正文类不显示参数表。社区版没有上传入口。没有这类包时不出现额外卡片。

## 验收

- 企业版可上传模板类和正文类各一包，并各建两个配置不同的渠道实例。
- 未带用途的旧上传仍按集成包处理。选集成却上传渠道包，或选渠道却上传集成包，均失败且不入库。
- 社区版没有上传路由。
- 模板类按电话和参数发送，正文类按标题和正文发送。
- 某个接收人没有电话时跳过这个人并给出原因，其他人继续。包未加载、配置不全、密钥解不开、模板声明不合法，或 `template_params` 不是对象也不是字符串数组，都在调用包之前整次失败。键、槽位和空值不符时由包返回可见原因。正式发送不看测试结果。
- 已受理或未知不自动重发。
- 包标识不能覆盖内置渠道或内置 Provider。
- 仍有渠道实例时不能卸载。已有渠道实例且读不出原包时，替换返回 409，渠道配置不变。
- 正文类测试发送使用固定英文标题和正文。模板类测试发送使用已保存的测试值，没有登记变量时传空。
- 集成实例创建列表不出现通知渠道包。
