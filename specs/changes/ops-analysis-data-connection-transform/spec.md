## Problem Statement

运营分析的数据源同时承载「连到哪里」和「取什么 / 怎样给组件」。MySQL、PostgreSQL、REST 的地址和凭据无法复用，轮换凭据时容易遗漏。

MySQL/PostgreSQL 已经通过 SELECT 承担转换职责，缺少的是可复用连接。REST/Excel 则缺少一个可预览、可复用且有安全护栏的数据转换环节。历史上把转换逻辑放入 NATS 内置接口的方式无法随场景无限扩展。

本变更需要在不改变组件绑定模型、不强制迁移存量数据源、不改动 NATS/Prometheus 的前提下，补齐可复用数据连接和 REST/Excel 可选 Python 转换。

## Solution

- 新增组织隔离的「数据连接」，V1 支持 MySQL、PostgreSQL 和 REST。
- 数据源仍是组件唯一绑定对象，保存查询、请求、转换和字段定义。
- MySQL/PostgreSQL 使用「数据连接 + 每个数据源自己的 SELECT/表查询」，不提供 Python。
- REST 在单次 HTTP 响应解析为完整行集后可选实时执行 Python。
- Excel 保存原文件，异步生成可选 Python 转换后的物化结果，组件只读当前成功结果。
- Python 只在独立、有操作系统/容器资源隔离的薄 Runner 中执行；Runner 未达到安全门槛时不开放 Python 功能。
- 未配置脚本时跳过转换；脚本失败时明确失败，不回退到未转换宽表。
- NATS 继续使用既有 NameSpace，Prometheus 保持现有实现；二者不并入数据连接，不增加 Python。

## User Stories

1. 数据源管理者可以复用同一 MySQL/PostgreSQL/REST 连接，无需重复录入凭据。
2. 多个数据库数据源可以引用同一连接并维护各自的 SELECT，产生不同的组件就绪结果。
3. 连接地址或凭据修改后对后续取数立即生效，且管理者能在修改前了解影响范围。
4. 仍被数据源引用的连接不能删除；管理者可停用连接以中断取数。
5. 数据源可覆盖数据库名或 REST 相对路径/请求配置，但不能覆盖公共连接的主机与凭据。
6. 数据源管理者可以在 REST/Excel 上编写可选 Python，将宽数据转换为多个组件可复用的窄结果。
7. 未配置脚本的 REST/Excel 继续沿用现网数据语义，不增加额外转换。
8. REST 的预览与运行时使用同一转换顺序；Excel 预览与最终候选使用同一原文件和脚本契约。
9. 转换超时、超限、过载或返回非法时给出可区分错误，不产生静默少数据。
10. 存量内联数据源继续可运行，并可显式提取为公共数据连接。

## Product Contract

### 1. 能力矩阵

| 类型 | 数据连接 | 取数 / 转换 | Python | V1 组件类型 |
|---|---|---|---|---|
| MySQL/PostgreSQL | 支持 | SQL/表查询 | 不支持 | 表格 |
| REST | 支持 | 请求 + 响应提取 + 可选实时转换 | 支持 | 表格 |
| Excel | 不支持 | 原文件 + 可选物化转换 | 支持 | 表格 |
| NATS | 使用既有 NameSpace | 保持现状 | 不支持 | 保持现状 |
| Prometheus | 不支持 | 保持现状 | 不支持 | 保持现状 |

- 不引入独立 Dataset/语义层；组件仍只绑定数据源。
- MySQL/PostgreSQL 的转换责任继续下推到 SQL。
- REST/Excel Python 挂在数据源上，不是组件级 Transform。

### 2. 数据连接

- V1 连接类型为 MySQL、PostgreSQL、REST；连接类型创建后不可修改。
- MySQL/PostgreSQL 保存主机、端口、默认数据库、用户名和密码；V1 不新增 TLS/SSH 隧道配置。
- REST 保存 Base URL 与公共 Headers；Header 名可见，Header 值按敏感数据处理。V1 不新增 OAuth、Token 刷新或 HMAC 流程。
- 密码和 Header 值必须加密存储；列表、详情、引用列表、分享和报表链路不得返回明文。编辑回显使用占位符，占位符回传表示保留原值。
- 连接按 `groups` 授权；引用它的数据源必须满足 `data_source.groups ⊆ connection.groups`。数据源保存和运行时都需要 fail closed 校验。
- 缩小连接授权范围会造成引用数据源越界时，拒绝保存并展示冲突引用。
- 连接修改对后续取数立即生效；修改端点或凭据前展示引用数和影响确认。
- 停用连接后，引用数据源明确失败；存在引用时禁止删除并提供引用摘要。
- 数据连接沿用现有数据源增删改查权限，V1 不新增独立权限位；设置侧栏「数据连接」与「数据源」共用 `data_source` 权限键，API 仅校验 `data_source-*`。
- 测连结果是当次反馈，V1 不持久化连接健康状态。

### 3. 数据源引用与兼容

- MySQL/PostgreSQL/REST 数据源支持引用公共连接或继续使用历史内联配置；不强制迁移存量数据源。
- 新建引导优先选择公共连接，同时保留「独立配置」入口。
- 数据库数据源只允许覆盖数据库名；REST 数据源保存方法、相对路径、Query、Body、超时和响应路径，不允许覆盖主机和公共 Headers。
- REST 相对路径不得切换到绝对/跨源 URL，不得借重定向泄露公共 Headers。
- 内联数据源提供显式「提取为数据连接」操作；创建连接和切换引用必须原子完成。
- 组件绑定与取数入口不变，仍通过数据源 ID 取数，运行时继续返回 `{data,warnings}`。

### 4. Python 转换契约

- V1 只允许 REST/Excel 保存 Python 转换；MySQL、PostgreSQL、NATS、Prometheus 必须拒绝 Python 配置。
- 脚本入口固定为 `transform(rows, params)`，其中 `rows` 为 `list[dict]`，V1 的 `params` 固定为空对象；返回值必须是 `list[dict]`。
- 空脚本或未启用转换时直接使用取数结果。
- V1 只允许 `json`、`math`、`datetime`、`collections` 等已声明白名单模块；AST/import 限制用于收窄脚本能力，不作为安全隔离边界。
- 输入和输出各最多 10,000 行，同时受可配置的序列化字节上限保护；执行超时为 5 秒。
- 输入/输出超限、超时、非法 import、非法返回或 Runner 不可用均明确失败，不截断、不回退原始结果。
- 默认每组织同时执行 3 个转换，超过容量返回可区分的繁忙错误，不排队。V1 通过部署锁定单 Runner 副本与单 Web Worker，使进程内并发计数即为全局上限；多副本/多 Worker 下的共享并发控制留待扩容前实现，扩容前不得水平扩展 Runner。
- 编辑 Python 沿用数据源管理权限；这是 V1 已确认的权限扩展。脚本变更接入平台已有操作记录能力，不为此新建独立审计子系统，且操作记录不得包含脚本正文。

### 5. Runner 安全与失败语义

- Python 必须在独立运行单元中执行，不得使用 Server 同权子进程作为生产安全边界。
- Runner 不持有数据库凭据、REST Headers、Django 配置或用户 Token；Server 只向它传递脚本、行数据和空 `params`。
- Runner 必须与 Server 隔离用户、文件系统、环境变量和业务网络权限，并具备 CPU、内存、PID、临时空间和超时限制。
- 脚本、输入数据和结果不写入日志，不作为队列消息正文持久化。
- Runner 是运行期非关键依赖，不参与 Server `batch_init`，不得阻止 Server 启动。
- Runner 不可用时，无脚本数据源不受影响；有脚本 REST 明确失败；Excel 候选失败但继续使用旧成功结果。

### 6. REST 转换与出站安全

REST 预览和运行时必须共用以下顺序：

```text
发起单次受控 HTTP 请求
→ 读取完整单次响应
→ response_path
→ 归一化为完整行集
→ 校验不超过 10,000 行
→ 可选 Python
→ 校验返回值和输出上限
→ 字段推断/应用
→ 预览采样或组件分页
```

- 「完整」仅指当次 HTTP 响应中 `response_path` 选中的数组；V1 不自动跟踪第三方分页并拉取后续页。
- 转换必须发生在预览采样、截断和组件分页之前；不得对 50–1000 行样本做聚合后宣称是完整结果。
- REST 出站复用平台已有安全请求能力，校验 Base URL、DNS/IP 及每次重定向目标。
- 公共 Headers 不得在跨源重定向中继续携带，不允许 Host、Content-Length 等受控 Header。
- 保留现有 REST 超时和 2MB 响应字节上限。

### 7. Excel 原文件与物化生命周期

- V1 只支持 `.xlsx`，保持现有 2MB 文件上限。文件大小和行数是两道独立护栏。
- 必须探测第 10,001 条数据；超过 10,000 行明确失败，不得静默只读前 1,000 或 10,000 行。
- 新 Excel 数据源保存原文件。每个数据源最多维护一个当前成功结果和一个候选结果，不提供通用历史版本产品。
- 候选绑定原文件和脚本快照；上传新文件或修改脚本/转换开关会生成新候选。
- 候选成功后原子切换为当前成功结果；旧任务不得覆盖更新的候选。
- 候选失败时，已有成功结果继续服务并通过 `warnings` 提示；首次创建且没有成功结果时不可运行。
- Excel 物化身份随数据源的 Excel 身份存在：删除数据源时级联删除槽位，槽位删除后在事务提交时删除对象存储文件。切离 Excel、导入覆盖为非 Excel，或补偿扫描发现非 Excel 数据源仍挂槽位时，走同一放弃入口：解绑指针、generation 归零、删除全部槽位与文件。切回 Excel 视为新建，状态为 `needs_upload`，必须重新上传。
- 在途物化不得写回非 Excel 数据源：Worker 在认领前后检查 `source_type` 与当前候选指针，槽位已删或类型已变则停止且不提升成功结果。不依赖撤销 Celery 任务。
- **界面新建 Excel**：必须选择文件；上传后在请求内同步完成解析/可选转换/写结果；**仅成功后该数据源才视为已创建且可用**。同步处理失败时必须丢弃本次新建的数据源（含槽位与已落盘原文件），列表不得残留半成品空壳。
- **界面编辑 Excel**：替换语义——新候选成功才切换；失败保留旧成功结果。仅修改脚本/开关时从已保存原文件重算。
- **重试处理**：仅当已保存原文件且当前为处理失败（含「更新失败但仍可用旧结果」）时可用；`needs_upload` 或无原文件时不得展示重试，只能重新上传。
- 上传路径（`submit_excel` / 显式重试）在 V1 体量下默认同步物化；脚本变更触发的后台重提与 PENDING 补扫仍可走 Celery。
- 无脚本时仍从原文件生成物化结果；编辑脚本后必须从原文件重算，不得对上一物化结果二次转换。
- 原文件与物化结果使用项目现有对象存储能力；关系数据库只存元数据和存储地址，新结果不写入 `query_config.imported_items`。
- 存量 Excel `imported_items` 继续可运行。修改名称、描述、标签、授权组织或字段展示不得使它失效；只有用户显式重新上传原文件时才进入新物化模型。

### 8. 导入导出

- 公共数据连接不作为 YAML 一级对象导入导出。
- 引用公共连接的数据源导出为脱敏内联配置；敏感值使用占位符，导入时不按名称自动关联公共连接。
- 导入预检必须明确列出需补充的凭据；不得将缺少凭据的数据源展示为可运行。
- 新格式 Excel YAML 保留脚本、字段定义等非数据配置，不包含原 `.xlsx` 或物化行。导入后状态为 `needs_upload`，重新上传并成功物化前不可运行。
- 旧 YAML 如包含 `query_config.imported_items`，继续按存量格式导入并保持可运行。

### 9. 交互契约

- 设置菜单顺序为「数据源 → 连接库 → NameSpace」，界面文案使用「连接库」；领域对象仍称数据连接。前两者菜单可见性与按钮操作均绑定 `data_source` 权限，不单独依赖 `data_connection-*`。文案中明确连接库与 NATS NameSpace 的差异。
- 数据连接页（界面称「连接库」）提供列表、搜索、创建/编辑、测连、启停、引用摘要和删除拦截。
- 数据源继续使用一个 Drawer 和单一表单状态，内容分为「基本信息、连接与取数、转换与预览、字段与保存」四段；提供可自由跳转的步骤导航/锚点，不做强制线性 Wizard。
- 仅 REST/Excel 显示 Python 开关和编辑器；预览以样例展示原始结果和转换结果，不把完整 10,000 行渲染到浏览器。
- 修改连接、请求、原文件或脚本会使旧预览失效；关闭未保存表单时要求确认。
- Excel 至少显示 `processing`、`ready`、`update_failed_using_previous` 和 `needs_upload` 状态。存在旧成功结果的更新中/更新失败状态需明确显示当前使用的旧结果时间。
- 界面新建成功提示仅在同步处理成功后发出；不得先提示「创建成功」再异步失败。`needs_upload` 文案面向 YAML/配置导入待补文件，不得误写成「来自 YAML」以外的半成品创建路径。
- 复用 Ant Design、现有设置列表壳、Code Editor 和字段表；新业务组合保持在运营分析 app 内。
- loading、empty/error、permission denied、readonly、长文本、窄容器和亮/暗主题都必须有明确反馈和新鲜验证。

## Confirmed Changes from the Original Requirement

以下是需求评审后经用户确认的调整，不应被误认为原始文档本来就包含的要求：

| 原始文档 | 最终契约 | 调整原因 |
|---|---|---|
| Server 受限子进程 | 独立薄 Runner；未就绪时不开放 Python | 子进程无法兑现禁网、禁盘和 Server 资源隔离 |
| 连接和数据源各自按组织可见，不做子集校验 | 强制 `data_source.groups ⊆ connection.groups` | 防止跨组织间接使用凭据或可见但不可运行 |
| Excel 预览后写入 `query_config.imported_*` | 保存原文件，使用当前成功/候选两槽位 | 支持修改脚本重算、失败保留旧版，避免对旧结果二次转换 |
| REST 脚本可接收已声明参数 | REST/Excel V1 `params={}` | 现网非 NATS/Prometheus 未建立参数保存和统一筛选绑定链路 |
| REST/Excel 图表类型不限制 | V1 继续仅支持表格 | 保持现网行为，不顺带新增图表字段语义 |
| Python 输入超限的处理曾出现截断继续方案 | 输入/输出超限明确失败 | 避免聚合、排序和过滤产生静默错误 |
| Excel YAML 数据资产语义未明确 | 新 YAML 不携带文件/物化行，导入后待重新上传；兼容旧 `imported_items` | 避免巨大 YAML 和「有结果但不可重算」的伪可用状态 |

除本节列出的已确认调整外，任何新的产品语义偏离都必须先经用户确认，不得由实施者以「简化」或「安全增强」名义自行改变契约。

## Acceptance Criteria

- 一个公共数据库连接可被多个不同 SQL 数据源引用；修改连接后各引用方立即使用新配置。
- 连接凭据在存储、API、日志、异常、指标、导入导出、分享和报表链路均不泄露明文。
- 数据源保存、运行和缩小连接授权范围时均验证组织子集不变量。
- 连接停用、缺失、越权、有引用删除和缺少凭据都返回可区分状态。
- REST 转换一定在完整单次行集校验后、采样/分页前执行；预览与运行时的转换语义一致。
- REST Base URL、DNS/IP、重定向和公共 Header 行为符合平台安全出站策略。
- Runner 无数据源凭据和业务网出站，且受 CPU/内存/PID/文件系统限制；Runner 不可用不影响 Server 启动和无脚本数据源。
- 转换超限、超时、非法 import、非法返回和容量不足均明确失败，不返回原始宽表。
- Excel 可准确识别第 10,001 行并拒绝；候选成功原子切换，候选失败或旧任务晚到不覆盖当前成功结果。
- 界面新建 Excel 同步处理成功才可用；失败丢弃新建数据源。编辑失败保留旧成功结果；重试仅在已保存原文件时可用。
- Excel 修改脚本时从保存的原文件重算；存量 `imported_items` 在未显式重新上传时继续可运行。
- 新 Excel YAML 导入后为 `needs_upload`，重新上传前不可运行；旧 `imported_items` YAML 仍可导入运行。
- NATS、Prometheus、无脚本 MySQL/PostgreSQL/REST 和存量 Excel 保持回归兼容。

## Out of Scope

- 独立 Dataset/语义层/计算列产品。
- MySQL/PostgreSQL/NATS/Prometheus 上的 Python。
- 脚本内连库、发 HTTP 或访问平台凭据。
- 第三方 Python 包、脚本市场、脚本版本中心和在线调试器。
- NATS NameSpace 并入数据连接，或改动 NATS/Prometheus 取数逻辑。
- 强制迁移存量内联数据源或存量 Excel。
- 跨组织共享数据连接。
- REST 自动翻页、REST 统一筛选参数和非表格图表。
- Excel 多版本历史、超过 10,000 行的分块/流式处理。
- 组件侧 Grafana 式 Transform 管道。
- 借本变更全面重构 MySQL/PostgreSQL SQL 防护；V1 保持现有单 SELECT/行数护栏并推荐使用只读账号。
