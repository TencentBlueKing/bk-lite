# 监控策略模板可保存与跨项目复用

## 背景

现有 `PolicyTemplate` 以“监控对象 + 插件”为一条记录，将多条内置模板存入
JSON 数组。所有数据均由插件目录中的 `policy.json` 初始化，没有用户自定义数据。
数组下标被用作页面模板标识，无法稳定支持单条保存、覆盖、导入、导出和删除。

本变更将模板重构为“一条记录一个模板”，在同一模型中区分内置模板和项目
自定义模板。内置模板继续由 `plugin_init` 幂等对账；页面保存和 ZIP 导入只产生
自定义模板，任何用户操作都不能覆盖或删除内置模板。

## 领域定义

- **内置模板**：来源于插件 `policy.json`，`template_type=builtin`，全局可见，
  只能由初始化对账更新或删除。
- **自定义模板**：来源于策略页面“保存模版”或 ZIP 导入，
  `template_type=custom`，归属当前项目，可由有策略操作权限的项目成员覆盖和删除。
- **模板 key**：模板的稳定可移植身份。内置模板由监控对象、插件和模板显式 key
  或名称确定性生成；自定义模板由页面保存时生成 UUID，导入时沿用包内 key。
- **覆盖**：只在当前项目的自定义模板集合内发生。内置模板不参与重复匹配。

## 数据模型

`PolicyTemplate` 一条记录表示一个模板：

| 字段 | 语义 |
|---|---|
| `key` | 稳定业务标识 |
| `scope_key` | `builtin` 或 `custom:<项目ID>`，用于跨数据库一致的唯一约束 |
| `template_type` | `builtin` 或 `custom` |
| `organization` | 自定义模板所属项目；内置模板为空 |
| `monitor_object` | 监控对象 |
| `plugin` | 监控插件 |
| `name` | 模板名称 |
| `description` | 模板描述 |
| `config` | 不含项目运行环境的策略定义 |
| 维护与时间字段 | 创建人、更新人和时间 |

约束：

- `(scope_key, key)` 唯一。
- `(scope_key, monitor_object, plugin, name)` 唯一。
- 内置模板 `scope_key=builtin` 且 `organization` 必须为空。
- 自定义模板 `scope_key=custom:<项目ID>`。
- 自定义模板必须有 `organization`。

现有模板数据可重建，结构迁移删除旧表内容；迁移本身不调用初始化命令，随后既有
`batch_init -> plugin_init -> migrate_policy` 链路重新生成内置模板。

## 内置模板初始化

初始化先完整读取、排序和验证全部 `policy.json`，再在单个数据库事务内：

1. 按 `template_type=builtin, key=<稳定 key>` 执行 `update_or_create`。
2. 更新名称、描述、监控对象、插件和配置。
3. 删除本次期望 key 集合中不存在的内置模板。
4. 不查询、不更新、不删除任何自定义模板。

下列情况视为配置错误：

- 多个文件声明相同“监控对象 + 插件”；
- 同一文件内模板 key 重复；
- 引用的对象或插件不存在；
- 模板不是对象或缺少名称。

验证失败时不进入写事务，保留上一次有效内置数据。初始化错误沿用现有记录方式，
不得依赖 API、Worker、Broker 消费者或其他运行期进程。

## 模板配置范围

保存可复用检测定义：策略/告警名称、插件、指标或公式定义、筛选条件、数据周期、
分组维度、聚合算法、阈值、触发次数、恢复条件、单位和无数据告警配置。执行频率
作为默认值保存，应用模板时允许覆盖。

不保存所属组织、具体资产、通知人、通知渠道、启停状态、定时任务和运行状态。

## 查询与权限

- 列表返回全部内置模板和当前项目可见的自定义模板。
- 自定义模板严格按当前项目隔离，不因“包含子项目”自动跨项目展示。
- 保存、导入和删除要求对应监控对象的策略操作权限。
- 导出要求模板可见；内置和自定义模板均可导出。
- 后端返回 `template_type` 和 `deletable`，并在删除时再次强制校验。

## ZIP 契约

```text
monitor-policy-templates.zip
├── manifest.json
└── templates/
    └── <模板类型 + key 的 SHA-256>.json
```

`manifest.json` 包含格式名、`schema_version=1`、导出时间和模板文件清单。包内不包含
数据库主键、项目 ID、资产 ID、用户名或通知渠道 ID。插件、对象和指标使用稳定名称。
同一批选择中如果内置和自定义模板具有相同可移植 key，导出包只保留自定义版本，
确保包内 key 唯一且可被直接导入。

导入限制 ZIP 文件类型、文件数量、单文件大小、解压总量和压缩比，并拒绝绝对路径、
路径穿越、目录项及符号链接。所有模板验证通过后才在单个事务中写入。

重复匹配顺序：

1. 当前项目自定义模板的 `(organization, key)`；
2. 当前项目自定义模板的 `(organization, monitor_object, plugin, name)`。

两个条件命中不同记录时拒绝导入。首次上传默认 `overwrite=false`，存在重复时返回
冲突列表且不写数据；页面确认覆盖后使用同一文件重试 `overwrite=true`。覆盖保留
数据库记录 ID，更新 key、名称和配置。内置模板完全不参与匹配，即使同名也与
导入后的自定义模板共存。

## 页面交互

### 策略配置页

底部操作为“确认 / 保存模版 / 取消”。保存模版只校验模板配置所需字段，不要求
组织、资产和通知字段；保存成功后保留表单，不创建策略、不跳转。

### 事件—模版页

- 搜索框位于工具栏左侧。
- 右侧依次为“导入”和“批量操作”。
- 批量操作包含“批量导出”和“批量删除”。
- 未选择模板时两项禁用。
- 选择包含内置模板时批量删除置灰并提示“内置模版不可删除”，导出仍可用。
- 内置模板仍可选择、应用和导出，并以标签和自定义模板区分。

## 验收

- 重复运行 `plugin_init` 不新增重复内置模板，并能更新、增加和删除内置模板。
- 页面保存和 ZIP 导入只创建自定义模板，不能覆盖或删除内置模板。
- 同一 ZIP 重复导入先提示，确认后覆盖当前项目自定义模板。
- 导出后可在另一个项目导入并应用，项目和运行环境字段不会泄漏。
- 包含内置模板时批量删除不可用，构造请求也会被后端拒绝。
- 单指标和公式指标模板均能往返保存、导出、导入和应用。
