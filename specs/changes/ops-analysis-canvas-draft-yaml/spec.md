## Problem Statement

搭建者希望以后用自然语言改运营分析画布，但现在还不能接智能体：编辑态改动只活在浏览器里，取消只能回到进入编辑的那一帧；YAML 只服务于整包导入导出（含数据源和命名空间），一应用就会写正式对象。仪表盘等类型的 `view_sets` 几乎没有可投影性校验，坏配置能存进去，打开才失败。没有个人快照历史、没有校验后的实时投影、也没有给后续智能体用的读/校验接口。

## Solution

在运营分析内为所有已支持 YAML 导入导出的画布类型，提供按人隔离的快照历史：单画布 YAML 切片的读/校验、显式检查点（最多 20 条），以及编辑页把合法 YAML 投影到画布（**仅内存**）。人手拖动、改配置、YAML 预览/应用都只在编辑页内存完成；**持久化仅**「存一版」（追加检查点）与「保存正式画布」。**不维护**编辑过程中的服务端「当前草稿行」。数据源和命名空间不改。正式保存、取消编辑仍由人触发。本变更不嵌入 OpsPilot，也不让智能体写正式画布。

## User Stories

1. 作为有编辑权的画布搭建者，我希望进入非内置画布编辑态时始终从正式画布开始，从而编辑起点与发布态一致、未存一版的试错刷新即丢。
2. 作为画布搭建者，我希望用单画布 YAML 切片在页面上立刻看到布局变化（预览/应用仅内存），从而文本改动和画布所见一致，且试穿不必写库。
3. 作为画布搭建者，我希望可以先预览 YAML、取消后回到预览前画面，从而试看不必占用检查点。
4. 作为画布搭建者，我希望非法 YAML 被整份拒绝且画布停在上一帧合法状态，从而坏文档不会 silently 丢掉组件。
5. 作为画布搭建者，我希望每次显式「存一版」都进入最多 20 条快照历史，并能回到其中一条，从而试错可以回滚，而不必取消整次编辑。
6. 作为画布搭建者，我希望点保存才把当前编辑内容写成正式画布、点取消回到进入编辑时的成品，从而未发布工作和已发布画布仍然分开。
7. 作为只读查看者或内置/分享页使用者，我希望不出现快照与 YAML 应用，从而内置保护和分享只读语义不被打开。
8. 作为后续智能体调用方（仅编辑态），我希望用 `GET yaml` 读上下文、`preview` 校验，生成结果由人预览/应用进内存，满意后「存一版」才落库，从而接智能体时不必发明第二套画布协议。

## Implementation Decisions

### 范围与身份

- 覆盖导入导出中的全部画布类型：仪表盘、拓扑、架构图、大屏、报表、网络拓扑。不覆盖数据源、命名空间。
- 快照主语是 `(resource_type, resource_id, user)`。正式画布仍是组织内一份成品。
- 仅当调用者对该对象有编辑权（各画布现有 `view-EditChart`，与今日保存画布相同）、对象非内置、且不处于分享态时，才可读写快照/YAML 接口。否则返回 403。查看态不加载这些接口，不展示 YAML 应用与存一版。
- 不另发明草稿专用权限点。

### 编辑生命周期（人）

- **进编辑**：始终加载正式画布到内存。不拉服务端工作副本、不弹「发现未发布编辑」。可拉取快照记录列表供手动恢复。
- **改布局 / 改配置**：只改内存，不写服务端，不入历史。
- **预览 YAML**：仅编辑页内存临时展示；取消预览恢复预览前内存。不写库、不入历史。
- **应用 YAML**：走与接口相同的整份校验与投影；成功则**仅更新内存**。不写库、不入历史。
- **存一版**：把当前内存态**追加一条检查点**。最多 20 条，超出丢最旧。
- **离开编辑**（取消按钮 / 切换画布）：若内存相对进入编辑时的正式画布有改动，沿用现网未保存确认（留下 / 放弃），不新增「离开时顺便保存」第三条路径。放弃：编辑器回到进入本次编辑时的正式画布；快照历史保留。
- **保存正式画布**：仍走现有保存 API 与对象级乐观锁，payload 来自当前内存。保存失败不改正式画布。保存成功后快照历史保留。
- 不处理关浏览器未点保存、未存一版的纯内存改动恢复（含已应用未存一版的 YAML）。刷新后再进编辑一律从正式画布开始；要从检查点找回须手动「恢复」。

### 存储

- 检查点存与该类型保存接口同构的 JSON（`view_sets` 以及该类型已有的 filters / other 等），数据源引用为数字 ID。
- **仅** `CanvasDraftCheckpoint` 表；每人每画布最多 20 条，只在人手显式「存一版」时 append。不因 YAML 应用、恢复或进编辑而额外写服务端行。
- 检查点可有可选 `label`（最多 30 字），在快照记录内单击编辑，存一版时不必填写。
- 不做按天 TTL。删除画布时删除该对象上所有人的检查点。
- 库存不存 YAML 原文，避免空白和键顺序造成假变更。查看 / 复制历史 YAML 时由库存 JSON 再编码。

### YAML 契约

- 对外文档是单画布切片：`type` 加该类型导出条目的字段（名称、描述、`view_sets`、该类型已有的筛选/其它配置等）。数据源使用现有导入导出业务键，不出现数据库 ID。
- 禁止切片内携带 `datasources` / `namespaces` 或完整导入包的 `meta` 多章节结构。
- **GET yaml**：把**最新检查点** payload（若无检查点则从正式画布投影）改写成业务键 YAML。响应带 `revision`：有检查点时为最新检查点 `id`，否则为 `0`。不因此创建任何行。
- **POST yaml/preview**：解析与校验，返回投影用 payload，不写库。
- **无 PUT yaml**（本期）。Agent 生成结果经 preview 校验后由编辑页内存应用；落库仅经人手「存一版」。
- 不得调用导入提交去写正式画布或创建数据源。业务键解析失败即整份失败，不隐式建数据源。
- 六种类型共用同一套检查点信封与 YAML 编解码。校验器与页面投影器按 `type` 分派，复用该类型已有的导出条目模型和业务键改写。

### 校验（整份拒绝）

校验回答「能否投影成该类型编辑态 layout」，不回答「查询是否有数据」。过不了则错误列表，页面不动。至少包括：

- YAML 可解析且 `type` 与目标对象一致
- 业务键均能在当前用户可见数据源中解析
- 组件或节点类型在该画布白名单内
- 布局坐标与组件/节点必填字段
- 筛选绑定引用存在的组件或参数

不在应用前打数据源取数。报表可建立在已有 `view_sets` 规范化之上；仪表盘和大屏须把目前只存在于组件配置提交路径中的规则抽成与 UI 无关的校验，供 YAML 路径与表单提交共用。

**本期已知限制（校验深度）：**

- **较完整：** 仪表盘、大屏、网络拓扑（布局、组件/节点类型、筛选绑定等）。
- **偏弱：** 拓扑、架构图、报表仅做结构级检查（如 id / sections 形状），未覆盖上文「至少包括」的全量清单；复杂坏配置仍可能经存一版写入检查点，打开或取数时才失败。后续应抽成与表单提交共用的校验器并补测。

### revision（只读标识，无 CAS）

- `revision` 仅出现在 **GET yaml** 响应：等于最新检查点 `id`，无检查点时为 `0`。
- **无 If-Match、无 409、无服务端乐观锁**。存一版、恢复、取消、保存均不维护单独的 revision 同步或重试。
- 对人编辑：内存是工作拷贝，直到存一版或保存。对 Agent：`GET yaml` / `preview` 读上下文与校验；落库仅经存一版。
- 用户侧不必展示 revision。

### 页面投影

- YAML 应用（内存）与 preview 校验后投影走同一套：合法 JSON → 该类型现有反序列化（仪表盘 GridStack、大屏 viewport 条目、报表 sections 等）→ 同步该类型已有的筛选绑定副作用。不得绕过投影直接改 DOM。
- **恢复**某帧：读取该检查点 payload，**仅投影到编辑器内存**；不追加新检查点、不写额外服务端行。
- 预览 / 应用按钮若出现在后续对话宿主里，也必须由运营分析编辑页执行投影，不由宿主改 DOM。本期不实现该宿主。

### 模块边界

- 运营分析服务端：检查点持久化、YAML 编解码、分类型校验、历史裁剪、权限与内置/分享拒绝；`GET yaml` / `preview` 供 Agent，非编辑页人手应用路径。
- 运营分析各画布编辑页：**本期已交付** 进编辑拉快照记录、存一版与恢复入口、整份投影（恢复时）。**本期未接线** 编辑页 YAML 预览/应用按钮（人机工具栏不暴露）。
- 不改 OpsPilot、WebChat、全局助手。不把草稿 API 注册为智能体工具。本期不在编辑页做助手对话面板。Agent 仅编辑态。

## Testing Decisions

好测试只断言外部行为：给定身份与对象，读写检查点/YAML 的成功、403、整份拒绝、历史上限、保存与取消是否动正式画布；不锁 React 内部 state 形状。

优先最高缝：

- 服务端 HTTP：无检查点时 GET yaml 从正式画布投影；存一版 append 检查点；检查点 `label` PATCH；YAML GET/preview；错误列表；内置/分享/无编辑权 403；历史最多 20；仅存一版入历史；恢复只读 payload、不追加检查点；删画布级联删除检查点；业务键无法解析时不建数据源且不写检查点。
- 纯函数：各类型 YAML 切片 ↔ 存储 JSON（业务键改写）、整份校验器、仪表盘/大屏/报表现有 layout 反序列化在「合法切片」上的投影结果。
- 编辑页：恢复检查点时整份替换 layout。

先验：导入导出预检与业务键改写测试、报表 `view_sets` 规范化测试、仪表盘 GridStack 序列化往返测试。YAML 校验应复用或并列于这些缝，而不是走导入提交集成。

双组织/跨用户：用户 A 的检查点不可被用户 B 读写；B 保存正式画布不覆盖 A 的个人检查点（正式画布仍可能被后保存者覆盖，与今日两人保存行为一致）。

## Out of Scope

- OpsPilot / WebChat 嵌入、页面宿主工具、智能体自动写正式画布
- 服务端「当前草稿行」、If-Match / 409、进编辑自动加载工作副本、编辑中轮询同步
- `PUT yaml` 程序化落库（若后续 Agent 需要，另开变更评估是否恢复）
- 用导入提交或完整导出文件驱动检查点
- 数据源、命名空间、密钥的创建或修改
- 内置画布沙箱、分享页可写检查点
- 应用前真实取数、按天 TTL、WebSocket、检查点分叉合并
- 布局防抖落库、崩溃后恢复未存一版的纯内存改动
- 离开编辑时「顺便保存」第三条按钮
- 大屏/拓扑/报表以外的新 `view_sets` 方言；本变更只为现有六种类型提供信封和校验/投影分派
- 两人同时保存正式画布的合并（仍为对象级后写/现有乐观锁）

## Further Notes

- 本变更是智能体驱动画布的运营分析前置，不是助手功能本身。后续 Agent 在**编辑态**作为 YAML 客户端：`GET yaml` 读上下文、`preview` 校验；生成结果交给人预览/应用（内存）；满意后「存一版」落库。
- **不要**再引入「当前草稿行 + 20 条历史」双层存储。服务端只有检查点历史；编辑过程只在内存。
- 若未来 Agent 必须无人值守 `PUT yaml` 且不入历史，那是**独立协议决策**，不得与人机「存一版」混为一谈。
