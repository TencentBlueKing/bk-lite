## A. 对话中的施工草案（2026-08-25，当时未入库）

# 运营分析画布个人草稿与 YAML 驱动契约

Status: ready

### Problem Statement

搭建者希望以后用自然语言改运营分析画布，但现在还不能接智能体：编辑态草稿只活在浏览器里，取消只能回到进入编辑的那一帧；YAML 只服务于整包导入导出（含数据源和命名空间），一应用就会写正式对象。仪表盘等类型的 view_sets 几乎没有可投影性校验，坏配置能存进去，打开才失败。没有个人未发布文档、没有校验后的实时投影、也没有给后续智能体用的读写接口。

### Solution

在运营分析内为所有已支持 YAML 导入导出的画布类型，提供按人隔离的未发布工作区：当前草稿防抖落库、稀疏历史检查点、单画布 YAML 切片的读写与整份校验，以及编辑页按 revision 把合法草稿投影到画布。数据源和命名空间不改。正式保存、取消编辑仍由人触发。本变更不嵌入 OpsPilot，也不让智能体写正式画布。

### 与仓库交互稿的主要分歧（合成前）

| 点 | 本草案 | 仓库交互稿 / 原型 |
|---|---|---|
| 进编辑 | 自动建/加载服务端草稿 | 只加载正式画布到内存 |
| 人手拖动 | 防抖写当前草稿 | 只改内存 |
| YAML 应用 | 自动入历史 | 不入历史，存一帧才入 |
| 历史存什么 | 库存 JSON，不存 YAML 原文 | 存 YAML 原文便于复制 |
| 崩溃恢复 | 要 | 明确不做 |
| 离开编辑 | 未改现网弹窗形态 | 继续编辑 / 放弃 / 保存 |

## C. 产品定稿（2026-08-25，已写入 `spec.md` 与交互稿）

| 行为 | 定稿 |
|------|------|
| 拖格子 / 改配置 | 仅内存 |
| YAML 预览 / 应用 | 仅内存 |
| Agent | 仅编辑态；人预览/应用；`GET yaml` + `preview`；落库经「存一版」 |
| 持久化 | 仅「存一版」（追加检查点，最多 20 条）与「保存」（正式画布） |
| 进编辑 | 正式画布 → 内存 |
| 取消 / 保存 | 内存还原或写正式画布；快照历史保留；**不** DELETE 任何服务端工作行 |

## D. 实现 pivot（2026-08-26，已写入 `spec.md`）

| 点 | 2026-08-25 定稿 | 2026-08-26 实现 |
|---|---|---|
| 服务端存储 | 当前草稿行 + 检查点 | **仅** `CanvasDraftCheckpoint` |
| revision / CAS | If-Match、409 | **无**；`GET yaml` 的 `revision` = 最新检查点 id 或 `0` |
| `PUT yaml` | 保留给 Agent | **未实现** |
| 恢复 | CAS 写回当前草稿行 | 只读 payload，投影到内存 |
| 取消/切换/保存 | 删除当前草稿行 | **无** delete 逻辑 |
