# ADR 0009: RUM public gateway is separate from APM trusted OTLP

Status: accepted

## Context

ADR 0008 requires APM OTLP/HTTP 4318 to remain on a trusted regional network
without application-level Browser Tokens. RUM telemetry originates from end-user
browsers on the public internet and therefore cannot reuse that ingress.

The upstream RUM gateway already defines a working public contract:

- `POST /rum/v1/collect` (Faro JSON, `X-API-Key`, `X-RUM-Application`, `Origin`)
- `POST /rum/v1/replay` (segmented gzip replay)
- Redis Lua admission: application enabled, key membership, origin allowlist,
  minute budgets, erasure fence

## Decision

1. BK-Lite introduces a dedicated RUM public gateway (ports/config under
   `deploy/rum/`), independent of APM regional collectors.
2. Authentication for RUM is Browser Key + exact Origin allowlist + budgets.
3. ADR 0008 remains unchanged; APM 4318 stays intranet-only.
4. Opening or changing RUM public exposure requires this ADR to be accepted
   before production traffic.

## Consequences

- Redis becomes required when RUM is enabled (see companion decision T06).
- Edge Traefik / reverse proxy must publish only the RUM collect/replay paths
  publicly, not APM OTLP.
- SDK snippets generated by `apps.rum` must point at the RUM gateway URL, never
  at APM 4318.
