# ADR 0008：APM OTLP 入口采用受信区域网络边界

Status: accepted

## Context

APM 接入配置由 Server 根据用户有权访问的云区域解析受信代理地址，并生成固定的
OTLP/HTTP 4318 端点。首次生产上线的数据面由区域 Collector 清洗客户端属性、注入可信区域，再通过
受 ACL 约束的 JetStream Subject 送往中心。旧 PRD 曾提出独立 APM Gateway、接入源和一次性
Bearer Token，但当前领域模型没有接入源，生成配置也不持久化凭据。

如果把 4318 暴露到公网或其他不受信网络，任意客户端都能伪造
`service.namespace`，污染应用目录和遥测数据；而只在片段中增加一个共享 Token 既不能证明
工作负载身份，也会引入签发、轮换、撤销、泄漏和多租户隔离等尚未设计的生命周期。

## Decision

- 区域代理的 OTLP/HTTP 4318 只向受信区域内网开放，不作为公网或跨不受信网络入口。
- 受管区域代理正式包含区域 Collector 与宿主机 4318 映射；防火墙、安全组或等价网络策略
  必须把来源限制到该区域获准上报遥测的工作负载网络。
- 当前接入配置不生成、不保存 APM Token，也不发送 Authorization Header。
  `service.namespace` 只用于应用归属，不能作为认证、授权或租户隔离依据。
- Collector 删除客户端提交的 `bk.*` 属性并注入部署可信的区域 ID；区域到中心的 NATS
  身份继续使用 TLS、独立凭据和精确 Subject ACL，与应用侧 OTLP 入口身份分离。
- 公网、跨租户或其他不受信网络接入当前明确不支持。开放前必须单独设计并评审代理层
  TLS/mTLS、工作负载或租户凭据、签发与轮换、撤销、限流、审计和失败语义；不得通过扩大
  4318 监听范围或把共享秘密写入 SDK 片段临时绕过。

## Consequences

- 接入流程保持无状态且不向用户展示秘密，Server 无需承担遥测认证服务的启动依赖。
- 受信网络中的受损工作负载仍可能伪造其他应用的 namespace；这是当前接受的剩余风险，
  通过缩小网络可达范围、Collector 清洗和运行期异常观测来降低，而不是宣称已有应用级认证。
- 自定义代理或非受管部署必须显式完成 4318 私网映射与来源限制；未完成时不能视为可用的
  APM 接入入口。
- 未来若产品需要不受信网络接入，应新增领域对象和上线方案，而不是恢复从未发布的旧 PRD
  Token/Gateway 契约。
