# ADR 0005：日志聚合分组身份采用版本化规范摘要

Status: accepted

## Context

日志聚合告警把 `group_by` 字段和值用 `field=value, ...` 拼接后直接写入
`Alert`、`Event` 和 `AlertSnapshot` 的 `source_id`。分组值来自日志，长度无界，
而三个模型的字段上限均为 100 字符；拼接格式也没有转义，两个不同分组可能产生
相同字符串。`source_id` 同时承担告警生命周期关联和事件幂等身份，超长会使整批
持久化失败，歧义会错误合并告警。

直接切换身份格式还会让升级前仍活跃的告警失去关联，并在升级后重复创建告警。

## Decision

- 有分组的日志聚合告警使用 `policy_<policy_id>_g2_<digest>` 作为主身份；摘要输入是
  带版本号的规范化 JSON，明确记录字段名、字段是否存在和值，并按字段名排序。
- 摘要使用 SHA-256，并按 `source_id` 的 100 字符存储契约限制输出；正常整型策略 ID
  可保留完整的 64 位十六进制摘要。
- 无分组聚合告警保持历史身份 `policy_<policy_id>_`，避免无关生命周期迁移。
- 新事件携带满足 100 字符契约的旧身份作为兼容别名。持久化时先匹配新身份，再用
  旧别名复用已有活动告警；复用时不改写已有告警的 `source_id`。新建告警在旧身份
  可存储时也保留旧 `source_id`，支持排空旧任务后的版本切换和代码回滚；超长旧身份
  不可存储时，告警与事件均使用 `g2` 身份。
- `g2` Event 与旧身份 Alert 的关联是兼容别名的持久化认领记录。一个旧别名最多由
  一个新身份认领；认领状态跨扫描读取。新版本 worker 在策略行锁内重新查询并认领，
  防止并发扫描重复占用同一别名。若历史格式已经把多个真实分组合并，升级后的其他
  分组创建独立告警，从其首次命中开始解除碰撞。
- 复用升级前 Event 时保留原记录及其旧身份，另建确定性 `g2` Event 记录认领；这样
  主数据提交后即使快照失败，普通可表达别名仍能被旧版本重试路径发现。
- 生命周期通知和 `AlertSnapshot` 使用 Alert 的 `source_id`，保证 created/closed 的
  外部资源身份一致；Event 保留 `g2` 身份用于扫描幂等和分组区分。
- 分组可读内容继续保存在事件内容和 `raw_data.query_result`，不从摘要反向解析。

## Consequences

- 任意长度的分组值都不会突破三个模型的 `source_id` 长度契约，不同结构的分组不再
  因分隔符或字符串化规则碰撞。
- 存量活动告警在升级后继续原生命周期。数据库无需迁移或批量回填，回滚不会改写
  已有记录。
- 已经发生的历史碰撞无法无损判断旧告警原本属于哪个真实分组；系统保留其中一个
  生命周期，其余分组从升级后的首次命中开始独立。
- 发布时必须先排空旧日志扫描任务，再启用新 worker；兼容别名只保证切换前后的数据
  衔接，不承诺新旧 worker 并行认领。回滚也应先排空新任务再切换，并在可回滚窗口内
  冻结 `group_by` 顺序等会改变旧身份文本的策略编辑。只有可存储、无歧义且自升级后
  旧身份文本未变化的分组，才能由保留的 Alert/Event 继续衔接；超长旧身份、已经由
  新版本拆分的歧义旧身份，或旧身份文本发生过变化的策略，回滚前必须暂停，或回退到
  包含本 ADR 兼容读取逻辑的补丁版本。
