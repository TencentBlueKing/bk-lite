# 僵尸机报表前置配置手册

运营分析内置目录里的「僵尸机报表」只负责筛选和出表。真正的数据来自 **CMDB、监控、日志**。下面按模块说明：报表依赖什么、现场要提前配什么。未配齐时，常见结果是空表、指标为空，或登录列显示 `uncollected`（未采集）。

产品口径见 `docs/design/product-decisions/ops-analysis-zombie-host-report.md`。

## 报表本身会做什么

1. 用户必须勾选 **应用系统**。未选不扫全量，直接空表。
2. 沿 CMDB 关联 `system_contains_application` → `application_run_host` 展开主机，且只保留已回填 `monitor_id`、当前用户有监控权限的主机。
3. 一次最多 **100 台**（展开后）。超出报错，不会截断。
4. 在所选时间窗（默认 7 天）内拼：成功登录次数、网卡入包 pps、CPU / 内存 / IO 百分比；再按阈值 **全部 AND** 过滤。`-1` 表示该边界不限。
5. 阈值不随时间窗缩放。默认闲机口径：登录 max=2，入包峰值 200 pps、均值 50 pps，CPU 均值 8% / 峰值 20%，内存均值 25% / 峰值 40%，IO 峰值 10%。

交付环境执行 `init_builtin_canvases` 后，内置目录会出现只读的「僵尸机报表」。不要改内置报表本身；缺数去上游模块补配置。

## 依赖数据一览

| 报表列 / 行为 | 数据从哪来 | 没有它会怎样 |
|---|---|---|
| 应用系统下拉 | CMDB 应用系统实例 | 下拉为空，无法圈范围 |
| 主机行（业务、主机名、IP、系统类型） | CMDB 主机，且能从系统展开到该主机 | 选了系统仍空表 |
| 能进表 | 主机已关联监控实例 `monitor_id`，且当前用户有该实例权限 | 无权或未监控的主机被省略 |
| CPU / 内存 / 入包 / IO | 监控 VictoriaMetrics，主机采集（Linux Host 或 Windows WMI） | 对应指标为空；设了上限时该行会被滤掉 |
| 成功登录次数 | 日志 VictoriaLogs：Windows `winlogbeat` 4624，或 Linux `file` / `filebeat` 的 SSH 成功登录 | `login_status=uncollected`，次数为空，不按 0 过滤 |
| 僵尸机白名单筛选 | CMDB 主机枚举字段 `zombie_whitelist`（是/否） | 空值视为否 |

## 1. CMDB

入口：CMDB 模型与实例。

**应用系统**

- 维护应用系统实例（报表下拉用 `inst_uuid` / `inst_name`）。
- 配齐关联：应用系统 **包含** 应用（`system_contains_application`），应用 **运行于** 主机（`application_run_host`）。
- 只建系统、不拉关联，展开结果为空。

**主机**

- 主机要有主机名、IP、`os_type`（1 Linux / 2 Windows）。
- 主机必须能关联到监控实例，`monitor_id` 非空。未纳管监控的资产不会出现在表里。
- 初始化会给主机模型补人工枚举字段 **僵尸机白名单**（`zombie_whitelist`：是 / 否）。采集不得覆盖。没有该字段或空值视为否。要把某台机器排除出闲机口径时，在主机详情里改成「是」。
- 业务列取主机所属组织显示名，需主机挂在正确组织下。

## 2. 节点管理 + 监控

入口：节点管理安装采集器；监控创建主机采集任务。

**节点**

- 目标主机安装 Controller / Agent，并在节点管理中在线。
- 登录是否「已采集」按主机上的 `node_id` 是否挂了对应日志采集实例判断。节点 ID 对不上，登录永远是未采集。

**主机监控（出 CPU / 内存 / 入包 / IO）**

- 为每台要进报表的主机配置 **操作系统主机监控**（Linux 用 Host/Telegraf 一类；Windows 用 WMI 主机监控）。
- 至少要能采到与主机综合盘同一口径的指标：
  - CPU：`cpu_usage_*` 或 Windows `cpu_usage_total_gauge_value`
  - 内存：`mem_used_percent`
  - 入包：`net_packets_recv`（报表按 **pps** 展示，不是百分比、也不是 bps）
  - IO：`diskio_io_util`（按盘取窗内峰值，再取该主机最大盘）
- 时间窗内要有点。刚接采集、窗口内无数据时，指标为空。
- 当前用户必须对这些监控实例有权限，否则即使用 CMDB 能展开，也会被授权过滤掉。

## 3. 日志

入口：日志模块采集实例。本报表 **不新增采集类型**，必须用现有 Winlogbeat / 文件采集。

**Windows**

- 采集类型：`winlogbeat`。
- 采集 Windows 安全日志，成功登录事件 **4624**。
- 采集实例必须挂在该主机对应的 `node_id` 上。

**Linux**

- 采集类型：`file` 或 `filebeat`。
- 采集 sshd / 本机鉴权成功日志。报表只计 `Accepted password`、`Accepted publickey`、`session opened`；失败、`Invalid user`、sudo、解锁不计。
- 同样必须挂在该主机 `node_id` 上。

日志字段里的主机名或 IP 要能对上 CMDB 主机名 / IP（大小写不敏感，先主机名再 IP）。对得上采集实例但窗口内没有成功登录，次数为 **0**（状态仍是 `counted`）。对不上采集实例，状态为 `uncollected`，次数为空，**不会**因为「登录上限」被当成闲机筛掉。

## 4. 运营分析

- 跑过内置画布初始化后，到 **运营分析 → 内置目录 → 僵尸机报表**。
- 报表只读。切换中英文时，报表名、筛选、列名走运营分析语言包。
- 查询前必须勾选应用系统；展开后超过 100 台会失败，请缩小系统范围。
- 默认阈值偏严。现场机器入包 pps 较高时，把对应上限改成 `-1` 再搜，避免误以为没数据。

## 现场验收顺序

1. CMDB：选一个应用系统，能顺着关联看到其下主机，且主机有 `monitor_id`。
2. 监控：这些主机在时间窗内能在主机监控里看到 CPU / 内存 / 网卡 / 磁盘 IO。
3. 日志：Windows 有 4624，或 Linux 有 SSH Accepted；采集实例的节点等于主机节点。
4. 打开僵尸机报表，只勾该系统，阈值可先全部改为 `-1`，确认行数与主机数一致；再收回默认阈值看闲机结果。

## 不在本报表范围内

- 未勾选应用系统时扫描全部主机
- NetFlow / sFlow / Packetbeat 代替网卡入包
- 登录失败、sudo、网络登录
- 按时间窗自动缩放阈值
- IIS / MSSQL 等业务采集脚本
