# 删除 LLM 模型时保留智能体设计

## 背景

`LLMSkill.llm_model` 允许为空，但当前外键删除策略是 `CASCADE`。通过模型管理接口删除 `LLMModel` 时，数据库会连带删除所有引用该模型的 `LLMSkill`，造成用户创建的智能体及其配置不可恢复地丢失。

## 目标

- 删除 LLM 模型时保留关联智能体。
- 将关联智能体的 `llm_model_id` 自动置为 `NULL`。
- 保持现有模型删除接口的成功语义，不引入软删除或使用中禁止删除。

## 设计

将 `LLMSkill.llm_model` 的 `on_delete` 从 `models.CASCADE` 改为 `models.SET_NULL`。该字段已经配置 `null=True`，无需修改字段可空约束。

新增 OpsPilot 数据库迁移，更新外键删除行为。迁移只修改约束，不执行数据清理或回填；已经被历史级联删除的智能体无法通过本迁移恢复。

模型删除后，智能体继续出现在列表中，序列化结果中的模型名称为空。用户需要重新选择模型后才能再次执行智能体；本次不改变既有执行链的错误处理。

## 回归测试

扩展 `LLMModelViewSet.destroy` 的真实 DRF 与数据库测试：

1. 创建一个模型和引用它的非模板智能体。
2. 调用模型删除接口并断言返回 HTTP 204。
3. 断言模型已删除。
4. 断言智能体仍存在，且 `llm_model_id` 为 `NULL`。

测试先在当前 `CASCADE` 实现下失败，再修改模型和迁移使其通过。

## 风险与回滚

- 风险仅限删除模型后智能体进入“未配置模型”状态，这是期望的可恢复降级。
- 回滚迁移可恢复 `CASCADE` 约束，但不能恢复迁移期间已经置空的模型关联。
- 不修改模型删除 API、工作台数据或其他模型引用关系。
