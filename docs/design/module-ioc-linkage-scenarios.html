节点 / CMDB / 监控推送联动

一期共识：推模型；页面默认勾选、取消则不推（无级联暗推）；推送失败节点仍成功并有限重试； 有 ID 只认 ID，存量无 ID 时按对象类型认领并回填 node_id。一期对象：主机 / 网络设备 / 物理服务器 IPMI。 规格 specs/changes/node-cmdb-monitor-push-linkage/spec.md。

总览：允许的数据流

节点管理 ──可选推送──► CMDB ◄──互相推送──► 监控中心 │ ▲ └──────────可选推送──────────────────┘ 禁止：CMDB → 节点　｜　监控 → 节点 落地后关闭：CMDB「拉取节点同步」

推送由页面决定

  • 创建节点：按已售模块默认勾选；取消则该目标不推
  • 无级联：只勾 CMDB 时不会自动再推监控
  • 推送失败：节点仍创建；重试 2～3 次后跳过，详情可再推
  • 字段变更不自动推；详情可补推 / 重新同步

判同规则（被推送方）

  • 有关联 ID：node_id 优先，否则 cmdb_id
  • 存量无 ID：按对象类型认领（一期主机/网络/IPMI），成功则回填 node_id
  • CMDB↔监控互推：有节点 ID 则必带
  • 双键指向不同行 → 冲突，不静默合并

形态 ① · 节点起点（完整联动）

用户创建节点并确认推送 CMDB + 监控（或随后补推）。CMDB 创建后也可推监控；两边都带 node_id=99，监控只落一条。

1. 创建节点 id=99（默认勾选已售目标） 2. 节点 → CMDB：CMDB 得 _id=abc，存 node_id=99；节点回填 cmdb_id=abc 3. 节点 → 监控：监控得 m-555，存 node_id=99；（有则带 cmdb_id） 4. CMDB → 监控：带 node_id=99 + cmdb_id=abc → upsert 同一 m-555 5. 监控 ↔ CMDB：互推时继续带 node_id，补齐 monitor_id / cmdb_id

node_id=99
cmdb_id=abc
monitor_id=m-555

cmdb_id=abc
node_id=99
monitor_id=m-555
监控中心

node_id=99
cmdb_id=abc
防冲突：节点先推监控、再 CMDB 推监控（或反过来），只要都带同一 node_id，监控只认一条对象。

形态 ② · CMDB 手建 → 推监控

资产不是从节点来的。CMDB 推监控时只有 CMDB ID；单向为主，无节点桥，不与节点推送对象自动捏合。

1. 用户在 CMDB 手动创建主机 _id=abc（无 node_id） 2. 页面选择推送到监控 3. 监控按 cmdb_id=abc upsert → m-777 4. 双方互存 cmdb_id + monitor_id

页面行为清单

场景行为
创建节点 按已售模块默认勾选推送目标；用户可取消
创建时不推 详情里再点推送；或对端手建后再推（形态②/③）
已有未推节点 详情统一入口勾选目标补推
已同步 展示关联 ID；提供「重新同步」（幂等 upsert）
改 IP/名称等 不自动推；可提示未同步变更
删/卸节点 确认是否 lifecycle 退役已关联 CMDB/监控（默认归档/停采）
推送内容 全量事实 + 已知关联 ID；目标白名单覆盖
拉取节点同步 本能力上线后关闭并退役；存量不靠批量迁移，可对节点再推，由 CMDB 按对象规则认领并填 node_id
一期对象 主机、网络设备、物理服务器 IPMI
