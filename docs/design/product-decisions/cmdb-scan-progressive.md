# CMDB 扫描三阶段渐进发现产品决策记忆

- 最近更新：2026-10-28
- 当前规格：`specs/changes/cmdb-scan-progressive-discovery/spec.md`
- 实现计划：`specs/changes/cmdb-scan-progressive-discovery/plan.md`

## 产品定位

扫描是网段上的渐进发现：先网络指纹，再登录后的进程指纹，最后才在凭据足够时复用配置采集。它不是专业采集打一枪，也不是监控接入。

## 已确认范围

- 一阶段按特征库端口指纹 TCP 探测，与采集凭据无关。
- 二阶段在 SSH / Agent 登录成功的主机上匹配进程指纹；每台主机只登录一次。
- 三阶段仅当任务为该对象提供了采集凭据时，才跑现有 `*_info`。
- 任务勾选只为录入凭据；指纹扫描范围由特征库决定，不看勾选。
- 特征库新增进程指纹 Tab；端口指纹与进程指纹都初始化一批「可网段主机发现」的配置采集对象。
- 命中带可信度，回填到本次执行清单；用户勾选后再写 CI。
- 数据库 / 中间件进监控：先写 CI，再走 CMDB→监控同步任务。

## 已确认设计决策

- 不勾数据库也能因 3306 或 `mysqld` 得到疑似 MySQL。
- 内置指纹只覆盖数据库 / 缓存 / 中间件这类能在主机上被端口或进程看见的对象；排除云账号、K8s、vCenter、存储阵列管理 API、SSH/IPMI/Redfish 管理口。
- 同一端口允许多类型；进程指纹消歧；端口命中默认低可信。
- Stargazer 新增扫描调度模块，独立队列和配额，不得占用原配置采集槽位。
- 三阶段失败或 VM 空指标不得删一、二阶段命中。
- 扫描结果不任务级同步成采集任务；现有 NATS 命中回填保留。
- 发现凭据与监控凭据继续分离；扫描不得用 SSH / 库账号创建中间件或数据库监控采集。

## 明确后置

- Windows WinRM 二阶段执行器（特征库可先有 Windows 匹配字段）
- 自动猜测监控 URL / Exporter 并建 Telegraf
- 取消族勾选、改成纯凭据袋
- Agent 改为只扫已纳管节点列表
- 把云 / K8s / 存储管理口纳入网段指纹

## 仍待确认

无。

## 已替代决策

- 2026-10-28 替代 `cmdb-scan-discovery`：「扫描=对 collect_info 打一枪」不再作为发现本体。
- 2026-10-28 替代 `cmdb-scan-middleware`：中间件发现不再以 7 个 JOB 配置脚本为本体；脚本只用于三阶段补全。
- 2026-10-28 替代 `cmdb-scan-port-fingerprint` 中「中间件端口可登记但不探、数据库白名单仅三库」：特征库内启用的端口指纹一律进入一阶段。
- 2026-10-28 替代 `cmdb-scan-work-queue` 用 Server 切批模拟扫描调度：发现调度改到 Stargazer 扫描模块。

## 决策来源

- 用户于 2026-10-28 确认三阶段渐进扫描、勾选=凭据、指纹范围由特征库决定、初始化可网段发现对象的端口/进程指纹、疑似对象按可信度回填、数据库监控走 CMDB→监控同步任务。
