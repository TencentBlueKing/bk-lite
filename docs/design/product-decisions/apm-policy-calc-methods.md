## 产品定位

APM 策略仍是叠加的几句话：看哪个数、相对谁、够不够数 / 先满足什么、怎么比线。能力用命名指标、下拉和数字表达，
不做查询语言框，不做机器学习异常检测。竞品（Datadog APM Monitor、New Relic APM Conditions、Elastic APM Rules、
SkyWalking Alarm、阿里云 ARMS、蓝鲸监控）只做能力覆盖与术语输入；落法以 VictoriaTraces LogsQL 单条 `stats`
聚合为准，尽量不增加每目标的查询次数。三域（监控 / 日志 / APM）共用用户词汇，不共用引擎。

## 已确认范围

- 第一批（已落地）：相对上一等长窗 Δ / %、N 小时 / N 天前同窗 %（用户填 N，不给写死的 1h / 24h 选项）、最低请求数、只读试算。
- 第二批（implemented，2026-10-27）：
  - 指标面扩为 12 个：时延 avg / p50 / p75 / p90 / p95 / p99 / max、错误率、错误数、慢请求数 / 占比（策略级慢阈值）、Apdex（策略级 T）、吞吐、无流量。
  - 比较基准加「近 N 天同窗均值」，N 2～7，允许 Δ / %。
  - 触发条件「N 次 ⟨连续 | 最近 N 个周期内⟩」；恢复阈值（滞回）一条线。
  - 全局评估延迟 `APM_POLICY_EVALUATION_DELAY`，默认 60s。
  - 试算、快照、告警详情随契约扩展。
- 第三批（implemented，2026-10-28）：
  - 最多 3 条常规条件，全部满足；前置条件最多 2 条，只做绝对门槛。
  - 作用范围：单服务、多服务或按应用；端点模式为整体 / 手选 / 全部端点；实例维度为不拆 / 按实例。
  - 下游依赖作为目标类型，不按端点或实例拆。
  - SLO 燃烧率：一条策略一组长短窗，快燃 / 慢燃用预设各建一条。
  - `baseline_days` 且 N ≥ 3 时可选 σ；试算可回放最近 24h，只读。
- 第四批（implemented，2026-10-29，场景回归）：
  - 去掉「汇聚方法」。非计数指标的评估值就是整窗 RED 统计值，不对子桶做 avg / max / min / last 二次汇聚。
  - 去掉策略级「无数据告警」开关，无流量用 `no_traffic` 指标表达。
  - `offset_hours / offset_days` 对照窗与 `previous_window` 一样允许 Δ 和 %。
  - `metric_window ≥ evaluation_interval`，否则拒绝保存；`slo_burn_rate` 不受约束。

## 已确认设计决策

- 指标面扩扁平枚举而不是拆「指标 + 统计量」两字段。原因：`p95` / `p99` 已被快照、告警中心副本、SLO 引用；分组下拉在表单层解决可读性。
- 新指标全部并入现有那一条 LogsQL `stats`（`avg / max / quantile / count() if`），零额外查询；本机 VT 已实跑确认。
- 计数类指标（错误数、慢请求数）是整窗总数，不套汇聚方式，也不允许最低请求数；率 / 分位 / 均值 / Apdex 才受最低请求数门控。
- 近 N 天同窗均值用一条多段 `_time:[s, e)` 加 `stats by (_time:1d)` 的查询拿齐；区间必须半开。可用天数 < ⌈N/2⌉ 记 `missing_baseline`。
  第三批在 N ≥ 3 时追加 σ：比较值是 `(当前 − 均值) / 样本标准差`，不是把均值线画成动态阈值带。
- N 中 M 用 `ApmPolicyTargetState.hit_history` 位串，不重查前 N 窗；保持态不推位；触发后清空。
- 恢复阈值方向必须与阈值阶梯相反；带内 `hold` 不触发、不计恢复、活动告警保持，与监控 `hold_events` 同义。
- 评估延迟做全局环境变量而不是策略级。原因：延迟是采集链路属性；竞品要么显式默认 2 分钟（New Relic），要么靠分钟桶天然晚 1～2 分钟
  （SkyWalking / ARMS / 蓝鲸）。这是第二批唯一改变存量行为的决策（告警晚 D 秒，换相对计算不系统性放大下跌）。
- 慢阈值与 Apdex T 放策略级，不放服务级。原因：没有服务级配置实体；同一服务不同接口需要不同阈值。
- 用户词汇沿用「当前值 / 相对上一等长窗 / 同窗 / 变化量 / 变化率 / 恢复阈值」，不出现「环比 / 同比 / 昨天」。
- 2026-10-29：评估值取整窗 RED 统计值，策略没有汇聚方法。原因：p95 / 错误率 / Apdex 不可加，15 秒子桶在低流量服务上全是噪声；
  适配器本来就算好了整窗值。竞品（Datadog / New Relic / Elastic / SkyWalking / ARMS）都是「评估窗内一个数比阈值」。`timeseries` 只画趋势图。
- 2026-10-29：没有策略级无数据开关。原因：APM 的无数据就是窗内 span 为 0，与 `no_traffic` 同源；一个场景只留 APM 原生词「无流量」。
- 2026-10-29：吞吐单位维持 `req/s`，不随 SkyWalking / ARMS 改 cpm。已有快照与告警中心副本按 `req/s` 记录，改单位的收益不抵迁移成本。

## 明确后置

机器学习异常检测、时序预测、查询语言框、任意满足、复合策略、静默期、通知间隔、维护窗、策略级评估延迟和服务级统一慢阈值仍不做，不记成待排期项。
触发条件按时长表达（「持续 N 分钟」）：第四批只补「窗口 ≥ 频率」校验与提示文案，表达方式后续再看。
