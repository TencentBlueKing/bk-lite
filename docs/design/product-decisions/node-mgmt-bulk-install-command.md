# 节点管理批量安装命令产品决策记忆

- 最近更新：2026-11-23
- 当前规格：`specs/changes/node-mgmt-bulk-install-command/spec.md`

## 产品定位

批量命令给要自行分发安装的 Linux 管理员一条通用命令。它不替代远程安装，也不替代逐台指定身份的手动安装。

## 已确认范围

- 第一版只做 Linux。x86_64 和 ARM64 共用一条命令，架构在机器上识别。
- 安装页增加「批量命令」。每台执行时传入 `--node_ip`。
- 与手动安装共用安装配置、安装中、安装完成。批量命令换掉主机表，不另开页面。
- 节点名用执行时的主机名。页面不准备主机清单。
- 装上的节点记为手动安装，沿用现有列表、导出、远程卸载和 CMDB/监控勾选推送。

## 已确认设计决策

- 同一云区域里，IP 仍是节点身份。主机名可以重复。原因：与现有云区域 IP 唯一规则一致，批量命令不另造身份。
- 批量命令放在现有安装方式里，作为 Linux 的第三项。上半部分仍是操作系统、控制器版本和模块同步；选中后去掉主机表、导入和批量编辑，改为台数、有效期和一条命令。原因：管理员仍从节点安装进入，只是不再逐台填表。
- `--node_ip` 必须是本机 IPv4。正在安装或已经存在的 IP 都提示重复，命令失败，不新建节点、不重装控制器。原因：重复执行和并发执行都不能装出第二台。
- 安装失败或超时后释放占位，同一 IP 可以再执行。节点删除后也不再因为「已安装」被判重。原因：失败的机器必须还能重试。
- 判重范围是整个云区域，不限于同一批次。原因：不同批次也不能对同一个 IP 各建一台。
- 命令只携带批次令牌。组织、云区域和控制器版本在生成时固定。NATS 凭据留在受理后的单台会话里。原因：一条要复制到很多机器上的命令不能再带每台身份，也不能带安装通道密码。
- 成功台数从 10、50、100、500、1000 里选，默认 100。有效期从 1、3、5、7 天里选，默认 3 天。失败尝试累计达到台数上限的 5 倍后批次停用。原因：限制泄露命令的可用窗口和乱试次数，页面不再手填任意数字。
- 撤销、过期和停用只拒绝新的受理。已装节点保留，已受理的安装继续收敛。原因：撤销不能把已经开始的安装做成半截状态。

## 明确后置

- Windows 批量命令。
- 网段白名单、事先导入允许清单、安装审批。
- 不传 `--node_ip` 的自动猜 IP，以及 IPv6。
- 把批量安装做成新的安装方式枚举。
- 向 OpenAPI 网关暴露批次生成或受理。
