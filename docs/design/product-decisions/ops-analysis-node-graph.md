# 运营分析通信关系图产品决策记忆

- 最近更新：2026-09-03
- 当前规格：`specs/changes/ops-analysis-node-graph/spec.md`

## 产品定位

通信关系图是运营分析的通用数据源图表，用来把 instant 排行画成有向流量图。它不是第二套 NTA 产品，也不是 CMDB 网络状态拓扑的皮肤。Flow 是第一个使用方，组件本身不绑定 Flow。

## 已确认范围

- 新增图表类型 `nodeGraph`（通信关系图），可放仪表盘和大屏。
- 绑现有 instant 排行数据源，不新开 NATS。
- 同一组件两种粒度：`ip`（IP ↔ IP）和 `service`（源 IP → 目的 `IP:端口`）。
- 本变更交付通用图表，并把通信关系图挂进 Flow 样例盘 YAML。

## 已确认设计决策

- 做成数据源图表，不做成 scene 组件。原因：网络状态拓扑自拉 CMDB 设备链路，对象模型和 Flow 会话不是同一件事。
- 不放宽关系拓扑契约。原因：关系拓扑节点要 CMDB 身份和告警计数，边没有流量权重。
- 端口图用服务视角，不用两端 `IP:端口`。原因：源端口多为临时端口，力导向会碎成毛线团；要看的是谁在打哪些服务。
- 源端口不上图。`service` 目的节点为 `目的字段:目的端口字段`。
- 布局左右分栏（源左、目标右）；边用流量色，节点用角色色；不保存坐标。
- 单位与换算走画布现有展示设置。
- 空设备选择为空图，不退化成全量。

## 仍待确认

无。

## 已替代决策

- 「第一期盘上直接复用网络状态拓扑画 Flow」未采纳。原因：取数和节点都是设备实例，不是会话 IP。
- 「两端都做成 IP:端口节点」未采纳为第一期端口图。原因：源临时端口会撑爆图。改为服务视角。

## 决策来源

- 用户于 2026-09-03 确认：新增通用 `nodeGraph`；IP 聚合；端口图按源 IP → 目的 IP:端口；不复用网络状态拓扑。同日确认把组件挂进 Flow 样例盘 YAML。
