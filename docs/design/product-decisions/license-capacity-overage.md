# 许可容量超额产品决策记忆

- 最近更新：2026-10-14
- 当前规格：`specs/changes/license-capacity-overage/spec.md`

## 产品定位

许可有两种超额，分开处理。时间超额是许可过期，保持现有整模块拒绝。容量超额是 CMDB、监控、日志的用量超过已购容量，用 30 个自然日观察期，期满后只收掉新增和修改。

## 已确认范围

- 只补容量超额。过期许可仍整段拒绝该模块接口，不进入 30 天观察期。
- 容量范围只有已提供用量接口的 CMDB、监控、日志。告警无容量口径，作业按单次任务目标上限，都不在这次。
- 观察期内系统照常使用。期满仍超额，该模块返回的权限里不再有新增和修改，查看和删除保留。
- 已有采集、接入、处理继续运行，可继续写入新实例。不丢数据，不因许可删除已有数据。

## 已确认设计决策

- 按每日计算生效，不在删除或扩容当时立刻改权限。30 天从第一次算出超额的那天起，回到额度内也要等下一次计算才解除。原因：产品明确恢复按正常周期计算。
- 判定用模块总量，不用专用节点分别判定。额度小于等于 0 视为未配置容量，不进入判断。用量查失败不能当成 0，也不能因此解除或进入观察期。
- 权限在返回前过滤，不改角色勾选，不把滤完的结果写入权限缓存。操作名以 Add 或 Edit 开头的去掉，Setting 也去掉；View、Delete、Execute 保留。超管的全量菜单同样过滤。原因：产品要求权限列表里不再出现 modify 和 add，且超管不能绕过。
- 写接口超额拦截走独立的 `LicenseCapacityGuardMiddleware`，清单是 `LICENSE_CAPACITY_WRITE_PERMISSIONS`，不复用 `LicenseCreateGuardMiddleware`。超管不例外。未列入的路径不拦，删除、查询和采集写入不列入。`HasPermission` 超管仍放行。原因：过期与超额分开；清单可后补，避免改装饰器。
- 菜单和写接口拦截可用 `LICENSE_CAPACITY_RESTRICT_DISABLED=true` 关掉，避免上线后无法回退。变量不存在，或值不是 `true`，超额限制照常生效。设为 `true` 后仍计算并在许可页和顶栏展示容量状态，只是不再过滤权限列表，也不在中间件拒绝写操作。原因：拦截挂在中间件和权限返回路径上，需要一个语义单一的紧急开关。
- 日志角色菜单里，Operate 只出现在事件下的告警，表示处理告警，已限制时保留。采集相关的新增和修改已经拆成 Add、Edit、Setting，与 CMDB 一样从返回列表去掉；Delete 保留。原因：权限矩阵本身已经把删除和修改分开，不需要再为日志保留一个共用的 Operate。
- 监控停用不单独放开。用户主动把数量降下来靠删除。用量统计仍只计未删除且已启用的实例，发现对账把实例标成停用后，下一次计算自然不再计入。
- 日志用量下降靠扩容，或 VictoriaLogs 保留期让磁盘自己下降。日志中心不提供手动删除已入库日志。
- 顶栏许可提醒只在壳层挂载时请求一次 banner。导入或停用许可后后端会立刻重算，许可页会重新拉列表和摘要，但已挂载的顶栏不自动刷新；要看最新提醒需整页刷新。原因：与 WeOps 把提醒挂在登录信息、进系统时取一次的做法一致，这次不补推送或轮询。

## 明确后置

- 告警的容量对象和用量接口。
- 作业平台单次任务目标数上限。
- 在采集和自动纳管链路上拒绝新的收费实例。
- 按专用 key 分别判定超额。
- 日志保留期配置和手动删除已入库日志。
- 导入或停用许可后顶栏许可提醒自动刷新。
- 容量超额的渠道通知：进入观察期、观察期剩余 7 天、进入已限制、解除各发一次。顶栏展示和现有到期、节点、日志阈值提醒保持不动。

## 决策来源

- 需求 p398_786「许可管理 / 超额处理」，其中第 5 条要求不停止已有采集、接入和处理，不丢数据，不因许可自动删除已有数据。
- 产品说明：超额满 30 天后过滤该模块新增和修改权限；删除使数量下降后按计算周期恢复，不要求当场生效。
- 产品说明：时间超额保持现状，本次只补容量超额；过滤的是权限中心返回的 Add、Edit 这类操作。
