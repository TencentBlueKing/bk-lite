# 运营分析统一筛选产品决策记忆

- 最近更新：2026-08-20
- 当前规格：`specs/changes/ops-analysis-unified-filter-string-list/spec.md`

## 产品定位

运营分析是可视化与配置层。画布级对象选择（主机、机房、业务等）走统一筛选；单张卡片自己换口径走组件内切换。取数和下拉选项都下沉到数据源，运营分析不在前端拼多组件聚合。

## 已确认范围

- 扩展统一筛选，新增可绑定类型 `stringList`。
- 下拉选项源可自定义：静态或动态数据源（与机房列表同一模式）。
- 选中值按数组传给所有已绑定组件；单选是长度为 1 的列表。
- 空选择省略参数，不传空数组表示「全量」。
- 仪表盘、大屏、报表等已有统一筛选栏的画布共用这套语义。

## 已确认设计决策

- 不新增场景控制器组件，不把 `componentSwitch` 升成全页控制器。原因：统一筛选已经按「同 key 传给多组件」建模；组件内切换只服务单卡，硬提升会导致多卡状态分叉。
- 列表从一开始就是一等契约，不用标量单选以后再改数据源。原因：主机等多对象场景会卡住传参形状；长度为 1 的数组可以同时覆盖单选。
- 禁止逗号拼接 ID。原因：权限、解析和类型匹配都会变脆。
- `string` 与 `stringList` 不能互相绑定。需要标量的接口继续用 `string`。
- Top10 换指标、3D 机房换当前机房继续用 `componentSwitch`。只有第二张卡需要同一对象时，才把该参数提成统一筛选。
- 主机查询数据源共用 `instance_ids`。趋势按主机出线；网卡求和、磁盘使用/IO/延迟取最大、读写速率求和。不做健康/异常主机数。

## 明确后置

- 筛选方案收藏、级联下拉、图表钻取。
- 跨仪表盘共享筛选状态。

- 把 3D 机房下拉从组件内切换迁到统一筛选。

## 仍待确认

无。健康主机口径已明确不做。趋势第二维度与子维度收口已按「一主机一线」确认。

## 已替代决策

无。评估阶段考虑过的三条路中，组件内切换升全页、独立场景控制器均未采纳。

## 决策来源

- 用户于 2026-08-20 确认：按统一筛选扩展；值按列表传参；选项源可自定义；可传给多个组件；健康指标不做，其余主机取数继续。
- 对照实现：3D 机房 `componentSwitch` + `cmdb/get_room_list` 动态选项；统一筛选现仅绑定标量类型。
