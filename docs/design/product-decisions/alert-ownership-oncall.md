# 告警归属与值班产品决策记忆

- 最近更新：2026-08-26
- 当前规格：`specs/changes/alert-ownership-oncall-split/spec.md`

## 产品定位

告警中心同时服务「按组织看自己的资产告警」和「共享值班处理别人组织的告警」。归属组织是数据隔离根；处理人是值班队列根。二者不合并成一个 `team` 语义。

## 已确认范围

- 组织列表、趋势：都按当前页面可见集合。未勾「我的告警」时是「当前组织 ∪ 处理人是我」；勾了则只统计处理人是我的单。
- 「我的告警」按当前处理人跨组织汇总，并允许详情、认领、转派、关闭。
- 手动分派、转派、自动分派、升级都可把处理人指定为租户内任意有效用户。
- 转派替换处理人（交班）；升级并入处理人（加签）。

## 已确认设计决策

- `Alert.team` 表示数据归属，分派不改写归属，也不扩大 Action / 作业目标范围。
- 默认告警列表 = 当前组织归属 ∪ 当前处理人；「我的告警」不再叠在当前组织过滤之上，只保留处理人是自己的单。
- 未分派告警只出现在归属组织列表，组织外的人不能通过「我的告警」抢单。
- 有效处理人 = 同租户、存在、未禁用；不再要求属于告警归属组织。
- 机器身份（OpenAPI 组织绑定、NATS 团队上下文）不按处理人补可见性。
- 本条告警的原始事件对当前处理人开放；邻近告警仍按归属组织裁剪。

## 明确后置

- Incident 协同人跨组织可见，以及事故操作是否要求负责人。
- 分派规则、屏蔽规则、未分派兜底通知的按组织隔离。
- 转派后仍可见但不能操作的观察者。
- 将 `Alert.team` 收成单一归属值。

## 仍待确认

无。

## 已替代决策

- 「组织列表只看归属、不被处理人身份污染」：2026-08-26 起默认列表改为「当前组织 ∪ 处理人是我」；同日稍后页面趋势改为与当前列表同一套过滤，不再单独 `org_only`。
- 「手动分派 / 转派处理人必须属于 Alert.team」：2026-08-26 起仅适用于组织列表可见性，不再作为处理人写入条件。自动分派组织目标旁路不再是特例，而是值班模型的一部分。
- 「我的告警 = 当前组织列表再筛 operator」：2026-08-26 起改为跨组织处理人入口。

## 决策来源

- 2026-08-26 告警中心组织与用户约束评审：选定模型 B，确认「我的告警」跨组织、全路径可跨组织分派、转派交班 / 升级加签。
