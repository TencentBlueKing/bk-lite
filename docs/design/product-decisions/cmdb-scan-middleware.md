# CMDB 扫描中间件产品决策记忆

- 最近更新：2026-09-18
- 当前规格：`specs/changes/cmdb-scan-middleware/spec.md`

## 产品定位

中间件扫描是网段上的 JOB 发现：用与专业采集相同的发现脚本找出进程，写入 CMDB 并生成持续采集。它不是监控接入，也不用 URL / Exporter 当发现手段。

## 已确认范围

- 扫描任务增加「中间件」族；运行时拆成 nginx / tomcat / kafka / zookeeper / rabbitmq / consul / etcd。
- 复用现有 Stargazer `*_info` 脚本，不新写发现器。
- 凭据可空：空则 Agent，填写则 SSH；与专业采集一致，无单独模式单选。
- 写 CI、按同通道生成采集；监控第一期不自动建采。

## 已确认设计决策

- 发现凭据（SSH / Agent）与监控凭据（URL / Manager / Exporter）分离；扫描不得用前者创建后者。
- 主机与中间件共用一份 SSH；都空则都走 Agent。
- Agent 仍扫网段，按 IP + 云区域匹配已纳管节点；未装 Agent 的地址不进清单。
- 清单按模型 + IP + 监听端口落行；登录成功但无进程不进清单。
- 只扫中间件时不新建主机；`run host` 仅在同 IP 主机已存在时挂上。
- 表单、云区域、清单凭据列、推监控禁用四处必须有提示。
- 主机族展示名不再叫「主机 SSH」。

## 明确后置

- 中间件类型子勾选
- 端口探测作为发现本体
- 自动猜测监控 URL 并建 Telegraf
- Redis / Mongo / ES 以及 Beta 中间件
- Agent 改为只扫节点列表
- 新发现脚本

## 仍待确认

无。

## 已替代决策

- 2026-09-18 `cmdb-scan-discovery` 将中间件 JOB 列为扫描族范围外；本规格将其纳入第一期，发现走 SSH/Agent，监控建采仍后置。
- 2026-09-18 讨论中一度考虑「只勾中间件且 SSH 时也不要云区域、Agent 也不要」；已改为：Agent 必须有云区域。

## 决策来源

- 用户于 2026-09-18 确认：监控可停在已发现未建采；复用现有发现脚本；空凭据走 Agent；表单必须加提示。
