# APM 服务拓扑产品决策记忆

- 最近更新：2026-09-01
- 当前规格：`specs/changes/apm-topology-ops-followup/spec.md`、`specs/changes/apm-topology-request-slice/spec.md`、`specs/changes/apm-user-request-entry/spec.md`

## 产品定位

服务拓扑是从观测 Trace 聚合出的服务调用图，也是停在图上的排查入口。它可以按请求切片后重画，从而回答「这类请求怎么走」。它不是 CMDB 架构图，也不等同于告警状态视图。

## 已确认范围

- 节点叠服务级 RED（吞吐、错误率、P95）；健康度按错误率分档。
- 点选节点/边打开右侧调查栏：上下游、最多 5 条样本 Trace、深链到服务详情或调用链。
- Isolate 一跳、悬停高亮、服务名过滤、滚轮缩放与拖拽平移。
- 服务拓扑可按耗时下限切片后重画；不再提供「仅错误请求」和操作名切片。边带真实 P95/错误数。
- 点边后的样本 Trace 必须同时包含 caller 与 callee。
- 未插桩下游只出现在应用详情画布上本应用已插桩服务的直接下游；全局服务拓扑不展示推断节点。不进目录。见 `apm-inferred-downstream.md`。

## 已确认设计决策

- 拓扑健康度只表示错误率，不是告警级别：`>=5%` 严重、`>=1%` 警告、有样本且更低为正常、无样本/查询失败为未知。
- 拓扑窗口最长 7 天；组织内最多 30 个拓扑目标。
- 单个节点或单条 Trace 聚合失败不得让整张图失败。
- 点选停在图上，不直接跳走。
- 「只看异常」只保留 `error_calls > 0` 的调用及其两端服务，隐藏正常下游边；不重新取数。
- 插桩服务卡片异常数 = 出站边异常数之和，避免整条 Trace 冒泡导致多服务重复计数。有异常的连线为红色，无异常为灰色。
- 服务拓扑摘要为「X 服务 / X 异常 / X 调用」；异常服务指出站异常数 > 0 的插桩服务。
- 拓扑布局不得为塞进视口而缩小到卡片重叠；看全图靠平移和缩放。
- 请求切片只复用调用链探索已有字段（`min_duration_ms` / `environment`），不开放任意属性或用户粘贴 TraceQL。服务拓扑不再暴露 status / span_name 控件。
- 图、节点指标、边指标和样本 Trace 共用同一有界 Trace 样本（上限 200）；有切片时不再叠未过滤的服务级 RED。拓扑是调查图，不是时间窗全量流量图；全量 RED 在服务列表/详情。
- 取样分层（2026-08-28）：窗口 ≤15m 单片取最近；≤1h 按 15 分钟切片；≤1d 按小时切片；更长按天切片；跨片轮转合并到 200。使 15m/1h/1d/7d 覆盖不同时段，而不是一律取最新 200 条。天级切片的 ID 查询先取最近 5000 条 Span 再 `stats by (trace_id)`，避免对整天全量 Span 分组。截断黄条写「当前拓扑按最多 200 条 Trace 抽样聚合，指标不代表所选时间窗的全量流量」；摘要计数称为「服务调用」，表示样本里的跨服务跳数，不是 Trace 条数。
- 用户请求入口（2026-08-28）：应用详情拓扑查询时合成 `kind=user_request` 虚拟节点，表达「外部 HTTP/RPC 请求打进本应用」；判定为根 `server` Span、父 Span 不在本条 Trace、带 HTTP/RPC 语义属性；每环境折叠一个节点，边指标来自命中的根 SERVER Span。入口画成胶囊源节点（单行标签+请求总数，无健康点），不套服务卡片；P95/错误只在入口边上。只挂应用详情拓扑，全局服务拓扑不展示——入口相对应用边界才有意义，全局挂总入口会把多个应用流量拧成假根。不改探针 / Collector，不进服务目录。它与「推断下游」方向相反（上游触发源 vs 未插桩下游），不共用 `kind`。见 `specs/changes/apm-user-request-entry/spec.md`。
- 应用详情画布上的推断下游（2026-08-28）：应用拓扑要讲完整请求路径，因此展示本应用已插桩服务的**直接**推断下游。不进下属服务表、关键信息 KPI、应用卡片或服务目录。一跳邻居（其它应用服务）自己的推断下游不进入本应用图。应用详情仍无调查栏，点选不进服务详情。

## 明确后置

- 任意 span 属性、用户、高基数字段过滤。
- Gateway/Sidecar 折叠、Entry Service（全局服务拓扑上的入口服务标记；应用详情的用户请求节点已另行确认，见上）。
- 全局服务拓扑展示用户请求节点；消息消费 / 定时任务等非用户触发源入口；应用详情拓扑调查栏与用户请求节点点选下钻；按路由 / 客户端拆分入口节点。
- 自定义时间范围、60 天窗口、提高 30 个目标上限。
- 独立拓扑指标流水线 / VictoriaMetrics rollup（Datadog 式预聚合流量图）。

## 已替代决策

- 「点击拓扑节点直接进入服务详情」：2026-08-26 改为先打开调查栏，再由用户选择服务详情或调用链。
- 「未插桩下游出现在全局服务拓扑」：2026-09-01 改为只在应用详情画布呈现，全局服务拓扑不再请求推断节点。
- 「只看异常按节点健康度过滤，且与仅错误请求切片并存」：2026-09-01 改为只看异常按失败调用裁边；服务拓扑移除仅错误请求和操作名控件。
- 「节点异常来自该服务入口 Span」：2026-09-01 改为只统计出站下游调用失败，叶子服务自身 Server Span 失败不记在卡片上。
- 「边标签展示调用数、平均耗时和错误数」：2026-08-26 改为只展示调用量，因为当时依赖接口没有边级时延和错误。
- 「依赖边继续来自 VictoriaTraces Jaeger `dependencies`」：2026-08-26 调查闭环切片内有效；按请求切片切片改为从有界 Trace 样本聚合跨服务父子关系，以便过滤后重画并计算边级 P95/错误。
- 「无切片时节点 RED 来自服务级 overlay、边只有调用量」：2026-08-26 起改为与切片共用同一聚合路径。

## 决策来源

- 2026-08-26 用户确认走调查闭环（方案 A），后置按请求切片与边级时延。
- 2026-08-26 方案 A 在本机 demo Trace 上走通后，用户确认继续下一刀：按请求切片重画拓扑，并一并给出边级 P95/错误。
- 2026-09-01 用户确认：服务列表批量调整组织/归档；服务拓扑加大图标、禁止重叠、去掉推断节点、摘要三项、去掉仅错误请求和操作输入；只看异常只留失败调用；卡片与连线异常数按出站下游对齐，连线有异常才为红。
- 2026-08-28 用户对照竞品「入口」节点提出用户请求触发源诉求，确认：只做用户 HTTP/RPC 请求（消息/定时后置）；只挂应用详情拓扑，全局服务拓扑不加；与推断下游是两个功能（上游触发源 vs 下游依赖发现），复用「查询时合成虚拟节点」模式但判定与 `kind` 独立。随后确认应用详情拓扑也要画本应用的直接推断下游，否则请求路径不完整。
- 2026-08-28 用户确认拓扑保持有界 Trace 样本调查图，不做独立指标流水线；15m/1h/1d/7d 用分层切片取样拉开覆盖，文案改为样本语义。
- Honeycomb Service Map 作为能力对照，不是目标架构。`apm-mvp` 禁止用户透传 TraceQL。
