# 被动接收日志提取器产品决策记忆

- 最近更新：2026-08-26
- 当前规格：`specs/changes/log-extractor-passive-collect/spec.md`

## 产品定位

syslog、snmptrap 是无采集实例的被动接收日志。它们也需要提取器，但规则不能绑定 `CollectInstance`。搜索页可以从一条具体日志创建提取器，并按类型跳到对应作用域。

## 已确认范围

- 在 syslog / snmptrap 接入详情左侧增加「提取器」页，表格交互与现有实例提取器一致。
- 规则按采集类型全局生效：全部 syslog 一套、全部 snmptrap 一套。
- 需要按主机或来源区分时，使用已有结构化条件（如 `hostname`、`source_ip`、`node_ip`），不为来源自动创建实例。
- 执行端仍是中心系统 Vector；不改 fusion-collector / 采集侧 Vector。
- 日志搜索页对**当前选中的一条日志**提供「创建提取器」：syslog / snmptrap 跳到类型级创建页；其他采集类型跳到该日志所属采集实例的提取器创建。

## 已确认设计决策

- 不为 syslog / snmptrap 补虚拟采集实例，也不把采集侧写死的 `instance_id = "base"` 当成业务对象。原因：这两类日志没有用户创建的实例身份；假实例会污染「日志接收」列表、权限和删除路径。
- 规则归属采集类型，`collect_instance` 为空。这是第一版提取器为「没有实例身份的日志」预留的数据演进，不是旁路。
- 不按来源 IP/主机拆多套规则包。原因：被动接收是一条共享管道；类型级规则加条件即可覆盖当前闭环。
- 类型级提取器不按实例、不按设备、不按个人授权。能进入日志集成、当前团队对该页有编辑权限的人可以新建/修改/删除/调序/重试；有查看权限的人可以看规则、样本和预览。原因：这两类没有可挂靠的采集实例；能配接入页的人就是管这条共享管道的人。无 `current_team` 时 fail closed。不新建权限模块。
- 搜索页创建提取器只针对当前这一条日志，用该事件做预览样本，不从选中文本反推正则。分流以 `collect_type` 为准：`syslog` / `snmp_trap` 永远走类型级页，即使事件上带有 `instance_id = "base"`。其余类型用事件上的 `instance_id` 打开实例提取器；没有实例身份则不能创建。

## 明确后置

- 按主机或接收节点拆分规则包。
- 搜索页选中文本反推正则 / Grok。
- 历史日志重新提取。
- 为实例提取器新增独立路由页（第一版从搜索跳到「日志接收」并打开现有抽屉即可）。

## 已替代决策

- 2026-08-26：第一版提取器「不允许创建无实例规则」对 syslog / snmptrap 不再成立。实例绑定提取器对其余采集类型仍然有效。
- 2026-08-26：第一版「不得从日志搜索页反向新建」改为允许「从当前这条日志跳转创建」；仍禁止选中文本生成规则。该跳转覆盖类型级与实例级。

## 决策来源

- 需求：【日志系统】syslog、snmptrap 日志提取器能力。
- 用户确认：这两类不能绑定实例，提取器按采集类型全局生效。
- 用户确认：有页面权限即可；能进日志集成、当前团队有编辑权限的人就能改这两类提取器。
- 用户确认：搜索页选中某条日志创建提取器；syslog / snmptrap 跳类型级创建页，其他类型跳该日志所属实例的提取器创建。
