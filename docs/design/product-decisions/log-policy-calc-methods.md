# 日志策略计算方式产品决策记忆

- 最近更新：2026-10-29
- 当前规格：`specs/changes/log-policy-scenario-fit/spec.md`（implemented，2026-10-29）；阈值阶梯 `specs/changes/log-policy-level-ladder/spec.md`（implemented，2026-10-29）；计算方式第二批 `specs/changes/log-policy-calc-catalog/spec.md`（implemented，2026-10-27）；第一批 `specs/changes/log-policy-calc-methods/spec.md`（implemented）

## 产品定位

日志聚合策略的条件从「本窗聚合值比固定阈值」扩展为「函数 × 比较方式 × 对照」，覆盖竞品（Datadog、Elastic、Loki、Splunk、SLS）日志告警里客户实际会配的场景：突增、占比、影响面、同比、分位、抖动抑制。能力用命名函数和下拉表达，不做公式编辑器。整段查询断流用未分组的 `count < 1`，不做策略级无数据开关。
两类策略语义不同：关键字是「出现即告警」的事件型，抑噪旋钮是「本窗命中 ≥ N 条」，告警人工关闭；聚合是「一个数比阈值」的指标型，可配「连续 N 个周期不满足则自动恢复」。

## 已确认范围

- 第一批（已落地）：`count_rate`（条/秒）、变化量、只读试算端点、聚合样本 ≤10、回跳查询冻结、通知带命中数 / 样本 / 检索链接。
- 第二批（已落地，2026-10-27）：
  - 函数新增 `count_uniq`（去重计数）、`quantile`（P50/P90/P95/P99）、`ratio`（占比，分子为 LogsQL 过滤、分母为策略查询）、`bytes_rate`（字节/秒）。
  - 比较方式 `absolute / delta / percent`。对照是上一窗，或用户填写的 N 小时前 / N 天前（1..8760 小时，1..365 天）。固定的 1 小时 / 24 小时 / 7 天只作为旧值读入。适用于 `count / sum / avg / max / min / count_uniq / quantile`。
  - 规则级连续满足次数 `trigger_count` 1..5，无状态重查前 N−1 窗。
  - 策略级无数据告警已于 2026-10-28 撤回。断流用未分组 `count < 1`。
  - 试算、通知命中行、告警名称模板、详情页随契约扩展为逐条件展示。
- 阈值阶梯（已落地，2026-10-29）：同一个聚合数挂 warning / error / critical 三档阈值，一个分组只开一条告警并取最高档。关键字策略仍是单级别。
- 场景回归（approved，2026-10-29）：
  - 聚合策略 `rule.recover_after`（1..10，缺省不恢复）：同一分组连续 N 个检测窗不满足则告警进入 `recovered`，只推送告警中心生命周期事件；关键字策略维持人工关闭。
  - 关键字策略去掉 `trigger_count`，改为 `rule.min_hits`（本窗命中 ≥ N 条才告警，默认 1）。
  - 聚合运算符收口为 `> >= < <= = !=`；`in` / `nin` 只回显旧值。
  - 聚合告警 `Alert.value` 取第一条常规条件的算出值，不再恒为计数。
  - 「连续满足次数」保持无状态平移窗实现，文案改为「最近 N 个相邻周期都满足」；频率 / 周期提示改为日志措辞。

## 阈值阶梯

规格：`specs/changes/log-policy-level-ladder/spec.md`。

- 条件内 `thresholds: [{level, value}]`，1～3 档，运算符共用。级别只有 warning、error、critical。`value` 镜像最轻一档，供旧读法使用。
- 比较运算符 `>` `>=` `<` `<=` 才允许多档，并且必须按级别严格单调。`=` `!=` `in` `nin` 以及非数值比较只允许一档。
- `and` 时各条件启用的级别集合必须一致；`or` 不限制。聚合策略的 `alert_level` 由已启用档的最高级别推导，页底级别单选不再出现。关键字仍由用户选级别。
- 活动告警级别只升不降：本窗命中档高于当前告警级别时，覆盖告警级别并重置通知；降级保持告警级别、不重置通知。`Event.level` 始终写本窗真实命中档。
- 没有 `thresholds` 的旧条件，保存、扫描、通知、试算仍按策略 `alert_level` 单档处理。

明确不做：自动恢复、关键字多档、按级别路由通知、每一档单独的运算符、info 档。

## 已确认设计决策

- 条件模型为正交三元「函数 × 比较方式 × 对照」，`compare` / `params` 作为条件内可选字段，无新模型列、无迁移。原因：七个可比较函数乘三种比较方式不能再用函数枚举铺开；与监控 `compare_mode` 同一套词。
- 第一批的 `count_delta` 在读写两侧归一为 `count + delta + previous_window`，仍接受旧载荷。原因：已提交未发版，不构成对外契约破坏。
- 对照窗跑与本窗同一条聚合查询（只换起止），一次拿到所有函数的对照值；每个不同的对照时段查一次。
- `percent` 对照为 0 时无定义，该条件判 False、试算显示「对照为 0」；`delta` 对照缺分组：计数类记 0（可触发），均值 / 分位记缺失（不触发）。原因：没日志对计数是 0，对均值是「没有值」。
- `ratio` 用 VictoriaLogs 条件计数 `count() if (<filter>)` 在同一条查询里算，分母为 0 不触发；不另写分母查询。
- 对照查询失败：依赖它的条件判 False，不告警不通知，记有界 WARNING；不重试不阻塞。
- 日志不做策略级无数据开关。日志会自然空窗，开关默认关也容易被打开后持续误报；分组消失不是当前要保的能力。整段查询断流配未分组 `count < 1`。VictoriaLogs `stats` 在 0 条时返回一行 `count=0`，条件会计算。已保存的 `no_data` 忽略，不迁移。
- 连续次数无状态实现（重查前 N−1 窗），N ≤ 5 限住查询放大；任一平移窗失败本轮该策略全部分组不判（实现时按策略粒度而非分组粒度，原因：失败的是整条查询，不是某个分组）。
- 不做公式编辑器 / 任意 SQL / 自定义触发表达式。原因：表达式会让校验、试算、回跳、通知渲染全退化成字符串。
- `ratio` 分子筛选拒绝 `|`，并经检索同一套 `message → _msg` 映射后整体加括号拼接。
- 速率单位固定条/秒；`delta` 允许负阈值表示骤降。
- 样本上限 10；`limit` 默认 5；通知默认带截断样本与检索链接，不做策略级开关。
- 回跳查询由后端在事件产生时冻结；试算与保存同一授权；试算弹窗为 log app-local 组件。
- 2026-10-29：聚合策略自动恢复用 `Alert.info_event_count` 记连续不满足窗数，分组消失视为不满足，本轮查询失败既不计数也不清零；`recovered` 为终态，再触发新开告警。
  原因：聚合告警已是指标型（阶梯、同比、分位、只升不降），不恢复会让活跃列表越积越多；Datadog / Elastic / Grafana / SLS 对阈值型日志告警都自动恢复。恢复不走普通通知渠道，避免日志空窗抖动刷屏。
- 2026-10-29：关键字策略不走连续次数。原因：事件型告警要的抑噪是「本窗命中 ≥ N 条」，「连续 N 窗都出现」会吞掉偶发但严重的异常，且与「命中即告警」的定位相悖。
- 2026-10-29：速率单位维持「条/秒」，不改为「条/分钟」。已保存阈值与通知正文按条/秒记录，改单位需要迁移存量阈值，收益不抵成本。

## 已替代决策

- 2026-10-27 替代「用条件函数枚举而不是策略级计算方式字段」：改为条件内正交字段「函数 × 比较方式 × 对照」。原枚举思路在加入百分比与多对照后膨胀为二十余个组合。
- 2026-10-27 替代「对照固定上一等长窗，只做绝对差」：对照改为四档可选，比较方式加入变化率；「对照为 0 时百分比无定义」的顾虑通过「判 False 并在试算里展示」处理，`delta` 仍保留「缺分组记 0、新分组突增可响」。
- 2026-10-27 把「1h / 24h / 7d 环比、百分比、错误占比、无数据」从明确后置移入第二批范围。
- 2026-10-28 撤回策略级无数据告警。日志空窗是常态，分组消失先不做；断流交给未分组 `count < 1`。
- 2026-10-29 替代「日志告警仍由人工关闭，不引入恢复状态机」：聚合策略按 `recover_after` 自动恢复，关键字策略维持人工关闭。阈值阶梯规格里「级别只升不降」的理由（没有恢复状态机）随之由「有恢复、无滞回」接管：级别仍只升不降，恢复由连续不满足窗数判定。
- 2026-10-29 替代「关键字策略也校验 / 使用 `trigger_count`」：关键字改用 `min_hits`。
