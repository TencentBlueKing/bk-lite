# 日志策略计算方式产品决策记忆

- 最近更新：2026-10-27
- 当前规格：`specs/changes/log-policy-calc-methods/spec.md`

## 产品定位

日志聚合策略的条件函数从「本窗聚合值比固定阈值」扩展到「本窗速率」和「较上一等长窗的变化量」，并补齐保存前试算、聚合样本、命中窗口回跳三个闭环。关键字策略保持「命中即告警」。日志告警仍由人工关闭，不引入恢复状态机。

## 已确认范围

- 条件函数新增 `count_rate`（条/秒）、`count_delta`（本窗 count − 上一等长窗 count），可与现有函数用 `and / or` 组合。
- 新增只读试算端点，复用正式扫描判定，按分组返回数值与判定；不写告警、事件、快照、游标，不发通知。
- 聚合触发分组取 ≤10 条样本；事件冻结回跳查询（原始查询 + 分组过滤 + 命中窗口）。
- 通知正文带命中条数、速率 / 变化量、检测窗口、≤10 条单行截断样本、检索链接；告警中心 payload 带结构化字段。

## 已确认设计决策

- 用条件函数枚举而不是策略级计算方式字段。原因：沿用「函数 + 字段 + 比较符 + 阈值」模型，可与 `count > N` 组合，无新模型列、旧策略零迁移。
- 对照固定上一等长窗，只做绝对差。原因：需求只要「比上一窗变了」；百分比在上一窗为 0 时无定义，会让新分组突增不触发。
- 上一窗该分组无行记 0（对照存在，可触发）；上一窗查询失败记缺对照，含变化量的条件本轮判 False，不告警、不通知，记有界 WARNING。原因：没日志是业务事实，查询失败是系统事实，不能混为一谈。
- 速率单位固定条/秒，阈值允许小数。
- `count_delta` 允许负阈值表示骤降。
- 样本上限 10；现有 `limit` 默认 5 不变，后端钳到 1..10；表单不新增样本条数字段。
- 通知默认带截断样本（每条取 message、≤200 字符）与检索链接；不做策略级开关。
- 回跳查询由后端在事件产生时冻结，前端不重写分组过滤转义；策略事后修改不影响旧告警的回跳。
- 试算与保存同一授权（组织可分配、日志分组数据范围、编辑时策略 `Operate`）。
- 试算弹窗为 log app-local 组件，不升 shared。

## 明确后置

- 1h / 24h / 7d 环比、百分比、倍数、近 N 周均值。
- 异常 / 突增检测、自动恢复。
- 错误占比。
- 留存不足探测。
- 通知样本的策略级开关；样本条数进表单。
