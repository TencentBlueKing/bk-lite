# 运营分析内置数据源可见性产品决策记忆

- 最近更新：2026-08-20
- 当前规格：`specs/changes/ops-analysis-builtin-datasource-org-visibility/spec.md`

## 产品定位

运营分析内置数据源是平台接口目录，不是组织私有资产。可见性与定义保护分开：内置只锁定定义，组织名单只控制谁能看到和选用。取数范围仍由下游按当前组织与权限过滤。

## 已确认范围

- 内置数据源允许所属组织为空；空 = 全员可见、可选用、可取数。
- 非空 = 组织白名单。
- 前端超管可改内置源的所属组织，其它字段只读。
- 自定义数据源继续必选组织。
- 存量仅为 Default 的内置名单清成空；已定制名单保留。

## 已确认设计决策

- 空名单语义只作用于内置数据源。原因：自定义源漏传空数组不能变成全平台目录。
- 改内置所属组织仅超管。原因：否则任意组织的数据源编辑权能把全员目录锁成自家。
- 超管在管理列表可见全部内置源；画布取数不给超管旁路。原因：收口后还要能改回来，但不能从错误组织把受限接口取出来。
- 不按组织枚举补名单，也不拆两套数据源对象。原因：空名单即可让新组织零维护；拆模型超过当前诉求。
- 目录收口不替代下游 NATS 鉴权，也不拦截同 path 自定义源。原因：组织白名单是产品控制，不是唯一安全边界。
- 初始化新建内置源写空名单，升级保留已有名单且不再把空名单补成 Default。原因：否则升级会打回全员可见或敏感收口。

## 明确后置

- 内置画布 / 目录同样做「空 = 全员可见」。
- 平台目录与组织数据源拆成两套对象。
- 敏感 NATS 在下游按组织强制拒绝（超出目录隐藏）。
- 组织管理员申请开通某个已收口内置源。

## 仍待确认

无。

## 已替代决策

- 2026-08-20 前：内置数据源与内置画布共用「新建写 Default、更新保留 `groups`」；有编辑权即可 PATCH 组织可见性。现仅内置画布/目录仍走该规则；内置数据源改为空 = 全员、仅超管可改名单。
- 评估阶段考虑过的「内置 NATS 永远全员可见、不能按组织隐藏」未采纳。原因：少数接口需要按组织收口。

## 决策来源

- 用户于 2026-08-20 确认：内置源组织可空且空 = 全员；前端只开放改组织；敏感源可收白名单；改名单仅超管；内置画布本期不做。
- 对照实现：数据源已允许内置只 PATCH `groups`，但初始化写 Default、列表/取数不认空名单、前端内置只能查看且组织必填。
