# 节点管理 Agent 状态筛选产品决策记忆

- 最近更新：2026-09-28
- 当前规格：`specs/changes/node-mgmt-agent-status-filter/spec.md`

## 产品定位

节点清单要把「看见 Sidecar / 组件状态」补成「按状态圈出来并跨页勾选后批量处置」。这一期是现有纳管闭环的筛选与勾选补强，不是导入导出中心。

## 已确认范围

- 在现有组合筛选中增加在线状态、组件状态，与现有条件 AND。
- 组件状态支持只选状态（任意组件命中）或再限定组件名。
- 勾选跨页保留；批量操作和系统/架构校验作用于全部已选节点。
- 改筛选、切换未归属、换云区域时清空已选。
- 能看列表就能筛；批量仍用现有动作权限。

## 已确认设计决策

- 在线状态与列表 Sidecar 列同一口径（60 秒心跳），不另做控制器「正常/异常/未安装」枚举。原因：现网列表展示的就是心跳，第三套枚举会和表格对不上。
- 组件状态与托管程序列同一口径：上报状态 + 未进入上报清单的安装任务叠加 + 列表已有的空跑错误改写。同一字段多选为 OR，与其他字段 AND。原因：筛出来的集合必须等于用户看见的集合；一个组件不可能同时处于两个互斥状态。
- 指定组件按展示名匹配，不按带操作系统后缀的内部 ID。原因：运维说的是 Telegraf，不是 `telegraf_linux`。
- 无组件或未安装指定组件的节点不命中组件状态条件；「未安装」不做筛选项。原因：本期目标是圈异常做启停，不是圈待安装集合。
- 过滤必须在服务端分页前完成。原因：页内过滤会漏检、也会让跨页勾选建立在错误集合上。
- 跨页勾选只保留用户逐页勾选的 ID，不做「一键全选筛选结果」。原因：全选容易误操作整库。
- 离线节点仍按最后上报的组件状态筛，结果上不标过期。原因：与当前列表展示一致，过期提示后置。

- 按「组件未安装」筛选。
- 快捷「运行不健康」OR 视图。
