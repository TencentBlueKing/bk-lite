# K8s 事件接入入口产品决策记忆

- 最近更新：2026-11-26
- 当前规格：`specs/changes/alert-k8s-cloud-region-ingress/spec.md`

## 产品定位

K8s 集群把事件交给它所在云区域的入口，再由现有区域代理转到这一套告警中心。操作员选择云区域，不填写控制台地址。

## 已确认范围

- 去掉手填服务地址，也不再用浏览器打开的控制台地址。
- 选择云区域后，上报地址只读展示。地址来自该区域 `NODE_SERVER_URL` 的协议、主机和端口，加上 K8s 告警源已配置的接收路径。
- 没有可用云区域，或所选区域的 `NODE_SERVER_URL` 缺失、不合法时，不能下载部署清单。提示写明 `NODE_SERVER_URL`。
- 集群名称和监控源保持两个字段。监控源默认 `k8s`，写入 `BK_LITE_PUSH_SOURCE_ID`。
- 安装命令的拉取地址使用同一区域入口。
- 已经应用的采集器保持原地址，直到重新下载并应用。

## 已确认设计决策

- 自定义云区域部署的是区域代理，不是第二套告警中心。代理上的 Traefik 已按 `PathPrefix(/)` 转到平台中心，不新增路由。
- 默认云区域的 `NODE_SERVER_URL` 就是中心地址。选它表示集群能直接访问中心。
- 云区域清单不过滤组织。新区域可以还没有节点，但代理已经可被集群访问。
- YAML 环境变量名保持 `BK_LITE_*`。页面文案不再把上报地址或跳过证书校验称为 BK-Lite。

## 明确后置

- 每个云区域单独部署告警中心。
- 重命名 `BK_LITE_*`。
- 把集群名称和监控源合成一个字段。
- 改 Zabbix 或 REST 的 webhook 主机。

## 仍待确认

无。

## 已替代决策

- 页面默认填入当前控制台地址，由操作员手改。替代原因：集群和操作员浏览器经常不在同一张网，这个地址不是集群能访问的入口。
