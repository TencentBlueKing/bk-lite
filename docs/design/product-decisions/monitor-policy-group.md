# 监控策略组产品决策记忆

- 最近更新：2026-10-26
- 当前规格：`specs/changes/monitor-policy-group/需求文档.md`

## 产品定位

策略组是一套告警规则的生效单位。用户把实例加入组，而不是逐条挑选模板再按实例复制策略。模板保留为单条规则的配方库。

## 已确认范围

- 接入页、实例页、策略组实例管理三处都可以加入或更换策略组，动作相同。
- 每个组织的每个监控对象至多一个默认策略组，只用于节点管理新建和 CMDB 首次对上。
- 旧策略和单独规则继续有效。停用在单策略列表关掉是否生效。实例页和策略组实例列表只展示是否仍在告警。

## 已确认设计决策

- 组内一条规则对应一条现有监控策略，策略的实例范围等于当前成员。不为每个成员复制策略，也不新做检测引擎。结论来自要复用现有告警、调度和通知。
- 规则从模板复制后与模板断开。改组不改模板，改模板不改已建成的组。
- 一台实例同时只属于一个策略组。换组是离开再加入。
- 关闭加入、退出、删除所属组，都记为不自动入组。第一次没有默认组或已有旧策略，记为未入组。这两类之后的同步都不再匹配。无记录不会被批量补进默认组，只有节点管理新建和 CMDB 首次对上可以自动加入。
- 退出、换组，或更换采集插件导致不再被某条规则覆盖时，该实例在原规则上尚未恢复的告警结束。
- 自动加入使用实例创建时的唯一组织。多个组织且没有明确选择时不猜测，记为未入组。接入页使用当前组织。
- 通知方式、通知人和处理人在策略组上设置一次，保存时写入该组当前全部规则对应的策略。存储仍在每条策略已有字段上，不另建通知或分派模型。只改这些字段不结束未恢复告警，也不改写已有告警的处理人，不发分派通知。处理人是之后新告警的默认分配人，候选人是该组所属组织内未禁用用户，可空、可多选。新建组不预填处理人或通知人，也不猜测通知方式；告警中心要作为选中的通知方式写到策略上才会推送。开启通知且需要通知人、通知人仍为空时，把已选处理人带入一次，用户删除后不补回。关闭通知不清处理人。生产主机和测试主机要发给不同的人时，分成两个策略组。
- 策略组按监控对象建。同一对象的多种采集插件放进同一个默认组，规则记住插件，只覆盖正在使用该插件的成员。改阈值也只影响这条规则当前覆盖的成员。
- 删除策略组时，组内每条规则对应的监控策略一并清理，不再回到策略列表。
- 事件下四个入口依次为告警、策略组、单策略、策略模板。单策略是不在组里的策略，一条仍可覆盖多台实例。单策略列表保留新建。实例页不新建单策略。模板页只从模板创建策略组，不把模板批量生成按实例复制的策略。
- 策略组的检测配置分两层。组级设置检测频率和无数据告警，保存时写入组内策略：频率写到每条规则，无数据只写到每个插件的一条承载规则。规则修改是独立页面，复用单策略编辑：可改规则名称、告警名称、定义指标和告警条件（阈值、连续周期、恢复、同比环比、容量预测、数据窗口）。组织、实例范围、检测频率、无数据、通知和处理人在页上只读，保存不写这些字段。改指标、算法、阈值或连续周期会结束这条规则上尚未恢复的告警；只改名称不会。入口只在策略组规则列表。
- 无数据承载规则按插件派生，不另存字段：优先取分组恰好是实例的规则里 id 最小的一条；该插件没有实例级规则时取 id 最小的一条。一台成员停止上报时，每个插件只产生一条无数据告警。子维度指标（磁盘、网卡）若各自打开无数据，一台主机会按维度拆出多条基准、也就多条告警，所以无数据不写进全部规则。关闭无数据后，承载规则上尚未恢复的无数据告警结束，基准清空。只改窗口、级别、名称或恢复窗不结束已有无数据告警，也不重建基准。
- 改阈值、连续触发周期、连续恢复周期或恢复阈值后，这条规则上尚未恢复的告警结束。只改告警名称不结束正在响的告警，之后的新告警使用新名称。
- 接入页选择策略组后不列出组内全部规则。本次插件的规则都有对应指标时，选择框下不额外展示。没有对应指标的规则标明这次没有数据。这组没有本次插件的规则时，说明加入后不会按这个组告警。其他插件的规则不在接入页出现。
- 告警详情仍显示策略名称。组内规则在名称旁标「组策略」，编辑置灰。单策略和旧策略仍可从告警详情进入策略编辑。
- 策略组列表可以整组生效或停用。停用停止组内全部规则的扫描，并结束这些规则上尚未恢复的告警；成员仍留在组里。再次生效从当前时间继续扫描，不补历史告警。默认组停用后，新实例仍会加入，但在重新生效前不会告警。
- 指标自动发现的新实例不自动加入策略组。

## 明确后置

- 子对象规则铺开、接入时挑选指标子集、自动收编或停用旧策略、某一条规则单独改通知或处理人、插件升级后合并新内置规则。单独改某一条时，改的是那条策略上的同一组字段；在那之前，组上再次保存会覆盖组内全部规则。
- 把组内规则另存为模板、在成员列表展示如何加入、在实例页新建单策略。

## 仍待确认

无

## 已替代决策

- 接入时逐条选择策略模板、填写名称前缀并决定是否推送告警中心，不再作为新实例的默认路径。
- 「改模板会同步到已下发策略」不适用于策略组规则。
- 2026-10-10 起，不再把通知人和处理人放在每条规则上单独填写，也不把组级统一通知人继续后置。通知方式和通知人改在策略组上设置，并写入组内每条策略。
- 2026-10-10 起，不再要求单策略页取消空白新建，也不再把单独规则的唯一新建入口放在实例页。单独规则不再限定为只挂一台实例。组内规则不另存为模板。
- 2026-10-22 起，不再把「组内只修改规则阈值、无数据等条件保持模板值、在组里修改无数据等条件后置」作为当前决策。检测频率和无数据在策略组上设置；连续周期、恢复阈值和告警名称在规则上设置。无数据按插件写入承载规则，避免子维度指标把一次中断报成多条。

## 决策来源

2026-10-08 对策略组规格和交互原型的审查，并确认策略组按对象建且规则按插件生效。2026-10-10 确认通知方式和通知人按组设置、写入每条策略，并确认策略组可以整组生效或停用。同日确认文档向现有产品对齐：单策略列表保留新建和是否生效，实例页与策略组实例列表只展示旧策略是否仍在告警。2026-10-20 确认处理人与通知放在策略组同一处，写入每条策略的 `handlers`，只作为之后新告警的默认处理人。2026-10-22 确认检测配置分层：组级频率与无数据、规则级连续周期和告警名称，无数据按插件写入承载规则。2026-10-26 确认规则修改改为独立页面，复用单策略编辑里的定义指标和告警条件；组织、实例范围、频率、无数据、通知和处理人仍只在策略组上改。需求见 `specs/changes/monitor-policy-group/需求文档.md` 与 `specs/changes/monitor-policy-group-detection-config/spec.md`。
