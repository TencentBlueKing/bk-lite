# CMDB 服务树产品决策记忆

- 最近更新：2026-09-16
- 当前规格：`specs/changes/cmdb-service-tree/spec.md`
- 展示稿：`docs/design/product-decisions/cmdb-service-tree-preview.html`

## 产品定位

服务树是应用系统下的组织/挂载主线，用来选节点、分配主机和按路径导入。它不是五带应用拓扑，也不把 CMDB 收成蓝鲸那种「主机只能进一个模块」的硬树。

## 已确认范围

- 应用系统详情新增「服务树」，与「应用拓扑」并列。
- 内置「业务分组」，可自嵌套 1–2 层；应用可直挂系统或挂在分组下。
- 左树右表：左树到应用为止，主机只出现在右侧列表。
- 分配、转移、解除挂靠、按路径导入导出。
- 第一期只覆盖 CMDB 与运营分析（含 3D 部署树和「系统下主机」）。

## 已确认设计决策

- 与应用拓扑拆开：服务树管组织挂载；应用拓扑继续做跳数展开的五带资源依赖图。CMDB 应用专题仍是应用拓扑。
- 组织脊柱是树：分组和应用都只有一个父。主机只挂应用，且可挂多个应用（沿用 `application_run_host` n:n）。
- 选中系统或分组只能看其下主机汇总、建子节点；右侧不展示子节点表。选中应用才能分配/转移/解除挂靠。切换节点时先清空主机再加载。默认只有「新建应用」。不展示「新建业务分组/应用分组」。用户在应用系统与应用之间加了自定义模型后，才出现「新建{模型名称}」。
- 添加只加边。转移、解除挂靠只作用于勾选的主机。写操作不重建带主机的整棵服务树。转移只拆当前选中应用上的边，目标可以是用户可见的任意应用（含其它系统）。解除挂靠只拆当前应用边，保留主机和其它挂靠。
- 树上可新建、重命名分组和应用；主机不在树上新建。分组有子则不能删。删应用保留主机资产。第一期不做拖拽改挂。
- 导入一行 = 已有主机 + 路径；缺分组/应用则创建，主机必须已存在。语义是分配。导出同一套列。
- 运营分析与 CMDB 服务树统一沿 `系统 → 业务分组* → 应用 → 主机`。其它模块仍走旧两跳，不改共用展开函数语义。

## 明确后置

- 专题视图默认改为服务树。
- 监控等其它模块跟新口径。
- 拖拽改挂、空闲机、在树上新建主机、自定义层类型。
