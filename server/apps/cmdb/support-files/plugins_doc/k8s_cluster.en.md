### Overview
Collects core Kubernetes cluster objects (nodes, namespaces, workloads, Pods) and syncs them to CMDB in a standardized form.

> This plugin differs from others: **no username/password is required**. Data comes from the K8S collector deployed in the target cluster (kube-state-metrics + metric reporting). The collector reports metrics, which are then synced to CMDB.

### Entry Point and Execution Location
This plugin provides an in-page **guided onboarding wizard**. You do not need to write a deployment manifest by hand:

1. In the CMDB Web UI: go to "CMDB → Management → Auto Discovery → Collection → Professional Collection", select the **K8S Cluster** plugin, and enter the guided onboarding wizard.
2. The wizard generates an install command that includes a token. Copy and run that command in the target cluster (to deploy kube-state-metrics and the metric-reporting component).
3. After execution, the wizard automatically polls to verify that reporting succeeded; `cluster_name` is set by the wizard/deployment parameters and must match the selected cluster instance.

### Procedure
#### Step 1: Enter the wizard and run the install command
After selecting the K8S Cluster plugin, enter the guided onboarding wizard. Copy the token-bearing install command generated by the wizard and run it in the target cluster to deploy kube-state-metrics and the metric-reporting component. `cluster_name` is set by the wizard/deployment parameters.

#### Step 2: Wait for the wizard to verify reporting
After you run the install command, the wizard automatically polls to verify that metric reporting succeeded. Also confirm that the identifier of the selected CMDB K8S cluster instance matches `cluster_name` (`collector_cluster_id` is used to associate reported data).

#### Step 3: Verify results
- After saving and running, check the `Added / Updated / Deleted` summary in the task details. In CMDB you should be able to query nodes, namespaces, workloads, and Pod instances under that cluster.
- If the inventory is empty, the collector usually failed to report, the cluster identifier does not match the instance, or the ServiceAccount lacks permissions. Recollect after checking.

### Onboarding Notes
This plugin does not require username/password credentials. Key points:
- The onboarding command is generated by the in-page guided wizard (with a token). Copy and run it in the target cluster to deploy collection components; no hand-written deployment manifest is needed.
- Cluster identifier: `cluster_name` is set by the wizard/deployment parameters and must match the selected CMDB K8S cluster instance. `collector_cluster_id` is used to associate reported data.
- The collector must run inside the target cluster and be able to report metrics to the platform.

### Prerequisites / Permissions
1. A K8S collector (kube-state-metrics + metric reporting) is already deployed in the cluster and can access kube-state-metrics metrics.
2. The ServiceAccount used by the collector must have a corresponding ClusterRole with `get` / `list` / `watch` on the following resources:
   `pods`、`nodes`、`namespaces`、`deployments`、`daemonsets`、`statefulsets`、`jobs`、`cronjobs`、`replicasets`.

### Collected Data (Field Dictionary)
**Node (k8s_node)**

| Key | Description |
| :--- | :--- |
| name | Node name |
| ip_addr | Node IP |
| os_version | OS version |
| kernel_version | Kernel version |
| kubelet_version | Kubelet version |
| container_runtime_version | Container runtime version |
| pod_cidr | Node Pod CIDR |
| cpu | Total CPU |
| memory | Total memory |
| storage | Storage capacity |
| role | Node role |

**Pod (k8s_pod)**

| Key | Description |
| :--- | :--- |
| name | Pod name |
| ip_addr | Pod IP |
| namespace | Namespace |
| node | Scheduled node |
| created_by_kind | Upstream controller kind |
| created_by_name | Upstream controller name |
| limit_cpu | CPU Limit |
| limit_memory | Memory Limit |
| request_cpu | CPU Request |
| request_memory | Memory Request |

**Workload (k8s_workload)**

| Key | Description |
| :--- | :--- |
| name | Workload name |
| workload_type | Workload type (deployment / daemonset / statefulset / job / cronjob / replicaset) |
| replicas | Replica count |
| labels | Labels |

**Namespace (k8s_namespace)**

| Key | Description |
| :--- | :--- |
| name | Namespace name |

**Relationships**
- `namespace belong cluster`: Namespace belongs to the cluster.
- `node group cluster`: Node belongs to the cluster.
- `workload belong namespace`: Workload belongs to the namespace.
- `pod run node`: Pod runs on the node.
- `pod group workload`: Pod belongs to the workload.
