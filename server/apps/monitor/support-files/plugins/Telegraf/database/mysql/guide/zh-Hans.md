# MySQL 监控接入指南

本能力通过 Telegraf `inputs.mysql` 直连一个 MySQL 主机和端口，并按当前模板采集连接、查询、InnoDB、复制和缓存等统计。

## 前置要求

- 采集节点能够访问目标 MySQL 主机和实际端口。
- 准备可登录实例并读取全局状态、全局变量及模板所需统计的专用监控账号。
- 进程列表统计通常需要 `PROCESS`；复制统计通常需要 `REPLICATION CLIENT`。按实际启用的数据遵循最小权限原则。
- 当前模板固定 `tls=false`，页面没有 TLS、数据库名或自定义连接参数字段。
- 模板会采集进程列表、InnoDB、旧版复制状态、二进制日志、全局变量及表等待统计；不会采集用户统计或新版 replica 状态查询。

## 接入步骤

1. 从实际采集节点验证目标地址、账号和基本状态查询权限。
2. 填写用户名、密码、主机、实际端口和采集间隔（默认 `60` 秒）。
3. 在监控对象表格中选择节点，填写主机、端口、实例名称和可选分组。
4. 保存后等待至少一个采集周期。

## 接入前校验

`--password` 会交互式询问密码：

```bash
mysql --host db.example.com --port 3306 --user monitor --password --execute "SHOW GLOBAL STATUS LIKE 'Uptime';"
```

命令应成功返回 `Uptime`。如需复制数据，再用同一账号验证目标版本支持且账号有权执行相应复制状态查询。

## 页面字段说明

| 页面字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 用户名 | 是 | MySQL 监控账号。 |
| 密码 | 是 | 对应账号密码。 |
| 主机 | 是 | MySQL 主机名或 IP，不包含协议。 |
| 端口 | 是 | MySQL 实际监听端口。 |
| 间隔 | 是 | 采集周期，单位秒，默认 `60`。 |
| 节点 | 是 | 能够访问 MySQL 的采集节点。 |
| 实例名称 | 是 | 平台内展示的实例名称。 |
| 组 | 否 | 实例所属分组。 |

## 接入后验证

保存并等待一个采集周期后，在平台确认以下指标可查询：

- `mysql_uptime`
- `mysql_threads_connected`
- `mysql_queries_rate`
- `mysql_innodb_buffer_pool_pages_total`

## 常见问题

### 登录失败

- 核对账号允许从采集节点来源地址登录。
- 使用交互式密码提示复核，避免 shell 对特殊字符的解释造成误判。

### 只有部分数据

- 结合 Telegraf 日志确认是 `PROCESS`、复制还是 `performance_schema` 相关权限不足。
- 非复制实例没有复制状态数据属于正常情况。
- 当前模板使用旧版复制状态采集开关，不会自动切换到新版 replica 状态查询。

### 目标强制 TLS

- 当前模板固定禁用 TLS，页面没有证书或 TLS 模式字段；强制 TLS 的目标不能用此配置直接接入。
