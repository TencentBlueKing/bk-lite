# ZooKeeper 监控接入指南

本能力通过 Telegraf `inputs.zookeeper` 向一个 ZooKeeper 客户端地址发送 `mntr` 四字命令。

## 前置要求

- 采集节点能够访问目标 ZooKeeper 的一个 `host:port`。
- 服务端必须明确允许 `mntr`；若配置了 `4lw.commands.whitelist`，需包含 `mntr`。
- 当前页面只接收一个服务器地址，模板也只从该值生成一个 `servers` 条目。
- 当前页面和模板没有认证字段；要求认证会话的目标无法用当前配置直接接入。

## 接入步骤

1. 从实际采集节点验证目标地址能够执行 `mntr`。
2. 填写单个服务器地址、超时时间（默认 `10` 秒）和采集间隔（默认 `60` 秒）。
3. 在监控对象表格中选择节点，填写同一服务器地址、实例名称和可选分组。
4. 保存后等待至少一个采集周期。

## 接入前校验

```bash
printf 'mntr\n' | nc -w 10 zk.example.com 2181
```

响应应包含多行 `zk_` 开头的键值。若返回四字命令未在白名单中，应在 ZooKeeper 侧按安全策略启用 `mntr`。

## 页面字段说明

| 页面字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 服务器地址 | 是 | 单个 ZooKeeper 客户端地址，格式为 `host:port`。 |
| 超时时间 | 是 | 单次请求超时，单位秒，默认 `10`。 |
| 间隔 | 是 | 采集周期，单位秒，默认 `60`。 |
| 节点 | 是 | 能够访问该客户端地址的采集节点。 |
| 实例名称 | 是 | 平台内展示的实例名称。 |
| 组 | 否 | 实例所属分组。 |

## 接入后验证

保存并等待一个采集周期后，在平台确认以下指标可查询：

- `zookeeper_num_alive_connections`
- `zookeeper_outstanding_requests`
- `zookeeper_avg_latency`
- `zookeeper_znode_count`

## 常见问题

### `mntr` 无输出或被拒绝

- 核对 `4lw.commands.whitelist` 是否明确包含 `mntr`。
- 从实际采集节点验证网络与命令，不要只检查端口监听状态。

### 集群只有一个节点有数据

- 当前 UI 只配置一个服务器地址，不支持在同一实例填写多个服务器。
- 如需观察多个成员，应分别按当前产品模型创建监控对象。

### 目标要求认证会话

- 当前模板没有认证字段；需要认证会话的目标不在当前能力范围内。
