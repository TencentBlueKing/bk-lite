# 运营分析：3D 机房、3D 应用、网络状态拓扑、关联拓扑

本文说明这四个组件**依赖哪些本项目数据**、**在 CMDB / 监控中心要先配什么**、以及**在运营分析里怎么选用**。四个组件都不接外部 REST/Excel，数据全部来自本仓库的 CMDB 与监控中心。

内置数据源和大屏随 `batch_init`（含 `init_source_api_data`、`init_builtin_canvases`）写入。内置画布对组织可见，但常规用户不能直接改；要改设备列表或标题，请先复制一份再编辑。

## 1. 四个组件分别是什么

| 名称 | 选用入口 | 类型 | 可用画布 | 内置示例 |
| --- | --- | --- | --- | --- |
| **3D机房** | 添加组件 → **内置场景** | 场景组件，自拉 CMDB 机房列表与布局，不用选数据源 | **仅大屏** | 大屏「3D机房大屏」 |
| **3D应用** | 添加组件 → **内置场景** | 场景组件，自拉数据，不用选数据源 | **仅大屏** | 大屏「3D应用大屏」 |
| **网络状态拓扑** | 添加组件 → **内置场景** | 场景组件，自拉 CMDB 结构，前端叠监控 | 仪表盘、大屏 | 无默认内置大屏，需自行添加 |
| **关联拓扑** | 添加组件 → **内置场景** | 场景组件，按单个资产画邻居 | 仪表盘、大屏 | 无内置画布，需自行添加 |

报表不支持这四个组件。3D 应用仅大屏。

---

## 2. 公共前置

1. **模块**：已开通并有权限进入 **CMDB**、**运营分析**；要看告警叠色 / 健康态，还需开通 **监控中心**。
2. **身份**：实例一律用 CMDB 的 `inst_uuid`（UUIDv4），不要用数字图数据库 ID。
3. **权限**：组件按当前登录人裁剪。看不到的机房、设备、应用系统、主机不会出现在图上；无权圆心会直接失败，而不是画一张空图。
4. **监控绑定**：告警叠色、3D 应用健康、机柜设备红光晕都走 CMDB 实例上的 `monitor_id`。资产详情点「建立监控关联」；扫描 / 采集任务里可「推送到监控」。未绑定的节点是灰色「未知 / 未关联监控」，**不会**当成绿色正常。

可同步到监控的常见模型：`host`、`switch`、`router`、`firewall`、`loadbalance`、`physcial_server`，以及部分数据库 / 中间件模型。`k8s_cluster` 等模型没有这条同步入口。

## 3. 3D机房

展示**一个机房**的 3D 机柜网格、U 位占用和柜内设备。配置抽屉可钉一个默认机房，并选择机柜顶两行显示（位置码 / 机柜名称 / 机柜类型 / 机柜状态；默认位置码 + 类型，第二行可留空）。查看和分享时在组件内切换机房。
### 3.1 要准备的 CMDB 数据

按这条链配，缺一环就会空柜或整间房出不来：

```text
机房 server_room
  └─ 关联 run → 机柜 rack（位置 location、U 数 u_count、类型 datacenter_type）
        └─ 关联 contains → 设备（交换机 / 路由器 / 防火墙 / 负载均衡 / 物理服务器）
              └─ 设备填写 rack_u_start、u_size 才会画到柜内
```

**机房**

- 模型：`server_room`
- 入口：CMDB → 资产 → 选「机房」模型新建；或 **CMDB → 视图 → 机房机柜**

**机柜**

- 模型：`rack`
- 必须挂到某个机房上（`server_room --run--> rack`）
- **位置 `location`**：填 `A3` / `A03` 这种格式。字母是列（A 起），数字是行（1 起）。填错或留空的机柜**不会进 3D 场景**，接口会带提示「位置格式错误未展示」
- `u_count`：机柜总 U 数，决定柜体高度
- `datacenter_type`：计算 / 网络 / 存储等枚举，用于顶部类型名和图例；可不填
- `datacenter_state`：启用 / 停用，用于顶部状态名；可不填

推荐在 **机房机柜** 专题视图或机房实例的「关联关系 → 机房视图」里拖放机柜，位置会按俯视图写入，不必手填坐标。

**柜内设备**

可上架模型只有：

- `switch` 交换机
- `router` 路由器
- `firewall` 防火墙
- `loadbalance` 负载均衡
- `physcial_server` 物理服务器（模型 ID 拼写就是 `physcial_server`）

上架后必须写：

- `rack_u_start`：起始 U，从 **1** 起
- `u_size`：占几 U，至少 1

只挂了「机柜包含设备」、但没填 U 位的设备会计入「未上架」，3D 柜内看不到。主机 `host`、应用等模型不能上架。

**告警光晕（可选）**

设备实例上有 `monitor_id`，且监控中心对该实例有当前活跃告警（`critical` / `error` / `warning`，不含 `info`）时，设备内部会出红色警告光晕。未绑定监控显示「未关联监控」；绑定了但告警查不到显示「暂不可用」。

### 3.2 在运营分析里怎么配

1. 打开或新建一张**大屏**（仪表盘里没有 3D 机房）。
2. 添加组件 → **内置场景** → **3D机房**。
3. 可选：在配置抽屉钉一个默认机房；留空则进入后展示第一个可见机房。
4. 可选：选择机柜顶两行显示。查看和分享时可在组件内切换机房。默认机房当前不可见时，提示「默认机房不可用」。
5. 保存。内置「3D机房大屏」复制后即可直接换机房看。

### 3.3 常见空态

| 现象 | 原因 |
| --- | --- |
| 机房下拉是空的 | 当前用户看不到任何 `server_room` |
| 「暂无机柜布局数据」 | 该机房下没有位置合法的机柜 |
| 柜是空的 | 设备未 `contains` 到机柜，或没填 `rack_u_start` / `u_size` |
| 提示若干机柜位置格式错误 | `location` 不是 `A3` / `A03` |
| 设备没有红光晕 | 未建立监控关联，或监控里没有活跃告警 |

## 4. 3D应用

以 3D 应用墙展示当前用户可见的**全部应用系统**健康态。墙卡颜色按当前用户看得见、且监控实例读得了的主机聚合。点进一张卡片可看详情或「部署架构」（系统 → 应用 → 主机）。**不用勾选系统列表**，墙成员随权限自动变化。分享大屏与分享人权限同一套。

### 4.1 要准备的 CMDB 数据

健康口径只认这一条精确关联，不会沿任意关系乱爬：

```text
应用系统 system
  └─ system_contains_application → 应用 application
        └─ application_run_host → 主机 host
              └─ host.monitor_id → 监控中心活跃告警
```

在应用系统实例上维护这棵树：

**CMDB → 资产 → 应用系统 → 点进某条 → 关联关系 → 服务树**

左侧是系统 / 应用树。选中系统可「新建应用」；选中应用后才能「添加主机」。也可以在关联关系的「列表」里手工加 `contains` / `run` 关联，效果相同。

| 层级 | 模型 | 作用 |
| --- | --- | --- |
| 墙上的卡片 | `system`（应用系统） | 每张卡一张系统；零应用的系统也会上墙 |
| 中间层 | `application`（应用） | 必须经 `system_contains_application` 挂到系统下 |
| 健康来源 | `host`（主机） | 必须经 `application_run_host` 挂到应用下 |

**健康怎么算**

当前用户看不见的子应用、业务分组、主机会从这张墙和部署架构里省略，颜色只聚合剩下的可见成员。告警条数与监控告警列表同一套可见性。

- 没有可见子应用：灰色 **未知**（`no_application`）
- 有可见应用、没有合法主机：灰色 **未知**（`no_host`）
- 有可见主机，其中已接入且当前用户读得了监控的：只拿这些主机上的可见活跃告警上色
  - 当前没有可见告警：绿色 **运行正常**
  - 有可见告警：按最高级别上色，状态行写「严重告警 2」这类条数
- 可见主机未绑 `monitor_id`：留在部署架构里，灰柜灰名，点开浮层为「未接入监控」，条数是「—」
- 可见主机有 `monitor_id`、监控实例当前用户读不了：同样以灰柜留下，浮层为「监控不可读」，条数是「—」
- 可见主机都未接入、或监控都读不了：墙卡灰色 **未知**，状态行右侧写「监控覆盖 0/N」
- 部分接入：墙卡按已接入可读的那些主机上色；状态行右侧写「监控覆盖 m/n」（如 `监控覆盖 6/9`）
- 覆盖微标只出现在墙卡状态行右侧，条件是可见合法主机数大于 0，且已接入可读数小于可见主机数
- 子应用、业务分组芯片只按各自下面读得了的主机上色；底下没有可读主机时芯片为未知，其下灰柜仍在
- 详情展示可见告警列表；策略名、指标名为空时显示「—」。无可见子应用或无合法主机时，详情告警区为「告警数据暂不可用」。有可见主机但零可读时，详情是空的可见告警列表

主机要先成为 CMDB `host` 实例（自动发现「主机」插件，或手工录入），再在监控中心采集性能指标并产生告警。CMDB 主机采集只同步清单，不产生 CPU / 内存这类监控告警。

查看态可用「应用系统运行状态」多选过滤墙成员，筛的是系统自己的 `status` 字段。

### 4.2 在运营分析里怎么配

1. 打开或新建一张**大屏**。
2. 添加组件 → **内置场景** → **3D应用**。
3. 只需填标题、外观；不要勾选应用、也不要绑数据源。
4. 保存后查看 / 分享即可点卡片。编辑态只预览，不能点进详情或部署架构。

内置「3D应用大屏」已放好该组件，有可见应用系统即可直接看。

### 4.3 常见空态

| 现象 | 原因 |
| --- | --- |
| 「暂无可见应用系统」 | 没有 `system` 实例，或当前用户对系统无查看权限 |
| 墙上全是灰卡 | 可见范围内没有已接入且监控可读的主机：没建 `system_contains_application` / `application_run_host`，主机未绑定监控，或监控实例当前用户读不了 |
| 墙卡有颜色，右侧有「监控覆盖 m/n」 | 可见主机里有一部分未接入或监控不可读；颜色只代表已接入可读的那些 |
| 部署架构只有系统没有应用 / 主机 | 关联方向或模型不对，或这些成员当前用户看不见；必须是系统包含应用、应用运行于主机 |
| 部署架构主机柜是灰的 | 该主机未接入监控，或监控实例当前用户读不了；点开浮层分别是「未接入监控」「监控不可读」 |
| 详情告警列表为空 | 当前可见且可读的主机上没有可见活跃告警 |
| 详情提示告警数据暂不可用 | 该系统当前没有可见子应用，或有应用但没有合法主机 |

## 5. 网络状态拓扑

按**勾选的网络设备闭集**画接口直连图，再叠监控中心活跃告警和接口流量。图上只出现你勾过的设备；没勾的对端不会自动扩进来。设备和设备之间没有 `interface --connect--> interface`，就只看到孤点、没有线。

### 5.1 要准备的 CMDB / 监控数据

**哪些模型算网络设备**

判定标准：该模型存在 `interface --belong--> 该模型` 的模型关联。内置的交换机、路由器、防火墙、负载均衡都满足。主机、应用不算网络设备，勾进去会保存失败。

**设备与接口**

1. **CMDB → 管理 → 自动发现 → 采集 → 专业采集 → 网络设备**
2. 接入点到设备 `161/UDP` 通，SNMP 只读凭据可用
3. 需要连线时，任务参数打开 **`has_network_topo`（拓扑发现）**
4. 采集完成后应能看到设备实例，以及其下的 `interface` 口；拓扑开启后会写入 `interface_connect_interface`

也可手工建设备和接口并加「关联」关系，但口名、对端要对得上，否则图上没线。

**告警叠色（节点颜色）**

组件会自动使用三个内置数据源（不用在组件里再选）：

- `CMDB 实例监控ID映射`（`cmdb/get_monitor_ids_by_inst_uuids`）
- `监控活跃告警`（`monitor/query_latest_active_alerts`）
- `监控接口最新指标`（`monitor/query_latest_interface_metrics`）

在资产详情「建立监控关联」，或采集任务「推送到监控」，并在监控中心对该设备做 SNMP / 接口采集后：

| 节点状态 | 含义 |
| --- | --- |
| 灰 / 未知 | 没有 `monitor_id` |
| 绿 / 正常 | 已监控，当前无活跃告警 |
| 黄 / 红 | 有警告或严重级活跃告警；角标是该监控实例的活跃告警数 |

**连线流量与断开叉（可选）**

叠色拿到 `monitor_id` 后，再按监控接口最新指标对口。CMDB 端口名会和监控 `ifDescr` 做规范化匹配（如 `GigabitEthernet` ↔ `Gi`）。对不上时端口显示「未匹配到监控接口」，不会编造流量。任一端运行状态为断开时，连线中点画红叉。

### 5.2 在运营分析里怎么配

1. 打开仪表盘或大屏。
2. 添加组件 → **内置场景** → **网络状态拓扑**。
3. **网络设备**：勾选要进图的交换机 / 路由器 / 防火墙等，可按模型筛选、跨页保留勾选。
4. **节点上限**：默认 100，最多 200；勾选数不能超过上限。
5. 可选：常驻入/出流量、流量阈值配色。
6. 保存。查看态可拖节点看清关系，但只有画布编辑态拖动的位置会随页面「保存」落库。布局分层级 / 力导 / 环形三套，互不影响；「重置布局」只清当前这一套。

### 5.3 常见空态

| 现象 | 原因 |
| --- | --- |
| 「请重新配置要展示的网络设备」 | 未勾选，或列表里有非网络设备 / 无效 UUID / 无权设备 |
| 「暂无支持网络拓扑的模型」 | 模型上没有 `interface --belong--> 设备` |
| 有点没线 | 未开拓扑发现，或两台设备之间没有接口直连，或对端没勾进闭集 |
| 全是灰点 | 设备未建立监控关联 |
| 有线但没有流量 / 红叉 | 监控未采接口指标，或口名与 `ifDescr` 对不上 |

## 6. 关联拓扑

以**一个资产实例**为圆心，画与资产详情「关联拓扑」同一套邻居（默认深度 3，含权限裁剪），再叠该邻居关联监控实例的当前活跃告警。任意 CMDB 模型都可以做圆心，不限网络设备。

告警中心活动告警详情里的「关联拓扑」Tab 是同一件能力：告警快照里要有非空 `cmdb_id`（CMDB 实例 UUID）。运营分析画布上则是自己选圆心。

### 6.1 要准备的 CMDB 数据

1. 圆心实例存在，当前用户对它有查看权限。
2. 希望出现在图上的邻居，已在 CMDB 里建好实例关联（资产详情 → 关联关系，或各专题视图里维护）。
3. 无权邻居会被裁掉，不会出现。
4. 告警角标：邻居实例有 `monitor_id`，且监控中心有活跃告警。没有 `monitor_id`、或已监控但 count=0，都**不显示角标**，也不会画成「0 条告警的健康点」。

### 6.2 在运营分析里怎么配

1. 打开仪表盘或大屏。
2. 添加组件 → **内置场景** → **关联拓扑**。
3. 选 **资产模型**，再选 **资产实例**（`inst_uuid`）。两项都必填，否则不能保存。
4. 不需要选数据源、深度或设备列表。深度固定为 3，与资产详情轻量拓扑一致。

### 6.3 常见空态

| 现象 | 原因 |
| --- | --- |
| 「请选择要展示的资产实例」 | 还没选圆心 |
| 「暂无关联」 | 该实例没有可见邻居（没建关联，或邻居都无权） |
| 「实例不存在 / 无权限查看该实例」 | UUID 无效，或当前用户对圆心无权 |
| 有邻居但没有告警角标 | 邻居未绑定监控，或当前没有活跃告警 |

## 7. 配置对照（最短路径）

**只想先看到内置大屏**

1. 确认 `batch_init` 已跑过。
2. 运营分析大屏目录里打开「3D机房大屏」「3D应用大屏」。
3. 3D 机房：在组件里选一个已配好机柜位置的机房。
4. 3D 应用：CMDB 里至少有可见的应用系统。
5. 网络状态拓扑：在自己的仪表盘或大屏里添加该内置场景，勾选真实网络设备。

**从零配一间能出 3D 的机房**

1. 建 `server_room` → 在机房机柜视图里放入 `rack`，位置用 `A01` 这种格式。
2. 把交换机 / 物理服务器等上架到机柜并填写 U 位。
3. 大屏添加内置场景「3D机房」，配置抽屉可钉默认机房。

**从零配一面能变绿的应用墙**

1. 建应用系统 `system`，用服务树挂应用 `application`，再给应用挂主机 `host`。
2. 主机建立监控关联；当前用户要能读这些监控实例。有可见活跃告警时墙卡按最高级别上色，没有则是运行正常。
3. 大屏添加内置场景「3D应用」。未接入或监控读不了的主机会留在部署架构灰柜里；可见主机只有一部分可读时，墙卡状态行右侧会出现「监控覆盖 m/n」。

**从零配一张有线、能叠色的网络图**

1. 网络设备采集（打开拓扑发现）→ 设备建立监控关联 → 监控侧采接口。
2. 仪表盘 / 大屏添加「网络状态拓扑」，勾选这些设备。

**从零配一张关联拓扑**

1. 在 CMDB 给目标实例建好关联。
2. 仪表盘 / 大屏添加「关联拓扑」，选该模型与实例。
